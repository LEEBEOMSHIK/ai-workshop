# OpenAI·Gemma 저장 비교의 평가·실행 화면 연결

## 후속: 상단 탐색 링크 스타일

사용자는 비교 상세 상단의 상시 밑줄이 오래된 표현처럼 보인다고 피드백했다. 낮은 위험의 CSS 수정으로 분류하고 주 담당이 프론트/문서를 갱신했으며 독립 리뷰어가 영향 범위를 확인했다. `Comparisons.module.css`의 `.page nav .navigationLink`에만 옅은 표면 배경·둥근 경계·hover 강조·기존 토큰을 적용했다. 기존 링크 의미·URL·44px·키보드 포커스와 nav 밖의 원문 인용·목록 제목·저장 성공 링크를 보존했다. 비교 데이터·생성 코드·모델 설정 변경은 없다.

본래 인증 화면에서 상세3개/목록2개 링크의 `text-decoration: none`, 높이44px, Tab 초점2px outline을 확인했다. 목록 제목은 underline을 유지하고 상세→목록→상세 이동도 정상이다. Chrome viewport320/375px에서 상세의 document client/scroll 폭305/305·360/360px, 링크높이44px와 줄바꿈을 확인한 뒤 원래 viewport로 복원했다. 실기기 모바일 확인은 아니다. 사진: `.local-data/project-agent-work/comparison-navigation-style-20261029/navigation-live.png`.

독립 기존 비교 회귀8파일31개는 변경 전 기능 기준선으로 통과했다. 최종 CSS는 독립 specificity/적용범위 리뷰와 위 실제 브라우저 검증으로 확인했고, 전체 TypeScript 및 비교 ESLint도 통과했다. 낮은 영향의 CSS 변경에 구현 문자열을 복제하는 새 테스트는 추가하지 않았다. 기본 Python의 PyYAML 부재는 기존 `backend/.conda/python.exe`로 역할 선택을 수행해 해결했으며, pnpm/Corepack 다운로드 실패 후 설치된 Vitest 실행 파일을 직접 사용했다. 설치·의존성 변경은 없다. 디자인 정본의 [화면 이동 링크](../guidelines/ui-style-guide.md#화면-이동-링크), 적용현황과 ISSUE-00040 후속 이력을 갱신했다.

## 정정: API 왼쪽·로컬 오른쪽으로 대상 위치 고정

사용자는 API 결과를 왼쪽에, 로컬 결과를 오른쪽에만 모으려는 의도라고 명확히 정정했다. 앞선 조건별 구역 분리는 담당자의 해석 오류이며 아래 기록은 당시의 구현·검증 이력이다. 현재 배치 기준은 **대상 → 조건 → 지표**다.

시간과 사용량·비용에서 공급자+모델별 구역을 만들고 각 구역 내부에 첫 요청/반복 열을 둔다. 기존 기록의 최초 대상 순서에 따라 OpenAI API는 왼쪽, Ollama 로컬은 오른쪽이다. 요청 번호는 보존하고 회차만 오름차순으로 표시하며 누락 회차를 생성하지 않는다. 이름 문자열이나 청구 여부로 임의의 원격/로컬 분류를 만들지 않는다. 실제 답변 카드도 같은 공급자+모델 순서를 사용해 반복 실행 순서가 달라져도 좌우가 뒤집히지 않도록 수정했다. 신규 모델 호출·API/저장 관측 변경은 없다.

본래 로그인 화면의 시간표는 API x297.55/로컬843.5에 같은 y205.49, 비용표도 같은 좌우 x와 y2355.01에서 표시됐다. 시간 행은 API3.781/3.347초, 로컬159.723/11.123초로 각 대상에만 속한다. 실제 컴포넌트/CSS의 공개합성 iframe320/375/1280px 페이지와 표에 가로 넘침이 없었고, 좁은 화면은 API 위/로컬 아래를 유지했다. 반응형 증거와 본래 화면 캡처는 `.local-data/project-agent-work/comparison-lanes-20261029/`에 따로 보존한다. 실기기 모바일 검증과 구분한다.

디자인 시스템의 [비교 정보 배치](../guidelines/ui-style-guide.md#비교-결과의-정보-배치)와 [적용 현황](../guidelines/design-system-coverage.md#2026-10-29-비교-대상별-구역-정리)도 사용자 정정에 맞춰 교체했다. ISSUE-00040에는 이전 이력을 삭제하지 않고 해석 오류와 수정 결과를 후속 기록으로 남긴다.

최종 수정본 비교8파일31개(독립6개), 전체 TypeScript·변경 ESLint·독립 리뷰가 통과했다. 새 대상별 테스트2개의 기존 배치 실패를 확인했으며, 독립 검토가 발견한 반복 실행 역순의 답변 좌우 뒤집힘도 실패 재현 후 공유 식별자/정렬로 해결했다. 이전30개 검증을 새 배치의 수용 결과로 재사용하지 않았다.

## 후속: 조건별 비교 배치와 디자인 시스템

사용자가 시간 비교 표의 빠른 인지를 위해 구분된 배치를 요청했다. 기존 실행 순서 중심의 넓은 표와 중복 완료시간 카드를 `ComparisonMetricGroups`로 교체했다. 첫 요청/반복 회차를 각각 제목·경계가 있는 구역으로 나누고, 같은 지표 행에서 각 모델을 비교한다. 시간과 사용량·비용에 동일한 패턴을 적용하며 모델/공급자/요청 번호와 순서를 보존한다. 존재하지 않는 모델 회차를 새 관측으로 채우지 않고, 최초 등장 모델 순서를 유지한다. 실제 답변·인용·품질 판정과 저장 데이터·생성/API 계약은 변경하지 않았다.

당시 비교 표현 정본은 조건 구분, 대상 열/지표 행, 핵심 수치 강조, 단위·미측정/0·미보고·청구 상태 구분을 기준으로 작성했으나 사용자 의도와 달랐다. 현재 [UI 스타일 기준](../guidelines/ui-style-guide.md#비교-결과의-정보-배치)과 [적용 현황](../guidelines/design-system-coverage.md#2026-10-29-비교-대상별-구역-정리)은 위 정정 기준을 따른다.

비교 회귀8파일30개(독립 경계5개 포함), 전체 TypeScript·변경 ESLint·독립 코드 리뷰를 통과했다. 본래 로그인된 비교 상세를 새로고침해 시간/사용량·비용4개 표의 모든 수치와 첫/반복 실제 답변 선택을 확인했다. 새 모델 호출은0이다. 공개 동결 자료와 실제 컴포넌트/CSS의 iframe320/375/1280px에서 페이지와2모델표 가로 넘침0, 좁은 조건 구역의 세로 정렬과 넓은 구역의 동일 행 정렬을 확인했다. 320px의 완료 시간 단위 줄바꿈은18rem 이하 표 여백·열 비율을 토큰으로 보완해4개 완료 수치가 한 줄로 보이도록 수정했다. 실기기 모바일 검증이 아니며3개 이상 모델의 표는 단위 검증만 수행했다.

기록은 `.local-data/project-agent-work/comparison-groups-20261029/`의 독립 테스트·리뷰, `responsive-verification.json`, `comparison-groups-live.png`, 좁은 화면 캡처에 보존한다. 기존 디자인 시스템 ISSUE-00040의 후속 이력으로 원인·수정·검증 경계를 기록한다.

## 후속: 왼쪽 메뉴 진입점 누락 수정

운영 이력: [ISSUE-00044](http://127.0.0.1:5173/admin/system/issues?offset=0&issue=3c5cf1f8-685c-471f-a7f6-2e5395a0f0af). 본래 관리자 화면으로 등록하고 전체 새로고침 후 재조회했다.

2026-10-29 사용자가 비교 결과를 왼쪽 메뉴에서 찾을 수 없다고 보고했다. 화면 내부 링크만 연결하고 공통 `adminMenuGroups` 등록을 누락한 것이 원인이다. 기존 관리자 `RAG 관리`의 `실행 모니터링` 다음에 `모델 비교 결과`를 추가했다. 목록과 하위 상세에서 현재 메뉴가 표시되며 작업소에서는 `관리자` 영역으로 먼저 이동한다. 데스크톱/모바일은 같은 메뉴 정의와 기존 owner 제한을 사용한다.

수정 전 새 메뉴·목록/상세 선택 검사가 3건 실패함을 확인했고, 수정 뒤 독립 navigation 8파일65개·전체 TypeScript·변경 ESLint·diff 검사를 통과했다. 본래 로그인 브라우저에서 왼쪽 메뉴 클릭→비교 목록→저장된 OpenAI·Gemma 상세와 양쪽 `aria-current=page`를 확인했다. 실제 모바일 장치는 재검증하지 않았고 공통 drawer 동작은 기존 자동 회귀 범위다. 제품 변경은 메뉴 등록 한 줄이며 API·모델·저장된 비교 내용은 그대로이고 신규 모델 호출은0이다. 작업 근거는 `.local-data/project-agent-work/comparison-nav-20261029/`의 독립 결과와 `nav-live.png`에 보존한다.

- 요청: 기존 4회 비교의 속도·실제 답변·인용·품질 검토·사용량·비용·상세 분석을 사이트에서 함께 조회한다.

## 제공한 화면

- 평가: `/admin/rag/configurations?tab=comparison&view=stored`의 **저장된 모델 비교**.
- 실행: `/admin/rag/executions`의 별도 비교 기록 링크.
- 공유 목록 `/admin/rag/comparisons`, 상세 `/admin/rag/comparisons/[comparisonId]`.

상세는 첫/반복 요청의 완료 응답 시간, 관측된 로드·입력·출력 시간, 회차별 실제 답변과 인용 원문 링크, 형식/인용 검사와 항목별 의미 검토, 사용량·예상 비용·청구 확인 상태, 분석 7항목과 검증 한계를 표시한다. 작은 화면에서는 4개 완료 시간을 요약 카드로 확인하고 상세 표만 가로 스크롤한다. 기존 다크·청록 토큰, ChoiceGroup, Button과 44px 조작 규격을 사용한다.

첫 토큰 시간은 미측정이다. Gemma 캐시 토큰은 미보고이며 0으로 바꾸지 않는다. OpenAI 예상 비용 USD 0.000667과 실제 청구 미확인을 구분한다. 이 고유 질문에서 OpenAI의 일반 지급 규칙 설명은 충족했고 Gemma는 기존 답변/인용과 같지만 규칙·조건 누락으로 미충족이다. 단일 질문의 두 반복을 모델 전체 정확도로 표현하지 않는다.

## 저장·권한 경계

불변 `rag_comparison_reports`에 별도 저장한다. 기존 실행 건수·평가 통계·기본 승격 게이트에 합산하지 않는다. import/list/detail은 기존 owner 인증과 현재 원문 접근권한을 검사한다. 정확한 원문 버전·projection·index·evidence ID, 내용과 위치를 DB 자료와 대조한다. 같은 소유자/수입 키/본문은 같은 ID로 재사용하고 변경된 본문은 충돌로 거절한다. 저장 후 수정·삭제는 DB trigger로 차단한다.

수입 본문은 파싱 전 2MiB 제한, 명시 Origin·요청 표식, 타입/필드 allowlist, private no-store를 적용한다. 키·계정 잔액·원시 provider 응답·응답 ID·내부 추론은 저장하지 않는다. 원본 SHA는 출처 식별자이며 서버가 실제 모델 수행을 인증한다는 뜻은 아니다.

본래 DB는 private pg_dump 31,778,081bytes를 보관하고 archive 목록을 검사한 뒤 추가 migration을 적용했다. 복원 실험은 하지 않았다. DB 통합 시험은 COMMIT 차단과 outer rollback으로 합성행을 남기지 않았다. 새 모델/임베딩 호출0, 기본 모델/프롬프트/근거 선택/런타임 파라미터 변경0, 새 환경/계정0, commit/push0이다. 관측 조회 기능의 비퇴행 검증이며 모델 답변 품질을 다시 평가한 것은 아니다.

시작 시점2237파일 중2226개 SHA 동일, 허용 범위11파일 변경, 누락0을 확인했다. 기존 결과와 ledger, 검토한 import 파일 SHA도 보존됐다. 공개 자료를 잠시 제공한 반응형 검증 서버와 탭은 종료했고 본래 API는 유지한다. 최초 비교 목록 진입은 `/login?next=%2Fadmin%2Frag%2Fcomparisons`로 이동해 기존 로그인을 기다렸으며, 아래 후속 실제 수용으로 마감했다.

## 실제 수용 완료

기존 관리자 계정으로 로그인한 뒤 평가의 저장된 모델 비교에서 준비된 JSON을 저장했다. [실제 보고서](http://127.0.0.1:5173/admin/rag/comparisons/79efa1f6-58d0-4833-83a3-dd4a6bba600d)의 ID는 `79efa1f6-58d0-4833-83a3-dd4a6bba600d`다. 같은 파일 재수입은 같은 ID와 목록1건을 유지했다.

상세의 4개 완료시간, 첫/반복 실제 답변·품질 판정·인용, 입력/출력 토큰과 예상 비용·청구 미확인을 확인했다. e16을 눌러 본래 PDF2페이지의 문맥 강조 위치로 이동하고 복귀했다. 실행 목록515건의 별도 비교 링크→비교 목록→같은 상세→전체 새로고침에서도 결과가 복원됐다. DB 읽기 전용 재조회에서4회·28근거를 포함한 전체 payload가 검토한 import와 동일하고 canonical SHA는 `9d3a5f1cf219a96da14b762928c92a784e5c43dcd058603a3fc2c3d903a9a731`이다. 실제 저장 뒤에도 기존123테이블은 내용 해시가 같았다. 이후 허용된 ISSUE-00038 진행 이력 및 ISSUE-00043 등록은 별도 관리 쓰기다.

실제 증거는 작업 폴더의 `live-browser-verification.json`, `stored-report-verification.json`, `comparison-live.png`, `comparison-live-source.png`에 남겼다. ISSUE-00038은 기존 성능·품질 미완료 상태를 보존하며 진행 이력만 추가했다.

준비 파일은 `.local-data/project-agent-work/comparison-site-20261029/openai-gemma-comparison.import.json`이며 43,324bytes, SHA `bb224d1dfd9a24afcb93e99c8c735229737be2e46ec5a356bb2bf3a9d6fe6151`다. 기존 원본 결과/ledger/code는 수정하지 않는다. 검증 영수증·rollback 검사·독립 JUnit·반응형 좌표·private 백업도 같은 작업 폴더에 보존했다. 이 폴더나 보고서를 공개 정적 경로로 복사하지 않는다.

## 사용자 보고: 본래 Next 모듈 빌드 오류

사용자가 `ConfigurationStudioPage.tsx:11`에서 `../comparisons/ComparisonListPanel`을 찾지 못하는 실제 Next 오류 화면을 보고했다. 앞선 타입/단위 검사와 별도 컴포넌트 렌더 검증은 본래 Next 경로의 빌드·브라우저 수용을 대체하지 못했다. 이를 이번 전달의 검증 누락으로 기록한다.

파일은 정확한 경로에 존재하고 named export도 일치한다. 독립 TypeScript Bundler 해석에서 새 모듈의 상대 import45개가 모두 해결됐으며 symlink·대소문자·ignore·alias 이상은 발견하지 못했다. 본래 프론트엔드 PID13864와 부모5092는2026-10-15부터 실행 중이었고, 실제 개발 로그에10월29일15:18경 해당 오류가 남았다. 정적 경로 오타나 파일 유실의 근거는 없다. 개발 서버/브라우저의 모듈 갱신 상태가 조사 대상이며 내부 watcher 오류를 확정한 것은 아니다.

오류 로그와 프로세스 식별자를 보존한 뒤 해당 프로젝트의 확인된 Next 부모/서버/PostCSS 자식4개만 종료하고 같은 설치·설정·5173포트로 재기동했다. `.next` 삭제·의존성 재설치·API/DB/모델 변경은 하지 않았다. 재기동 뒤 평가 경로는307, 로그인 화면은200으로 정상 응답했고 Next 서버 stderr는 비어 있다. 이 시점은 로그인 전 확인이며, 별도 산출물의 Next 실빌드와 로그인 이후 화면 검증 결과는 아래와 같다.

로그인 후에는 본래 Next의 평가·실행·비교 목록·비교 상세 모두 정상 표시됐다. 오류를 재현한 같은 구성 화면의 실제 패널·JSON 저장 성공을 확인했으므로 이번 개발 화면 장애는 복구 완료다. 재발 시점의 모듈 변경/브라우저·watcher 내부 상태는 추가 원인 자료가 필요하며 특정 Next 내부 결함으로 단정하지 않는다. 재발 대응과 검증 누락은 [ISSUE-00043](http://127.0.0.1:5173/admin/system/issues?offset=0&issue=393dd216-4448-45f2-9c4e-e10fcc9c4b59)에 보존했다.

독립 Next production compile은 별도 `.next/instances/comparison-20261029` 산출물에서 약359초 동안 초기 빌드 단계 이후 진전이 없어 작업 소유 프로세스만 종료했다. 성공으로 계산하지 않는다. 잔류 프로세스0·`tsconfig.json`/`next-env.d.ts` 바이트 동일, 산출물과 중단 로그는 보존했다. 이는 실제 개발 서버 화면의 성공과 구분되는 미완료 생산 빌드 검사다. 제품 소스·설정 수정이나 새 모델 호출은 없다.
