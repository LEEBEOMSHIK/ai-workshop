# ADR-0048: 화면과 분리된 대화 실행

- 상태: 구현·본래 API 반영 및 실제 화면 이동·탭 종료 수용 검증 완료 (2026-10-26)
- 문제: ISSUE-00039
- 범위: RAG Conversations, 앱 조립 계층, 대화 화면

## 문제와 목표

대화 POST가 전체 검색·생성을 기다리며 화면 이동과 HTTP disconnect가 취소에 연결된다.
검색의 동기 임베딩·근거 선택도 API 이벤트 루프를 점유할 수 있다. 사용자는 긴 질문을
보낸 뒤 다른 대화·파일함·화면을 이용하고, 돌아와 저장된 상태와 답변을 확인할 수 있어야 한다.

## 결정

1. 프론트는 `Prefer: respond-async`로 접수 후 응답을 요청한다. 서버는 기존 원자적
   예약·사전 검증 뒤 기존 `ConversationDetail`과 202를 반환한다. 헤더 없는 호출은
   기존 동기 계약을 유지한다. 조회/취소 API와 저장 스키마를 재사용한다.
2. 앱이 소유하는 실행 관리자가 독립 작업 루프에서 기존 start/submit 코어를 수행한다.
   DB session·engine·검색 클라이언트·실행 의존성은 작업 안에서 생성하고 종료까지 유지한다.
   API 이벤트 루프와 분리해 동기 검색 작업 동안에도 다른 화면의 API를 처리한다.
   기존 로컬 모델의 프로세스 단위 admission을 보존하며 모델·입력·검색·인용 정책은 바꾸지 않는다.
3. 접수 신호는 원자적 예약이 성공한 뒤 전달한다. 동일 request ID의 재접수는 기존
   digest/revision 검증을 통과해 현재 상태만 반환하며 자동으로 모델을 다시 실행하지 않는다.
4. 화면 이동·새 대화·탭 종료·새로고침은 서버 실행 취소가 아니다. 명시 취소와 대화 삭제만
   기존 취소 계약을 사용한다. 접수 전 응답 손실도 원래 작업의 수명을 종료하지 않는다.
5. 선택한 대화가 실행 중이거나 종료 확인 중이면 현재 권한으로 상태를 자동 조회한다.
   화면 소유권이 바뀌면 조회만 중단하고 늦은 결과는 새 화면에 적용하지 않는다.
   다음 질문의 입력은 허용하되 같은 대화의 전송은 기존 `blocksNextTurn` 동안 제한한다.
6. 서버 정상 종료는 소유 작업을 취소하고 정리까지 기다린다. 프로세스 강제 종료 뒤
   모델 작업을 자동 재시도하지 않으며 기존 만료/중단/종료 미확인 계약을 유지한다.
   브라우저 이탈 뒤 계속 실행되는 보장과 서버 재시작을 넘는 작업 복구는 구분한다.

## 대안과 제한

브라우저에서 POST만 유지하면 탭 종료와 서버 의존성 수명 문제를 해결하지 못한다.
요청 의존성을 그대로 `create_task`에 넘기거나 `shield`만 적용하는 방식은 배제한다.
기존 Platform 작업은 Asset 검증/색인 계약이며 생성 평가 작업은 frozen 평가 계약이므로
일반 대화에 억지로 재사용하지 않는다. 별도 영속 큐·migration·자동 재시도는 추가하지 않는다.

현재 요청 한정 생성 입력 진단은 저장 범위를 확대하지 않는다. 백그라운드 완료는
기존 대화 응답과 권한 검증된 실행 기록에서 확인한다. 품질 통과나 활성 연결 승격을 뜻하지 않는다.

## 검증

느린 합성 실행 중 접수 응답과 다른 API 응답, 화면 이동 후 완료, 복원 자동 조회,
명시 취소·중복 접수·실패·권한 철회·늦은 결과·앱 종료를 검증한다.
기존 DB에서 rollback 통합 검증을 수행하고 관련 테스트·타입·린트·API 계약을 확인한다.
초기 구현 검증은 실모델을 호출하지 않았다. 이후 사용자의 명시적인 일반 연결 복구·실제
수용 요청으로 새 공개 질문2건·Gemma2회·자동 재시도0회 범위를 실행했다.
동일 모델·입력·근거 정책의 구성에 정상 검색 평가를 반영하고 도메인 연결4를 활성화한 뒤,
첫 질문의 파일함 이동·복귀와 두 번째 질문의 탭 종료·재접속에서 자동 결과 표시를 확인했다.
입력·답변·근거28개·인용은 기존 기준선과 같았으며 기존 생성 정답0/2와 첫 입력134.335초의
한계는 남는다. 전역 기본값은 변경하지 않았다. [실제 수용 결과](../worklogs/2026-10-26-conversation-live-connection.md).
