# 문서 외부 전송 승인 복구 흐름

- 상태: 상세 계약 사용자 승인(2026-09-10), 구현 중
- 대상: 문서 버전은 유지하고 승인·철회·재승인 이력을 분리한다.

## 확인된 문제

현재 `rag_codex_evidence_approvals`는 asset revision을 기본키로 사용한다.
승인 행의 revoked_at을 설정하면 같은 revision에 새 승인을 넣을 수 없다.
UI도 철회된 revision의 승인 동작을 영구 차단한다. 같은 파일을 업로드하면
SHA-256 중복 방지가 작동하므로 파일 수정/복제는 올바른 복구 수단이 아니다.

## 사용자 흐름

1. 문서 카드에 미승인·승인됨·승인 취소·승인 요청 중 상태를 구분한다.
2. 권한 있는 사용자는 미승인/취소 문서에서 승인 또는 다시 승인을 선택한다.
3. 문서명·문서 버전·공급자·자료 분류·외부 전송 고지를 확인하고 명시적으로 승인한다.
4. 승인 취소 이력은 남고 새 승인 이력이 추가된다. 파일·해시·색인·임베딩은 그대로다.
5. 권한 없는 사용자는 접근 가능한 문서에 한해 승인을 요청한다. 요청은 승인이나 실행이 아니다.
6. 승인 완료 후 준비 상태를 재조회한다. 평가·도메인 연결은 자동 통과시키지 않는다.

UUID와 SHA-256은 접힌 기술 상세에 둔다. 승인 이력에는 시각·행위·처리 주체와
승인 대상 버전·공급자를 보여주며 문서 본문은 감사 로그에 복제하지 않는다.
문서 내용이 바뀌면 새 문서 버전은 별도 승인이 필요하다.

## 저장·동시성 계약

- 문서 버전과 공급자를 기준으로 현재 승인 상태와 증가하는 승인 세대를 관리한다.
- 승인/철회는 별도 불변 이벤트에 기록한다. 기존 승인·철회 시각과 승인자는 이관 시 보존한다.
- 기존 데이터에 없던 철회 주체는 추정해서 채우지 않고 미기록으로 표시한다.
- 요청은 예상 승인 세대를 포함한다. 화면 조회 후 상태가 바뀌면 409로 재조회하도록 한다.
- 중복 제출은 요청 식별자로 멱등 처리한다. 요청자/문서/공급자별 대기 요청은 중복 생성하지 않는다.
  다른 요청자의 요청 존재·처리 내역을 일반 사용자에게 노출하지 않는다.
- 다른 요청이나 관리자 직접 승인으로 이미 승인된 문서는 현재 승인 세대·해시·분류가
  명시적 처리 입력과 모두 일치할 때 대기 요청을 완료할 수 있다. 새 승인 세대는 만들지 않는다.
  요청의 과거 처리 결과와 문서의 현재 승인 상태는 분리해 표시한다.
- 현재 상태와 이벤트는 한 트랜잭션에서 변경한다. 기존 전송 정책/공간/asset/document 잠금 순서를 유지한다.
- 기존 승인 테이블의 불변 트리거를 해제해 취소 행을 덮어쓰지 않는다. 별도 현재 상태/새 승인/이벤트 저장으로 이관한다.
- 원문과 새 문서 버전을 생성하거나 파싱·임베딩 작업을 발행하지 않는다.

## 보안 경계

재승인이 과거 일회성 모델 호출 승인을 되살려서는 안 된다.
호출 승인에는 근거별 승인 세대를 결합하고 실행 직전 현재 세대/상태와 비교한다.
취소 후 같은 해시로 재승인해도 이전 세대의 대기 호출은 거절한다.
새 호출 binding 버전을 사용하며 승인 세대가 없는 기존 v2 대기 호출은 실행 불가로 처리한다.
과거 호출에 현재 승인 세대를 소급해서 채우지 않는다. 이관 시 실행/승인 writer를 중지하고
새 스키마·검증 코드로 함께 전환한 뒤 재개한다. 구버전 서버가 세대 검사 없이 실행하지 못하게 한다.
이미 외부로 전송된 자료는 승인 취소로 회수되지 않음을 안내한다.

공간 전송 금지, 현재 문서 접근권한, READY/활성 상태, 공급자와 구성 정책 검사는 유지한다.
승인은 기존처럼 비활성 READY 버전에도 가능하지만 실제 실행은 현재 활성 버전만 허용한다.
승인 담당자도 해당 문서의 현재 접근권한이 필요하며 마스터가 개인 공간 경계를 우회하지 않는다.
재승인은 기존 정책을 덮지 않는다. API/클라이언트가 공급자·actor를 임의로 위조하지 못하게 한다.

Codex는 ADR-0017의 개인 owner 전용을 유지한다. 일반 사용자 승인 요청은 자료 검토 요청이며
Codex 실행 권한을 부여하지 않는다. 기술 configure 권한도 외부 전송 승인 권한으로 간주하지 않는다.
기존 일반 사용자 문서 접근 경로와 요청 관리 기능을 추가할 때 현재 권한을 매 요청 재검사한다.

## 단계와 영향

1. 현재 Codex 관리 경로: 이력/세대 migration, 승인·철회 CAS, 호출 binding 변경, 조회 DTO,
   관리자 재승인/이력 UI. 기존 취소 문서로 정상 복구 가능한 최소 단위다.
2. 일반 사용자: 문서 접근 경로에 승인 요청·진행 상태·관리자 처리함 연결.
   요청자에게 다른 사용자/비공개 공간 정보가 노출되지 않도록 DTO와 권한 테스트를 추가한다.

다른 공급자의 실제 전송 어댑터 확장은 이 작업에서 자동으로 하지 않는다.
범용 데이터 식별은 공급자를 구분하되 첫 실제 적용 대상은 현재 Codex 경로다.
상세 API/migration 목록과 실행 순서는 문서 확인 후 구현 계획에서 확정한다.
실제 DB migration 적용·서버 재시작과 사용자의 문서 승인 클릭은 코드 검증과 별도로 고지한다.

## 성공 기준

- 동일 문서 승인→취소→재승인 후 이전 이력이 보존되고 파일/색인 식별자가 불변이다.
- 취소·재승인 전후 오래된 호출/중복 제출/경합이 안전하게 거절 또는 멱등 처리된다.
- 잘못된 해시·문서 버전·공급자·권한/정책 거절을 우회하지 못한다.
- 일반 사용자의 요청은 전송·모델 실행을 유발하지 않고 승인자 권한도 얻지 못한다.
- UI는 처리 중/성공/오류/권한 부족을 구분하고 결과 재조회 실패를 승인 실패와 혼동하지 않는다.
- 기존 승인/철회 데이터 migration 및 검색·평가·호출 검증 회귀를 격리 PostgreSQL에서 확인한다.
- 프론트 Vitest, Python 단위/통합 테스트, TypeScript/mypy·린트·OpenAPI 일치 검사를 수행한다.
