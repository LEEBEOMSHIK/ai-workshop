# 새 질문의 Terra·Gemma 비교와 SDK 생략 관측 수용

## 사용자 요청과 범위

이전 질문과 다른 공개 합성 질문을 두 모델에 동일한 근거와 함께 전달하고 각각 첫 요청과 동일 입력 반복을 비교한다. 기존 모델·프로파일·설정·계정·자료는 보존한다. 새 평가 자료/실행/비교 결과만 정상 인증 UI로 추가한다. SDK 고정 평가의 `history=skipped/not_executed`가 새 실행 화면에서 ‘이전 대화 준비 생략’으로 표시되는지 확인한다.

질문: **AM-SYN-101의 환매를 영업일 15:00까지 신청한 경우와 15:00이 지난 뒤 신청한 경우, 접수일과 적용 기준가격을 어떻게 정하나요? 정확한 날짜를 알려면 어떤 정보가 더 필요한가요?**

고정 rubric: 15:00 정각 포함, 마감 내 당일/마감 후 다음 영업일 접수, 두 조건 모두 접수일 기준 T+2 기준가격, 신청일·영업일 달력 필요, 근거 없는 특정 날짜 단정 없음. 인용 지원성과 완전성을 별도로 판정한다. 기존 지급일 질문의 답변을 새 질문의 정답/동일성 기준으로 사용하지 않는다.

## 수행 순서와 한도

1. 기존 공개 fixture와 현재 원문 권한을 재검증하고 새 질문의 평가 자료를 정상 UI에서 고정한다. 기존 비기본 직접 답변 후보를 사용해 서버 이력 수집 없는 평가 2회를 접수한다.
2. 단일 실행기에서 정확한 새 run만 실행한다. HTTP 전송 전 새 질문/공개 본문/근거/입력 한도와 전체2회·attempt당1회·재시도0을 검사하고 내구성 ledger를 쓴다. 첫 입력과 반복 입력의 digest가 다르면 전송 전에 중단한다.
3. 검증된 실제 Gemma HTTP 입력의 system/user 문자열과 근거를 Terra Responses input으로 동일 전달한다. 응답 스키마 표현 차이는 기존 어댑터를 따르며 모델 ID `gpt-6.1-terra`, reasoning none, temperature0/top_p1, 출력512를 명시한다. 호출순서는 결과에 기록한다.
4. 새 승인 범위는 이번 사용자 직접 요청에 따른 Gemma2회/Terra2회, 자동재시도0·직렬 실행이다. 이전 종료 예산을 재사용하지 않는다. Terra 계산 비용 상한USD0.05, 사용량 누락/timeout은0비용으로 취급하지 않고 미확인 예약을 남긴다. 실제 토큰은 품질 판정보다 먼저 기록한다. API 키는 기존 비교 전용 env에서 읽고 출력하지 않는다.
5. 새로운 실측을 저장 비교 보고서로 연결하고 새 실행 화면의 history 생략·완료 상태·답변/원문 인용·화면 복귀를 확인한다. 실제 청구 대조가 불가능하면 응답 token 기반 계산 비용과 명확히 구분한다.

## 공정성과 해석

모델 HTTP 완료 시간과 검색/근거 준비를 포함한 전체 SDK 시간을 분리한다. 비스트리밍 첫 토큰 시간은 미측정으로 표시한다. 첫 요청을 cold start로 단정하지 않으며 Ollama load/prompt/eval 시간·토큰과 반복 입력 재사용 조건을 기록한다. 두 번의 동일 질문 실행은 재현성 확인이며 전체 질문 정확도·P95·일반 추론 우열의 증명이 아니다. 기존 Luna 결과와 새 Terra 결과의 모델 차이도 기록한다.

## 역할과 검증

높은 위험의 외부 API 실측/기존 DB 추가 기록 작업이다. AI/테스트 담당은 새 질문 계약·루브릭, 백엔드/RAG 담당은 SDK 경로·호출 가드, 독립 reviewer/privacy 담당은 공개 입력·예산·품질·비용, 메인은 DB/인증 UI·통합·실제 실행·기록을 맡는다. 운영 기본값·UI 개편·학습·서비스 재기동은 제외한다. 준비 코드는 `.local-data/project-agent-work/terra-gemma-new-question-20261030/`에 두고 기존 도구는 보존한다.
