# ISSUE-00045 원문 정의 기반 영업일 인용 검증

- 범위: [설계](../superpowers/specs/2026-10-30-relative-day-citation-design.md), [계획](../superpowers/plans/2026-10-30-relative-day-citation.md), [ADR-0035](../decisions/0035-rag-exact-value-canonicalization.md).
- 사용자 승인: 기존 다음 작업의 실행. 신규 모델 호출/외부 전송 0회. 기존 모델·프롬프트·프로파일·기본값·과거 응답과 판정 보존.
- 역할: 메인 요구/RAG/통합·기록, 백엔드·테스트 구현, 분리된 통합 검증·코드 리뷰. UI·모델 런타임·DB 구조 변경 제외. 기존 변경이 많은 본래 checkout을 해시/파일 범위로 보호했다.

## 수정

기존 schema1/2 검사는 원문 `T+2`와 답변 `2영업일`을 서로 다른 값으로 보아 거절했다. `CitationValidator`에 누락 값이 있을 때만 호출하는 순수 helper `relative_day_citations.py`를 추가했다. 기존 `exact_values.py`와 schema3 계산·증명 경로는 변경하지 않았다.

helper는 **같은 주장에 실제 인용한 근거**에서 동일 문서/버전/projection/chunk/page/section/source의 연속 정의, 명시적 기준점과 다음 영업일부터 N일을 세는 규칙, 유일한 PDF 대상 머리·항목·값의 행/열 관계를 확인한다. 주장 자체의 기준점·시작·기간·상대 오프셋·항목과 명시 상품명도 일치해야 한다. 부정·상충 정의, 잘못된 기간/단위/상품/표 위치, 출처 혼합·누락·재정렬·추가 문장은 새 허용을 얻지 못한다. 원문·주장·citation ID와 기존 실패 상태/코드는 그대로다.

원문 정의는 일반 기준 문자와 접수일 등 명시된 기준명을 사용하며 숫자나 상품/모델을 하드코딩하지 않았다. 합성 `R/검수일/6`도 검증했다. 지원하는 한국어 전체 문장 문법과 PDF 위치 조건은 의도적으로 좁다. 다른 동치 문구를 일반적으로 이해하는 기능은 아니다.

## 저장 응답 재생

새 질문 비교의 동일 28근거·원시 응답을 기존 파서와 수정 검증기에 재생했다. 응답을 재생성하거나 과거 비교 보고서를 수정하지 않았다.

| 저장 응답 | 기존 자동 검사 | 수정 검사 | 의미 판정 |
| --- | --- | --- | --- |
| Terra 첫 요청 | 거절 | 수용 | 기존 원문 의미 검토 통과 유지 |

모든 claim 문자열·citation ID가 그대로임을 검증했다. 기존 숫자 검사에 없던 Gemma의 의미 오류까지 이번 수정이 해결한 것으로 보고하지 않는다. 검사기는 질문을 받지 않으므로 생략된 상품이나 `두 경우 모두`의 질문 조건 전체를 증명하지 못한다.

## 검증

- 새 단위 51개: 변경 전 5실패/46통과 → 수정 후 통과. 실제 Terra 두 표현의 schema1/2, 일반 기준 문자 사례와 거절 경계 포함.
- 새 단위+기존 citation/짧은 수치 검사 161개 통과.
- 독립 저장 재생/변이 57개와 기존 citation/numeric catalogue/validation 69개, 합계126개 통과. 위 검사와 중복 범위를 포함하며 합산하지 않는다. 독립 검토의 차단 결함 없음.
- 변경 3개 Python 파일 Ruff 및 strict Mypy 통과. 최초 긴 줄 2곳과 잘못된 작업 디렉터리의 tests import 타입 오류를 고친 뒤 최종 검사 통과를 별도 보존했다.
- 원시 응답·원장·비교 import·semantic review 등 기존 9파일과 `exact_values.py` SHA 보존을 독립 확인했다.
- 서비스 정책·provider 부족 근거·숫자 생성/검증·schema2/3 파서의 코어 6파일 137개 통과(4.86초). 실제 모델 대신 fake runtime/MockTransport를 썼다.
- 전체 generation 폴더의 추가 확장 검사는 출력 없이 5분 이상 지속되어 중단·미집계했다. 제한 환경의 첫 코어 검사도 같은 무출력 지연으로 중단했다. 동일 코어 6파일은 승인된 제한 외부 실행에서 즉시 통과했으며 제한 환경의 async 초기화 제약과 일치하는 관측이나 정확한 정체 위치/원인은 확정하지 않는다. 중단 증거와 최종 결과를 별도 보존했고 잔존 테스트 프로세스가 없음을 확인했다.

## 본래 환경

시작 시 본래 PostgreSQL/Redis/Elasticsearch는 정상이나 웹/API는 꺼져 있었다. 기존 Next 실행 명령과 승인된 Conda API 실행기로 각각5173/18000을 시작했다. 새 환경·계정·DB·migration·모델 실행은 만들지 않았다. 실제 관리자 로그인 상태로 ISSUE45 상세 조회에 성공했으며 API health/ready가 각각ok/ready다.

본래 DB를 READ ONLY로 전후 조사해 **124개 테이블·162,077행의 내용 해시가 모두 같음**을 확인했다. `.env`·스키마·승격 gate도 보존했다. 이 검사는 아래 이슈 이력 편집 전이며, 정상 관리 화면으로 수행하는 이슈 변경은 별도다.

증거는 비공개 `.local-data/project-agent-work/citation-relative-days-20261030/`의 RED/GREEN·정적 검사 출력, 독립 `review.md`/원본 해시/재생 테스트, DB 전후·검증 JSON, runtime receipt와 `issue45-verified.png`에 있다. 본래 API 실행 경로·시작 시각과 수정 파일 해시를 남겼다. 실제 새 모델 생성 품질·속도 재측정은 수행하지 않았다.

## 기록과 후속
