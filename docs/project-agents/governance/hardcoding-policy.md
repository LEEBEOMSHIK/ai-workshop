# 하드코딩 방지 정책

## 변경 가능한 리터럴과 민감값 금지

환경별 URL, 자격 증명, 토큰, 비밀값, 테넌트·사용자 ID, 모델명, 가변 한계값과 기능 노출 정책을 소스에 직접 넣지 않는다. 로그·예제·테스트 픽스처에도 비공개 본문과 실제 비밀값을 넣지 않는다.

## 허용되는 프로토콜과 도메인 불변식

표준 HTTP 상태, 고정 파일 시그니처, 불변 상태 전이, 안정 오류 코드, 명시된 권한 경계처럼 변경이 계약 변경을 뜻하는 값은 코드 가까이에 둘 수 있다. 허용 여부와 근거를 문서화하고, 설정으로 위장해 불변식을 흐리지 않는다.

## 프론트엔드 기능·Lab 레지스트리와 디자인 토큰

React route, 메뉴, 기능과 현재 활성 Lab은 명시적 레지스트리에서 선택한다. 색상, 간격, 타이포그래피와 반응형 값은 디자인 토큰을 사용한다. 아직 시작하지 않은 Lab의 가짜 메뉴·경로·상수는 만들지 않는다.

## 백엔드 typed settings, enum과 도메인 정책

FastAPI와 worker의 환경 의존 값은 검증되는 typed settings에서 읽는다. 상태, 유형, 권한과 재시도 정책은 enum 또는 도메인 정책으로 명명하고, handler에 문자열 비교나 숫자 정책을 흩뿌리지 않는다.

## DB 명명된 식별성과 repository 조회

스키마 이름, 제약, 인덱스, migration ID와 쿼리의 업무 식별자는 이름을 가진 모델·migration·repository 경계에서 관리한다. 호출자가 임의 SQL이나 매직 ID로 소유권과 권한 필터를 우회하지 않는다.

## 인프라 환경과 검증된 배포 설정

Docker, Compose, 포트, 이미지 태그, 리소스 한도와 외부 endpoint는 환경별 검증 설정으로 제공한다. 안전한 기본값, 시작 시 검증, 회복 절차를 함께 정의하고 배포 파일에 개인 환경 경로를 박아 넣지 않는다.

## AI 모델 레지스트리와 버전 프로파일

모델과 provider는 레지스트리에서 선택하고, 색인·검색·생성은 버전된 profile로 분리한다. 임베딩·청킹 변경은 새 호환 색인 버전을 만들며, LLM만 바꿨다고 검색 색인을 재구축하지 않는다.

## 공개 합성 테스트 픽스처

테스트 데이터는 공개 또는 합성 데이터만 사용한다. 의미가 있는 식별자는 fixture builder와 명명된 상수로 표현하고, 운영 문서·계정·개인정보를 복사하지 않는다.

## 구현 인계 체크리스트

인계 전에 담당자는 변경 가능한 값의 설정 위치, 불변식의 근거, registry·profile·migration 영향, 비밀값 부재, 합성 fixture 사용, 검증 결과와 남은 운영 결정을 기록한다. 검토자는 이 목록을 근거로 하드코딩 우회가 없는지 확인한다.
