# 문제 이력 상위·하위 카테고리

## 승인 범위와 작업 분담

사용자는 기술별 상위와 세부 기능별 하위의 2단계 분류를 승인했다. 기존 문제와 문서 버전 연결을 유지하면서 DB·API·화면·최초 이관을 함께 변경한다. 백엔드/프론트 구현과 독립 통합검증을 분리한다. 기존 본래 DB·계정·체크아웃을 사용한다.

## 성공 기준

- 기존 8개 분류는 같은 ID의 하위로 유지하고 RAG 6개/공통 플랫폼 2개로 묶는다.
- 상위만 필터하면 하위 전체를 조회한다. 하위 목록은 선택 상위에 종속된다.
- 문제 배정은 하위만 허용하고 신규 배정 시 상위·하위 활성 상태를 확인한다.
- 순환·3단계와 기존 문제/하위 관계를 깨는 전환을 차단한다.
- 원본·대화·문서 버전·문제 수량과 ID를 보존하고 검증 쓰기는 롤백한다.

## 실행 순서

1. 실패 테스트 → DB parent 관계·0052 migration·service/API·필터 구현.
2. 실패 테스트 → 상위/하위 선택·관리·경로 표시 구현.
3. 최초 이관 호환, 생성 타입·린트·타입·독립 리뷰.
4. 본래 DB 백업·수량/ID 기록 → migration → 롤백 통합 검증 → API 재시작·실제 조회.
5. 작업 보드·관리 규칙·검증 결과 갱신 및 이번 변경 commit/push.

## 적용·검증 결과

- 본래 DB0051 백업 `.local-data/backups/20260927-issue-history-pre0052.dump` 생성 및 archive catalog 확인 후 0052 적용.
- 2개 상위 + 기존 8개 하위. 기존 하위 ID/문제 ID·배정/문서 연결·버전 해시 보존을 적용 전후 대조했다. 이관된 하위 revision은 1 증가한다.
- 단위22건, 본래 DB 롤백 통합8건(서비스·직접 SQL 제약 포함), 프론트/내비게이션47건 통과. 테스트 데이터 잔존 없음.
- Python/TypeScript 타입 검사, Ruff/ESLint, 생성 OpenAPI 타입 일치 및 문서 링크 검사 통과.
- 마스터 브라우저에서 RAG6개 → 검색·근거1개 → 공통 플랫폼2개 조회, 상위 변경 시 하위 초기화, 경로 표시·관리 진입과 DB 문서 버전1 조회를 확인했다.
- 기존 API18000을 재시작해 반영했다. 실제 문제·원본·문서 내용은 편집하지 않았다.
- 데스크톱 배치 확인 중 기본 파란색 링크 대비와 목록 카드 밑줄을 보완했다. 모바일 실기기 검증은 포함하지 않았다.
