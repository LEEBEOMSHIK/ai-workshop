# SDK 대화 문맥 관측 보강 (2026-10-27)

ISSUE-00035의 대화 턴 실행 연결, 최종 채택 문맥과 질문 문맥화 기록을 구현하고 본래 API에 반영했다. 기존 문맥 선택과 HTTP 입력·답변/인용 계약을 보존하는 관측 변경이다. 실제 모델 호출은 0회이며 새 연속 질문의 답변 품질 수용은 남는다. 목록/스레드 성능 실험 보류는 유지한다.

## 원인과 변경

- 실행 상세에서 같은 대화의 다른 질문으로 이동하기 어려웠고 최종 모델 문맥으로 채택된 메시지·출처·제외 이유가 저장되지 않았다. 기존 권한 조회를 이용한 질문별 실행 탐색을 추가했다. 현재 표시는 턴 ID와 연결된 실행 ID가 있으면 함께 비교하며 권한이 가려진 질문이나 실행 없는 턴에 링크를 만들지 않는다.
- 서비스가 준비한 마지막 20개 메시지에서 기존 ContextPolicy가 실제 선택한 suffix를 관측한다. 객체 동일성을 사용해 중복 문장을 잘못 연결하지 않고 토큰 계산을 다시 호출하지 않는다. 서버가 가진 의존 턴 ID만 private scope로 전달하고 역할·메시지 수·출처 순서가 맞지 않으면 출처를 추정하지 않는다.
- request stage의 선택형 `history_selection`에 채택 여부·메시지/토큰 한도·제외 이유를 저장한다. 이는 준비 이전의 모든 자격 필터 탈락 사유를 기록하는 기능은 아니다. Q/A 쌍과 메시지 수를 구분한다.
- SDK 로컬 프로파일의 질문 문맥화 stage에 실제 전송 HTTP 입력·지침과 안전성 검사를 통과한 최종 출력을 기록한다. 모델 식별자·URL·인증 헤더는 포함하지 않는다. 실패·형식 위반·추론 출력은 본문/해시를 보관하지 않고 불완전 상태로 남긴다. 허용된 Ollama reasoning 부가값은 기존처럼 버리며 업무 결과는 바꾸지 않는다.
- 상속된 실행 observer가 있어도 `include_diagnostics=false`이면 비공개 단계 수집을 놓치던 분기를 수정했다. 공개 응답 진단은 계속 꺼져 있고 비공개 관측만 기존 recorder에 전달된다.
- 문맥화와 SDK 전체 본문은 항목당 32,768자·합계 131,072자를 공유한다. 저장/재조회 시 길이·해시·단계·원 대화 의존 관계와 현재 권한을 확인한다. 반복 summary 계산에 전체 검증을 추가하지 않고 현재 읽기 경계에서 검증한다. 과거 미기록 본문은 복원하지 않는다.
- 화면은 다크·청록 토큰, 접힌 문맥 패널, 최대 높이의 턴 목록, 줄바꿈·키보드 초점을 사용한다. 실제 화면에서 발견한 실행 목록/기존 대화 이동 링크의 약 23.33px 높이를 44px로 보완했다.

공개 계약은 [ADR-0049](../decisions/0049-conversation-context-observation.md), 구현 순서는 [계획](../superpowers/plans/2026-10-27-sdk-context-monitoring.md), UI 적용 현황은 [디자인 시스템 목록](../guidelines/design-system-coverage.md)을 따른다. DB migration·의존성 설치·새 계정/환경·프로파일 변경은 없다.

명령은 기존 Conda 활성화와 `Resolve-ApprovedLocalPython` 뒤 작업 폴더의 `run-qa-regression.ps1`, `run-qa-db.ps1`, backend 검증 스크립트 및 frontend의 `pnpm exec vitest run`, `pnpm typecheck`, 변경 파일 `pnpm exec eslint --max-warnings 0`, `api-types.ps1`을 사용했다. 모델·네트워크가 필요한 전체 실사용 DB 테스트를 대신 실행하지 않았다.

## 본래 환경 반영과 브라우저

진행 중 실행이 없음을 읽기 전용으로 확인한 뒤 기존 API PID 181028의 실행 경로·부모·시작 시각·포트·설정 해시를 검사하고 동일 공식 launcher로 한 번 재시작했다. 최종 API PID 175916, launcher 159528, 기존 127.0.0.1:18000의 health/ready 200 및 실제 OpenAPI의 새 두 필드를 확인했다. 새 서버·DB를 본래 환경으로 대체하지 않았다. `trace-runtime-restart.json`, `runtime-after-check.json` 참조.

기존 DB 25표·2,560행의 PK별 해시를 시작/rollback 이후/API 반영 이후 대조해 변경·삭제·추가 0과 `.env` 동일을 확인했다(`preservation-after-apply.json`). 이 범위는 RAG 보존 대상이며 아래 관리자 문제 이력 갱신은 별도 정상 쓰기다.

본래 인증 Chrome에서 저장 실행의 같은 대화 1번 질문·현재 실행, 기존 답변·인용 2개·생성 근거 28개, 과거 선택 미기록 및 문맥화 생략 안내를 확인했다. 실행→기존 대화→동일 실행을 왕복했다. 새 질문을 제출하지 않았고 저장된 품질 미검증 표시를 유지했다.

실제 컴포넌트/CSS를 사용하는 합성 iframe에서 320/375/1000px를 확인했다. 내용 폭 299/354/979px, 관측 컨트롤 33개 모두 44px 이상, 가로 넘침 없음, 긴 턴 목록은 높이 352px 내부 스크롤이었다. Tab으로 다음 질문에 이동해 2px 청록 초점과 자동 스크롤을 확인하고 Enter로 7번→8번 실행 전환 및 이전 질문 제거를 확인했다. 선택/제외·출처 미기록·실제 HTTP 형식/안전한 JSON 결과 펼침을 확인했다.

본래 탭의 viewport 설정 시도는 측정 폭이 계속 1920px여서 실제 모바일 수용으로 집계하지 않았다. viewport 설정을 복구했다. 인증된 실기기 모바일·전체 업무 E2E와 합성 반응형 검증을 구분한다. 합성 서버는 로컬 GET fixture만 사용하며 API 요청은 차단한다.

## 남은 작업과 인계

1. 새로 승인된 모델 호출 범위에서 같은 대화의 실제 후속 질문을 실행해 새 문맥 기록·답변·인용과 화면 이동 후 복귀를 확인한다. 이번 구현/오프라인 성공을 실제 멀티턴 품질 통과로 확대하지 않는다.
2. 과거 manager 후보는 문맥화+관리자+답변 3회 경로였고 현재 활성 direct 구성은 문맥화 1+답변 1의 2회 경로다. 새 대화 첫 질문 1+후속 질문 2의 이론상 총 3회는 계획 계산이며 승인된 실행이 아니다. 기존 소진 예산을 재사용하지 않는다.
3. 기존 정답 0/2와 첫 입력 처리 지연은 이번 관측 변경으로 해결되지 않았다. 답변 생성·인용 판정·모델 설정을 변경하지 않았다. 목록/스레드 성능 실험은 보류한다.

ISSUE-00035에 기존 이력을 보존하며 이번 구현·검증·제한과 2026-10-27 진행 이력을 추가했다. 새로고침 후 `implemented`(구현됨·검증 남음) 상태·새 내용·현재 direct/과거 manager 구분을 재조회했다. 작업 보드의 다음 순서는 실제 SDK 멀티턴 수용이며 벡터 저장소·파인튜닝·Kubernetes 작업을 먼저 자동 실행하지 않는다.

시작 파일 2,252개 중 2,236개 동일·이번 범위 16개 변경·누락 0, 신규 12개와 `.env` 동일을 확인했다(`files-after.json`). 기존 접근 제한 테스트 임시 폴더의 Git inventory 경고는 그대로 남겼고 폴더 권한/내용을 변경하지 않았다. 관측한 파일 범위 밖의 접근 불가 내용을 검증했다고 주장하지 않는다. 합성 미리보기 서버와 탭은 종료하고 본래 API·사용자 문제 이력 화면은 유지했다. 무관 변경 정리·staging·commit/push·캐시 삭제는 수행하지 않았다.
