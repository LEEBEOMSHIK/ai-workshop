# ADR 0014: 스캔 PDF 페이지를 저장 OCR 프로파일로 처리한다

- 상태: 승인된 스캔 PDF 확장 작업의 구현 결정
- 기준일: 2026-09-07

## 최초 결정: v1

Windows에서 검증한 PP-StructureV3와 기존 PyMuPDF를 사용한다. Linux native 실행 검증은
운영 환경 준비 시 별도로 수행하며 로컬 개발을 차단하지 않는다.

새 불변 문서 처리 프로파일은 PDF route `pymupdf-ocr`, version `1`을 선택한다. 이전
`pymupdf` route와 OCR 없는 프로파일의 동작은 유지한다. 새 프로파일은 기존 10개 OCR 모델
binding을 재사용하며 평가 전 기본값으로 승격하거나 기존 저장 구성을 자동 변경하지 않는다.

PDF는 페이지별로 비공백 텍스트 유무를 판정한다. 텍스트 페이지는 기존 추출 경로를 사용하고
텍스트 없는 페이지는 RGB PNG로 렌더링해 OCR한다. 한 페이지 안의 텍스트와 그림을 모두
OCR하는 기능은 이번 범위 밖이다. OCR 실패를 텍스트 추출이나 다른 모델로 대체하지 않는다.

렌더 DPI, 페이지당 최대 픽셀 수, 최대 페이지 수는 프로파일에 저장한다. 초기 초안 값은
144 DPI, 16,000,000 pixels, 200 pages이며 품질·자원 평가 후 새 버전으로 조정한다.
렌더 전 상한을 검사하고 초과는 안전한 오류 코드로 실패한다. 생성 페이지 이미지는
파서 임시 디렉터리에만 두고 성공·실패 시 정리한다.

OCR의 정규화 bbox를 렌더된 원본 페이지 좌표로 변환하고 `source_kind=pdf_page`,
1부터 시작하는 page, 문자 범위, 표 셀 위치와 confidence를 보존한다. 회전·CropBox가
있는 페이지에서도 뷰어와 같은 표시 방향을 사용한다. 낮은 confidence 요소는 산출물에
경고와 함께 보존하되 evidence_eligible=false로 검색·LLM 근거에서 제외한다.

원문 페이지는 기존 권한 검사·원본 SHA-256 검증을 통과한 PDF 뷰어 API로 제공한다.
새 API나 페이지 이미지 저장소를 만들지 않는다. 프로파일 변경은 새 Projection과 색인을 만든다.

## 2026-09-07 혼합 페이지 보완 결정

사용자가 본문과 이미지가 같은 페이지에 있는 문서도 OCR하도록 보완을 승인했다.
`pymupdf-ocr` v2와 별도 비기본 초안 프로파일을 추가한다. v1의 불변 실행 계약과 기존
저장 구성은 유지하며 v2를 선택하면 새 Projection·색인이 필요하다.

v2는 본문을 직접 추출하고 표시되는 이미지 영역을 페이지에서 잘라 RGB로 렌더링해 OCR한다.
이미지 바이트를 원본 크기로 미리 해제하지 않는다. 겹치는 이미지 영역을 합쳐 중복 실행을
줄이고 설정된 픽셀 상한을 렌더 전에 적용한다. 회전·CropBox와 렌더 픽셀 원점을 반영해
OCR 좌표를 원본 페이지 표시 좌표로 되돌린다.

같은 위치에서 본문과 정규화된 글자가 같은 OCR 결과는 중복 경고와 함께 근거에서 제외한다.
v2의 동일 위치 판정은 두 bbox 교집합이 작은 bbox 면적의 50%를 초과할 때만 성립한다.
이는 얕게 겹친 인접 행을 보존하기 위한 버전된 알고리즘 기준이며 NFC·공백 정규화 외
퍼지 문자열 삭제는 하지 않는다. 기준 변경은 새 파서 버전으로 평가한다.
다른 위치의 반복 문구나 글자가 다른 결과는 임의로 삭제하지 않는다. 순수 장식 이미지에서
텍스트가 없는 정상 OCR 결과는 허용하지만 런타임 실패는 생략하거나 다른 모델로 대체하지 않는다.
순수 스캔 페이지는 기존 전체 페이지 OCR을 유지한다.

검증에는 제목+스캔 이미지, 본문+표 이미지, 겹친 이미지, 텍스트 레이어 중복, 회전·CropBox,
장식 이미지, 낮은 confidence와 실패·자원 상한을 포함한다. 벡터 도형의 의미 해석이나
사진 설명 생성은 OCR과 구분하며 이번 변경에 포함하지 않는다.

## 기존 v1 검증

합성 PDF로 스캔·텍스트/스캔 혼합·회전·CropBox·좌표 변환·표 셀·confidence·실패 전파·자원
상한·임시파일 정리를 자동 검증한다. 모델 호출은 단위 테스트에서 fake runtime을 사용하고
실제 Windows 모델 검증은 별도 opt-in으로 수행한다. 저장 프로파일 해석과 worker 연결,
검색 근거와 원문 뷰어까지 연결되는 흐름을 검증한다. Linux 실행 검증 결과로 대체하지 않는다.
