# ADR-0040: 비공개 에이전트 단계 본문 보관과 재조회

- 날짜: 2026-10-23
- 상태: 사용자 요청으로 구현. 실제 모델 재실행은 별도 검증 범위다.
- 변경 근거: 사용자가 단계별 지침·입력·결과의 수집 → 보관 → 상세 조회를 명시했다.
- 관련: [ADR-0039](0039-rag-agents-sdk-monitoring.md), [ADR-0038](0038-request-local-generation-input-inspection.md)

## 결정과 범위

새 SDK 실행의 실제 지침·입력·반환값을 기존 비공개 `rag_executions.stages._agent_trace_v1`에 보관한다. 질문과 최종 답변은 기존 대화 turn 또는 평가 snapshot/result 저장을 유지한다. 실행 본문은 대화 응답 JSON, 평가 결과 JSON, 일반 로그 또는 Git에 중복 보관하지 않는다. 별도 테이블·파일 저장소·외부 관측 서비스는 추가하지 않는다. 기존 실행 삭제 수명과 함께하며 자동 삭제 작업을 만들지 않는다.

이 결정은 ADR-0039의 SDK 단계 본문 미보관 정책을 대체한다. SDK가 아닌 기존 `generation_input`의 요청 한정 계약과 SDK 선택 여부·모델·검색·평가 기준은 유지한다. 본문 보관 승인은 모델 재실행이나 기존 대기 작업 실행 승인이 아니다.

## 수집과 구분

- 서버의 실행 본문 수집은 `include_diagnostics`와 분리한다. 이 옵션은 현재 응답의 진단 노출만 제어한다.
- 에이전트에는 실제 Runner 입력 또는 하위 에이전트 input builder의 결과와 실제 지침을 기록한다. 모델 단계에는 전송 직전 허용된 HTTP 본문 필드, 위임 단계에는 실제 도구 인자·반환값을 기록한다.
- 단계에 존재하지 않는 필드는 `not_applicable`로 표시하고 미수집·미보관과 구분한다. SDK 입력과 HTTP 요청 본문을 같은 것으로 표현하지 않는다.
- trace의 `content_retention`은 `metadata_only` 또는 `retained`다. 필드 없는 과거 기록은 `metadata_only`이며, 과거 payload에 임의 본문이 있어도 노출하지 않는다. 신규 수집기는 `retained`를 선언한다.
- 한 본문 최대 32,768자, 실행 총 131,072자, 최대 64단계의 기존 관측 상한을 유지한다. 이는 모델 입력 제한이 아니다. 초과한 본문은 잘라 실제 전송값처럼 보이지 않고 전체 생략 사유·길이·SHA-256을 기록한다. 저장·조회 경계에서도 합계·길이·해시·상태의 일관성을 검증한다.
- 메타데이터 projection은 명시적으로 분리한다. 기존 revision 단조 증가, 동일 run/span 식별성, 종료 뒤 늦은 쓰기 거부를 유지한다.

## 반환 결과와 보안

저장되는 반환값은 비공개 모니터링용 관측 결과다. 인용/답변 검증 전 결과와 품질 실패 결과도 원인 분석을 위해 저장할 수 있으며, 화면에서 검증된 최종 답변과 명확히 구분한다. 일반 대화 응답의 검증 실패 초안 가림은 유지한다. 안전한 메시지 경계를 통과하지 못한 응답, 인증 정보·주소·헤더·예외 원문·모델의 비공개 내부 추론은 수집하지 않는다. 출력이 없는 실패는 오류 코드와 상태만 보관한다.

기존 owner API와 `Cache-Control: no-store`를 사용한다. 상세 조회는 실행 actor, 대화/평가 소유자와 정확한 연결, 대화 의존 관계, 구조화된 원문 manifest의 현재 ACL을 검증한다. 마지막 비동기 사용량 조회 뒤에도 권한·연결을 재검사한다. 현재 권한을 잃거나 연결이 달라지면 본문을 포함한 상세를 반환하지 않는다. 저장된 본문 문자열을 권한 근거로 파싱하지 않는다. 목록 응답·브라우저 영구 저장·공개 앱에는 본문을 추가하지 않는다.

## 화면과 호환성

권한 검증된 상세의 `retained` 본문은 새로고침 후에도 각 단계의 전달 지침·입력·반환 결과에서 읽는다. 일반 텍스트로 렌더링하며 HTML이나 링크를 실행하지 않는다. 실제 빈 문자열, 당시 미수집, 당시 미보관, 해당 없음, 크기 제한, 검증 실패 가림을 구분한다. 기록 선택·실행 ID 변경·권한 실패 시 이전 본문이 남지 않아야 한다.

과거 실행의 미수집 본문을 현재 설정으로 재구성하거나 채우지 않는다. 질문·최종 답변·근거·상태·시간 등 기존 기록은 보존한다. 실행 완료와 답변 품질 통과는 별도다.

## 검증

합성 SDK HTTP 왕복으로 실제 입력·지침·출력 수집과 저장 경계를 검사한다. 진단 비활성 요청, 평가 경로, 중복 없는 대화 저장, 레거시, 상한·손상·권한 회수·다른 actor·실행 연결 변경·늦은 쓰기를 검증한다. 기존 DB의 rollback-only 통합 검증으로 저장→재조회 일치를 확인하고 실제 데이터 변경/삭제가 없음을 확인한다. 프론트 타입·관련 테스트·실제 CSS의 합성 저장 본문 화면과 본래 과거 실행 안내를 확인한다. 합성 검증을 새 Gemma 실행으로 표현하지 않는다.
