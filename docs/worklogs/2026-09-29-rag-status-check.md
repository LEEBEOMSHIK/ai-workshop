# 본래 환경 RAG 상태 점검 — 2026-09-29

사용자의 확인 우선 요청에 따라 기존 환경을 조회했다. 관련 문제는 ISSUE-00005다. 서버 재시작, 평가 제출·재시도, 활성 구성 변경은 수행하지 않았다.

## 환경

- API18000 health, 프론트5173 경유 health와 로그인 페이지 모두 HTTP200.
- PostgreSQL, Redis, Elasticsearch 컨테이너 모두 healthy.
- 프로세스 조회에서 API 실행을 확인했으나 Celery worker/beat는 없었다.
- 브라우저는 기존 비교 실험 경로를 next로 가진 로그인 페이지다. 사용자에게 기존 마스터 로그인을 요청했다. 인증 화면 이후의 PC·모바일 배치 검증과 DB 문제 이력 반영은 미완료다.

## 검증 근거와 다음 순서

Invoke-WebRequest3경로, Get-CimInstance 프로세스 분류, docker ps, 기존 inspect-full-generative.py와 저장 결과 집계를 사용했다. DB 조회 산출물은 기존 로컬 full-generative-results.json에 있으며 비공개 원문은 이 문서에 복사하지 않았다.

로그인 후 최종 UI 검증과 인증된 DB 이력 갱신을 진행한다. 미종료5건은 작업 lease·큐·복구 동작을 확인한 뒤 기존 실행을 이어가는 방법을 결정해야 한다. 이 점검만으로 전체 품질 검증이나 평가 완료를 선언하지 않는다.

## 후속 복구와 본래 화면 검증

기존 마스터 로그인 확인 후 PC1440×741에서 답변 비교 페이지 높이1206px를 측정했다. 모바일390×844에서는 clientWidth와 scrollWidth가375px로 같았고 질문 목록/상세 전환 및 다음 페이지 이동을 확인했다. 모바일 답변 상세 페이지 높이는1493px다. 임시 viewport는 복원했다.

근거·진단 탭에서 기준선 검색 충족률100%·문맥 충족률0%인 사례를 확인했다. 실제 진단에는 선택 기준 코사인0.9/키워드0.5와 후보 코사인0.8222·키워드0.1429·기준점수미달 등이 표시됐다. 진단 후보10개를 펼치면 페이지가 길어지는 사용성 문제는 남는다.

기존 .env로 worker40836·beat78236을 숨김 기동했다. 정상 stale 처리로 기존 완료139·실패6을 보존하고 미종료5건을 interrupted로 기록했다. run은 failed로 정리됐다. 이는 완료가 아니라 중단 사실을 명시한 것이다.

기존 미종료 별칭 작업의 별도 프로파일 `1d4eff32-d337-4210-b649-a3a90b697a93`에서 rag_index_attempt_busy 오류를 다시 확인했다. 평가에 고정된 E5 프로파일과는 다르며 수동 잠금 해제는 수행하지 않았다.

실제 재시도 버튼에서 `Codex mutations require application/json.` 거부를 재현했다. 프론트 retryGenerativeRun이 본문과 Content-Type 없이 요청하고, 서버가 승인 관련 mutation에 JSON을 요구하는 계약 불일치다. 프론트 요청 회귀 테스트와 최소 수정 후 본래 브라우저에서 다시 검증한다.

여기까지의 점검·중단·UI 검증·재시도 결함·별칭 오류를 정상 관리자 UI로 ISSUE-00005 진행 이력에 추가했고 저장 성공 표시를 확인했다. 상태는 진행 중으로 유지한다.

## 재시도 수정과 추가 차단

retryGenerativeRun에 json:{}를 추가했다. 실제 apiRequest/fetch 경계의 회귀 테스트는 수정 전 Content-Type 누락으로 실패하고 수정 후 통과했다. 관련8개·TypeScript·변경 파일 ESLint 통과. 불필요하게 확대한 전체 프론트 suite는 결과 없이 중단했으므로 전체 통과를 주장하지 않는다. 구현 담당과 분리된 메인 브라우저 검증에서 기존 실행에11개 후속 시도 접수를 확인했다.

Redis celery 큐에는 주기 점검5065건과 평가1건이 적체돼 있었다. 큐를 삭제하지 않고 같은 .env에서 기존 execute_run의 claim·heartbeat 경로를 단발 실행했다. 기존 queued task는 동일 claim 검사로 중복 실행을 막는다. 별도 DB·계정·프로파일은 만들지 않았다.

후속11시도는 deployment_not_ready10건·evaluation_execution_failed1건으로 종료했다. 누적161시도는 완료139·실패17·중단5다. 설치된 npm Codex CLI는0.158.0이고 설정 고정 버전은0.157.1이다. 읽기 전용 registry.resolve에서 codex_runner_hash_mismatch를 확인했다. 신뢰 해시/버전 변경은 사용자 확인 대기이며, 반복 재시도하지 않는다. 실제 생성 복구와 최종 정답 판정은 미완료다.

재시도 수정·검증·추가 차단 결과도 ISSUE-00005 DB 진행 이력에 추가했다.

공식 npm registry의 @openai/codex 0.158.0-win32-x64 배포 아카이브를 메모리에서 읽어 SHA512 integrity를 검증했다. 포함된 codex.exe SHA256은 af02050cc0c95f5aeb714af2c1077e635c58e9896c13c89d75099cf5b96477be로 설치본과 일치했다. 다운로드 파일·압축 해제 파일을 남기거나 실행하지 않았고 설정도 변경하지 않았다. DB 저장 성공 화면은 `.local-data/browser-verification/rag-status-history-20260929.png`에 보존했다.

## 승인 후 CLI 호환성 후속 확인

사용자가 합성 질문·대화 이력·서비스 지침의 OpenAI 전송과 계정 사용을 명시 승인했다. 정상 UI 후보 연결 검사 결과는 codex_verification_failed였다. 명령 조립기의 명시 호환 목록에0.158.0이 없음을 확인했고, 기존 exact-argv 회귀에0.158.0을 추가하자 codex_command_contract_unsupported로 실패했다. 설치본 --version/exec --help에서 strict-config, ignore-user-config, read-only, ephemeral, JSON, output-schema와 stdin 입력 옵션을 확인했다. 호환 목록을 최소 확장하되 미검증 버전과 preview 차단은 유지한다.

호환 수정 후 명령 테스트103개·generation 단위893개 통과(4skip), Ruff·Mypy 통과. 실제 UI 재검사도 실패해 추가 조사한 결과 09-28 중단 요청의 실행 슬롯1개가 이전 설정 지문으로 남아 있었다. 슬롯 저장소는 잔여 슬롯과 새 지문이 다르면 실행 전 codex_slot_settings_mismatch로 차단한다.
