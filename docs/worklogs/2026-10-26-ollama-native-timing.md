# Ollama 생성 내부 시간 수집 — 2026-10-26

## 바뀐 동작과 해결할 문제

기존 실측의 첫 생성219.886초는 관리자25.146초와 답변 담당193.894초로 나뉜다. 답변 담당 시간이 큰 것은 확인했지만 HTTP 시간만으로 모델 준비·입력 처리·출력 생성 중 원인을 판정할 수 없었다. 이슈 기록에 멈추지 않고 Ollama가 반환하는 실제 내부 시간을 수집하도록 제품 코드를 수정했다.

버전이 고정되는 orchestration policy의 `local_http_api=ollama_chat`을 명시 선택하면 SDK 관리자·답변 담당 요청을 같은 로컬 Ollama의 `/api/chat`으로 전송한다. 생략한 과거 프로파일은 기존 `/v1/chat/completions`를 사용한다. 현재 모델·온도·출력 예산·위임 흐름은 유지하며 API 선택만 별도 검증 후보에 적용할 수 있다. 과거 보류한 Transformers/native 런타임 복구나 실행 아키텍처 전환과 다른 변경이다.

각 모델 span의 `model_timing`에 client 시간과 별도로 `server_timing`을 저장한다. 서버 출처, 총시간, 준비·로드 시간, 입력 처리 시간, 출력 생성 시간을 ns에서 ms로 한 번 변환하고 기존 입력/출력 토큰 필드와 함께 보관한다. 준비·로드에는 서버 대기가 포함되므로 순수 가중치 적재 시간이라고 표시하지 않는다. 지표가 없거나 잘못되면 missing/invalid로 기록하며 유효한 답변 자체를 실패시키지 않는다. 과거 기록은 서버 지표 없음으로 읽는다.

실제 native 전송 입력과 반환 도구 ID를 유지한다. 미지원 요청·모델 불일치·누락 도구 ID는 실패시키며 자동 대체 호출을 하지 않는다. 모델2회·도구1회·retry0, 1MiB 응답 제한, 취소·시간 초과·로컬 종료 확인과 현재 권한 상세 조회를 유지한다. 비공개 내부 추론은 저장하지 않는다. 별도 DB migration은 필요하지 않다.

설계와 의미 경계는 [ADR-0043](../decisions/0043-ollama-native-timing.md), 선행 HTTP 계측과 기존 실측은 [이전 기록](2026-10-26-rag-generation-timing.md)을 따른다.

## 확인한 검증

- 독립 검토자가 오프라인 orchestration·executions·generation·evaluation 단위 범위를 실행해 **2,201 passed, 4 skipped**를 확인했다. 실제 모델 호출은 없었다.
- native 독립13개는 잘못된 지표·기본 경로 보존·실제 전송 입력·호출 예산·미지원 binding·부분 수신/크기 초과/timeout/cancel·최종 시간 기록 변경 차단을 검증했다. 최종 불변성 assertion 추가 후 해당13개만 다시 통과했다.
- 기존 본래 DB에 대한 명시 opt-in 검증 **2개**가 호환/native 저장·현재 owner 재조회·다른 owner 거절·과거 JSON을 통과했다. COMMIT 거절·SAVEPOINT·외부 rollback으로 합성3행이 남지 않고 기존5표 지문도 같았다. 새 DB/계정은 만들지 않았다.
- codec31개, 메인 연결6개와 독립13개는 위 넓은 범위와 중복되는 검증이다. 전체 고유 테스트 수로 합산하지 않는다.
- 관련 소스11파일 범위 strict Mypy, 변경 Python 파일 Ruff, OpenAPI 생성 및 일치 검사, frontend TypeScript 검사를 통과했다. 전체 저장소 Mypy 통과를 뜻하지 않는다.
- 독립 검토에서 native 전송 입력의 model 누락을 발견해 trace에 포함했고 최종19개 연결/독립 테스트로 확인했다. Mypy가 발견한 길이가 다른 tuple 추론은 가변 길이 tuple 타입을 명시해 수정했다.

독립 검토의 첫 넓은 실행은 없는 basetemp 상위 경로로 인한 WinError3이었다. 경로를 만든 뒤 정상 실행했고 실패 자료도 보존했다. 코드 결함으로 혼동하지 않는다. 범위 타입 검사에서 생략한 보조 모듈의 Any 반환은 해당 보조 소스까지 명시 검사해 확인했으며 제품 코드를 cast로 우회하지 않았다.

상세 검증 근거는 로컬 `.local-data/project-agent-work/ollama-native-timing-20261026/independent-review.md`와 검사 결과에 남겼다. 구현 책임과 독립 검토 책임을 분리했다.

## 확인된 병목과 다음 수정

첫 답변 담당은 입력 처리181.092초가 서버 총시간196.492초의 약92.2%다. 이 호출의 준비·로드19ms나 출력 생성15.262초가 주된 지연은 아니다. 동일 입력의 반복에서는 입력 처리가0.292초까지 줄었다. 캐시 재사용과 일치하는 관측이지만 캐시 히트 수를 읽지 않았으므로 물리적 원인을 확정하지 않는다.

실제 입력의 본문을 덤프하지 않고 크기·중복을 분석했다. system1,499자, user6,172자, 출력 format1,020자이며 user의 근거 블록은5,586자, 고유 근거 텍스트는659자다. 28개 근거 본문은 중복되지 않고 JSON도 이미 compact여서 구조 공백 제거의 절감은0자다. 기존 compact_evidence는 source 메타데이터도 이미 묶는다. 긴 식별자와 각 fragment의 위치 필드·구조가 많은 부분을 차지하지만 v5에서 임의로 제거하면 인용·원문 위치 계약이 바뀐다. 효과 없는 공백 제거를 성능 수정으로 추가하지 않았다.

다음 구현 후보는 **새 버전의 입력 형식에서 짧은 참조 ID와 공유 원문 위치 사전으로 중복 메타데이터를 표현하고, 출력은 기존 실제 인용 ID로 복원하는 것**이다. 원문·28개 근거·위치·인용 매핑이 손실 없이 왕복되는지 먼저 오프라인 검증하고, 비기본 후보에서 실제 입력 토큰·첫 실행 시간·답변/인용을 비교해야 한다. 이 형식 변경은 아직 구현·승격하지 않았으며 절감률과 실제 성능 효과도 미측정이다. 이미 소진한 이번4회 예산을 자동 연장하지 않는다. 기존 품질 개선 보류·정답0/2·후보 비승격을 유지한다.

ISSUE-00038은 여전히 실제 지연 개선이 남은 상태다. 이번에 완료한 것은 내부 시간 수집의 구현과 실제 수용, 입력 처리 병목 확인이다. commit/push·설치·캐시 제거·기본 모델 변경은 수행하지 않았다. 상세 근거는 같은 로컬 작업 폴더의 independent-live-acceptance.md, review-native-final.json, review-native-comparison.json, review-final-preservation.json, input-cost-analysis.json에 남긴다.

본래 로그인 화면에서 ISSUE-00038에 실제4회 결과와 다음 후보를 진행 이력으로 추가하고 수정 내용·검증·남은 작업도 갱신했다. 새로고침으로 저장을 확인했다. 과거 이력과 문서 연결 버전은 보존했고 이번 보고서는 경로로 연결했으며 새 DB 문서 버전을 등록하지 않았다. 브라우저 연결 오류 후 같은 브라우저의 새 결과 탭으로 복구해 실제 완료 화면을 확인했다.
