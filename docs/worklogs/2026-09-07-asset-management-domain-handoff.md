# 자산운용 도메인 전환 누락과 파일 관리 진입 보완

- 기준일: 2026-09-07
- 상태: 도메인 등록·파일 관리 안내 완료, 생성 구성 부재로 대화 연결 미완료
- 사용자 승인: 기존 자산운용 연결 전환과 파일 관리 진입 개선

## 실제 확인 결과

새 도메인 모델을 추가하고 검색 입구를 교체했지만 기존 자산운용 서비스의 연결 전환을
완료하지 않았다. 이전 인계의 “기존 구성 연결만 하면 된다”는 설명은 불충분했다.

- 전사 자산운용 지식공간에 문서 2건이 있다.
- DB 전체 문서 10건·버전 13건 중 합성 테스트 공간의 데이터도 포함된다. 전체 수를
  자산운용 사용자 문서 수로 해석하지 않는다. 이번 작업에서는 원문 본문을 조회하지 않았다.
- 저장 구성 1건은 시스템 BM25 기준선 v1, 평가 pending, extractive 모드다.
- 구성의 공간 구독 0건, 생성 프로파일 0건, LLM 실행 설정 버전 0건이다.
- 따라서 기존의 완성된 생성 구성을 찾아 연결하는 것만으로 복구할 수 없다.

## 수행한 변경

사용자가 이전에 제공한 계정 식별자와 일치하는 활성 owner를 확인한 뒤 기존 DomainService로
`asset-management` / `자산운용`을 등록했다. 단일 owner를 가정한 최초 읽기 전용 검사에서는
중단했고, 계정을 명시한 검사 후 진행했다. 비밀번호·세션을 읽거나 변경하지 않았다.

등록 전 read-only 점검 → 명시적 등록 → read-only 재검사 순으로 확인했다.
도메인은 0→1건, 연결 0건, 구성 1건, 문서 10건·버전 13건은 유지된다.
재실행 검사는 기존 도메인을 그대로 유지했다. 권한·공간 구독·평가·LLM·색인을 변경하지 않았다.

관리자 서비스 조회는 자산운용과 `domain_connection_missing`을 반환한다. 사용자 서비스
조회는 빈 목록이다. 연결 없는 도메인은 권한 범위를 정할 수 없어 사용자 목록에 임의 노출하지 않는다.
**도메인 등록 완료는 사용자 대화 복구 완료를 의미하지 않는다.**

프론트 내비게이션의 `지식 공간`을 `파일 관리`로 변경하고 도메인 선택 화면에도 같은 링크를
항상 표시한다. 실제 경로는 기존 `/workshop/workspaces`를 재사용한다. 공간 선택 후 문서
목록·업로드로 이동한다. 관리자 도메인 링크의 owner 제한과 기존 권한 검사는 유지한다.

## 검증

- 구현 담당: 회귀 RED 3건 → 관련 3파일 9건 통과, TypeScript·ESLint 통과.
- 메인: 내비게이션·도메인 선택·지식공간 3파일 5건 통과, 21.59초.
- 메인 TypeScript·수정 파일 ESLint·diff 검사 통과. 로컬 웹·API health HTTP 200 확인.
- 독립 리뷰: 등록 경계·UI 변경 승인. 준비되지 않은 도메인의 사용자 노출을 주장하지 않도록 확인.
- 실제 로그인 브라우저·LLM 호출은 수행하지 않았다. 모델·Docker 변경, 문서 삭제, commit·push는 없다.

## 남은 작업

실제 사용할 LLM 실행 방식·모델을 확인하고 생성 프로파일과 자산운용용 Hybrid 구성을
등록해야 한다. 승인된 데이터 처리 정책, 호환 색인 준비와 평가를 확인한 뒤 도메인에 연결·활성화한다.
외부 API 비용·전송 승인을 임의로 가정하거나 BM25 기준선을 대화 구성으로 승격하지 않는다.
합성 데이터 정리와 임시 작업 스크립트 삭제는 별도 정확 대상 조사·승인 경계를 따른다.
