## 배경

현재 검증기는 주장에 직접 인용된 원문에서 동일 단위·동일 값을 찾는다. 이는 숫자와 날짜의
표기 차이를 안전하게 처리하지만 원문 두 비율의 차이처럼 계산해서 얻는 값은 인정하지 않는다.
고정 평가 Q05의 차이 요구와 이 직접 값 계약의 충돌을 확인했다. 실패 초안은 저장하지 않았으므로
과거 실패의 정확한 숫자나 수식이 올바르다고 소급 판단하지 않는다.

실패7 재시도의 첫 거절 주장에서는 퍼센트포인트3·통화3·날짜1 종류를 확인했다. 연산은 관측하지 않았다. Q08의 필요한
원문은 단위 없는 셀 내용인데 현재 parser는 paragraph·table_cell=null로 저장했다.
현재 전달 근거로는 단위·행 연결을 입증할 수 없다. Q12의 필요한 원문에는
완전한 날짜가 직접 존재한다. 종류만으로 통화 환산이나 날짜 추론이 원인이라고 단정하지 않는다.

## 대안과 선택

| 방식 | 효과와 한계 |
| --- | --- |
| 직접 값만 허용 | 기존 안전 계약은 유지하지만 정상 계산 질문에 답할 수 없다. |
| 인용 숫자의 가능한 계산을 모두 탐색 | 서로 다른 상품·시점 숫자 조합과 우연히 같은 결과를 통과시킬 수 있어 채택하지 않는다. |
| 모델이 지정한 원문 피연산자와 연산을 서버에서 검증 | 원문 위치·연산·결과를 추적할 수 있다. 새 응답 계약이 필요하며 이 방식을 권고한다. |

## 제안하는 결정

- 기존 schema1/2와 ADR-0035의 직접 값 검증을 유지한다. 별도의 불변 생성 프로파일,
  schema3·새 프롬프트·명시된 계산 정책을 지원하는 런타임에만 파생값 검증을 추가한다.
- 권한과 외부 전송 승인을 통과한 이번 생성 근거에서 서버가 숫자 토큰 목록을 만든다.
  모델은 원문 값이나 임의 수식을 제출하지 않고 목록의 토큰 ID와 주장 결과 위치를 지정한다.
- 첫 연산은 비율 두 개의 부호 있는 퍼센트포인트 차이와 원/만원/억원의 정확한 단위 환산이다.
  Decimal로 재계산하며 반올림·환율·연산 사슬·연도/영업일 추론은 허용하지 않는다.
- 각 피연산자는 해당 주장에 직접 인용한 근거여야 한다. 원문 단위와 표의 관계를 모델이
  임의로 보충할 수 없다. 검증 가능한 단위 결속이 없는 표 셀은 계산 대상으로 승격하지 않는다.
- 정상 결과에만 검증된 원문 위치·연산·결과 위치를 비공개 기록에 남긴다. 실패 초안과
  원문 숫자는 로그·문제 이력에 남기지 않고 안전한 단계/원인 코드와 개수만 기록한다.
- 계산 일치는 상품·기간·질문의 의미까지 증명하지 않는다. 주장별 원문 의미 평가와 기존
  권한·인용·후보 승인 정책을 그대로 적용한다. 기존 평가 결과와 digest는 변경하지 않는다.

## 승인·반영 경계

작성된 명세·구현 계획은2026-10-05 사용자 승인을 받았고 결정론적 회귀·독립 코드 검토·본래 rollback SQL 시험을 마쳤다. 2026-10-06 실제 반영 승인을 받아 정확한0062→0063과 API를 반영하고, 합성 연결 통과 후 새 불변 프로파일의75회 평가를 완료했다. 정상64·검증 거절11 및 독립 의미63통과/1실패로 정상API 승격409를 확인했다. 실제%p proof10개와 통화환산proof0을 구분하며 브라우저는미검증이다. 새 계약 자체로 현재 후보를 승격하거나
기존 색인을 다시 만들지 않는다. Q08 표 구조 보강과 Q12의 상세 실패 원인은 별도 진단 조건이다.
