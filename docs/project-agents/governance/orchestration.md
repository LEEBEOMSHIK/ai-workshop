# 오케스트레이션

프로젝트 오케스트레이터는 요구를 행동 변경, 공용 계약, UI, API·worker, AI 런타임, DB, 배포, 보안, 개인정보, RAG, 문서 구조 신호로 분류한다. 활성화 규칙이 만든 최소 역할 집합에 실제 범위가 필요한 도메인 역할만 더하고, 필요하지 않은 역할은 제외 이유를 기록한다.

배정 전에 오케스트레이터는 사용자에게 참여 역할과 제외 역할의 이유를 알린다. 한 역할의 산출물 경계와 책임을 다른 역할에 중복 배정하지 않으며, 구현 담당과 독립 통합 검증 또는 독립 코드 리뷰 담당을 같은 변경 책임으로 합치지 않는다.

각 배정에는 입력, 수정 가능 범위, 예상 산출물, 검증 명령과 다음 인계 대상을 명시한다. 범위, 공용 인터페이스, 데이터 분류, 운영 조건이 달라지면 오케스트레이터는 활성화 신호와 역할 명단을 다시 계산하고 사용자에게 변경을 고지한 뒤에 새 배정을 한다.

실제 역할 호출, 결과 수락, 충돌 해소, 최종 통합, 커밋과 push 결정 권한은 메인 프로젝트 오케스트레이터에만 있다. 역할 담당은 자신의 승인 범위를 넘는 통합이나 다른 역할의 독립 검증 결과를 대체할 수 없다.
