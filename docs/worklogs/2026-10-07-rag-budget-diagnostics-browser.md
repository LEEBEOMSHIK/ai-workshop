# 본래 RAG 예산 진단의 요청·저장·화면 복원 검증

- 기준일: 2026-10-07
- 관련 문제: ISSUE-00005
- 승인 계약: [입력 예산 진단 설계](../superpowers/specs/2026-10-06-rag-budget-diagnostics-design.md)
- 선행 구현 보고서: [구현·본래 API 반영](2026-10-07-rag-budget-diagnostics-implementation.md)의 DB 문서 `dbe3e35f-907a-4038-a6fe-0590a3a380f1` exact v1을 변경하지 않는다.
- 상태: 예산 진단의 본래 새 요청·실행 저장·대화/모니터링 새로고침 복원·옛 미기록 표시 확인 완료. RAG 전체 마감이나 답변 품질 완료는 아니다.

## 실제 사용자 경로

사용자가 로그인한 기존 Chrome 대화 탭과 기존 선택된 합성 PDF를 사용했다. 별도 환경·계정·DB·문서·세션을 만들지 않았다. 합성 자료 분류와 이번 요청의 외부 처리 확인을 적용하고, 이전과 같은 승인된 합성 질문을 UI에서 한 번 제출했다. 질문이나 원문 본문은 이 보고서에 복제하지 않는다.

새 턴은 `4d8dd5b3-e3ae-4189-bcaa-784ace8eb0b7`(sequence9), 실행은 `bf73d112-aee6-4394-8add-b5b9e87a3f48`이다. 상태는 `completed`, `execution_terminated=true`, 오류 없음, 답변 상태 `insufficient_evidence`다. 실행 모니터링의 전체 소요 시간은24.00초이며 요청·권한2.31초, 이전 대화1.01초, 검색16.22초, 선택3.08초, 저장0.07초를 표시했다. 이 합성 질문 한 번의 관측이며 일반 지연 보장이나 성능 개선 결과로 확대하지 않는다.

대화의 최신 ‘검색 근거·유사도’에서 다음 두 값을 확인했다.

- 원문 단위33개 / 남은32개 (전체 한도32개)
- 원문 단위36개 / 남은32개 (전체 한도32개)

관련성 미달 그룹은 ‘예산 검사 전 제외’로 구분된다. 대화를 새로고침해 저장된9턴이 로딩된 뒤 최신 진단을 다시 열었을 때 같은 값이 복원됐다. 처음 로딩 중 기본3초 locator 제한이 끝났지만 로딩 완료 화면을 확인하고 정상 복원을 검증했다. 결과 오류나 추가 질문 재시도로 처리하지 않았다.

새 실행의 ‘검색 근거·유사도·선택 사유’에서 후보 카드3개, 동일한 두 초과 수치와 검사 전 제외 표시, 원문 연결3개를 확인했다. 실행 상세를 새로고침해도 같은3개 카드와 수치가 복원됐다. 기존 실행 `35a9ae93-614f-4cf4-82fa-27e0cfa98fc0`에서는 ‘세부 예산 미기록’2개, 검사 전 제외 표시, 추정된 수치0을 확인했다. 옛 대화에서도 같은 미기록 구분을 확인했다.

## 독립 저장·보존 검증

질문 제출 전 별도 독립 검증 담당이 READ ONLY 연결로55개 보호 테이블, 기존8턴·전체5세션·선택 대화revision17, 동결 보고서7개 exact v1·파일/DB SHA, schema0063·원래 환경·활성v4·gate OID·frozen1/receipt0, 과거 평가와 새75회 결과/64판정·64계산 복원을 기준선으로 확보했다. 독립 검증 담당의 DB/API 쓰기·모델 호출은0이다.

새 응답의110후보는 그룹3개와 원문 단위107개다. 실제 저장된 두 예산 기록은 다음과 같다.

| 항목 | 첫 적격 그룹 | 둘째 적격 그룹 |
| --- | --- | --- |
| 입력 원문 단위 | 33 | 36 |
| 입력 문자 수 | 712 | 683 |
| 검사 직전 사용량(그룹/단위/문자) | 0 / 0 / 0 | 0 / 0 / 0 |
| 적용 상한(그룹/단위/문자) | 8 / 32 / 12000 | 8 / 32 / 12000 |
| 실제 초과 종류 | units | units |

정확한9필드·strict integer·양수 한도·중복 없는 최대3개 enum을 독립 검증했다. 실행 selection의3개 후보와 응답 그룹의 값이 정확히 일치했다. 관련성 미달 그룹과 원문 단위107개에는 `budget_trace`가 없다. 선택0으로 생성·인용 검증은 생략됐으며 허용 감사1건의 근거0·사용량 미보고·숫자 receipt0을 확인했다. 이 요청은 생성 LLM 성공이나 성공한 멀티턴 증거가 아니다.

기존8턴의 전체행 SHA와 선택 대화의 불변 필드는 보존됐다. 승인된 기존 대화1행만 revision/updated_at이 변해 revision19가 됐고 다른4대화는 불변이다. 보호 테이블54개의 사전 기존행 SHA가 같고 새 profile/model/config/permission/projection/evaluation/numeric receipt 행은0이다. 새 턴1개·새 세션0·진행 실행/평가0이며 동결7보고서·환경·schema·gate·기존 평가를 보존했다. ‘55개 테이블 전체가 무변경’으로 기록하지 않는다.

위 증거는 본래 환경에서 실제 실행한 저장/복원 검증이다. 선행 구현 보고서에 기록된 단위·UI·타입 검사 결과는 그 시점의 증거로 유지하고, 이 작업에서 제품 코드가 변경되지 않아 전체 검사를 반복하지 않았다. 이번 후속 보고서와 문제 이력 등록 뒤의 정확한 문서 버전·기존행·로그 프라이버시 최종 비교는 별도 인계 메타데이터에 기록한다.

## 남은 경계와 다음 순서

예산 진단의 승인된 기능·본래 사용 검증은 완료했다. 활성32단위 상한과 전체 묶음 수용/제외는 유지되어 답변 근거 부족 자체를 해소한 작업은 아니다. 다음 개발은 질문별 예외 없이 필요한 원문 문맥을 안전하게 선택할 수 있도록 구조적 문맥 재구성 또는 평가된 불변 후보의 승격 계약을 검토하는 것이다.

유효 답변·성공한 멀티턴, 실제 권한 철회·첨부/모바일·모델 실패/timeout, ISSUE-00013 별칭 종료 proof/새 정상 parity·Git 인계 등의 기존 기능 마감 조건과 ISSUE-00029 DLL 재발 방지는 남아 있다. 이번1회 정상 검색으로 DLL 영구 복구를 주장하지 않는다. SDK 도입 → 벡터 저장소 비교 → 로컬 LLM 파인튜닝은 기존 RAG 기능 마감 후의 후속 순서를 유지한다. 아직 품질 개선만 남은 상태가 아니다.
