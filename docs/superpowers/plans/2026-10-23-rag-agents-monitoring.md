# OpenAI Agents SDK와 위임 모니터링 구현 계획

사용자 요청: 서비스 내부 에이전트를 SDK로 구성하고 실제 위임 관계와 전달 내용을 화면에서 확인한다. 설계 정본은 [ADR-0039](../../decisions/0039-rag-agents-sdk-monitoring.md)다. 기존 Gemma 첫 연동 완료와 관련 없는 미커밋 변경을 보존한다.

## 범위와 책임

- 메인: 공유 trace 계약, 요청 한정 본문, 실행 저장/조회, 의존성·통합·문서.
- SDK 담당: orchestration 어댑터, 프로파일 선택, 기존 생성 단계 연결, SDK 실제 Runner 오프라인 검사.
- UI 담당: 기존 실행 상세와 검색 진단의 공통 위임 패널, UI 경합·접근성 검사.
- 독립 검토: 권한·본문 노출·외부 trace·예산/종료 경계. 구현 책임과 분리한다.

## 순서와 수용 기준

1. [x] `executions/agent_trace.py`의 bounded typed span/trace 계약과 request-local collector, `_agent_trace_v1` 저장 projection을 테스트로 고정한다. 본문 비저장·revision/종료 경계·현재 ACL 검사를 포함한다.
2. [x] `openai-agents==0.24.0`을 고정하고 uv lock의 최소 변경을 검토한다. 기존 Conda 수치 패키지/파일을 보존하는 정본 설치 절차로 SDK import와 의존성 검사를 수행한다.
3. [x] `models/orchestration_policy.py`, `orchestration/`에 opt-in SDK 경로를 구현한다. 기존 모델/권한 해석 및 schema 2 serializer/parser를 재사용한다. 실제 SDK Runner로 최대 호출·deadline·retry 0·위임 입력·사용량·취소 의미를 검증한다.
4. [x] SearchDiagnostics와 ExecutionDetail에 nullable trace를 연결하고 OpenAPI types를 생성한다. 현재 응답에서만 본문을 반환하고 저장 직전 제거하는 회귀를 검사한다.
5. [x] 실행 상세 및 현재 대화 진단에 흐름·선택 상세·미보관/미측정 상태를 구현한다. 오래된 실행은 빈 상태로 표시한다. 수동 갱신과 execution ID 변경 경합을 수정한다. HTTP 생성 프로파일 폼에도 직접 생성/SDK 위임 선택과 총 호출·출력 한도를 추가한다. 로컬 HTTP 이외 배포에 SDK 설정을 조용히 전환해 제출하지 않는다.
6. [x] 영향 범위 pytest/Vitest, 타입·린트·문서/생성 API 검사, 독립 리뷰를 수행한다. 실제 결과와 중복 범위는 [작업 기록](../../worklogs/2026-10-23-rag-agents-monitoring.md)에 남긴다.
7. [x] 본래 환경에서 가능한 비추론 확인과 구현 결과/남은 실제 모델 수용을 구분해 기록한다. 승인 없는 프로파일 승격·실제 모델 반복·worker 실행·commit/push는 하지 않는다.

## 남은 실제 환경 수용

2026-10-23 후속 검증에서 평가가 로컬 HTTP 종료 추적 없이 다음 반복을 실행하는 경로를 확인했다. 실제 호출 전에 아래 항목을 보강한다. 수정은 기존 평가 workflow/repository와 관련 테스트에 한정하며 DB migration이나 기존 운영 복구를 포함하지 않는다.

- [x] 종료 미확인인 첫 시도 뒤 둘째 시도가 시작되는 RED 재현.
- [x] 요청별 종료 추적 연결, 첫 실패 기록과 같은 run의 미실행 반복 중단, claim 불일치·이미 끝난 run/다른 run 보존.
- [x] 정상 완료·응답 후 품질 실패의 기존 반복 유지, 관측 상태·후속 claim 거부·외부 모델0 오프라인 검증과 독립 리뷰. 단위21/독립44(중복), 본래 PostgreSQL rollback1을 양측에서 통과했다.

- [x] 실제 CSS 합성 화면에서 패널 폭320/375/1280px, 위임 선택·현재 입력/이력 비보관·빈 기록/관측 누락 확인. 기본 캡처 성공. 정확한 전체 모바일 viewport는 도구 override 한계로 미검증이며 패널 폭 검사와 구분한다.
- [x] 로그인한 기존 관리자에서 SDK 프로파일 등록→시험 구성→완료 실행 상세 흐름 확인. 새 계정·별도 DB로 대체하지 않았다. 진행 중 상세의 404는 아래 별도 보강 항목이다.
- [x] 정확한 프로파일·공개 합성 자료·호출 예산을 확인한 실제 Gemma SDK 도구 왕복. 질문1개×2회·실제 생성4회/최대4회·retry0으로 완료했다. 각 manager→as_tool→specialist 경로와 모델2회가 기록됐다. 기존 Gemma 직접 RAG 완료를 다시 여는 작업이 아니며, 이번 SDK 경로의 수용 확인이다.

사용자의 명시 승인 뒤 기존 API18000을 동일 환경으로 재기동했고 새 계약과 기존 로그인을 확인했다. 정상 UI로 draft 프로파일·시험 구성·1사례 자료·단일 run을 등록하고 공식 `execute_run`으로 해당 run만 처리했다. 실제 SDK 위임은2/2 성공했지만 정답0/2·P95 약141.8초로 품질 통과는 아니다. 추가 모델 호출이나 기본값·도메인 연결 승격을 하지 않는다.

- [x] 실행 중/최종 인용 없는 평가의 trace 조회 404 보강: 최종 인용 표시 목록 대신 동결된 서버 평가 근거와 현재 ACL로 trace를 검증한다. 기존 인용 표시 계약·소유권·권한 회수 차단을 보존한다. 실패 재현 후 관련41개·독립 동일41개와 본래 DB READ ONLY 권한 검증, Ruff/Mypy·diff를 통과했다. 본래 API에 반영하고 로그인된 완료 실행의5단계·위임 대상·생성 답변·본문 미수집 안내를 재확인했다.
- [ ] 보강 이후 새 실모델 실행 중 화면의 재검증. 현재4회 예산을 모두 소진해 추가 호출하지 않았다. 자동 상태/권한 회귀·완료 기록 조회와 구분한다.

실제 평가의 `include_diagnostics=false`에 따라 이력에는 본문을 보관하지 않았다. 이번 실모델 결과로 요청 직후 입력 본문 열람이나 근거 부족 사례의 거절 품질을 검증했다고 주장하지 않는다. 진행 중 화면의 수정 후 실모델 재검증도 이미 소진한4회 예산에 포함되지 않는다.

## 보관 선택

실제 입력 본문의 비공개 이력 보관 여부는 사용자에게 확인 중이다. 응답 전에는 기존 요청 한정 보관 정책을 유지한다. 본문 영구 저장이 승인되면 보관/삭제·ACL manifest·크기 정책을 별도 설계 변경으로 반영한다.
