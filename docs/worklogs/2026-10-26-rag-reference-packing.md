# 원문·인용을 보존하는 v6 입력 축소

2026-10-26, ISSUE-00038. 사용자의 현재 답변 품질 비퇴행 조건으로 [ADR-0044](../decisions/0044-rag-reference-evidence-input.md)를 구현했다. 첫 답변 담당의 입력 처리181.092초 병목에 대응하는 변경이다.

## 구현과 오프라인 검증

선택형 `rag-answer-v6`에서 긴 인용 UUID를 요청 한정 e1,e2,…로 표현하고 반복 fragment 필드 이름을 고정 열 순서로 묶는다. 근거를 삭제·요약하지 않고 기존 v5 출처·본문·위치·순서 전체를 복원한다. 답변은 엄격한 schema2 검증 후 원래 UUID로 변환한다. 미등록·비정규·중복 참조와 UUID 혼용은 거절한다. direct HTTP와 SDK의 native/호환 경로를 연결했고 기존 v5 입력·지침·응답 schema의 사전 SHA를 보존했다.

실패·취소 때도 인용을 추적할 수 있도록 specialist model span에 서버 소유 `citation_reference_map`을 호출 전에 보관한다. 모델에는 보내지 않으며 최대200개 고유 UUID의 순서만 담는다. 기존 private trace·현재 ACL을 따르고 실행 중·종료 후 변경을 막는다. 기존 기록은 None으로 읽는다.

- 구현 집중65개 및 독립19개 통과 후 최종 관련 generation/orchestration/executions/evaluation 단위 **2,285개 통과·4개 건너뜀**. 앞선 집중 검사는 최종 범위에 포함된다.
- 본래 DB opt-in rollback 통합 **2개 통과**: 실제 recorder→owner 상세 조회·다른 owner 거절·과거 기록·실패/취소 매핑을 검증했다. synthetic3행 잔류0·기존5표 fingerprint 동일.
- Ruff 제품9+테스트6파일, 명시 소스13파일 strict Mypy, OpenAPI 생성/일치와 전체 프론트 TypeScript 검사 통과. Mypy 결과는 전체 프로젝트 검사가 아니다.
- 공개 합성28근거 입력 **6,847→4,566 UTF-8 bytes(33.3% 감소)**, v6의 역변환과 v5 전체 구조가 같다. 이는 byte 측정이며 token·속도·답변 품질 개선을 뜻하지 않는다.

정적·독립 검증 기록은 `.local-data/project-agent-work/rag-reference-packing-20261026/`의 independent-review.md, independent-final-junit.xml, static-verification.md, independent-v5-before.json, independent-size.json에 남긴다. 새 codec·실행 연결·trace 테스트의 구현 전 실패를 확인한 뒤 구현했다.

## 실제 비교 승인과 수용 기준

구현 검증 뒤 사용자가 **추가 로컬 Gemma 최대4회**를 승인했다. 동일 공개 합성 질문2반복, 관리자/답변 담당 각1회, 자동 재시도0회다. 직전 native run `335cb67a-a5db-4c40-864a-f38db93427e1`을 동결 기준으로 사용한다. 같은 모델·근거·검색·온도0·출력512/호출·총1024·timeout360초를 유지하고 v6 비기본 후보만 등록한다.

실제 비교에서 원문·28근거 순서·위치·인용 복원 및 답변의 사실·조건·누락·거절을 대조한다. 기존 정답0/2를 기준 통과로 바꾸지 않으며 점수만 같다는 이유로 내용 비퇴행을 선언하지 않는다. 첫 실행과 반복의 입력 토큰·서버 준비/로드·입력/출력 시간, 전체 시간을 구분한다. 캐시 상태를 강제하지 않으므로 엄밀한 cold-start 실험으로 해석하지 않는다. 후보 승격은 수행하지 않는다.

본래 유휴 API6840을 같은 환경의 API42644(launcher142760)로 재기동했다. health/ready HTTP200, 실제 API의 인용 변환표 스키마와 기존 `.env` SHA 보존을 확인했다. 로그인된 관리자 화면에서 비기본 profile `4129a40c-b544-43e5-87b5-33ef067a8cb4`, configuration version `da01acf9-79b1-44a0-b611-8849e1ac09ae`를 등록했다. 독립 읽기 검사에서 기존 native 후보와 prompt_ref만 달라졌고 배포·owner·workspace·구성 요소·답변 정책은 같으며 활성 domain 연결0임을 확인했다.

새 run `16edd5ae-fb8e-4510-b6a0-c1fcab5d7d4a`를 등록하고 고정 snapshot·초기 대기2시도·기존 호출0·동시 작업0을 독립 검사한 뒤 정확한 한 run만 실행했다. 모델 **4/최대4회·자동 재시도0회**, 두 시도 모두 완료했다. 설치·commit/push·캐시 삭제·새 DB/계정·기본 프로파일 변경은 수행하지 않았다.

추가 독립 품질 검토에서 인용된 날짜 예시의 사실은 원문에 부합하고 새 환각·다른 상품 혼입·추가 조건 손실은 관찰되지 않았다. 다만 질문의 일반 지급 규칙(T+4영업일)과 예시의 휴일 없는 조건을 누락한 기존 한계는 유지됐다. **이번 두 응답에서 추가 품질 퇴행이 관찰되지 않았다는 결과이며 정답0/2·전체 품질 실패는 그대로다.** 품질 개선이나 전체 질문의 비퇴행 보장으로 확대하지 않는다.

로그인 화면에서 최신2/2완료·정답0/2·인용 유효와 평가 내부 시간204.3/46.6초를 확인했다. 이 시간은 모니터링 전체205.070/46.797초와 경계가 다르다. 브라우저 연결 오류 후 동일 브라우저의 새 결과 탭으로 복구했고 실행을 다시 시작하지 않았다.

## 반복 전체 시간과 다음 수정

반복 생성 단계는18.329→15.638초로 줄었지만 검색은6.821→14.178초, 선택은12.016→15.638초로 늘었다. 이번 반복의 임베딩 모델 준비는11.637초, 선택용 문서 임베딩은15.069초였다. tokenize 관측은 model_load를 포함하므로 두 값을 합산하지 않는다. 입력 축소로 이 단계들이 개선됐다고 주장하지 않으며 환경·메모리·캐시 영향의 기여도도 확정하지 않는다. 두 표본을 일반 지연 분포로 확대하거나 전체 응답 속도 해결로 보고하지 않는다.

다음 수정 대상은 동일 모델·고정 입력의 반복 검색/선택에서 임베딩 준비와 계산을 재사용할 수 있는 경계다. 모델 자체의 생성 전 해제는 보존하면서, 입력·프로파일·권한 경계가 맞는 계산 결과만 재사용하는 설계를 우선 검토한다. 일반 사용자 요청 간 무제한 캐시나 근거 삭제로 범위를 넓히지 않는다. 현재v6는 비기본·미활성 후보로 유지하며 이번4회 예산은 소진됐다.

독립 보존 검사에서 기존25표2,484행의 수정·삭제0, 정확히 허용된 신규15행만 확인했다. `.env`는 같고 owner 상세 재조회·다른 actor 접근 거절·결과/trace digest 검사를 통과했다. 원래230개 작업 파일은 이번 범위 밖 변경이나 누락이 없으며 시작 시 clean이던 프롬프트 등록/예산 허용 목록2파일과 신규 구현·테스트·문서는 별도로 구분했다.

독립 지표는 review-v5-final.json, review-v6-final.json, review-progress-2.json, review-comparison-final.json, review-preservation-final.json에, 의미·인용 검토는 quality-comparison-review.md에 남겼다. 정본 요약은 independent-live-acceptance.md다. 비공개 본문은 덤프하지 않았으며 해당 공개 합성 답변만 검토했다.
