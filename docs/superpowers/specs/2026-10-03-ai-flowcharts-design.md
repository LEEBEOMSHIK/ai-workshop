# AI 기술별 흐름도 메뉴

- 상태: 설계·Native 구현 계획 승인(2026-10-03), 구현·최종 검증 중
- 기준일: 2026-10-03
- 작업 등급: architectural — 기술별 콘텐츠와 공통 뷰어·메뉴의 새 구성
- 제품 구현: 콘텐츠·뷰어·메뉴·경로 및 상단 탐색 수정 반영, 본래 로그인 데스크톱·모바일 확인; 전체 키보드·실제404 복귀는 남음

## 목적과 성공 기준

사용자가 웹의 `흐름도` 메뉴에서 AI 기술별 처리 과정과 세션·멀티턴 관리 조건을 확인한다.
정상 경로뿐 아니라 분기, 실패, 생략 조건과 관련 화면을 설명한다.
선택한 흐름 하나를 읽는 화면으로 구성해 긴 설명과 여러 흐름의 누적 스크롤을 피한다.
현재 구현을 설명하는 정적 안내이며 실제 실행의 성공·준비 상태를 뜻하지 않는다.

## 구성 선택

추천은 기존 비공개 작업소에 읽기 전용 흐름도 뷰어와 버전 관리되는 콘텐츠를 추가하는 것이다.
현재 기능과 바로 연결하고 검토된 변경을 코드와 함께 관리할 수 있다.
기존 문서 링크만 모으는 방식은 웹에서 단계와 분기를 찾기 어렵다.
DB 편집기·실시간 실행 그래프까지 만들면 저장·권한·편집·감사 계약이 크게 늘어난다.
이번 단계에서는 읽기 전용 뷰어를 만들고 실제 실행 분석은 기존 실행 모니터링으로 연결한다.

## 메뉴와 분류

- canonical 주소: `/workshop/flows`, 상세 주소: `/workshop/flows/{category}/{flow}`.
- 기존 작업소 메뉴에 `흐름도`를 한 번 등록하고 기존 사이드바·모바일 메뉴를 재사용한다.
- 관리자 전용 메뉴가 아니다. 로그인한 작업소 사용자가 같은 경로를 이용한다.
- 상위는 기술 또는 공통 영역, 하위는 구체적인 흐름이다.
- 처음에는 다음 목록만 제공한다.

| 상위 | 하위 | 범위 |
| --- | --- | --- |
| RAG | 문서 처리·색인 | 원본 저장에서 검색 준비까지 |
| RAG | 검색·답변 생성 | 질문 접수에서 근거·인용·결과 저장까지 |
| RAG | 대화 세션 관리 | 첫 질문 생성, 목록·복원, 제목, 취소·삭제 |
| RAG | 멀티턴 문맥 관리 | 이전 대화 선별, 범위 변경, 질문 문맥화 |
| 공통 | 개발 에이전트 관리 | 역할 선정, 배정, 독립 검토, 통합·완료 |

에이전트 항목은 현재의 프로젝트 개발 에이전트 운영을 뜻한다.
사용자가 2026-10-03 제안 설계를 승인했으며 초기 항목은 개발 에이전트 관리다.
서비스 AI 에이전트 등록·실행 관리, 안내 캐릭터, Celery worker를 같은 개념으로 설명하지 않는다.
사용자가 서비스 AI 에이전트 흐름을 원하면 실제 기능 유무와 설계 범위를 다시 확인한다.
콘텐츠가 없는 미래 기술의 메뉴나 빈 화면은 만들지 않는다.

## 화면과 상호작용

2026-10-04 사용자 구체화: 기술 상세는 사용 기술·라이브러리와 내부 구성의 연결을 쉬운 말로 설명한다.
각 흐름의 기술 상세 첫 화면은 구성도(구성 요소·기술명·데이터 이동), 짧은 가상 사례를 보여준다.
사용 기술별 목적·구현 방식과 구현 근거·적용 범위는 접어서 읽고, 기존 세부 처리·예외 그래프도
필요할 때 펼친다. 전체 흐름의 큰 단계에서 진입한 경우 해당 세부 설명을 바로 펼쳐 선택한다.
두 설명 깊이·기술/흐름 상단 선택을 유지하며 내부 왼쪽 NAV나 중첩 스크롤을 추가하지 않는다.
SDK·저장소·프로토콜·자체 코드의 책임과 지원 런타임/실제 선택 상태를 구분한다.
OpenAI API 어댑터는 HTTPX 직접 호출이며 공식 SDK 사용으로 표기하지 않는다. 세션은 앱 DB,
멀티턴은 앱의 현재 권한·범위·문맥 예산에 따른 요청별 재구성으로 설명한다.
예시는 실제 질문 실행·답변 품질 확인이 아닌 설명용 가상 사례로 명시한다.

2026-10-03 사용자 후속 요청: 큰틀과 기술 설명을 분리한다. 기본 `전체 흐름`은4~5개 큰 단계의
목적과 주요 단계 간 연결을 표시하며, `기술 상세`는 기존 세부 조건 그래프와 선택 단계 설명을 제공한다.
큰 단계에서 기술 상세로 이동하면 대응하는 세부 단계가 선택된다. 단계와 큰 단계는 완전히 대응하고
누락·중복·없는 단계 참조를 콘텐츠 검증에서 차단한다. 기술 상세는 기술명과 쉬운 역할 설명,
동작 방식·확인 지점·구현 근거를 함께 제공한다. 한 번에 한 보기만 표시해 중복 그래프와 긴 설명의 누적을 피한다.
두 보기의 선택 단계는 같은 흐름 안에서 유지하고 다른 흐름으로 이동하면 기본 전체 보기로 초기화한다.
큰 단계 연결은 기존 세부 edge에서 파생하며 모든 예외·순환 조건의 정확한 확인은 기술 상세로 안내한다.

2026-10-03 사용자 UI 수정 요청을 반영해 페이지 내부의 왼쪽 분류 열을 제거한다.
기술 선택(RAG/공통)과 선택 기술의 개별 흐름 링크를 본문 위 두 줄에 배치한다.
다른 기술을 선택하면 해당 기술의 첫 흐름으로 이동하고 직접 상세 진입에서는 현재 기술과 흐름을 표시한다.
본문은 남은 화면 폭을 모두 사용한다. 상위 기술와 하위 흐름의2단계 분류는 유지한다.
본문 상단에 이름·목적·구현 설명임을 표시하고 아래에 흐름도와 선택 단계 설명을 둔다.
분류와 흐름은 이름이 보이는 링크 목록으로 제공하며 긴 콤보박스를 사용하지 않는다.
한 번에 흐름 하나를 표시한다. 모든 흐름의 상세 설명을 한 페이지에 펼치지 않는다.

흐름은 위에서 아래로 진행하는 단계와 이름이 있는 분기 연결로 표시한다.
분기선에 `허용`, `실패`, `이전 대화 없음`처럼 조건을 명시한다.
단계를 선택하면 해당 단계의 입력·처리·결과·실패 조건을 짧게 확인한다.
선택은 UI 안에서만 일어나며 검색·색인·모델 호출을 실행하지 않는다.
색상만으로 상태를 구별하지 않고 텍스트와 형태를 함께 사용한다.

모바일에서는 같은 상단 선택 항목을 줄바꿈하고 선택한 흐름의 단계 설명은 흐름 아래에 배치한다.
별도 목록 스크롤·본문 스크롤·설명 스크롤을 중첩하지 않는다.
긴 그래프는 단계 단위로 세로로 읽을 수 있게 구성한다. 본문 전체의 가로 넘침을 허용하지 않는다.
필수 조작은 키보드로 가능하고 그래프와 동일한 순서·분기를 표현하는 텍스트 설명도 제공한다.

상세 URL 직접 진입·새로고침·뒤로 가기로 선택이 유지된다.
알 수 없는 분류나 흐름은 404와 목록 복귀 링크를 제공한다.
다른 흐름으로 이동하면 단계 선택을 초기화한다.

## 초기 흐름의 내용과 분기

### 문서 처리·색인

원본 업로드·무결성 확인 → Platform Asset READY → 구독·색인 수요 확인 →
파싱/OCR → 공통 문서 구조 → 청킹 → 임베딩·BM25/벡터 색인 →
개수·provenance·별칭 검증 → RAG Projection READY·활성화.

Platform 원본 저장 완료와 RAG 검색 준비 완료를 별도 단계로 표현한다.
부분 실패·실패·비활성 원본·별칭 검증 차단은 검색 준비에 도달한 것으로 표시하지 않는다.
worker·beat가 담당하는 비동기 전달/복구와 사용자 요청의 응답을 구분한다.
현재 미종료 별칭 요청의 해제나 access epoch 전환이 완료된 것처럼 설명하지 않는다.

### 검색·답변 생성

요청·연결·권한 확인 → 이전 대화 준비 → 필요한 경우 질문 문맥화 →
권한 선필터를 적용한 BM25+dense 검색 → RRF 병합 → 현재 기준선의 리랭킹 생략 →
근거 선택 → 근거 제한 답변 생성 → 인용 검증 → 결과·실행 상태 저장.

문맥이 없으면 문맥화를 생략한다. 리랭커 미설정은 정상 생략이며 현재 구성 계약은 활성 리랭커 binding을 허용하지 않는다.
기술 상세는 리랭킹 개념과 현재 지원 상태를 구분한다. 인용 검증은 허용 근거 ID·원문 추적과
정규식 기반 날짜/수치 확인 범위를 설명하며 모든 문장의 의미적 참됨 검증으로 확대해 표현하지 않는다.
근거 부족, 모델 실패, 인용 실패, 취소를 별도 결과로 표현한다.
선택 모델이 실패하면 다른 모델로 조용히 전환하지 않는다.
예외 경로에서도 가능한 실패 상태와 관측 값을 저장하되 모든 실패가 같은 저장 경로를
반드시 완주한다고 표현하지 않는다. 유사도·실제 시간 확인은 기존 검색 진단/실행 모니터링에 연결한다.

### 대화 세션 관리

새 대화 열기 → 질문 전 첨부는 초안으로 관리 → 첫 질문 사전검사 →
질문 의도 기반 제목 산출 → 세션·제목·첫 turn·첨부 결합의 원자적 저장 → 실행·결과 저장.

제목은 첫 질문에서 결정적 규칙으로 산출하며 별도 LLM을 호출하지 않는다.

메뉴 진입만으로 세션을 만들지 않는다. 접수 이전 거절과 접수 후 실행 실패를 구분한다.
기존 세션 선택 → 현재 권한 확인 → 보이는 대화·문서 범위 복원 → 후속 질문 접수로 연결한다.
수동 제목 유지, 동일 요청 재전송의 멱등성, revision 충돌·동시 실행 제한을 설명한다.
취소·중단 상태와 실제 실행 종료 확인은 별개다. 삭제 후 대화 재실행 차단도 표시한다.

### 멀티턴 문맥 관리

현재 연결·문서·색인 범위 확인 → 동일 범위 segment의 과거 turn 선택 →
현재 권한·의존 근거 재확인 → 완료된 answered 답변과 검증 토큰 선별 →
최근 최대 10개 질의·응답 쌍 후보 → 프로파일의 메시지·토큰 예산 적용 →
질문 문맥화 → 현재 문서 재검색 → 답변 생성·인용 검증.

실패·취소·근거 부족 답변, 검증 불가 답변, 접근이 철회된 근거에 의존한 답변은 제외한다.
외부 처리에서는 현재 필요한 전송 승인도 다시 확인한다.
연결·문서 범위·활성 문서 버전·색인 변경 시 새 segment로 분리한다.
이전 메시지가 화면에 남아 있는 것과 모델에 전달되는 문맥은 다르다.
과거 답변은 질문 이해를 돕는 문맥이며 이번 답변의 원문 근거를 대체하지 않는다.
앱 DB에서 문맥을 재구성하며 모델의 내부 세션 resume을 사용하는 것으로 표현하지 않는다.

### 개발 에이전트 관리

요청·WORKBOARD 확인 → 작업 등급·위험·활성화 신호 분류 → 필수 역할 선택 →
범위에 필요한 전문 역할 추가 → 참여·제외 이유 고지 → 경계가 분리된 작업 배정 →
산출물·검증 증거 인계 → 독립 검토 → 수정 또는 메인 Codex 통합 → 기록·완료.

범위 확장은 역할 재선정으로 돌아간다. 구현자와 해당 변경의 독립 검증자는 분리한다.
모든 작업에 에이전트를 늘리는 것으로 설명하지 않는다.
staging·commit·push 결정은 메인 Codex에 속하며 각 작업의 승인·권한 조건을 따른다.
흐름도는 실제 호출 목록·현재 실행 상태를 제공하는 운영 관리 화면이 아니다.

## 모듈과 콘텐츠 소유권

공통 뷰어는 `frontend/src/features/flowcharts/`에서 타입과 렌더링만 담당한다.
노드·분기·설명·버전·기준일·근거 문서 참조를 가진 명시적 콘텐츠 계약을 정의한다.
RAG 콘텐츠는 `features/rag/flows/`에 두고 개발 에이전트 콘텐츠는 별도 소유 모듈에 둔다.
app route의 구성 계층에서 각 콘텐츠를 합쳐 뷰어에 전달한다.
공통 뷰어가 Labs/RAG 구현을 직접 import하거나 백엔드 업무 규칙을 복제하지 않는다.
서버에서 저장소 Markdown을 읽거나 임의 경로·HTML·Mermaid 스크립트를 실행하지 않는다.
노드와 조건 연결을 React로 렌더링해 초기 버전에 새 그래프 라이브러리를 추가하지 않는다.

원문 근거는 검토 시 확인할 저장소 문서·코드 참조로 관리한다.
제품에는 목적·검토 기준일과 안전한 문서 제목을 표시한다. 파일 경로를 런타임 조회 API로 만들지 않는다.
실제 연결 가능한 화면은 기존 canonical route를 사용한다.
실행 모니터링은 마스터에게만 링크를 노출하고 직접 URL 접근에서도 기존 서버 권한 검사를 유지한다.
일반 사용자는 허용된 RAG 대화·파일함 등으로 이동한다.

## 콘텐츠 갱신과 권한

카탈로그는 Git에서 코드와 함께 검토·버전 관리한다. DB 편집·문서 DB 연결은 이번 범위에 추가하지 않는다.
이번 메뉴는 기존 작업소 서버 인증을 그대로 사용한다. 공개 전시실에 비공개 콘텐츠를 제공하지 않는다.
계정·질문·자료·토큰·환경 비밀값·실행 로그를 예시 콘텐츠로 저장하지 않는다.
기능 변경 시 해당 흐름을 같은 작업에서 갱신한다. 검토일만으로 현재 서비스 정상이라고 표시하지 않는다.
콘텐츠 검증에서 중복 ID·없는 노드 참조·없는 category·유효하지 않은 시작/종료·고립 노드를 잡는다.

## 수용 검증

1. 로그인 사용자는 데스크톱·모바일 작업소 메뉴에서 흐름도를 열 수 있다.
2. 2단계 분류와 상세 URL에서 선택한 흐름만 표시하며 뒤로 가기·새로고침이 동작한다.
3. 키보드 단계 선택과 텍스트 대체 설명에서 분기 의미를 확인할 수 있다.
4. 비로그인 직접 진입은 기존 로그인 경로를 따르고 일반 사용자에게 관리자 링크를 노출하지 않는다.
5. 세션 생성·멀티턴 선별·권한 선필터·인용 실패 설명이 현재 서비스 코드와 일치한다.
6. 실제 브라우저에서 데스크톱 및 좁은 폭의 넘침·중첩 스크롤·메뉴 동작을 검증한다.
7. 관련 Vitest 테스트, frontend typecheck·lint, 문서 링크·diff 검사를 실제로 통과한다.
8. 기존 서버·계정·DB·문서·RAG 연결을 유지하고 새 테스트 환경을 만들지 않는다.
