# Codex 실시간 출력 검사 연결

## 범위

승인된 개인 Codex exec 설계 §6·9·10의 후속 구현이다.
계획: `docs/superpowers/plans/2026-09-08-codex-live-output.md`.
Python/AI 구현, 메인 독립 실행 검증, 별도 보안/privacy 리뷰로 책임을 분리한다.
main에서만 작업하며 사용자 DB·문서·CLI 인증·실제 모델·서버·UI는 변경하지 않는다.

## 기존 문제와 접합 방향

기존 Windows 실행기는 요청 소유 Job Object와 출력 한계를 관리하지만 stdout을 프로세스 종료 후
반환했다. 별도 JSONL 수신기가 있어도 종료 뒤에 검사하면 실행 중 금지 이벤트에 대응하지 못한다.

실행기의 bounded stdout read마다 신뢰된 동기 검사기를 호출한다. 위반 시 일반 실행 루프를
중단하고 기존 Job Object 정리로 해당 요청의 자식까지 회수한다. 종료 직후 남은 출력도 검사한다.
원시 stdout/stderr를 저장하지 않는 모드에서도 별도 byte 계수로 크기 한계는 유지한다.

RAG 전용 adapter는 호출마다 새 수신기를 만든다. 정상 exit·종료 이벤트·한계·자식 회수까지
확인해야 결과를 반환하며, 중간에 최종 답변을 봤더라도 이후 실패하면 폐기한다.
이 검사는 이미 발생한 도구 부작용을 되돌리거나 OS 격리·입력 전송 승인을 대신하지 않는다.

## 아직 남는 연결

- `config.py`에는 HTTP endpoint/secret 참조만 있고 Codex typed runner registry는 없다.
- `generation/runtime_resolver.py`는 Codex를 `deployment_not_ready`로 차단한다.
- 승인 저장소·실시간 실행기와 실제 검색/평가/명시 연결 검사 요청의 배선이 필요하다.
- CLI 버전/허용 설정·전용 임시 루트·정확한 명령 구성, 실제 모델 identity 확인이 필요하다.
- 요청 모델을 관측 모델로 복사하지 않는다. 관리자/자산운용 도메인 활성화와 실제 RAG 답변 검증은
  이 내부 프로세스 검사 완료와 별개다.

## 검증

합성 Python 자식 프로세스만 사용한다. 실제 Codex CLI 또는 계정 사용량이 발생하는 테스트는
실행하지 않는다. 최종 실행 결과와 독립 리뷰 판정은 아래에 기록한다.

- TDD: 실행기 신규 10개 실패→23개 통과, adapter 신규 28개 실패→통과.
- 자체 검토에서 종료 후 회수 실패가 확인된 경우에도 검사기가 호출되는 문제를 재현했다.
  검사기 진입 조건에 회수/입력 writer 실패 상태를 추가했고, 종료 후 잔여 출력 검사 3개를 포함해 검증했다.
- 메인 독립 실행: Windows 실행기 26개 + stream adapter 28개 + 기존 수신기 42개 = **96개 통과** (10.70초).
- 전체 backend unit/contract: **1,267개 통과** (61.51초), 기존 Starlette/httpx 폐기 예정 경고 1개.
- mypy **219개 소스 파일**, 변경 파일 Ruff 통과. 독립 보안/privacy 리뷰에서 명세·코드 품질 승인,
  미해결 수정 사항 없음으로 이 내부 단계의 인계를 승인했다.
- 실제 합성 Python 부모·후손을 생성한 거절 테스트는 TIMEOUT 대신 OUTPUT_REJECTED를 반환하고,
  요청 소유 Job Object의 잔류 프로세스 0과 회수 성공을 확인했다. 실제 사용자 프로세스는 종료하지 않았다.

## 인계

main의 기존 변경은 보존했고 commit/push·별도 worktree를 만들지 않았다. 새로운 라이브러리는 없다.
현재 결과는 실시간 출력 검사 부품의 완료이며 전체 RAG 사용자 테스트 준비 완료가 아니다.
실제 답변·인용·후속 질문 검증까지 끝난 시점에 테스트 경로와 순서를 안내한다.
