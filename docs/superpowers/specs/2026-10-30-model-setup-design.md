# 관리자 모델 연결·RAG 구성 통합

사용자 승인: 모델 연결 → 선택 → 검증 → 적용을 한 흐름으로 정리하고 OpenAI·로컬 모두 등록하며 RAG 구성을 쉽게 만든다. 기존 설정과 답변 품질은 보존한다. 다크·청록 공통 디자인을 따른다.

## 선택한 접근

기존 등록 화면마다 링크만 추가하면 관리자가 내부 참조를 계속 조립해야 한다. 일괄 자동 활성화는 평가·데이터 정책 경계를 흐린다. 따라서 `/admin/rag/setup`의 한 화면에서 단계별 실제 작업을 수행하되, 기존 API·불변 버전·평가/권한 게이트를 재사용한다. 기존 고급 관리 화면은 보존하고 양쪽에서 통합 화면으로 진입한다.

화면 순서는 **모델 연결 → 기존 RAG 구성 복제 → 연결 상태·답변 평가 → 도메인에 명시적 적용**이다. 기존 구성과 새 후보를 구분하며, 마지막 단계에서도 전역 기본값은 변경하지 않는다. 계약의 결정 근거는 [ADR-0052](../../decisions/0052-admin-model-setup.md)를 따른다.

## 계약

1. 모델 연결: 기존 배포 선택 또는 로컬/OpenAI 공급자 선택 후 이름·모델 ID·서버에 준비된 연결/인증 참조 선택으로 등록한다. 모델 정의도 같은 흐름에서 생성/재사용한다. 연결 참조와 설정 여부만 owner 전용 API로 제공하며 URL·키 값·프롬프트 본문은 제공하지 않는다. 서버 설정에 없는 연결/키는 준비 필요로 명시한다. .env나 비교 전용 키를 자동 복사하지 않는다.
2. RAG 구성: 저장된 구성을 기반으로 문서 처리·색인·검색·답변 정책·지식 공간을 그대로 복사하고 새 모델에 연결할 답변 설정을 고른다. 호환되는 기존 생성 프로파일의 config는 비표시 필드까지 전체 복사하며, 같은 배포에 이미 연결된 설정은 재사용할 수 있다. 공급자 비호환 설정은 오류를 표시하고 자동 변환·필드 제거를 하지 않는다. 추출식 구성이 기반이면 별도 체크박스로 이 후보의 LLM 생성 답변 전환을 확인해야 저장할 수 있다. 이때도 검색 임계값·인용/충돌 정책·범위와 원래 구성은 보존한다.
3. 검증: 연결 health, 검색·답변 준비 상태, 답변 품질 평가의 수용 상태를 분리한다. 기존 평가 컴포넌트를 재사용하되 검색 평가의 `passed`를 새 모델의 답변 평가 수용으로 사용하지 않는다. 화면 진입·선택·준비 상태 조회만으로 모델 추론이나 평가를 시작하지 않으며, 새 답변 평가는 사용자가 명시적으로 실행한다.
4. 적용: 정확한 후보 버전의 생성형 평가 수용 응답과 최신 준비 상태를 함께 확인한 뒤, 최신 도메인 연결을 조회해 적용 대상·모델·지식 공간을 보여준다. 사용자가 적용을 확인하면 기존 범위를 보존하는 연결을 생성/활성화한다. 확인 후 후보·도메인 연결이 바뀌거나 준비/평가 조건이 맞지 않으면 중단한다. 실패 시 기존 활성 연결을 유지하고 저장된 비활성 연결을 재사용한다. 전역 기본값 승격은 하지 않는다.

## 연결 옵션과 공급자 호환성

Owner 전용 `GET /api/v1/admin/rag/deployment-setup-options`는 `endpoints:[{reference,dialect}]`, `secret_references:string[]`, `environment`, `generation_presets:[{id,name,description,supported_providers,config}]`를 반환한다. 참조는 설정에 준비된 안전한 이름만 반환하고 응답은 저장하지 않도록 `Cache-Control: no-store`를 사용한다. 조회는 모델/외부 요청이나 DB 쓰기를 하지 않는다.

현재 추론 계약에 맞춰 명시적 프리셋을 나눈다. UI는 선택한 배포의 공급자가 `supported_providers`에 포함된 프리셋만 제공한다.

| 프리셋 | 공급자 | 기존 프롬프트·응답 계약 |
|---|---|---|
| `grounded-local-schema2-v1` | `local_openai_compatible` | `rag-answer-v3`, schema2, 명시적인 문맥 근거 제한 |
| `grounded-openai-schema1-v1` | `openai_responses` | `rag-answer-v1`, schema1 |

두 프리셋 모두 필수 인용과 제한된 대화·출력 정책을 가진 신규 평가 후보다. 프리셋 버전의 정책값은 `deployments/setup_options.py`에서 관리한다. OpenAI Responses의 기존 schema1 제약 때문에 두 프리셋을 구분하며 추론 코어·프롬프트 본문·활성 설정은 수정하지 않는다. 프리셋의 런타임 호환성과 새 모델의 답변 품질 수용은 별개다.

## 평가 수용과 새로고침 복구

- `canApplyCandidate`의 `evaluation_state=passed` 및 준비 상태만으로는 적용할 수 없다. `acceptGenerativeRun`의 성공 응답에 포함된 `configuration_version_id`가 현재 후보 버전과 정확히 같아야 하며, 그 뒤 새로 조회한 검색·답변·서비스 준비 상태도 충족해야 한다. 다른 후보의 수용 응답이나 검색 평가 통과를 대신 사용할 수 없다.
- 후보/배포·기반 구성·적용 범위가 바뀌면 관련 외부 전송 승인, 평가 수용 확인과 적용 미리보기를 무효화한다. 늦게 도착한 이전 선택의 비동기 응답은 현재 선택을 덮어쓰지 않는다.
- 새로고침 후 메모리의 수용 확인을 잃었을 때는 해당 버전의 기존 완료 답변 평가에서 **통과 반영**을 다시 수행해 수용 응답을 확인할 수 있다. 저장된 평가를 다시 검증하는 이 동작은 새 답변을 생성하거나 모델을 호출하지 않는다. 수용 응답을 추정해서 복구하지 않는다.

## 저장 실패와 화면 표현

모델 정의·배포·생성 프로파일·RAG 구성·도메인 연결 저장은 각각의 API 경계다. 부분 성공에는 저장된 대상을 표시하고 입력을 보존하며, 같은 입력 재시도에는 이미 저장된 객체를 재사용한다. 응답 유실로 성공 여부가 불명확하면 목록과 정확한 입력/버전/범위를 대조한다. 대조도 실패하면 중복 생성을 막고 결과 확인이 필요함을 알린다. 이중 제출은 차단한다.

다크·청록 공통 토큰, 단계별 상태·오류·완료 텍스트, 44px 조작 영역과 키보드 초점을 유지한다. 320/375px에서는 단계와 긴 식별자를 줄바꿈하고 페이지 전체 가로 넘침을 방지한다. 고급 모델·RAG 구성 화면으로의 링크는 보조 탐색으로 제공한다. 표현 규칙은 [UI 스타일 기준](../../guidelines/ui-style-guide.md#관리자-모델-연결과-rag-설정)을 따른다.

## 성공 기준과 경계

OpenAI·로컬 등록 요청의 provider/location/외부전송 계약, 비밀 미노출, 입력 보존·중복 요청 방지·부분 성공 안내를 테스트한다. RAG 복사에서 비표시 설정 보존, 공급자 호환성, 추출식 전환 확인, 외부 승인의 선택 변경 시 초기화를 검증한다. 검색 평가만 통과한 후보, 다른 버전의 수용 응답, 수용 뒤 준비 상태가 바뀐 후보, 확인 후 도메인 연결이 바뀐 경우의 활성화를 차단하는지 확인한다. 기존 완료 평가의 통과 반영으로 수용 확인을 복구할 때 새 모델 호출이 없는지도 검증한다.

기존 UI/단위·타입·린트·관련 서버 계약과 실제 desktop/375/320 화면을 확인한다. 기존 환경/계정·자료를 사용하며 등록 시험 데이터는 mock 또는 기존 DB rollback으로 제한한다. 합성 검증과 본래 환경 확인을 구분해 기록한다. 이 문서는 구현·수용 계약이며 실제 화면 검증이나 새 모델 품질 평가의 완료를 선언하지 않는다. 기존 모델 재실행 없이 확인한 UI/계약 보존을 새 모델의 품질 수용으로 보고하지 않는다.

참여: 메인 요구/설계·프론트 통합·문서, 서버 구현, 모델 UI 구현, 독립 권한/privacy·통합 검증/리뷰. DB migration·추론 엔진·학습·인프라 변경은 제외한다.
