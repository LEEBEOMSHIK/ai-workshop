# 위임 거절 관측과 실제 재위임 검증 계획

**Goal:** 거절 원인을 안전한 고정 분류로 구분하고 수정본의 실제 재위임·최종 답변·인용을 확인한다.
**Architecture:** ADR-0050의 자율 경로와 기존 실패 계약을 유지한다. 모델 출력 본문이나 비공개 추론을 추가 수집하지 않고 실패 단계에 고정 사유 코드만 기록한다.
**Tech Stack:** Python, OpenAI Agents SDK, FastAPI, 기존 PostgreSQL/Ollama, 기존 React 실행 상세.
**Spec:** [ADR-0050](../../decisions/0050-rag-relations-and-autonomous-handoffs.md).

- [ ] 기존 변경과 환경 해시 보존; 실패 분기 및 기록 경로 확인.
- [ ] 거절 사유의 실패 테스트를 먼저 실행하고 transport/handoff/hooks 경계를 최소 수정. 최상위 기존 오류 계약은 보존하고 실패 span에 고정 세부 사유를 남긴다.
- [ ] 직접답변·관리자·자율 SDK, 권한·취소·예산·본문 비공개 회귀, 타입·린트, 독립 검토.
- [ ] 본래 유휴 API에 반영하고 기존 계정에서 비기본 후보의 같은 공개 질문 2회 검증. 최초 8회 계획은 자동 승인 검토에서 이전 명시 6회 상한 초과로 거절됐다. 6회 범위를 사용자에게 재확인한 뒤 Gemma 합계 최대 6회, 실행당 최대 4회, 자동 재시도 0회. 과거 잔여 예산과 합치지 않는다.
- [ ] 실제 위임 경로·최종 답변·claim/원문 인용·저장 관측·화면 복귀를 확인하고 DB/기존 연결 보존과 함께 ISSUE-00035/WORKBOARD에 기록.

수용은 실행 성공과 답변 품질을 따로 판정한다. 기존 T+4 일반 규칙 누락/불필요 예시 반복은 비교 기준의 알려진 실패이며 이번 수정으로 해결됐다고 추정하지 않는다. 추가 자동 실험·기본 승격·새 DB/계정·설치·커밋은 없다. 기존 미커밋 구현에 의존하므로 현재 checkout을 사용한다.
