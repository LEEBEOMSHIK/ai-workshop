# 자산운용 도메인 연결 준비 상태 조사

- 범위: 사용자 승인에 따른 기존 구성·연결 원인 조사와 정상 관리자 등록 경로의 준비 작업.
- 역할: 메인은 DB·변경 기록 대조와 UI 등록, RAG 책임자는 조회 필터·활성화 조건을 독립 조사했다.
- 환경: main, 기존 로컬 API와 마스터 로그인. 서버·Docker 재시작 및 원문 조회·모델 호출 없음.

## 확인된 원인

9월 7일 도메인 전환 기록부터 시스템 BM25 구성 1개·공간 구독 0개·도메인 연결 0개였다.
9월 9일에는 Codex GPT 5.5 모델·배포·생성 프로파일을 등록했지만 이를 조합한 저장 구성,
연결 검사·검색 평가·도메인 활성화는 완료하지 않았다. 모델 등록은 서비스 연결 완료가 아니다.

실제 DB를 REPEATABLE READ READ ONLY로 확인했다. 정확한 local/loopback15432/
ai_workshop_local_clean 대상과 읽기 전용 트랜잭션, 시간 제한을 검사했다.
구성·도메인·배포·생성 연결·프로파일·평가·Codex 검사·승인의 14개 테이블 건수와 SHA-256은
최근 합성 정리의 보존 결과와 모두 같았다. 최근 정리에서 해당 연결을 잃었다는 근거는 없다.

- 도메인: 자산운용 1개, 비활성, 연결 버전 없음.
- 저장 구성: 시스템 BM25 v1 하나, pending/extractive, 공간 구독 없음.
- Codex: GPT 5.5 배포 v1과 생성 프로파일 v1은 존재한다. 합성 연결 검사 0건.
- 평가: 데이터셋·정책·실행 모두 0건.
- 검색: BGE Hybrid만 등록돼 E5 색인 선택 시 호환성 필터에 의해 BM25만 표시됐다.
- 정책: 설치 v2는 개발용 Codex 허용, 전사·개인 공간은 명시적 deny 유지.
- 문서 승인: 1건은 철회 상태여서 현재 유효한 Codex 근거 승인은 없다.

조회 API는 시스템/현재 사용자 소유의 최신 구성 버전을 반환한다. 평가나 생성 준비 실패를
이유로 구성을 숨기지는 않는다. 사용자 도메인 목록은 활성 연결이 없는 도메인을 제외한다.
활성화에는 생성형 구성·실제 평가 통과·서비스 준비가 필요하다. DB로 상태를 강제하지 않는다.

## 이번 등록과 남은 단계

관리자 모델 화면의 YAML 등록으로 기존 E5 색인 v2에 연결된 Hybrid 검색 프로파일을 등록했다.
처음 사용한 저장소 `model-profiles/rag/retrieval/hybrid-rrf.yaml` v1에는 현재 호환성 계약이
허용하지 않는 `reranker.optional`이 있었다. 등록 자체는 가능하지만 구성 선택에서 제외된다.
기존 불변 v1을 덮어쓰거나 삭제하지 않고, 해당 항목만 뺀 `hybrid-rrf` v2를 등록했다.
BM25 top_k30·dense top_k30·RRF k60·reranker enabled=false, draft·비기본 상태다.
정본 YAML의 구형 항목과 등록 시점/사용 시점 검증 차이는 후속 회귀 테스트·설정 보완 대상으로 남긴다.

새 구성 화면에서 v2 선택 및 Bi-encoder multilingual-e5-base, RRF k60 표시를 실제 확인했다.
기존 Codex 배포는 로컬 사전점검 통과로 초안 저장이 가능한 상태이며 연결 검사 통과는 아니다.
다음 입력만 준비했고 저장하지 않았다:

- 이름: 자산운용 E5 Hybrid · Codex 5.5 검증
- 문서 처리: 기존 legacy TXT/Markdown/텍스트 PDF (이번 연결 확인용; OCR 준비 완료를 의미하지 않음)
- 색인: e5-structure-aware v2 / 검색: hybrid-rrf v2 / 생성: 개인 Codex 근거 기반 대화 v1
- 범위: RAG 합성 참조 자료만 선택. 전사·개인 공간 미선택.

외부 전송 동의와 저장은 사용자에게 인계한다. computer-use의 앱 보안·개인정보 설정 제한을
다른 경로로 우회하지 않는다. 철회된 문서 버전을 재승인하거나 임의 새 버전으로 만들지 않는다.
저장 후 정확한 구성의 합성 연결 검사, 사용 가능한 승인 자료 확보, 실제 평가, 도메인 연결을
순서대로 진행해야 한다. 현재 사용자 전체 RAG 테스트 준비 완료가 아니다.

## 검증 및 산출물

- 관리자 실제 UI: Hybrid v2 표시·선택, Codex 생성 선택과 로컬 사전점검 안내 확인.
- 독립 읽기 전용 재검증: 신규 v1/v2 제외 기존 12프로파일의 전체 행 지문 유지,
  v2의 E5 참조·설정·draft/비기본 확인. 도메인·구성·정책·배포·승인 지문 동일,
  모델 실행·연결 검사·평가 기록 추가 없음. 마지막 UI 확인도 외부 동의 미체크·저장 비활성이다.
- 읽기 전용 조사 도구: `.local-data/project-agent-work/domain-connection-audit/configuration_inventory.py`.
  문서 본문·비밀값·인증정보는 출력하지 않는다. 최초 스크립트 이름의 stdlib 충돌은
  configuration_inventory.py로 변경했고 이후 DB 읽기 검증은 정상 종료했다.
- 애플리케이션 소스·마이그레이션·정책·문서 승인·모델 호출 변경 없음. 커밋·push 없음.

## 사용자 저장 알림 후 재확인

사용자의 저장 알림 뒤 현재 브라우저는 모델 레지스트리에 있었다. 구성 화면과 읽기 전용 DB를
대조했지만 BM25 구성1개·공간 구독0개로 Hybrid 패키지 저장은 확인되지 않았다.
어떤 저장 동작이 있었는지나 실패 원인은 단정하지 않는다. 현재 사용자 탭의 구성 화면에 위
동일 초안을 다시 준비했다. 합성 자료만 선택됐고 외부 동의는 미체크·저장 비활성임을 확인했다.
사용자에게 정확한 패키지 이름의 카드가 생성되는지와 저장 오류 표시를 확인하도록 인계한다.
실제 연결 검사·모델 요청은 하지 않았다.

## RAG-TEST 저장 확인과 생성형 전환 준비

후속 사용자 탭과 읽기 전용 DB에서 RAG-TEST v1 저장을 확인했다. Hybrid E5/RRF이나
추출식이며 생성 프로파일은 없다. 평가 대기, 도메인 연결0이다. 이전 미저장 확인과 시점을 구분한다.
동일 사용자·이름은 기존 identity의 다음 버전을 생성하는 repository 계약을 확인했다.
사용자의 다음 작업 승인으로 현재 RAG-TEST 탭에 같은 이름·생성형·합성 자료 공간을 입력했다.
배포 조회는 재시도 후에도 실패했다. API18000 health는 ok지만 새 관리자 페이지 요청은
`/login?next=%2Fadmin%2Frag%2Fmodels`로 이동해 현재 세션 재인증이 필요함을 확인했다.
기존 화면의 관리자 이름은 새 요청의 인증 성공을 보장하지 않는다. 만료·재시작 등 세션 무효 원인은
미확인이다. 직접 API 문서 탐색은 브라우저에서 ERR_BLOCKED_BY_CLIENT로 차단돼 우회하지 않았다.
로그인은 사용자에게 인계하며 기존 구성 탭의 초안을 유지했다. 외부 동의·v2 저장·모델 실행·
도메인 활성화는 하지 않았다. 로그인 후 배포 재조회부터 이어간다.

사용자 재로그인 후 새 사용자 탭에서 관리자 세션과 Codex 배포 조회가 정상임을 확인했다.
이전 구성 탭은 닫힌 상태여서 현재 탭 하나에 RAG-TEST 생성형 초안을 다시 준비했다.
GPT5.5 생성 배포 선택·로컬 사전점검 통과 안내·합성 공간 한정이 표시된다. 외부 동의는
미체크이며 저장은 비활성이다. 사용자에게 현재 탭에서 동의·저장하도록 인계했다.
이 확인으로 실제 합성 연결 검사 또는 모델 실행 성공을 주장하지 않는다.

## 생성형 구성 저장 422 차단 조사

사용자가 보고한 문구는 ConfigurationBuilder의 모든 HTTP422에 대한 공통 문구다.
해당 실패 응답의 원시 code는 이번에 캡처하지 않았다. 현재 DB를 읽기 전용 확인한 결과
설치 정책v2는 development_codex_exec 허용이지만 합성 자료 공간의 최신 정책v1은 deny다.
전사·개인 공간도 deny다. GenerationPolicyResolver와 구성 저장 경로는 이 조합을
workspace_external_transfer_denied/422로 거절한다. 현재 상태에서 확인된 실제 저장 차단 조건이다.
구성의 외부 전송 동의만으로 공간 정책을 덮을 수 없다. 사용자에게 합성 공간만 명시적으로
Codex 허용하도록 안내하며 회사·개인 정책과 철회된 승인에는 손대지 않는다.
정확한 오류 code별 안내와 저장 전 정책 점검은 후속 UI 보완 대상이다. 이 턴은 진단이며
애플리케이션 코드 수정·저장 재시도·정책 변경·모델 호출은 하지 않았다.

## 사용자 정책 변경 및 생성형 저장 확인

사용자 설정 후 읽기 전용 DB에서 합성 자료 공간 정책v2의 Codex만 허용, 전사·개인 공간
deny 유지와 RAG-TEST v2 생성 프로파일 연결을 확인했다. 실제 카드에서도 generative v2와
hybrid-rrf v2, 개인 Codex 생성 프로파일v1이 표시된다. 카드의 LLM 요약은 연결 모델 정보 없음으로
표시되는 반면 생성 선택지는 기존 GPT5.5 배포를 표시해 요약 표시의 후속 점검이 필요하다.
검색 준비는 완료, 답변 준비는 필요다. '저장된 검사 상태 조회'를 실행한 결과
codex_verification_required다. 이 조회는 실제 모델 검사가 아니다. 합성 입력의 외부 전송과
계정 사용량 동의·검사 실행은 사용자에게 인계한다. 새 정책/구성은 사용자가 저장했으며,
이번 에이전트 확인에서는 설정·DB 쓰기·모델 호출을 하지 않았다.

## 연결 검사 이후 도메인 준비 확인

사용자 Codex 검사 이후 RAG-TEST v2의 검색/답변/서비스 준비는 완료로 표시된다.
단, 평가 상태는 대기다. 도메인 활성화는 별도 PASSED 평가 계약을 요구한다.
새 문서 revision 조회 결과 합성 자료 공간에는 asset-management-reference.md revision1만 있으며
승인 취소·재승인 불가 상태다. 외부 전송 허용 정책만으로 이 취소를 대체할 수 없다.
평가나 활성화를 우회하지 않았다. 사용자 도메인 탭에서 RAG-TEST v2 선택까지 준비했으며
허용 지식 공간은 미선택, 연결 저장/활성화/모델 호출은 하지 않았다.
새로 사용할 비민감 평가 자료와 사용자의 정확한 revision 승인이 필요하다.
취소 우회를 목적으로 동일 자료의 새 revision을 자동 생성하지 않는다.
