# 일반 대화 연결 복구와 백그라운드 수용 실행 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for authorized operational steps; independent verification remains separate.

**Goal:** 기존 환경에서 일반 대화를 정상 연결하고 실제 질문의 화면 이탈·복귀와 답변/인용 비퇴행을 확인한다.

**Architecture:** 기존 정확한 구성 버전의 평가·연결 API와 ADR-0048 백그라운드 실행을 사용한다. 전역 기본값, 모델/입력/검색/근거/인용 규칙과 품질 게이트를 변경하지 않는다.

**Tech Stack:** Next.js, FastAPI, PostgreSQL, Elasticsearch, 로컬 Ollama, 기존 Conda.

**Spec:** 사용자 2026-10-26 요청, [ADR-0048](../../decisions/0048-background-conversations.md), [ADR-0020](../../decisions/0020-rag-evaluation-authoring.md).

## 범위와 역할

- 본래 체크아웃의 누적 변경을 보존한다. 새 환경/DB/계정·설치·커밋·푸시·캐시 삭제는 없다.
- 메인은 요구·경계·UI 운영·통합을 맡고, backend/AI/RAG/DB 조사와 독립 검증/보안 리뷰를 분리한다.
- 기존 Codex 활성 연결과 Gemma pending 구성의 원인을 기록한다. 정상 평가를 거치며 SQL로 상태를 변경하지 않는다.
- 기존 생성 정답0/2는 보존한다. 검색 평가 통과와 생성 답변 품질 통과는 서로 다른 판정이다.
- 새 실제 대화는 공개 합성 질문2건, 로컬 Gemma 최대2회, 자동 재시도0이다. 기존 실험 예산을 재사용하지 않는다.

## 검토 초점

1. 정확한 후보 버전의 정상 평가 수용과 비기본 도메인 연결인지 확인한다.
2. 기존 자료·계정·원문 권한·종료 미확인 기록이 보존되는지 확인한다.
3. 접수 후 화면 이동과 탭 종료가 실제 실행 취소를 발생시키지 않는지 확인한다.
4. 돌아온 대화의 자동 조회와 최종 답변·인용이 저장된 결과와 일치하는지 확인한다.
5. 기존 답변의 내용/인용/근거와 비교하고 품질 비퇴행과 정답 통과를 구분한다.
