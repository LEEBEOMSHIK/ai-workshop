# 도메인 파일함과 선택 문서 대화

상태: 1단계 코드 구현·독립 최종 검토 및 승인된 백엔드 재시작·새 API 반영 확인 완료. 로그인된 실제 화면과 실제 LLM 응답 검증은 대기 중이다.

## 범위

[상세 설계](../superpowers/specs/2026-09-10-domain-cabinet-conversation-design.md)와
[1단계 계획](../superpowers/plans/2026-09-10-domain-cabinet-selection.md)을 따른다.
도메인 내 기존 연결 공간의 회사·개인 문서를 탐색하고 선택한 문서로 대화한다.
새 임시 첨부, 사용자별 동적 개인 자료 연결, 보관·만료 정책은 별도 2단계다.

## 검증된 백엔드 변경

- 문서 선택 생략만 공간/폴더 검색을 의미한다. 명시적 null·빈 배열은 거절한다.
- 선택 수 상한은 `AI_WORKSHOP_RAG_SELECTED_DOCUMENTS_MAX_COUNT` 설정을 사용한다(기본 100).
  파일함 응답의 `selection_limit`으로 UI에 전달하며 검색 top-k와는 다른 정책이다.
- 선택 문서 전부의 권한과 현재 활성 원본·정확한 처리/색인 프로파일·활성 build를 검증한다.
  일부만 사용하거나 전체 문서 검색으로 자동 전환하지 않는다.
- BM25와 dense에 동일한 선택 범위와 asset/build 선필터를 전달한다.
- v3 assistant 서명은 문서 선택과 서버가 해석한 활성 버전 지문을 결합한다.
  인증된 범위 변경은 409, 위조된 기록은 422로 구분하며 모델 준비·호출보다 먼저 차단한다.
- 비선택 도메인 대화의 기존 v2 서명은 호환한다. 선택 모드의 공통 무범위 history는 지원하지 않는다.
- 응답 `selected_scope`는 실제 사용한 문서/원본 버전/projection/build와 지문을 반환한다.
  사용자 질문 history는 여전히 임의 입력이며 검증된 사실 근거로 간주하지 않는다.

## 현재 검증 기록

- Task1 관련 단위 163건, 일회용 PostgreSQL 3건, 대상 Ruff·strict mypy 통과.
  평가 어댑터 호환과 원시 중복 입력 크기 제한을 독립 검토 후 보완하고 재검토 승인받았다.
- Task2 집중 12건·관련 단위 75건, 대상 Ruff·strict mypy 통과. 독립 보안/코드 검토 승인.
- Task3 도메인 파일함의 메타데이터·목록·문서 조회 API와 Platform 응답 변환 재사용을 구현했다.
  생성 준비 상태를 조회하지 않고 매 요청의 도메인·연결·구성·사용자 공간을 재검증한다.
  대상 53건·Ruff·strict mypy 통과, 독립 검토 승인. 원문/버전 API는 기존 Platform 권한 경계를 유지한다.
- Task3 이후 통합한 관련 백엔드 200건 통과, 변경 Python 33개 Ruff 및 소스 17개 대상 strict mypy 통과.
- 로컬 OpenAPI exporter로 프론트 타입 생성과 일치 검사를 통과했다. 실사용 API는 호출하지 않았다.
- 기존 Starlette TestClient 경고는 별도 잔여 사항이다.
- 추가 OpenAPI 검사 6건 통과·1건 실패: 기존 technology-access 경로 기대 목록 불일치.
  전체 검사 통과로 보고하지 않는다.
- 실사용 DB·문서·모델은 검증에 사용하지 않았다. PostgreSQL 검사는 전용 격리 fixture의 생성·삭제 범위만 사용했다.

## 남은 작업

UI 구현 후 독립 검토에서 대화 내 파일함 URL 변경, 선택 시 기존 공간/폴더 경계 교체,
비Codex 외부 동의 유지, 선택 상태의 연결/권한 실패 무효화, 같은 공간 루트 이동,
기본 파일함 URL 뒤로가기 복원 문제를 발견했다. 회귀 테스트와 함께 여섯 항목을 보완하고 독립 재검토 승인을 받았다.
보완 후 프론트 대상 69건과 경로·공통 탐색 30건, 타입·린트 검사가 통과했다.
합성 A/B의 실제 서비스 경로 검증과 thin API 전달 검증 17건이 통과했고 독립 최종 리뷰가 이를 확인했다.
최종 리뷰에서 선택 상한 환경변수의 strict 숫자 파싱 결함을 발견해 정상/잘못된 값/범위 검증과 함께 보완했다.
모달 초기 초점·중첩 Escape와 무효화 안내 유지도 보완하고 최종 재검토 승인받았다. 남은 Critical/Important 지적은 없다.
마지막 보완 후 main의 백엔드 통합 262건(기존 경고 1건), 프론트 17파일 109건이 통과했다.
변경 Python 34개 Ruff, 소스 17개 대상 strict mypy, 프론트 TypeScript/ESLint,
로컬 OpenAPI 일치, `git diff --check`가 모두 통과했다. 전체 저장소 테스트 통과를 의미하지 않는다.
실제 로그인 화면 확인과 LLM 응답 검증은 아직 완료되지 않았다.
재시작 전 API의 `/api/openapi.json`에는 새 도메인 library 경로와 selected_scope가 없어 이전 코드임을 확인했다.
사용자 `재시작해` 승인 후 18000의 프로세스 소유권과 실행 스크립트를 재검증했다.
기존 자식 PID39224·launcher38456 종료 후 동일 venv/실행 스크립트/환경 로딩으로 launcher39808을 숨김 실행했다.
백엔드 health `ok`, 프론트 5173 경유 health HTTP200, 새 library3경로·document_ids·selected_scope 반영을 확인했다.
Docker·프론트·DB·문서·계정·모델은 변경/호출하지 않았다. 새 로그는 `.local-data/dev-logs/domain-selection-20260910-api.*.log`에 기록한다.

잔여 비차단 접근성: 접힌 트리/빈 폴더에서 숨겨진 상위 요소를 포함하는 Tab 끝점 계산은 후속 확인이 필요하다.
키보드 초점이 선택 창 밖으로 이동할 수 있으며 실제 좁은 화면·접힌 트리 검증에서 보완한다.
단일 최종 수정 이후 이 항목은 독립 리뷰의 비차단 판단에 따라 보류했다. 권한·데이터·검색 범위 제한은 유지된다.

## 실제 화면 확인 순서 — 도메인 준비에서 보류

승인된 백엔드 재시작 및 최신 API 반영은 확인했다. 사용자 로그인 후 마스터 세션으로 읽기 전용 확인했다.
`/workshop/rag/search`는 사용 가능한 도메인이 없다고 표시한다. 관리자 도메인 화면에는 자산운용
(`asset-management`)이 비활성이고 연결 버전 이력이 없다. 도메인이 삭제된 상태는 아니다.
관리자 구성 화면에는 평가 대기 BM25 기준선 v1 하나만 있으며 dense/fusion/LLM은 사용하지 않는다.
최초 확인에서는 원인이 미확인이었으며 후속 [연결 조사](2026-09-10-domain-connection-audit.md)에서
모델 등록 이후 저장 구성·연결이 미완료였음을 확인했다. E5 Hybrid 검색 프로파일은 등록했으나
도메인 활성화·구성 저장·외부 전송 승인·모델 호출은 수행하지 않았다.
아래 파일함→대화 검증은 연결 준비 후 진행한다.

1. `/workshop/rag/search`에서 도메인의 `파일함`으로 들어간다.
2. 해당 도메인에 연결되어 허용된 회사·개인 공간을 구분해 폴더와 원문을 확인한다.
3. 기존 문서를 선택한 뒤 `선택 문서로 대화`로 진입한다. 이름은 서버에서 다시 확인한 값이어야 한다.
4. `문서 추가`에서 현재 공간·폴더 제한 내의 기존 문서를 변경한다.
   마지막 문서를 해제하면 질문 전송이 차단되어야 한다.
5. 범위를 바꾸면 이전 대화는 남고 `검색 범위 변경` 구분선 뒤에 새 문맥을 시작한다.
   외부 전송 동의는 다시 확인해야 한다.
6. 실제 답변을 실행한 경우 `사용 버전 원문 열기`에서 그 응답 범위의 정확한 원본 버전을 확인한다.
   실제 모델 호출은 별도 사용자 테스트이며 이번 자동 검증에서 실행하지 않았다.

## 구현 판단

- main에서 기존 변경을 보존하고 커밋·push·worktree 생성 없이 진행한다.
- 문서 제한 도입 직후의 임시 history 차단은 v3 서명 구현 이후 도메인 경로에서만 해제했다.
- 공통 파일 탐색기뿐 아니라 트리와 URL 복원에도 일반 주입 지점을 추가해 도메인 문맥을 유지한다.
- 파일함→대화 URL에는 문서 본문·이름 대신 제한된 workspace/document UUID 쌍만 전달한다.
  서버에서 현재 도메인 권한과 문서 메타데이터를 다시 확인한다.
- 단일 최종 수정 후 남은 접힌 트리 Tab 끝점은 비차단 접근성 항목으로 실제 화면 검증에 인계했다.
  보완 전까지 해당 상태에서 키보드 초점이 선택 창 밖으로 나갈 수 있다.

main만 사용했고 커밋·push·실사용 데이터 변경은 하지 않았다. 코드 구현 이후 별도 사용자 승인으로 백엔드만 재시작했다.
임시 리뷰 기록은 실제 화면 검증 및 정리 승인 전까지 task 전용 경로에 보존한다. 회귀 테스트 소스는 구현의 일부로 유지한다.
