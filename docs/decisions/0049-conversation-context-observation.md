# ADR-0049: 대화 턴 연결과 실제 사용 문맥 관측

- 날짜: 2026-10-27
- 상태: 사용자의 SDK 모니터링 보강 요청에 따른 구현 결정
- 관련: [ADR-0040](0040-private-agent-step-content.md), [ADR-0048](0048-background-conversations.md)

## 목표와 결정

실행 상세에서 같은 대화의 질문별 실행으로 이동하고, 프로파일 제한 이후 실제 전달된 이전 메시지와 제외 이유, 질문 문맥화의 실제 입력·출력을 확인한다. 모델·프롬프트·검색·인용·문맥 선택 알고리즘·기존 의존 관계는 유지한다. 성능 실험과 품질 튜닝은 보류 상태를 유지한다.

1. 프론트는 기존 현재 권한 기반 대화 상세 API를 사용한다. 대화 턴의 sequence·segment·execution_id를 표시하고 실행 상세로 연결한다. 가려진 턴의 질문과 실행 링크는 노출하지 않는다. 평가 반복을 대화 턴으로 표현하지 않으며, 실패·권한 변경·route 변경 시 이전 데이터가 남지 않는다.
2. 최종 ContextPolicy 선택을 수행하는 `request` 단계에 선택형 `history_selection`을 추가한다. 앞서 끝난 `history` 단계의 시간·종료 상태를 다시 쓰지 않는다. `max_history_messages`, `max_history_tokens`, 입력/선택 메시지 수와 최대20개 메시지의 position·role·conversation_turn_id·selected·reason을 기록한다. 이유는 `selected`, `message_limit`, `token_limit`, `older_than_token_limit`이다. 단위는 메시지이며 Q/A 쌍이 아니다.
3. 관측 범위는 서비스의 현재 권한·구간·완료·서명 검증과 마지막20메시지 제한을 통과한 입력이다. 그 이전에 제외된 메시지를 모두 관측했다고 주장하지 않는다. 원 대화 턴 ID는 서비스가 만든 private scope에서만 전달한다. 공개 요청의 turn_id나 본문 동일성으로 연결하지 않으며, 정렬·개수·역할을 확인할 수 없으면 출처 ID는 null이다. 최종 선택과 토큰 계산을 한 번 수행하고 그 결과를 관측한다.
4. SDK 로컬 경로의 `contextualization` 단계에 선택형 비공개 본문 관측을 추가한다. 실제 HTTP 변환 후 허용 필드와 지침, 안전한 최종 응답 메시지를 보관한다. SDK 답변 trace와 구분하며 SDK가 선행 문맥화를 수행한 것처럼 가짜 부모·자식 span을 만들지 않는다. 비SDK 입력 진단의 요청 한정 계약은 유지한다.
5. 문맥화 관측은 `content_retention`, `input_kind=http_request`, instructions/input/output의 기존 AgentContent 상태·길이·해시, observation_complete·truncated를 사용한다. 비공개 내부 추론·헤더·endpoint·설정·원시 오류를 저장하지 않는다. 출력 관측 검증이 실패하면 본문은 생략하고 관측 불완전을 표시하며 업무 결과를 변경하지 않는다.
6. 기존 한 본문32,768자와 실행 전체131,072자 제한을 문맥화와 SDK trace에 함께 적용한다. 저장 및 조회에서 상태·해시·길이·총량을 검증한다. 대화/평가 결과 JSON·목록·로그에 본문을 중복 저장하지 않는다. 스키마 migration·새 테이블·외부 관측 서비스는 없다.
7. `include_diagnostics=false`여도 현재 observer를 상속한 일반 대화의 비공개 실행 기록은 수집한다. 요청 응답 진단 노출은 계속 해당 옵션을 따른다. 기존 actor/owner·정확한 실행 연결·현재 원문 ACL·전체 의존 관계·마지막 권한 재검증·늦은 쓰기 거부를 유지한다.
8. 과거 누락 필드는 미기록이다. 현재 설정으로 과거 선택이나 문맥화 전문을 복원하지 않는다. 실행 완료와 답변 품질 통과를 분리한다.

## 대안

저장된 본문을 비교해 턴을 추정하면 같은 질문·답변이 반복되는 경우 오인하므로 사용하지 않는다. 준비한 전체 이력을 사용 문맥으로 표시하면 최종 프로파일 제한을 숨기므로 사용하지 않는다. 선행 문맥화를 기존 SDK trace의 root로 합치면 실행 주체와 revision 계약을 바꾸므로 별도 실제 단계 관측을 택한다. 새 서버 목록·검색 API와 별도 본문 DB는 현재 요구에 필요하지 않다.

## 검증과 운영 경계

합성 자료로 동일 본문·서로 다른 ID, 부분 Q/A·빈 이력·메시지/토큰 경계, 서버 출처 불일치, 진단 off 상속 observer, 정상/손상/추론 포함 응답, 본문·합계 상한, legacy·권한 철회·종료 후 쓰기를 검증한다. 기존 DB의 rollback 저장/조회, 생성 API 타입·린트, 실제 화면의 과거 미기록과 턴 링크, 합성 모바일 레이아웃을 구분해 확인한다.

실제 멀티턴 모델 실행은 새 공개 합성 범위·질문·호출 예산을 별도로 정한 후 수행한다. 기존 소진된 모델 예산을 재사용하지 않는다. 본 구현의 오프라인 입력 동등성은 실모델 답변 품질 통과를 뜻하지 않는다.

## 2026-10-30 고정 평가의 미실행 history 관측

고정 입력 생성 평가는 서버 대화 이력 수집을 수행하지 않으므로 adapter 준비 전에 `history=skipped/not_executed`를 기록한다. 평가 결과 저장의 terminal trigger 이후에 미실행 단계 기록을 시도하지 않는다. snapshot history의 유효성 검사·최종 선택·문맥화는 기존 파이프라인 계약을 유지하며, 단계 생략을 입력 history가 비어 있다는 뜻으로 사용하지 않는다. 실제 미실행 단계의 시작 시각·소요 시간은 null이고 기존 누락 기록은 소급 보정하지 않는다. [검증과 본래 환경 확인](../worklogs/2026-10-30-sdk-history-observation.md)을 따른다.
