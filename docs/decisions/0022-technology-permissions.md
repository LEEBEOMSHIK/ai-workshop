# ADR-0022: 마스터와 기술별 관리 권한

- 상태: 승인됨, 단계별 구현 중(2026-09-09)
- 정본: [권한 상세 설계](../superpowers/specs/2026-09-09-technology-permissions-design.md)

owner 저장값은 유지하고 마스터로 표시한다. 기술별 view/configure/execute는 Platform Identity의
카탈로그·grant·revision·감사 계약으로 관리한다. configure와 execute는 view를 요구하나 서로 포함하지 않는다.
마스터만 부여/회수하며 마지막 활성 마스터 보호와 bootstrap은 하나의 설치 상태 잠금으로 직렬화한다.
문서·개인정보·외부 전송 승인·개인 Codex 권한은 기술 관리 권한으로 확대되지 않는다.

첫 구현은 권한 관리 기반과 마스터 전용 사용자 권한 화면이다. 기존 RAG/API owner 제한은
그대로 유지하고, grant가 저장된 것만으로 기술 경로를 개방하지 않는다. 후속 위임 연결 단계에서
명시적인 route+method 행렬과 안전 DTO, 페이지 guard, 비동기 실행 재검사까지 함께 적용한다.
해당 단계 전에는 UI에 권한 저장과 기능 적용 상태를 구분한다. 준비 중인 미래 Lab은 등록하지 않는다.

평가 스냅샷의 재현성은 보존한다. 후속 연결에서 현재 사용자/기술 실행 권한과 frozen 필수 공간의
현재 접근 여부를 별도 중단 gate로 검사하며 입력 hash나 범위는 변경하지 않는다.
기존 요청을 이미 외부로 전송한 경우 그 전송의 회수를 보장하지 않는다.

대안인 전체 owner guard 일괄 교체와 기술 권한에 문서 접근권한을 묶는 방식은 권한 확대 위험으로
채택하지 않는다. 대신 단계별 연결 비용과 두 종류 권한을 별도로 안내하는 UI 비용을 감수한다.
