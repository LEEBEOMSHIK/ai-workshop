## 범위와 성공 기준

사용자가 [실제12회 비교 결과](2026-10-19-rag-v5-evaluation-preparation.md#실제-12회-결과와-개선-판단)를 보고 “다음 개선작업 진행해”라고 요청했다. 필요한 규칙·조건은 전송됐으나 답변에서 누락됐고, B 줄배치/C 지침 강화는 해결하지 못했다. 이번은 기존 흐름의 제한된 코드 보완이며 새 실제 생성 예산이 아니다.

메인이 요구·아키텍처·AI/RAG·테스트 설계·문서를 맡고, 수정 범위가 분리된 구현 담당과 독립 코드 리뷰/통합 검증을 배정한다. 위험도 중간. UI·DB·인프라 변경은 없으므로 해당 전문 역할은 제외한다. 현재 작업 폴더의 미커밋 변경과 기존 실행 증거를 보존하며 새 환경·worktree·DB를 만들지 않는다.

1. 인용 검사는 [ADR-0035 확대 계약](../decisions/0035-rag-exact-value-canonicalization.md#2026-10-19-짧은-수치-표기의-지원-검사-확대)을 따른다. 실제 C1처럼 인용 밖의 짧은 날짜를 답한 초안은 거절하고, C2처럼 필요한 두 조각을 모두 인용한 경우 값 검사는 통과한다. 의미상 규칙·조건 누락은 기존 rubric의 실패로 계속 남긴다. 날짜·범위/식별자·상대 기준/단위·다른 업체와 값으로 반례를 검증한다.
2. 새 입력 후보 D는 저장된 v5 입력의 원문·순서·인용 ID·출처 경계·지침·모델 옵션을 유지하면서 좌표로 관측되는 행·열 배열만 추가한다. 근거를 더 검색하거나 삭제하지 않는다. 완전한 표·헤더·대상/규칙 의미를 확정하지 않으며 모호한 정렬/출처/순서는 힌트를 만들지 않는다. 같은 행/열의 ID 배열이 모델의 원문 읽기를 도울 수 있다는 가설이며 실제 효과는 미검증으로 둔다.
3. 기존 A/B/C 산출물은 바꾸지 않는다. D는 명시적으로 미실행인 오프라인 비교 후보로 저장하고 원본과 차이·보존을 검증한다. 운영 프로필이나 기존 v5 serializer 기본 동작에 연결하지 않는다.

구현 전에 실패를 재현하고 단위·관련 회귀·mock 통합, 변경 파일 Ruff/strict Mypy, 문서와 기존 증거 해시를 확인한다. 모델/임베딩·DB/ES 접근·서버 재시작·설치/다운로드·재색인·활성 설정/도메인 승격·commit/push는 하지 않는다. 실모델 품질 개선과 전체 RAG 수용은 이 오프라인 완료 기준에 포함하지 않는다.

## 인용 검사 변경과 실제 저장 답변 재판정

`generation/exact_values.py`에 짧은 수치 표기·한 글자 영문 상대 기준·정수 영업일의 별도 스캐너를 추가했다. 기존 `_VALUE`는 schema3의 숫자 목록·계산 증명이 직접 사용하므로 변경하지 않았다. 이번 확대는 schema1/2 경로에 해당하며 schema3의 인식 범위 확대를 뜻하지 않는다.

- `04-08`은 날짜/범위 의미를 결정하지 않는 문자값이며 `4-8`, `2031-04-08`, `4월 8일`과 자동으로 같게 만들지 않는다. `MODEL-04-08`, 복합 식별자, 소수·쉼표 수·잘못된 부호 일부를 떼어 지원 값으로 사용하지 않는다.
- `T+5`, `S+5`, `T-5`는 서로 다르다. 원문 `T+5 영업일`은 상대값과 명시된 영업일 값을 모두 제공하지만 `5 영업일`만으로 기준점 T를 만들어내지는 않는다. 값과 원문을 변경하거나 달력 계산을 하지 않는다.
- 한국어 조사에 붙은 `04-08이다`, `T+5영업일`은 인식하지만 일반 자연어, 슬래시 날짜, 소수 영업일 등은 지원 범위 밖이다. ASCII 식별자 경계 방어가 모든 언어의 제품 코드를 구분한다는 뜻은 아니다.

공개 합성 신규74개는 변경 전28실패, 후속 복합 부호3실패·쉼표 수 부분 추출2실패를 재현한 뒤 통과했다. 서로 다른 업체 상황·다른 수치로 검사하며 실제 질문별 정답을 코드에 넣지 않았다. 최종 생성 모듈 회귀는1,574통과·4skip이다. skip은 합성 symlink 생성에 필요한 OS 권한 부재이며 기존 Starlette deprecation 경고1개가 있다.

실제12답변은 원본을 바꾸지 않고 **네트워크를 차단한 오프라인 재판정**으로 비교했다. 새로 거절된 것은 `05-normal-C-1` 한 건이며 원인 코드는 `exact_value_not_supported`다. 실패 시 답변 초안·인용을 노출하지 않는다. C2는 필요한 두 조각을 인용해 값 검사를 통과하고 A/B도 기존대로 값 검사를 통과한다. 정상6건의 일반 규칙/휴일 조건 누락은 기존 rubric에서 모두 실패로 남는다. 거절6건에는 claims가 없어 인용 검사를 적용하지 않았다.

이 결과는 **인용 누락 탐지의 개선**이며 새 생성 답변의 품질 개선이 아니다. 기존 평가 결과·지표·감사 행은 재작성하지 않았다. ## 원문 배열 D 후보

`evaluation/offline_layout_candidate.py`는 완전한 v5 캡처를 검증하고, 같은 source_ref의 native PDF 원문에서 좌표가 정확히 정렬되는 연속 행들의 ID 배열만 만든다. 원문을 정렬·병합·교체하지 않는다. 좌표·문자 범위·ordinal의 결측/역전/겹침, source 재등장(A→B→A), OCR·명시적 table_cell은 힌트를 만들지 않는다. 근접 좌표를 반올림해 맞추지 않으며 행 높이·줄바꿈·셀 병합이 복잡한 표는 지원하지 않을 수 있다.

첫 행을 헤더로 지정하거나 회사/상품·규칙/조건 역할을 부여하지 않는다. 같은 정렬의 목록이나 선택된 표 일부일 수도 있으므로 `semantic_roles=not_assigned`, `coverage=selected_fragments_only`를 명시한다. 파서 table identity 추가, 실제 표 전체 복원, 청킹·검색·선택·예산·프로파일 변경은 없다. 다른 열/주석/조건을 삭제하지 않으며 질문 문자열로 격자를 선택하지 않는다.

## 2026-10-20 실제 A/D 비교 검증

사용자가 “개선했으면 검증 진행해”라고 실제 검증을 요청했다. 원본 A와 D를 정상/근거 부족2사례×2회, 총 최대8회 로컬 생성·retry0으로 실행 범위를 고지했다. 이번8회는 과거 소진된12회와 별도이며 실패·timeout도 소진으로 기록하고 보충 호출하지 않는다. 새 검색·임베딩·예열·일반 큐 worker를 실행하지 않는다.

현재 모델/프로필·정상 런타임 입장 조건·원문 권한과 대기 평가 부재를 먼저 읽기 전용으로 확인한다. 저장된 최종 입력과 D의 현재 검증된 파일을 고정하며, 실제 전송 직전 슬롯을 배타적으로 기록한다. 두 조건에 보강된 동일 CitationValidator를 적용한다. 별도 프로세스에서 현재 코드를 사용하는 생성 단계 비교이며 서버 재시작·DB 평가 등록·전체 RAG E2E가 아니다.

고정 순서는 정상A1→거절D1→정상D1→거절A1→거절A2→정상D2→거절D2→정상A2다. 조건·사례별2회, 조건당4회이며 각 조건의 평균 순서4.5다. 입력과 옵션은 고정하지만 로드/캐시·소표본 한계를 제거하지 않으므로 지연 평균으로 인과를 단정하지 않는다. D의 거절 입력은 A와 바이트 동일한 대조 조건이다. D 효과가 있다면 배열과 안내문을 합친 효과로만 판단한다.

메인이 요구·AI/RAG·실행·분석, 기존 별도 담당이 독립 코드/결과 검증을 맡는다. 위험도 중간이며 UI·DB·배포 변경 역할은 제외한다. 기존 원문·질문별 기대 기준·미커밋 변경을 보존하고, 결과와 품질 기준 통과를 구분한다. 도메인 활성화나 후속 추가1회는 이번 범위에 포함하지 않는다.
