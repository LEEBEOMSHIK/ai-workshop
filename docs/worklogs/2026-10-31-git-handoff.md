# 2026-10-31 누적 변경 정리와 Git 인계

## 요청과 범위

사용자가 불필요한 파일 정리와 커밋·푸시를 요청했다. 시작점은 `main`의
`c7071784c46f1c3be73f8ace29aff53ef17b6b29`이며, 원격 fetch 후 `origin/main`과 같았다.
수정167개·미추적369개, 총536개 파일을 조사했고 기존 index는 비어 있었다.

누적 범위는 RAG SDK 관측·재위임·대화 복귀, 입력·조회 응답성 개선, 원문 관계 기반
인용 검증, 저장 모델 비교, 관리자 모델 연결과 Claude 지원, 업무 화면 디자인 시스템이다.
관련 소스·migration·테스트·설계·실측 기록은 의존성을 함께 포함한다.
이번 인계에서는 새 모델 호출·외부 추론 전송·DB 쓰기·기본 모델 변경을 하지 않는다.
이전 실측의 품질 실패·미확인 항목을 커밋 성공으로 완료 처리하지 않는다.

메인은 파일 선별·문서·통합 수정·Git 작업을 맡고, 백엔드와 프론트엔드 독립 검증,
캐시·산출물 독립 감사를 병행했다. 각 담당은 제품 파일을 수정하거나 Git index를 변경하지 않았다.

  fixture gzip은 README의 고정 SHA-256·schema1·5개 packet과 일치하는 테스트 입력이다.

  내용은 유지하고 상대 링크만 조정했다. 현재 상태·다음 순서·최근 완료5개는 보드에 남긴다.
- 접근 거부된 오래된 테스트 디렉터리는 소유·내용을 강제로 추정하거나 삭제하지 않는다.
- ASA는 사용자 지시대로 유지한다. [ISSUE49 Windows 조사](2026-10-31-windows-memory-investigation.md)의
  미해결 진단 자료도 보존하며, 이번 디스크 캐시 정리는 커널 메모리 문제 해결을 뜻하지 않는다.

## 검증

- 백엔드 완료된 단위 회귀는 핵심1,170개·에이전트/실행673개, 합계 **1,843개 통과**다.
  전체 strict Mypy는 수정 후 **527개 소스 통과**, 변경 Python226개 Ruff와 수정 파일의 최종 Ruff도 통과했다.
- 추가 색인17파일 묶음은 계산량이 큰 합성 native 보호 시나리오에서 중단했다.
  697.45초 동안 부분 출력800통과·13건너뜀·실패 표시0을 관측했지만 최종 JUnit이 없으며
  **전체 묶음은 미완료**다. 위 완료 합계에 더하지 않았다. 소유 pytest만 종료하고 다른 서비스를 유지했다.
- 프론트엔드 전체 TypeScript·ESLint 통과. 최초 Vitest 실행은 **188파일·1,415개 통과**,
  위 Node 전용 파일1개만 수집 오류로 종료코드1이었다. 수정 후 실제 수집 목록188개가
  최초 통과 파일 집합과 정확히 같음을 대조했고, 설정의 타입·린트도 다시 통과했다.
  Node 디자인 검사2개와 runtime15개는 별도로 통과했다. 전체 Vitest 재실행 성공으로 표현하지 않는다.
- OpenAPI 계약 검사, 역할 계약 검사, 68개 migration의 단일 head/부모 연결, 의존성 lock 정합성 통과.
  프론트 소스163개·로컬 import444개의 누락0, 변경 문서의 상대 링크 누락0을 확인했다.

  파일 끝 빈 줄7곳만 정리했으며 고위험 비밀값 패턴은 없었다. 기존 로컬 실행 예제의 경로는 보존했다.

실제 모델 품질 재측정, production build, 브라우저 전체 E2E 또는 기존 DB를 변경하는 통합 실험은
이번 인계에서 실행하지 않았다. 두 검증 결함은 이 문서에 기록했으며 관리자 DB 이력 추가는 미실행이다.

## 캐시 정리

정확 범위 보고 후 사용자가 다음4곳의 삭제를 승인했다. 검증 종료·미사용·reparse·경로
경계를 다시 확인한 뒤 이 범위만 정리했다. 초기 파일별 SHA-256과 용량 감사를 보존했다.

| 저장소 상대 경로 | 초기 논리 용량 | 파일 수 |
| --- | ---: | ---: |
| `.mypy_cache` | 201,994,469 bytes | 3 |
| `backend/.mypy_cache` | 203,235,557 bytes | 3 |
| `.ruff_cache` | 43,814 bytes | 52 |
| `backend/.ruff_cache` | 103,978 bytes | 107 |
| 합계 | 405,377,818 bytes (386.598 MiB) | 165 |

`backend/build`와 기타 pytest 디렉터리는 이번 승인 범위에 포함하지 않는다.
논리 용량은 NTFS 압축·다른 프로세스 쓰기 때문에 실제 드라이브 여유 공간 변화와 다를 수 있다.
검사 중 Ruff 캐시1파일180bytes가 추가돼 최종 삭제는 **166파일·405,377,998bytes**였다.
네 경로 모두 제거됨을 확인했다. 디스크 여유 공간은 삭제 직전101,754,605,568bytes에서
직후101,897,564,160bytes로 **142,958,592bytes(136.34MiB)** 증가했다.
이는 호스트 전체의 짧은 구간 관측값이며 동시 쓰기의 영향까지 분리한 순수 회수량은 아니다.

이번 검사에서 별도로 생성된 로컬 Mypy 캐시3파일·201,298,149bytes는 승인된 삭제 경로 밖이므로
보존하고 가역적 NTFS 압축만 적용했다. 전후 SHA-256이 모두 같고 Windows 보고 압축 크기는
68,247,781bytes다. 테스트 로그·실패/중단 증거·기존 진단 원문은 삭제하지 않았다.
삭제 전 감지한 다른 프로젝트의 pytest2개는 경로/부모를 확인한 뒤 그대로 유지했다.
정리 후 기존 API health/ready·로그인 화면은 모두 HTTP200이며 `.env`와 사용자 참고 이미지의
SHA-256은 정리 전과 같다. 승인 경로 밖의 다른 프로젝트·실행 서비스·DB는 변경하지 않았다.

## 인계 상태

검증 로그·명시적 경로 목록·캐시 감사·복구용 보드 원문은 Git 제외된
`.local-data/project-agent-work/cleanup-commit-20261031/`에 둔다.
원격 대상은 기존 `origin/main`이며, 최종 Git 상태와 원격 SHA 일치를 확인한다.
별도 worktree는 생성하지 않았고 기존 등록은 본래 checkout 한 곳뿐이다.
이 문서를 포함하는 커밋 ID는 Git 이력에서 확인한다. 푸시 후 SHA 대조 결과는 최종 작업 보고와
로컬 인계 영수증에 남긴다. 현재 미해결 RAG 품질·운영 활성화·Windows 메모리 조사 경계는 유지한다.
