- 승인: 사용자의 “그래 개선 진행해”. [선행 조사](2026-10-25-rag-latency-audit.md)의 첫 개선 범위를 적용했다.

## 바뀐 점

coverage는 질의어가 얼마나 포함됐는지를 구하는 점수다. 기존에는 점수만 필요할 때도
각 접두사를 다시 정규화해 원문 위치를 복원했다. 긴 문맥에서는 이 O(n²) 비용이 커졌고,
질의·같은 본문을 추출 선택과 문맥 선택에서 다시 계산했다.

`KeywordMatcher`가 한 요청 안에서 질의어와 본문 정규화, 필요한 위치 배열을 재사용한다.
coverage와 충돌 비교에는 NFKC→casefold→공백 축약 결과만 계산한다. 실제 하이라이트의
위치 복원 알고리즘은 유지하고 필요한 경우에만 수행한다. 특정 질문·상품에 대한 분기는 없다.
선택 순서·임계값·충돌·예산·표·인용 위치·권한·임베딩 수명을 유지한다. 요청 간 본문 캐시는 없다.

단계 JSON의 선택적 `operations`에는 정해진 연산 이름과 경과시간·횟수·실패·입력 항목·재사용
항목 수만 저장한다. 검색 권한 확인/BM25/dense/원문 조회, 근거 선택, 문자열 계산,
임베딩 적재/토큰화/질의·문서 계산, frozen 검색의 describe/PIT 경계를 구분한다.
기존 단계 저장에 함께 넣으므로 연산마다 DB를 추가 호출하지 않는다. 새 테이블·migration은 없다.
기존 권한 상세 API로 조회하며 본문·질문·endpoint·예외 메시지는 추가 수집하지 않는다.

각 시간은 자식 연산과 대기를 포함한다. 병렬·중첩 값을 더해 전체 응답 시간으로 쓰면 안 된다.
기존 실행의 미수집 필드는 0으로 만들지 않는다. 전용 세부 시간 UI와 Ollama 내부
load/prefill/decode 측정은 이번 범위에 없다.

## 합성 입력 변경 전후

작업 전 소스 복사본과 수정 소스에 같은 합성 입력을 넣었다. 벡터는 고정 fake이며
모델·네트워크·DB를 사용하지 않았다. 각 조건 3회, 표는 중앙값이다. observer 없는 함수/선택
비교이며 실제 RAG와 DB 기록 시간을 포함하지 않는다.

| 1,000자 coverage | 484.610ms | 0.322ms | 점수 동일 |

0.17초가 됐다는 의미가 아니다. 앞선 조사와 합성 본문·측정 범위가 달라 절대 시간을 직접 합치지 않는다.

## 검증

- 최종 독립 단위 **871개 통과**: highlighting/executions/embeddings/retrieval/search/orchestration과
  취소 처리에 직접 영향받는 대화 테스트3파일. 독립 작성49개 포함이다.
- 최초833개 통과 뒤 독립 취소 회귀1개를 추가했다. 최종871개는 그833개+새1개+대화37개이며
  중복 실행 수를 고유 테스트 수에 더하지 않았다.
- Unicode 결합 문자·한글 자모·ligature·casefold·공백·substring·원문 bbox/ID, 요청 격리,
  선택·충돌·예산·권한, 계측 예외·동시성·늦은 완료·이전 JSON을 확인했다.
- 기존 DB rollback **1개 통과**: 실제 recorder 저장→현재 권한 상세 조회, 다른 actor404,
  과거 필드 미수집, terminal 기록 덮어쓰기 거부. 합성3행은 외부 트랜잭션 안에서만 생성했고
  rollback 뒤0행 및 기존5표의 수·지문 동등성을 확인했다. 영속 쓰기0이며 읽기 전용 테스트는 아니다.
- 변경 Python strict Mypy·Ruff, OpenAPI 생성·`api:check`, frontend 전체 `typecheck` 통과.
- 합성 벤치마크 이후 highlighting 두 소스 SHA가 동일하다.

독립 검토에서 **단계 저장 대기 중 취소될 때 관측 상태가 running으로 남는 회귀**를 발견했다.
수정 초기안은 `done/active`를 저장 await 전에 바꿨다. 같은 회귀는 초기안에서 실패하고
작업 전 observer에서는 통과했다. collector는 저장 전에 닫되 상태 이동은 저장 이후로
복원해 취소 finalizer가 단계를 찾도록 수정했다. 최종871개에 재현 검증을 포함했다.
실제 DB 취소 경합을 실행한 것은 아니다.

## 본래 환경 반영

실행 중 상태5종이 모두0임을 읽기 확인한 뒤 기존 API PID127584의 실행 파일·시작 시각·명령·
localhost18000 소유를 검증했다. 그 API 한 개만 종료·종료대기하고 승인된 `backend/.conda`와
루트 작업 디렉터리·같은 Selector loop/18000 설정으로 숨김 재기동했다. 새 PID는114716이다.

직접 health/ready와 프론트 경유 health 모두200, 새 선택적 operation schema를 확인했다.
전후25표 **2,448행의 수·지문과 `.env` SHA가 동일**하다. 모델·프로파일·worker·설정·색인을
변경하지 않았고 새 생성/임베딩 요청0이다. 로그인된 기존 실행 상세에서 Mermaid5단계,
저장 답변, **실행 완료·품질 실패·16.56초**가 그대로 조회된다. 이 과거 시간은 새 측정이 아니다.

관리자 문제 이력에 ISSUE-00038을 구현됨·검증 남음으로 등록했다. 기존 ISSUE-00005의
품질 상태·과거 이력은 수정하지 않았다. 커밋·push는 하지 않았다.

시작 시 기존 변경192파일 중186개는 SHA가 동일하며 이번 범위6개만 갱신했고 누락0이다.
추가 dirty 경로18개는 이번 제품·테스트·문서 범위다. 구현자·독립 검증자의 최종 파일 SHA와
합성 측정 소스를 대조했다. WORKBOARD 최근 완료는5개를 유지한다.
