# ADR-0055: 벡터 저장소 비교의 입력 봉인과 오프라인 준비

- 날짜: 2026-11-01
- 상태: 준비 도구 구현 결정. 실제 후보 설치·검색 실행·운영 채택은 미완료.
- 근거: [원래 실험 순서](../superpowers/plans/2026-10-04-rag-vector-store-and-local-llm-experiments.md), [명세](../superpowers/specs/2026-11-01-vector-store-comparison-design.md).

## 결정

Elasticsearch, pgvector, Qdrant 한 후보를 같은 float32 정규화 벡터와 권한 범위에서 비교한다. 첫 단계는 필터된 exact cosine이며, 기존 ES의 BBQ-HNSW와 후보 ANN 설정 비교는 후속 단계로 분리한다. Qdrant는 필터·exact 검색과 단일 노드 운영 경계가 명확해 준비 대상으로 선정했다. 더 빠르거나 메모리를 적게 쓴다는 결론은 아직 없다.

평가 모듈 안에 네트워크 없는 `vector_comparison` 도구를 둔다. 공개 합성 스냅샷 검사, 세 엔진의 읽기 요청 생성, 균형 잡힌 반복 순서, 수입 결과의 검색 품질·속도·자원 요약을 제공한다. 기존 `DenseRetrieverPort`, ES 물리 색인 계약, 제품 API, 승격 게이트와 기본 연결은 변경하지 않는다. 기존 생성형 평가 workflow를 실행하거나 평가 DB에 결과를 쓰지 않는다.

권한은 스냅샷의 허용 청크와 정확한 원문 identity 튜플로 모든 엔진의 후보 생성 전에 제한한다. 이 파일은 실행 권한 토큰이 아니며 미래 live runner는 현재 권한을 다시 확인해야 한다. pgvector 일반 ANN의 사후 필터를 동일한 prefilter라고 취급하지 않는다. 동일한 ES BM25 순위와 기존 RRF 함수를 재사용한다.

검색 결과의 관련도와 정확 벡터 이웃 재현율은 서로 다른 지표다. 청크 수준 지표는 기존 근거 단위 지표나 최종 답변·인용 품질을 대신하지 않는다. 수입된 관측은 자체 수집·검증 완료 증거가 아니다. 미측정·미판정 값은 null로 유지한다.

## 기존 환경과 실행 보류 조건

읽기 전용 조사에서 ES 9.5.2, PG 17.11, 활성 벡터22개/768차원, 평가38문항을 확인했다. pgvector 확장은 설치·available 모두 없고 실제 Docker 이미지는 ARM64다. 프로젝트 AMD64 방침과 일치시키는 방법, 제한된 가용 메모리, ISSUE-00013의 쓰기 게이트를 해결하기 전 후보 프로세스·볼륨·확장·테이블·색인을 만들지 않는다. 기존 PG 이미지를 pgvector 이미지로 교체하지 않는다.

Qdrant 1.20.0과 pgvector 0.8.7은 조사한 후보 버전이다. 실제 비교 전에 이미지 digest·아키텍처·설정·자원 예산을 고정한다. 소규모 22벡터에서 좋은 결과가 나와도 운영 규모 성능으로 일반화하지 않는다. 현재 원본/질문 벡터 전수 복제·해시 검증은 하지 않았다.

## 전용 후보 네 제품 추가 조사

사용자 요청에 따라 Qdrant·Milvus·Weaviate·Chroma를 기능·자원 구조·운영 부담으로 추가 비교했다. [상세 비교와 근거](../worklogs/2026-11-01-vector-store-candidate-comparison.md). 현재 운영 ES 유지, 전용 DB 첫 실측 Qdrant·다음 Weaviate를 권고한다. 기존 Qdrant exact 요청 준비 비용을 우선순위에 반영했으며 품질·속도·RAM 우위의 실측 결과는 아니다. Chroma local은 공개 강제 exact 경로가 확인되지 않아 후속 ANN 후보로, Milvus Standalone은 현재 자원 제약에서 후순위로 둔다. Milvus Lite는 별도 경량 모드로 구분한다.

이 조사는 준비 CLI의 지원 엔진을 늘리거나 후보 설치·실행·운영 채택을 승인/완료한 것이 아니다.22벡터/top-k30으로는 ANN 품질 차이를 판정할 수 없으며 승인 자료·실제 규모·동일 재현율과 권한 조건에서 결론을 재검토한다.

## 대안과 영향

- 제품 어댑터 즉시 교체: ES identity/권한/색인 수명주기 변경과 실제 자료 이관이 필요하므로 이번 준비 범위에서 제외한다.
- 후보 서버 즉시 설치: 원래 서비스 보존과 메모리·아키텍처 조건이 미해결이므로 제외한다.
- 문서만 작성: 반복 가능한 동일 입력과 판정 기준이 없으므로 오프라인 CLI와 합성 회귀 검증을 함께 제공한다.

실제 인프라 응답 형식·쿼리 계획·자원 수집은 후속 통합 검증이 필요하다. 이 ADR은 실제 세 엔진 동작 확인이나 운영 전환을 주장하지 않는다.
