# 대화 실행 실패 진단

- 날짜: 2026-09-27
- 상태: 원래 오류 원인 미확정, 승인된 세션 재시도 정상, 실제 브라우저 재로그인 대기

## 확인한 사실

본래 DB에서 첫 대화 요청이 약24초 후 conversation_execution_failed로 종료됐다.
서버는 일반 예외의 상세를 모두 버리므로 기존 메시지만으로 실패 지점을 식별할 수 없었다.
기존 DB·Redis·Elasticsearch는 정상 상태다. 별도 환경·계정·더미 대화는 만들지 않았다.

외부 생성을 차단한 동일 검색 경로 재현은 정상이고 생성에 전달할 근거가0개였다.
근거가 없는 경우에만 로컬 근거 부족 분기까지 진행하도록 가드한 재현도 insufficient_evidence로 정상 완료했다.
이 재현은 외부 모델을 호출하지 않았으며 정상 로컬 처리에 해당하는 생성 감사 메타데이터만 저장했다.
대화 문맥 준비도 원래 요청을 읽기 전용으로 확인해 정상 완료했다.
실제 세션 실행의 실패 원인은 아직 확정하지 못했다. 검색 결과 부재와 실행 예외를 같은 원인으로 단정하지 않는다.

## 변경 및 검증

일반 예외를 처리하는 지점에 요청 UUID·단계·예외 종류·코드 파일명/함수/라인만 기록한다.
예외 메시지, 질문, 문서, 지역 변수, 전체 경로와 traceback 본문은 기록하지 않는다.
9개 서비스 단위 테스트, Ruff와 mypy 및 독립 개인정보 보호 검토를 통과했다.
본래 .env·DB·포트18000을 유지해 API를 숨김 재시작했다. API 및 프론트 경유 health200 확인.

## 남은 확인과 승인 제한

자동 승인 검토가 외부 모델 재전송과 기존 대화에 재시도 turn 추가를 각각 거절했다.
외부 자료 재전송·사용량 발생과 추가 대화 이력 생성의 명시적 승인이 확인되지 않았다는 이유다.
두 동작은 실행하지 않았고 사용자에게 동일 요청1회 재시도·이력 저장·필요한 외부 처리 승인을 요청했다.
승인되면 본래 세션 경로에서 재현해 안전한 진단 로그의 실제 실패 위치를 확인하고 원인을 수정한다.

별도 읽기 전용 검토에서 긴 이전 답변의 이력 길이 제한 가능성도 발견했으나,
이번 장애는 첫 요청이므로 실제 원인 후보에서 제외하고 별도 후속 검토 사항으로 남긴다.

## 사용자 승인 후 실제 경로 비교

사용자가 동일 요청 재시도·기록 저장·필요한 외부 처리를 승인했다.
기존 마스터 브라우저에서 원래 선택 문서·분류·질문으로 전송했으나 로그인 쿠키30분 만료로401 not_authenticated였다.
이는 원래 conversation_execution_failed의 재현이 아니며 별도 인증 상태 문제다.
화면은 마스터 정보가 남아 일반 답변 오류로 표시하고 있었다.

이후 승인된 동일 요청을 원래 대화 세션과 HTTP와 같은 관리 트랜잭션으로1회 재시도했다.
외부 생성은 근거가 존재하면 즉시 중단하는 가드로 차단했으며, 실제 근거0개 분기가 실행됐다.
ConversationService.submit은 completed·error없음으로 종료했고 근거 부족 결과를 원래 대화에 저장했다.
이 결과는 백엔드 세션 경로 검증이며 브라우저 전송·결과 표시·새로고침 복원 검증을 대신하지 않는다.

401/not_authenticated는 명확한 로그인 만료 안내와 새 탭 재로그인 링크를 제공하도록 수정했다.
현재 탭의 질문 초안과 선택 문서를 유지하고 자동 재전송하지 않는다. 쿠키 수명·인증 정책은 변경하지 않았다.
실제 브라우저의 재로그인을 요청했고 로그인 탭을 열어 두었다.
원래 실행 예외의 확정 원인은 아직 없으므로 ISSUE-00011을 open으로 유지한다.
검증 단계별 보고 기준을 로컬 실행서에 명시했다.

후속 검증: 대화38건·실제 세션 전송 모듈7건(총45건) 통과. 기존 세션401 뒤 수동 재전송에서 동일 요청ID·검색 범위를 유지하고 새 세션을 만들지 않으며 정상 응답을 표시하는 회귀 검증을 포함했다. 타입·대상 린트·독립 링크/권한 검토 통과.
