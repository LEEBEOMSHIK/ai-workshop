# ADR-0039: 선택형 Agents SDK 실행과 위임 관측

- 날짜: 2026-10-23
- 상태: 사용자 요청 범위의 구현 결정
- 관련: [SDK 도입 계획](../superpowers/plans/2026-10-04-rag-agents-sdk-adoption.md), [ADR-0038](0038-request-local-generation-input-inspection.md)

> 본문 정책 변경(2026-10-23): 아래 요청 한정·본문 미보관 결정은 최초 구현 당시 정책이다. 사용자가 단계별 수집·보관·상세 조회를 명시한 이후의 새 SDK 실행은 [ADR-0040](0040-private-agent-step-content.md)을 따른다. 과거 본문은 복원하지 않으며 기존 역할·예산·권한·외부 전송 금지 계약은 유지한다.

## 결정

OpenAI Agents Python SDK를 RAG 생성 단계의 선택형 조정기로 사용한다. 생성 프로파일의 명시적인 `orchestration` 설정이 있을 때만 중앙 에이전트가 답변 담당 에이전트를 도구로 호출한다. 이것은 제어권을 넘기는 handoff와 구분한다. 검색·권한 검사·근거 선택·인용 검증·저장은 기존 애플리케이션 서비스를 사용한다. SDK 자료형은 RAG orchestration 어댑터 안에 둔다. 모델 공급자 종류에 SDK를 추가하지 않는다.

첫 경로는 기존 local OpenAI-compatible 배포와 schema 2 답변이다. 모델, endpoint, secret, 데이터 전송 허용 여부는 기존 배포 해석 경계를 따른다. 조정용·답변용 요청은 같은 배포를 사용하며 관리자는 근거·권한·배포를 변경할 수 없다. 프로파일에 설정한 총 모델 호출 수·출력 토큰·시간 한도를 공유하고 자동 재시도·대체 모델·병렬 위임·SDK 세션 저장·외부 trace 전송을 사용하지 않는다. 기존 로컬 HTTP 종료 미확인 의미를 유지한다.

평가도 대화와 같은 요청별 `GenerationTermination` 추적을 사용한다. 로컬 HTTP 호출의 종료가 미확인인 시도는 `provider_termination_unconfirmed`로 기록하고 같은 run의 아직 시작하지 않은 반복을 중단한다. 기존 claim token과 행 잠금으로 해당 run만 종료하며 이미 완료한 결과와 다른 대기 run은 보존한다. 이 표시가 남은 run은 실패 재시도 API로도 다시 실행하지 않는다. 이는 원격 모델의 종료 확인이나 강제 종료가 아니다. 완전한 HTTP 응답 뒤의 품질 실패와 실행 전 검증 실패는 원격 미종료로 간주하지 않는다. 평가 최소 2반복과 품질 기준은 유지한다.

## 관측 계약

실행마다 서버가 만든 run/span ID, 부모 ID, 순서와 revision으로 실제 agent/delegation/model/tool 관계를 기록한다. 이름은 등록된 역할·도구 이름이며 모델이 반환한 자유 텍스트를 메타데이터 이름이나 오류 코드로 저장하지 않는다. SDK as_tool은 `delegation_mode=as_tool`로 표시한다. 결정적인 검색 서비스를 LLM 에이전트로 표시하지 않는다.

기존 `rag_executions.stages` JSON의 예약 키 `_agent_trace_v1`에 독립적인 `AgentTrace` 계약을 저장한다. 기존 8개 단계의 스키마와 키는 유지한다. 행 잠금 하에서 동일 run의 증가하는 revision만 반영하며 종료된 실행의 늦은 쓰기는 거부한다. 본문을 제거하는 명시적 projection을 저장소 경계에서도 적용한다. 이전 실행은 trace 없음으로 표시하고 흐름을 추정하지 않는다. 별도 DB migration은 필요하지 않다.

기존 실행 조회의 owner·actor·대화 의존 관계·현재 원문 ACL 및 재조회 검증을 유지한다. 원문 식별자는 구조화된 manifest로 기록하며 문자열 JSON을 ACL 근거로 사용하지 않는다. 외부 trace exporter는 전체/부모/자식 실행에서 비활성화한다. 관측 실패는 업무 결과를 가리지 않고 `observation_complete=false`로 보고한다. 사용량 누락은 0으로 바꾸지 않는다.

## 본문 처리

지침·위임 입력·도구 결과·실제 모델 요청은 진단을 요청한 현재 응답에서만 제한된 크기로 제공한다. 실제 HTTP body와 SDK 입력은 구분한다. 본문 이력 보관에 대한 별도 사용자 선택 전에는 ADR-0038을 유지하며 DB·일반 로그·브라우저 영구 저장소에 본문을 추가하지 않는다. 서버의 기존 권한 재검증 이후에만 반환하고 대화 저장·평가 결과 저장 시 제거한다. 한도 초과는 본문 전체를 생략하며 그 이유와 길이·해시를 표시한다. 자격 증명, endpoint, 헤더, 비공개 내부 추론은 수집하지 않는다.

인용·답변 검증이 실패하면 기존 초안 비노출 규칙을 유지한다. 요청 한정 trace에서도 출력 본문을 제거하고 `omitted_validation_failure`와 길이·해시를 표시한다. 모델 호출 완료가 답변 검증 통과를 뜻하지 않는다.

## 화면

기존 관리자 실행 상세에 위임 흐름과 선택한 단계의 입력·결과·모델·사용량·시간을 추가한다. 현재 대화의 검색 진단에서도 같은 패널로 요청 한정 본문을 확인한다. 이력 조회에서는 본문 미보관을 명시한다. 완료와 품질 통과를 구분하며 미기록·관측 실패·실행 중·취소 요청/종료 미확인을 숨기지 않는다. 새 그래프 라이브러리 없이 접근 가능한 목록과 CSS 연결선을 사용한다.

## 검증과 한계

실제 SDK Runner와 합성 Model 또는 HTTP MockTransport로 부모→위임→자식 실행, 전달 내용, 예산·취소·오류·외부 전송 0을 검증한다. 프로파일 미설정 회귀, 현재 ACL·본문 비저장, 종료 뒤 쓰기, UI 경합·키보드·320/375/1280px를 확인한다. 오프라인 SDK 성공을 실제 Gemma 도구 호출 수용이나 품질 개선으로 보고하지 않는다. 운영 프로파일 활성화·실모델 호출은 정확한 조건·호출 예산을 확인한 뒤 별도로 수행한다.
