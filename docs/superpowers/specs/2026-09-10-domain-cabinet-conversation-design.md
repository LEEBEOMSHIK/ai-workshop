# 도메인 중심 파일함과 문서 대화

- 상태: 사용자 상세 계약 승인(2026-09-10), 1단계 구현 중
- 기준일: 2026-09-10
- 결정: [ADR-0023](../../decisions/0023-domain-cabinet-conversation.md)
- 기존 기반: [도메인 대화](2026-09-07-domain-first-rag-conversation-design.md),
  [문서 라이브러리](2026-09-09-document-library-design.md)

## 1. 승인된 사용자 흐름

도메인 선택 → 해당 도메인의 작업 화면 → 파일함 또는 대화.
파일함에서 문서를 선택한 뒤 도메인을 다시 고르는 앞선 제안은 대체한다.

- 도메인 안에 파일함과 대화를 별도 화면으로 둔다. 상단에 현재 도메인과 두 메뉴를 유지한다.
- 파일함은 회사·전사와 개인 영역으로 구분한다. 기존 폴더 트리·문서 목록·원문·버전 기능을 재사용한다.
- 파일함에서 여러 문서를 선택하고 `선택 문서로 대화`를 누르면 같은 도메인 대화로 이동한다.
- 대화의 `문서 추가`는 `파일함에서 선택`과 `새 파일 첨부`를 구분한다.
- 새 첨부는 현재 대화의 임시 자료가 기본이다. 개인 파일함 영구 보관은 명시적으로 선택한다.
- 선택 문서명, 원본/처리 상태, 실제 검색에 적용된 버전을 보여준다. 내부 UUID는 표시 이름으로 쓰지 않는다.

## 2. 화면 경로와 호환

| 경로 | 책임 |
|---|---|
| `/workshop/rag/search` | 도메인 선택 입구 유지 |
| `/workshop/rag/domains/{slug}/files` | 도메인 파일함 |
| `/workshop/rag/domains/{slug}/chat` | 같은 도메인 대화 |
| `/workshop/workspaces` 및 기존 하위 경로 | 기존 공통 파일 관리 주소 보존 |

RAG의 사용자 진입에서는 도메인을 먼저 고른다. 기존 공통 파일함은 타 기술도 사용하는 Platform 기능이므로
삭제하거나 특정 RAG 도메인으로 강제 리다이렉트하지 않는다. 도메인 전환은 진행 요청을 취소하고 선택과 대화 문맥을
분리한다. URL에 문서 본문·질문·승인 토큰을 넣지 않는다. 선택 ID는 신뢰하지 않고 서버가 매번 재검증한다.

## 3. 도메인과 저장소·권한 경계

도메인은 기술 사용 맥락이고, 회사/개인은 소유권과 접근 범위다. 도메인별 물리 파일 복제는 하지 않는다.
Platform Assets는 원본·폴더·버전·권한을 계속 소유하고 RAG는 도메인 연결·검색 가능 상태를 소유한다.
도메인 전용 UI는 조립 계층에서 기존 탐색 컴포넌트와 RAG 계약을 연결한다. Platform이 RAG 구현에 의존하지 않는다.

회사 파일함은 기존 도메인/구성에 연결된 공간과 현재 사용자 권한의 교집합이다. 문서를 열거나 선택하는 행위는
공유 권한이나 외부 전송 승인을 새로 부여하지 않는다. 파일함 열람에 LLM 준비나 외부 승인을 요구하지 않는다.
파일함 조회는 생성 준비를 요구하는 `resolve_search`를 재사용하지 않고 별도 열람 권한 계약으로 조회한다.

현재의 정적 도메인 공간 연결만으로는 모든 사용자의 개인·임시 업로드를 안전하게 지원할 수 없다.
이를 전사 연결 목록에 자동 추가하지 않고, 후속 첨부 단계에서 RAG 소유의 사용자별 도메인-문서 연결과
대화별 첨부 관계를 추가한다. 관계는 domain, actor, document, conversation(임시 첨부)의 소유 경계를 검증한다.
개인 자료는 본인 소유와 현재 도메인 연결을 모두 요구한다. 임시 자료는 동일 사용자·도메인·대화 및 만료 전 조건을
추가한다. 이름이나 파일 내용으로 도메인을 추측해 자동 연결하지 않는다.

이 확장은 기존 `configuration.workspace_ids` 검사를 단순 생략하는 방식으로 구현하지 않는다.
구성에는 개인/대화 첨부 사용을 허용하는 명시적 입력 정책을 두고, 별도 권한 해석기가 검증한 정확한 문서만
검색 범위에 합류시킨다. 새 정책의 기본값은 차단이며 관리자 설정 UI와 함께 제공한다.
첫 단계에서는 기존 허용 공간 범위만 지원하고, 개인/임시 확장 전에는 작동하지 않는 첨부 버튼을 노출하지 않는다.

## 4. 선택 문서 검색 계약

- `document_ids` 생략은 기존 공간/폴더 범위 검색, 명시한 배열은 선택 문서만 검색이다. 명시적 null과 빈 배열은 422이며
  전체 검색으로 해석하지 않는다. 중복 ID는 정규화하고 크기 상한은 명명된 서버 정책과 UI 안내로 일치시킨다.
- 제한은 도메인·구성·현재 권한·요청 공간/폴더와 교집합이다. 하나라도 존재하지 않거나 접근 불가이면
  동일한 일반 404로 전체 요청을 거절한다. 타 사용자 문서의 존재나 준비 상태를 응답으로 구별하지 않는다.
- 권한 검증 후 선택 문서 전부의 현재 활성 READY 원본과 정확한 색인/문서처리 프로파일의 READY projection,
  활성 build를 확인한다. 하나라도 미준비이면 409로 중단하며 일부만 사용하거나 전체 공간으로 넓히지 않는다.
- 위 검증은 질의 재작성·LLM 호출보다 먼저 끝낸다. BM25와 dense에 같은 정확한 asset-version/build 선필터를
  전달한다. 기존 ES 필터를 재사용하며 문서 선택만을 위해 새 모델·물리 색인이나 재색인은 요구하지 않는다.
- 도메인 API와 공통 검색 API에 동일한 제한 계약을 전달한다. 미지원 경로에서는 명시적으로 거절하며 미지 필드로
  무시하지 않는다. 응답에는 서버가 실제 확정한 문서·버전 범위와 문맥 지문을 반환한다.
- 최초 구현은 현재 활성 버전을 사용한다. 원문 뷰어의 과거 버전 열람은 과거 버전으로 대화한다는 뜻이 아니다.

## 5. 대화 문맥과 외부 전송

문서 추가·제거는 다음 질문부터 적용한다. 이전 대화와 인용은 화면에 남기고 `검색 범위 변경` 구분선 뒤에서
새 문맥을 시작한다. 이전 구간의 질문·답변을 새 요청 history에 자동 전달하지 않는다. 진행 중 범위 변경을 막고,
취소/전환 뒤 늦게 도착한 응답이 새 문맥에 붙지 않도록 한다.

서버가 해석한 문서 ID·활성 버전/build 지문과 제한 모드를 새 assistant 서명에 포함한다. 선택 범위 또는 활성 버전이
바뀌면 이전 서명을 거절하고 문맥 재시작을 안내한다. 구형 서명으로 선택 제한을 우회할 수 없어야 한다.
사용자 history는 서명된 근거가 아니라 임의 사용자 입력이며, 서버가 이전 문맥의 출처를 보증하지 않는다.
검증된 assistant history만 후속 답변 문맥으로 인정하고 사실 근거는 현재 검색 결과로 제한한다.

파일 선택·업로드는 외부 전송 동의가 아니다. 기존 데이터 분류·구성 정책·실제 근거 revision/hash 및 호출별 동의를
유지한다. 선택 변경 시 대기 중 동의 상태를 해제한다. 임시 첨부에도 같은 정책을 적용하며 미승인 파일을 자동 공개하거나
비식별 자료로 간주하지 않는다. 모델 출력의 완전한 통제를 보장한다고 설명하지 않는다.

## 6. 대화 첨부 처리

임시 업로드 → 원본 무결성 검증 → 파싱/필요한 OCR → 청킹/임베딩/색인 → 선택 범위에 추가 가능.
기존 ingestion 작업과 프로파일을 사용한다. 처리 중/실패/준비됨을 각각 표시하며 업로드 성공을 검색 성공으로 표시하지 않는다.
추가 중 문서는 아직 적용되지 않았음을 안내하고, 준비 완료 후 사용자 적용 동작으로 문맥을 전환한다.

첨부 소유권을 검증할 최소 영속 대화 식별자를 도입하되, 대화 목록·전체 메시지 영구 저장 기능과 분리한다.
임시 보관은 브라우저를 닫자마자 삭제한다는 뜻이 아니다. 만료 시각을 서버 정책으로 정해 업로드 전에 안내하고,
만료 즉시 조회/검색을 차단하며 물리 파일·projection 정리는 멱등 작업으로 수행한다.
개인 보관은 권한·중복 해시·보관 정책을 재검증한 명시적 작업이며 전사 보관으로 자동 승격하지 않는다.
중복 확인은 타 사용자 파일 존재를 노출하지 않는다. 개인 보관 원본의 영속 참조를 먼저 확보하고 임시 참조를 정리하며,
임시 자료 만료가 개인 보관 원본이나 다른 유효 참조의 파일을 삭제하지 못하도록 소유권·참조 검증을 적용한다.
실제 보관 기간·용량/파일 수 한도는 운영 설정과 테스트를 갖춘 첨부 단계의 상세 계약에서 확정하며,
그 계약 없이 업로드 endpoint를 활성화하지 않는다.

## 7. 단계와 검증 게이트

1. **도메인 파일함과 선택 대화**: 기존 연결 공간 내 도메인 파일함, 실제 문서 선택 검색 API,
   버전/권한 선필터, 문맥 서명, 파일함→대화 및 대화 내 기존 문서 선택을 함께 검증한다.
2. **개인·임시 입력 확장**: 사용자별 도메인 자료 연결, 구성 입력 정책, 대화 첨부 소유권·만료,
   업로드 처리 상태와 개인 보관을 구현한다. 공용 계약·migration·보관 정책을 상세 설계한 뒤 진행한다.
3. **종단 검증**: 격리된 합성 회사·개인·임시 문서로 새 첨부와 기존 자료 대화를 확인한 뒤 사용자 테스트를 요청한다.

필수 검증: 타 사용자/도메인 우회, 빈 선택, 혼합 미준비, 처리 프로파일 불일치, 선택 외 문서 배제,
버전 변경 후 옛 서명 거절, BM25/dense 동일 선필터, 미승인 외부 전송 차단, 파일함 원문 열람의 독립성,
문서 추가 후 문맥 구분과 늦은 응답 배제. 첨부 단계에는 만료·중복·재시도·개인 보관 실패 검증을 추가한다.
단위 테스트는 외부 모델 없이, 저장소 통합 검사는 실사용 DB/색인과 격리한다. 실사용 자료로 테스트 데이터를 만들지 않는다.

대화 저장 목록, 전사 공유 권한 편집, 파일 이동·휴지통, 공개 방문자 업로드와 자동 학습은 이번 설계의 구현 범위가 아니다.

## 8. 검토와 구현 상태

사용자가 도메인 우선 흐름과 대화 내 문서 추가를 승인했다. 이 문서는 이를 구현 가능한 단계로 구분한 상세 계약이다.
1단계 도메인 파일함·선택 문서 검색·v3 문맥 서명·UI는 구현과 자동 검증 및 독립 최종 리뷰를 마쳤다.
사용자 승인 후 백엔드 재시작과 새 API 반영을 확인했으며, 로그인된 실제 화면과 실제 LLM 응답 검증이 남았다.
2단계 새 첨부·동적 개인 자료 연결·보관/만료는 미구현이다.
검증 결과와 잔여 사항: [작업 기록](../../worklogs/2026-09-10-domain-cabinet-selection.md).
사용자 문서 승인 후 [1단계 구현 계획](../plans/2026-09-10-domain-cabinet-selection.md)을 작성했다.
main에서 작업하고 기존 변경·계정·문서·서버를 보존한다.
독립 보안 문서 검토에서 차단 모순은 없었으며 명시적 null, 열람 전용 권한, 임시/영구 참조 보존 기준을 보완했다.
