# 학습 출발점·개선 결과와 최신순 표시

## 요구와 결정

사용자는 각 실행이 이전 결과에서 이어진 학습인지 원본 모델에서 별도로 시작했는지, 무엇을 개선하려 했고 실제 무엇이 좋아졌는지 목록에서 확인하고 최신 학습을 먼저 보기를 요청했다. 현재 차수는 순서만 나타내며 모델 계승을 뜻하지 않는다. 기존 UI와 JSON 저장 경계를 확장한다. 원문에서 자동 추론하거나 차수만으로 계승을 단정하지 않는다.

카드는 차수·실행일, 제목, 학습 출발점, 개선 목표·확인된 결과·남은 문제 순으로 표시한다. 기존 색상·공통 폼·토큰을 재사용하고 원문 답변·상세 평가는 그대로 둔다. 연결선은 실행 순서만 뜻하며 출발점은 명시 텍스트로 표시한다. 관련 계획은 계속 별도 표시한다.

출발점과 요약은 `learning_sequence`의 선택 필드로 저장한다. `start_mode`는 `base_model | continued | unknown`(기본 unknown), `source_label`은 출발 모델/학습 결과 이름, `source_evidence`는 해당 판단의 실행 기록·체크포인트 식별 근거다. `continued`는 비어 있지 않은 source_label을 요구한다. 원본 모델 시작과 미확인의 의미를 구분한다. source_label은 기록 당시의 설명이며 자동 검증된 레코드 관계/FK가 아니다. 잘못된 자동 링크를 만들지 않으며 기존 참조 기능을 유지한다.

`objective`, `outcome`, `remaining`은 각각 개선 목표, 확인된 결과, 남은 문제의 선택 문자열이다. `outcome_status`는 `improved | no_improvement | mixed | not_evaluated`(기본 not_evaluated)다. 지표를 UI가 임의 계산하거나 텍스트 유사도로 성공 판정하지 않는다. 미입력 결과는 미평가로 표시하며 계획에는 실제 결과 판정을 부여하지 않는다. 기존 서비스의 길이 정책을 적용한다.

새 정렬 `learning_latest`를 기본 UI로 사용한다. 기존 흐름 그룹 순서와 계획 분리는 유지하고 각 흐름의 명시 차수를 내림차순(3→2→1)으로 정렬한다. 화면 명칭은 ‘학습 흐름별 최신순’으로 범위를 명확히 한다. 기존 `learning_order` 오름차순과 `updated`는 보존한다. 전체 서버 결과에 정렬하고 서명 커서에 정렬을 결합하여 페이지 일부만 뒤집지 않는다.

## 대안과 범위

수정일 정렬은 과거 기록 편집을 최신 학습으로 오인하므로 기본으로 쓰지 않는다. 문장 파싱으로 계승·성과를 생성하면 미평가를 성공으로 오인하므로 명시적인 기록 요약을 쓴다. 모델 계승 그래프·자동 실험 수집은 이번 범위가 아니다. 메타데이터 추가로 DB migration은 없다. 새 패키지·재학습·서비스 모델 변경·커밋·푸시는 없다.

## 확인된 실제 자료

기존 실행 보고서와 로컬 산출물의 입력/출력 어댑터를 대조하여 세 기록의 메타데이터를 인증된 편집 화면으로 저장한다. 첫 실행은 원본 가중치에서 한 번 갱신, 두 번째는 첫 어댑터에서 네 번 갱신, 세 번째는 두 번째 후보에서 열두 번 갱신한 기록이다. 추가 학습의 갱신 대상 축소도 출발점 근거에 남긴다. 실제 본문과 전후 답변·평가는 변경하지 않는다.

## 검증 및 역할

중간 규모 기능 변경이며 주요 위험은 성과 과장·계승 오인과 페이지 정렬 회귀다. 메인 Codex가 요구·아키텍처·문서·실제 화면 통합을 맡고, 백엔드와 프론트엔드 구현, 독립 코드/통합 검증을 분리한다. 모델 런타임·DDL·인프라·권한 노출을 바꾸지 않으므로 해당 구현 전문가는 제외한다.

구형 JSON, 미확인·원본·이어 학습, 빈 출발점, 미평가와 실제 결과, 계획, 다중 페이지 최신순, 정렬 커서 교차 사용, 소유권, 텍스트 보존을 회귀로 확인한다. 타입·린트와 실제 목록/상세/편집, 두 테마·모바일·키보드를 확인한다.

## 실행 결과

### 계승과 관측 범위

독립 검토에서 원본 로딩 코드와 실제 어댑터 파일의 SHA-256을 대조했다. 2차 입력의 parent 식별값은 1차 결과와, 3차 입력은 2차 결과와 일치한다. 2·3차는 어댑터 가중치를 이어받았지만 optimizer는 새로 시작했다. 모델 가중치 계승과 학습 진행 상태 복원을 구분해 각 기록의 펼침 근거에 남겼다.

| 실행 | 출발점 | 확인된 결과 | 남은 범위 |
|---|---|---|---|
| 1차 | 원본 모델·새 어댑터, 1회 갱신 | 저장된 실제 비교의 전후 문장 동일, 인용 누락 유지. 어댑터 갱신·저장 확인 | 입력에 근거 번호가 없었음. 새 문서 일반화 미평가 |
| 2차 | 1차 어댑터에서 4회 추가 갱신 | 비교 3문항 모두 전후 동일. 번호·지시 제공 조건에서 이미 기준 충족 | 미사용 평가는 문서 1개·질문 2개 |
| 3차 | 2차 후보에서 12회 추가 갱신 | 학습 1/3 개선, 미사용 0/7 개선, 회귀 2/2 정답 유지 | 날짜 오류·수치 누락 잔존, 미사용 한 답변의 근거 번호 소실 |

1차 생성 비교는 기존 인증 화면에 저장된 전후 원문·조건·결론을 확인했다. 로컬 최초 result.json은 갱신·저장 검증이므로 그것만으로 답변 품질 비교를 주장하지 않는다. 2·3차는 로컬 전후 생성 산출물도 독립 대조했다. 실험 내용과 한계의 정본은 [최초·인용 추가 학습](2026-11-04-gemma-local-training.md)과 [실패 사례 학습](2026-11-05-gemma-failure-driven-training.md)이다.

### 구현 파일과 검증

- 백엔드: `platform/learning/{schemas,repository,service,api}.py`, 관련 단위·API 계약·저장소 테스트. 새 내림차순 정렬은 쿼리와 커서에 같은 방향 키를 적용한다. 기존 길이 제한·소유권을 유지한다.
- 프론트엔드: `features/learning/{LearningSequence,LearningEditor,LearningListPage,api,registry}`와 전용 CSS·테스트, 생성 OpenAPI 타입. 공통 SelectField·TextField·TextAreaField·Disclosure·토큰을 재사용했다. 디자인 시스템 page에 실제 컴포넌트의 합성 예시를 추가했다.
- 변경 전 실패 확인: 백엔드 11건, 프론트엔드 새 사례 8건. 변경 후 백엔드 단위·계약 84건과 격리 PostgreSQL 2건, 프론트엔드 전체 learning 80건/12파일 통과. 스키마 기본값에 맞춘 마지막 수정 뒤 17건을 재확인했다. strict Mypy 4개 소스, Ruff, TypeScript, 대상 ESLint 통과.
- 독립 검증: 백엔드 단위 50건, PostgreSQL 정렬·여러 페이지 2건, 프론트엔드 17건 통과. 코드 검토 차단 결함 0건. 실제 모델 호출은 없었다.
- 제한 환경의 로컬 소켓 오류로 통합 검사 실행이 차단되어 허용된 실행 환경으로 재검증했다. pnpm 실행기의 registry 조회가 실패해 설치된 로컬 도구를 직접 사용했다. 패키지 설치·다운로드는 하지 않았다. 이번 작업에서 전체 운영 빌드는 재실행하지 않았다.

### 본래 환경 확인

진행 중인 RAG 실행이 모두 0임을 읽기 전용 조회로 확인한 뒤 기존 API만 같은 명령과 환경으로 재시작했다. health 정상과 새 계약을 확인했고 환경 파일은 보존했다. 기존 로그인 화면에서 실행 세 건의 출발점·목표·결과·남은 문제 및 후속 계획의 목표를 저장했다. 각 저장 후 편집 화면을 다시 열어 순서 메타데이터를 제외한 22개 원래 폼 값의 일치를 확인했다.

최종 목록은 `3차, 2차, 1차, 계획·미실행`이다. 처음부터 정렬은 `1차, 2차, 3차, 계획`으로 전환되며 다시 최신순으로 복원했다. 필터 후에도 차수는 유지됐다. 375px·320px에서 가로 넘침이 없고 라이트·다크의 상태/본문 대비를 시각 확인했다. 출발점 근거는 Enter로 펼치고 Space로 닫혔다. 임시 폭·테마를 복원하고 기존 목록 탭을 남겼다. 디자인 시스템 합성 예시도 실제 화면에서 확인했다.

ISSUE-00051에 검증 이력을 추가·재조회했다. DB migration, 재학습, 서비스 모델·검색 색인 변경, 커밋·푸시는 없다.

## 남는 한계

출발 설명과 판정은 명시적으로 작성한 실험 기록이며 자동 모델 계보 수집이 아니다. 흐름별 최신순은 실제 차수를 기준으로 하고 여러 흐름을 합친 전역 시간순은 아니다. 미입력 정보는 미확인·미평가로 남긴다. 세 실험의 제한된 결과를 전체 모델의 일반화 성능으로 확대하지 않는다.
