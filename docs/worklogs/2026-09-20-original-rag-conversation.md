# 본래 환경 RAG 대화 준비

## 범위와 보존

기존 마스터·본래 DB·파일·모델·도메인을 재사용한다. 사용자가 승인한 기존 합성 문서
1개와 합성 질문만 외부 생성에 사용하고, 평가 스냅샷·실패 기록을 본래 DB에 보관했다.
새 환경·계정·문서·모델·재색인을 만들지 않았다. 기존 sandbox 자료는 계속 보존한다.
메인 통합·실행 검증, 백엔드 구현, DBA/RAG 평가 진단과 독립 리뷰 책임을 분리했다.
UI 변경은 없어 프론트엔드 구현 역할은 제외했다.

## 발견한 오류와 수정

- Codex 실패 검사에서 `binding=None`이 JSON null로 저장되어 SQL NULL/object 제약을 위반했다.
  ORM을 `JSONB(none_as_null=True)`로 변경했다. 실제 실패 audit 저장도 확인했다.
- 평가 검색은 K개의 청크를 여러 근거로 펼쳐 DB의 근거 순위 K 제한을 위반했다.
  최초 등장 순서로 중복을 제거하고 근거 순위를 K개로 제한했다. 답변·관련 근거·하이라이트의
  권한 노출 검사는 K 밖에도 유지한다. 평가 정책·기대값·DB 제약은 바꾸지 않았다.
- 설치 Codex는 0.155.1인데 기존 실행 파일 고정값과 명령 계약은 0.153.4였다.
  설치 패키지·실행 파일을 대조해 로컬 설정을 갱신하고, 명시 지원 버전만 추가했다.
  [명령 계약 검증](2026-09-20-codex-01551-command-contract.md)을 참고한다.
- 도메인 활성화·편집은 UPDATE 이후 만료된 `updated_at`을 동기적으로 읽어 MissingGreenlet이 발생했다.
  변환 전에 해당 필드를 명시적으로 await refresh한다. 실제 본래 PG의 활성화 재시도도 통과했다.
- 키워드 근거는 제목의 일부 일치가 정답 본문보다 먼저 선택될 수 있었다. 높은 질의 단어
  일치율을 우선하고 동률에는 기존 순서를 유지한다. 키워드/의미 우선순위와 RRF는 유지한다.
  수정 전 실제 상품명 질문의 잘못된 제목 답변을 확인했고, 수정 후 같은 질문의 정답을 확인했다.

## 실제 평가

데이터셋 `9f097597-d05c-5b2e-a03a-f0eea870968e`, 정책
`ebeb1494-1533-4c7b-892e-54bf6d33b88d`는 실행 전에 고정했다.
양성 2개·음성 1개, K=5, 2회 반복이며 평가기는 검색·근거 선택을 검증한다.
생성 답변은 별도 실제 호출로 검증해야 한다.

기존 v2 실행 `27a36f08-50d5-4205-8855-6948f16f3a32`는 정상 실행됐지만
음성 질문에 무관한 의미 근거를 채택해 supported precision 2/3, false grounding 1/3이었다.
이 결과를 통과로 처리하지 않았다. 기존 구성의 불변 v3
`6b463754-c7c3-4b2c-ab0d-af87abbbb560`에서 의미 근거 기준만 0.7→0.9로 보수화했다.
모델·청킹·색인은 동일하며 평가 기준을 낮추지 않았다.

v3 실행 `f03fe368-db32-47b2-8db6-e800443db57b`는 기준을 통과했다.
Recall@5=1, MRR=0.5, nDCG≈0.63093, supported precision=1, false grounding=0,
highlight IoU=1, access leaks=0, reproducibility=1, p95≈8.913초다.
통과 결과는 정상 평가 승인 서비스를 통해 반영했다.

최종 근거 선택 수정과 본래 API/worker 재시작 후 실행
`4f3dfd45-6f40-4d25-9ba2-4a408e482f50`에서도 같은 기준을 통과했다.
품질 지표는 동일하며 v3 p95≈9.682초, BM25 기준선 p95≈16.884초다.
최종 실행 결과도 정상 평가 승인 서비스를 통해 확인했다.

이 세 사례는 설정 조정에 사용된 소규모 회귀 평가다. 양성 두 개가 키워드 경로이므로
일반적인 의미 재표현 질문의 재현율이나 전체 문서 품질을 보장하지 않는다.
의미 근거 기준을 높이면 정상 질문에도 근거 부족으로 답할 수 있어 후속 평가가 필요하다.

## 실행 검증과 한계

v2와 v3 모두 승인된 합성 입력으로 실제 Codex 연결 검사를 통과했다.
v2에서는 합성 문서 질문의 생성 답변·검증된 인용과 음성 질문의 생성 근거 부족 응답을 확인했다.
요청 모델은 gpt-5.5이며 CLI 이벤트에 관측 모델 ID가 없어 모델 identity는 unknown이다.
다른 모델로 대체하지 않았으며 실행 파일·출력 계약 검증을 모델 identity 증명으로 간주하지 않는다.

실제 인증은 사용자의 기존 마스터 세션을 사용한다. 운영 점검은 기존 owner의 애플리케이션
서비스를 호출했으며 암호 변경·새 계정·인증 토큰 생성은 하지 않았다.
실행 receipt는 Git에서 제외된 기존 백업/운영 기록 디렉터리에 있다.
최종 보존 확인: 사용자1·문서3·자산버전3·projection3·기존 jobs6을 유지하며
원본 자산3개의 크기·SHA-256이 DB와 일치한다. 도메인1에 연결1개만 추가했다.

기존 `asset-management` 도메인의 연결 `eb6d3999-4c97-4bfa-afff-dc4a3c78fe57`을
정상 서비스의 준비 상태 검사 후 활성화했다. 검색·답변·서비스 모두 준비 상태다.
정확한 v3와 DomainSearchExecutor 경로로 다음을 확인했다.

- `AM-LAB-730의 상품 이름은 무엇인가요?`: 오로라 연구 채권형, 정답 본문 근거
  `885742bf-02e6-42fe-b8e6-a8ef43afa2bd` 인용, 승인된 문서 projection 일치.
- `목성 대기압 측정값`: 검색·생성 모두 insufficient_evidence, 인용 없음.

이는 실제 DB·ES·로컬 E5·외부 Codex를 연결한 애플리케이션 검증이다. 브라우저 로그인
자동화나 사용자 암호 검증을 수행했다는 의미는 아니다. 프론트·백엔드 health와 대화 페이지는 HTTP 200이다.

## 코드 검증

평가·하이라이트·도메인과 Codex 명령/이벤트/연결검사 관련 단위 테스트 343개를 함께 실행해 통과했다.
수정된 제품 코드의 mypy와 제품·회귀 테스트 Ruff, `git diff --check`를 통과했다.
별도 검토자가 각 수정의 계약·회귀를 검토하고 독립 집중 테스트를 통과했다.
기존 `test_codex_command.py` 전체에 대한 strict mypy는 원래의 동적 부정 입력 테스트 등
26개 오류가 남아 있으며, 제품 코드 타입 검사와 구분한다. 새 DB·테스트 계정은 만들지 않았다.
