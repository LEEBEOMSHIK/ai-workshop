- [설계](../superpowers/specs/2026-10-03-ai-flowcharts-design.md), [계획](../superpowers/plans/2026-10-03-ai-flowcharts.md)

## 구현

비공개 작업소 메뉴의 `흐름도`에서 RAG 문서 처리·색인, 검색·답변, 대화 세션,
멀티턴과 공통 개발 에이전트 관리를 2단계 분류로 읽는다.
canonical 목록은 `/workshop/flows`, 상세는 `/workshop/flows/{category}/{flow}`다.
선택한 흐름 하나의 단계·조건 연결과 선택 단계의 입력·처리·결과·실패 조건을 표시한다.
텍스트 대체 설명은 기본 접힘 상태이며 관련 화면 링크와 검토 기준일을 제공한다.

콘텐츠는 RAG·개발 에이전트 모듈에 두고 app 구성 계층에서 합친다.
공통 뷰어가 Labs 구현을 import하지 않는다. FlowchartsPage는 서버에서 렌더링하고
선택 상태만 FlowReader로 분리해 route 생성 함수를 client props로 전송하지 않는다.
서버에서 기존 사용자 권한으로 관리자 링크를 제거한 뒤 클라이언트에 전달한다.
기존 workspace 인증과 admin 권한 검사는 유지한다.

정적 설명이며 실제 에이전트·검색·모델·색인 실행을 시작하지 않는다.
문서 본문·사용자 질문·계정·실행 로그·credential을 콘텐츠에 포함하지 않는다.
새 라이브러리·DB·계정·환경·worktree를 만들지 않았다. 기존 데이터와 별칭 차단 상태를 보존한다.

## 독립 검토 수정

별도 코드·권한·통합 검토에서 Critical0, Important2, Minor0이 나왔다.
다음 두 결함을 실패하는 회귀 테스트로 재현하고 한 수정 패스에서 처리했다.

1. 좁은 화면에서 선택 단계 설명이 전체 그래프 아래에 있어 찾기 어려웠다.
   단계/조건 선택 시 설명이 화면 밖이면 포커스·스크롤로 안내하고, 선택한 단계로 돌아오는
   버튼을 제공했다. 화면 안의 설명을 사용하는 데스크톱 선택은 기존 포커스를 유지한다.
   설명은 여전히 한 영역이며 중첩 스크롤을 추가하지 않았다. reduced motion을 존중한다.
2. 모델이 정상 응답했지만 근거 내용 부족을 반환하는 경로가 빠졌다.
   생성 → 근거 부족 분기와 인용 검증 생략을 표시하고 검색 시점의 근거 부족과 구분했다.
   기존 pipeline의 `generation_insufficient`/`evidence_content_insufficient`를 설명하는 변경이다.

검토 보고서와 RED/GREEN 기록은 현재 작업 전용 로컬 기록에 보존했다.
검토자가 판정을 제외한 기존 access epoch/별칭 복구 코드와 대화 회귀 실패는 이번 흐름도
수정 범위에 포함하지 않는다. 별칭 복구를 완료했다거나 품질 작업만 남았다고 보고하지 않는다.

기존 로그인 대기로 관리자 문제 이력 DB 등록·관련 문서 연결은 미완료다. 보존용 issues.json은 수정하지 않았다.

## 후속 기술 설명 — 큰틀과 실제 동작 분리

사용자가 전체 순서만 있고 기술을 이해할 설명이 부족하다고 보고했다.
기본 `전체 흐름`은4~5개 큰 단계의 목적과 연결을, `기술 상세`는 기존 세부 그래프와
선택 단계의 기술·쉬운 역할·동작 방식·확인 지점·구현 근거를 제공한다.
큰 단계를 누르면 대응하는 첫 세부 단계와 설명을 연다. 같은 흐름의 보기 전환은 선택을
유지하고 다른 흐름으로 이동하면 전체 보기로 초기화한다. 내부 왼쪽 NAV는 추가하지 않았다.
큰 단계 연결은 실제 세부 edge에서 파생하고 동일 묶음 내부의 조건·되돌림은 기술 상세로 안내한다.

RAG4개 흐름은 각각5묶음, 개발 에이전트는4묶음이다.51개 세부 노드 전체를 중복·누락 없이
큰 단계에 대응했다. 콘텐츠는 소유 모듈의 technical.ts에 두고 공통 뷰어가 Labs에 의존하지 않는다.
큰 단계와 세부 단계 대응·기술 설명·근거의 필수 값도 카탈로그에서 검증한다.
표시 버전은2로 올렸으며 실제 실행 상태나 모델의 비공개 내부 추론을 조회·저장하지 않는다.

코드 대조 중 기존 설명의 지원 범위를 보정했다. 현재 V1 구성은 활성 리랭커 binding을
거절하고 실행 코어에는 리랭킹 경로가 없어 정상 생략으로 설명한다. RRF 순위 결합 점수는
유사도 백분율이나 정답 확률이 아니다. 인용 검사는 주장별 허용 근거 ID·projection/chunk 추적과
정규식 대상 날짜·수치 확인이며 모든 문장의 의미적 참됨을 검증하는 기능으로 표현하지 않는다.
긴 기술 설명의 하단이 화면 밖이어도 상단이 보이면 데스크톱 노드 선택 시 포커스를 유지하도록 보정했다.

- 최초 요구 RED: 큰 단계/대응 검증·보기 전환3실패, 기존17통과.
- 긴 설명 포커스 RED: 패널 top100/bottom1500에서 노드 포커스 기대 실패1건 확인 뒤 가시성 조건 수정.
- 최종 관련 회귀:19파일109테스트 통과(exit0,116.88초), production TypeScript·전체 frontend lint exit0.
- 독립 코드·기술 검토: 포커스 결함 재현 후 수정 확인, 독립21테스트 통과·미해결 차단 사항 없음.
- 기술 설명의59개 근거 경로 존재 확인. 파싱/OCR·청킹/검색·원문 추적·READY/outbox,
  트랜잭션/멱등성/revision·현재 권한/segment/문맥 예산·결정적 역할 선택과 실제 코드를 대조했다.
