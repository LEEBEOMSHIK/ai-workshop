# 생성형 평가 경로 구현·검증 — 2026-09-28

## 범위와 상태

승인된 [실행 계획](../superpowers/plans/2026-09-27-rag-generative-evaluation.md)의 공통 실행 코어,
생성형 평가 저장·worker·판정·DB 승격 검증·관리자 비교 화면을 구현했다.
실제 PDF 생성 결과의 품질 검증과 후보 승격은 아직 수행하지 않았다.
현재 활성 구성·기존 계정·원문·색인은 유지한다. ISSUE-00005는 열린 상태를 유지한다.

## 사용자 경로

관리자 **RAG 구성 → 비교 실험 → 생성형 generative-v1**에서 평가 자료를 고정하고,
저장한 구성 버전과 승격 기준을 선택한 뒤 명시적으로 평가를 실행한다.
자료 저장과 결과 조회는 모델을 호출하지 않는다. 기존 추출형 v1은 별도로 유지한다.
질문별로 검색/문맥 근거 충족률, 생성 상태, 인용 유효성, 정답 판정, 거절 정확성과 시간을 표시한다.
실행 단계 상세와 인용 원문으로 이동할 수 있고, 실행·사례 링크는 새로고침 후에도 복원한다.

정답 문자열 규칙은 지정한 조건의 일치만 판정한다. 일반 의미 정확도로 표시하지 않는다.
규칙이 없는 양성 사례는 미검증으로 남으며, 검토자는 정확한 결과 digest에 판정을 기록한다.
측정하지 않은 시간·모델 관측값·토큰 사용량은 0이나 추정값으로 채우지 않는다.

## 실행·저장 계약

- 대화와 평가가 동일한 검색→문맥 선택/예산→생성→인용 검증 코어를 사용한다.
- 동결 입력에는 물리 색인 UUID, 원문 식별자, 정확한 구성/프로파일, 검색 K와 제공된 이전 문맥을 포함한다.
- 동결 문서는 현재 읽기 권한과 READY 상태를 다시 검사하되 현재 활성 버전에 종속시키지 않는다.
- 각 시도는 서버가 발급한 실행 ID와 연결한다. 중복 전달은 같은 시도를 다시 실행하지 않는다.
- worker heartbeat가 10분간 갱신되지 않으면 중단 처리한다. 자동 재호출하지 않고 명시적 재시도로 새 시도를 생성한다.
- 이전 실패와 원시 결과는 보존한다. 오래된 claim으로 완료를 저장할 수 없다.
- PostgreSQL이 전체 반복 사례, 정답 규칙, 승인 audit, 인용 구조와 판정 출처를 재검증한다.
- 통과 반영은 해당 구성 버전의 평가 상태를 바꾸며 활성 도메인 연결을 자동 변경하지 않는다.

## 실제 검증 대기와 후속 절차

기존 마스터의 브라우저 세션이 만료되어 로그인 화면이다. 인증을 우회하거나 새 계정을 만들지 않았다.
따라서 실제 모델 답변, 데스크톱/모바일 조작, 세션 재개와 실행 기록의 추가 지연·행 크기는 아직 미검증이다.
이 결과를 RAG 품질 개선 또는 원래 질문의 정답 생성 성공으로 보고하지 않는다.

기존 16문항 외 [새 질문 9개](2026-09-28-rag-held-out-cases.json)를 생성 실행 전에 고정했다.
같은 PDF의 새 표현·후속 질문 검증이며 새로운 문서에 대한 일반화 표본은 아니다.
정답표는 색인하지 않는다. 각 사례 3회 반복하고 현재 기준선과 사전 후보를 구분해 저장한다.
후보 결과를 본 뒤 이 9문항에 맞춰 재조정하지 않는다. 품질 기준을 충족한 후보가 없으면 활성 구성을 유지한다.

문제 관리의 ISSUE-00005에 이 문서를 DB 연결하는 작업도 기존 로그인 후 지원 API/화면으로 진행한다.
전체 완료 조건은 원래 환경에서 질문→답변→실행 단계→인용 원문→평가 사례 연결을 확인하는 것이다.

변경 문서의 상대 링크, 평가 JSON9문항, WORKBOARD 최근 완료5개와 Git 공백 검사도 통과했다.
