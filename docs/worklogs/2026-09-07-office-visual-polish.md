# 로비·LLM 연구실 그래픽 개선

## 승인 범위

기존 게임 입구 MVP에 대한 사용자 승인 후속 작업이다. 로비의 안내 데스크·소파·식물·바닥,
LLM 연구실의 모니터·화이트보드·연구 장비, 캐릭터 방향/걷기 표현, 공간을 덜 가리는
안내 UI를 개선한다. 한 장 배경 이미지를 사용하지 않고 기존 타일/SVG/코드 생성 sprite를
개선한다. 새 패키지·다른 연구실·실제 AI 실행·인증·백엔드 변경은 범위 밖이다.

## 구현·검증 경계

- 프론트 담당: 자산/배치/UI 및 필요한 동작 테스트. 기존 이동/충돌/대화 계약 보존.
- 메인: 승인 범위와 작업 보드 관리, 실제 브라우저/빌드 통합 확인.
- 독립 리뷰: 변경분의 요구 충족과 회귀 위험을 읽기 전용으로 검토.
- main에서 기존 dirty 변경 보존, 자동 커밋/푸시 없음.

## 확인할 사용자 경험

1. 로비에서 안내 데스크와 휴게 공간, LLM 연구실 방향을 인식할 수 있다.
2. 중앙 통로가 열려 있고 장식 때문에 NPC에게 접근할 수 없게 되지 않는다.
3. 책상·소파 등 가구에 발 영역이 충돌하고 바닥/러그는 걸어서 지나간다.
4. 캐릭터의 앞/뒤/좌/우와 걷기 포즈가 구분된다.
5. 작은 안내 UI에서 사용법을 확인하며 E 대화·닫기·키보드 복귀가 유지된다.
6. 넓은 화면과 960×640 화면에서 map resize·navigation·재진입이 유지된다.

## 구현 내용

- `frontend/public/office/tiles/office-placeholder.svg`: 바닥 줄눈·벽 조명·다중 모니터·식물 디테일.
- `frontend/public/office/maps/office.json`: 기존 두 구역/중앙 통로를 유지하고 로비와 LLM 장식 배치,
  가구 발 영역 충돌 및 통로 판정용 경계 추가. 바닥 러그는 충돌 없음.
- `frontend/src/features/office-game/assets.ts`: 몸/머리/팔/다리 방향과 보폭을 구분하는 sprite,
  Tiled 객체의 종류/위치를 사용하는 소파·안내 데스크·테이블·화이트보드·서버랙·모니터월 렌더링.
- `map.ts`, `scenes/OfficeScene.ts`: 장식 객체 읽기와 Y 기준 렌더 연결. 기존 Scene 종료 정리는 보존.
- `OfficeOverlay.tsx`, `Office.module.css`: 작은 픽셀형 안내 카드, 접기/펼치기와 aria-expanded,
  연구실과 어울리는 navy/cyan UI. 접어도 대화/이동 안내 접근 가능.
- `office.test.ts`, `GameClient.test.tsx`: 동선·가구 충돌 정합성과 안내 토글 회귀.
  캐릭터 방향/보폭 표현은 실제 브라우저에서 별도로 시각 확인한다.

좌표와 크기는 Tiled 데이터에, 캐릭터/장식의 미술 표현은 renderer에 둔다.
실제 sprite sheet나 제작 타일셋으로 교체하는 경계를 보존했다. 아직 최종 그래픽 자산은 아니다.

## 검증

- 신규 안내/맵 검증의 RED를 확인한 뒤 구현했다. 상세 결과는 담당 구현 보고서를 통해 검토한다.
- 수정 후 root·office·공개 화면·navigation 관련 15개 파일 83개 테스트 통과(46.60초).
- 최종 프론트 전체 63개 파일 292개 테스트 통과(264.03초):
  `node node_modules/vitest/vitest.mjs run --pool=threads --maxWorkers=1 --reporter=verbose`.
  pnpm 경유 전체 실행 2회는 결과 출력 지연으로 중단했으며 통과로 집계하지 않았다.
  실행 경로별 차이의 원인은 미확정이며 테스트/제품 코드를 우회 수정하지 않았다.
  기존 RAG 모델 화면 테스트의 React `act` 경고는 남지만 최종 종료 코드는 0이다.
- 수정 후 실제 Edge E2E 3개 통과(21.8초): 이동·벽/책상 충돌·NPC 대화/복귀·맵 로드 실패·resize·재진입.
- 별도 실제 브라우저에서 1440×900 로비/LLM/대화, 960×640 화면을 캡처해 시각 확인했다.
  이 시나리오의 페이지 실행 오류는 0개였다.
- 최종 프로덕션 빌드(14개 정적 페이지), TypeScript 및 ESLint 통과.
  화이트보드 보완 후 office 12개와 타입·린트도 재통과했다.
- 실제 키 입력으로 화이트보드에 접근해 (200, 336)에서 추가 전진이 차단되는 것을 확인했다.
- 독립 검토에서 발견한 화이트보드 충돌 누락을 수정하고 재리뷰 및 최종 통합 리뷰를 통과했다.
  종류 기반 필수 충돌 계약을 검사하여 `collides` 선언 자체가 빠져도 테스트가 실패하도록 보완했다.
- 남은 경미한 접근성 개선: 안내를 접으면 `aria-controls` 대상이 DOM에서 사라진다.
  버튼 이름·확장 상태·키보드 조작은 유지되며, 후속 개선에서 대상 노드를 `hidden`으로 유지한다.
