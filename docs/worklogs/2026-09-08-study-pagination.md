# 공개 연구 기록 카테고리·페이지 조회

## 승인된 조회 계약

기존 `/api/public/studies` 및 담당자 관련 기록 동작은 유지한다. 목록 화면용
`GET /api/public/study-catalog?page=1&topic_key=...`를 추가한다.
반환은 `{items: StudySnapshot[], total: number, page: number, page_size: 12,
total_pages: number, topics: {key: string, count: number}[]}`다.
topics는 현재 공개 projection 전체의 기술 주제별 건수이며 비공개 DB에 접근하지 않는다.
카테고리 선택은 기존 topic_key의 정확 일치이고 다중 주제 기록을 중복 행으로 반환하지 않는다.
표시명은 프론트 기술 주제 레지스트리에서 관리하고 미등록 주제도 원래 key로 표시한다.

SQL에서 공개 상태·주제 필터를 먼저 적용하고 slug 순서로 LIMIT/OFFSET 한다.
동일 읽기 트랜잭션에서 건수·주제·페이지를 조회한다. 선택 페이지의 무결성 오류는
정상 빈 목록으로 숨기지 않고 503으로 처리한다. 기존 조회 API 계약은 변경하지 않는다.
API page는 양의 정수로 검증하고 과도한 값은 안전한 상한으로 거절한다.
범위 밖 정상 페이지는 마지막 페이지로 보정, 빈 결과는 page 1/total_pages 0이다.

목록 URL은 `?topic=...&page=...`를 사용한다. 잘못된 page는 1로 정규화하고 주제 변경 시
1페이지로 돌아간다. 상세 링크도 검증된 topic/page만 전달하며 반환 URL을 외부에서 받지 않는다.
목록 카드·상세 복귀·새로고침에서 상태를 유지한다. 12개 기준 전체 건수·페이지 번호·이전/다음,
카테고리·빈 상태·서비스 오류를 구분한다. 많은 페이지 번호는 제한된 창과 생략 표시로 렌더링한다.

## 역할·검증

main에서 기존 변경을 보존한다. 백엔드/SQL/TDD와 프론트/TDD는 파일 범위를 분리하고,
메인의 실제 통합 검증과 독립 리뷰로 확인한다. 새 모델·패키지·인증·비공개 DB 변경은 없다.
합성 데이터로 12개 경계·필터·철회 제외·일관된 건수·순서·범위 밖·깨진 projection을 검증한다.
실제 공개 기록은 읽기만 하며, 적용 시 공개 reader만 같은 설정으로 재시작한다.

## 구현과 검증 결과

- 백엔드: 카탈로그 API·response schema·SQL reader와 합성 테스트를 추가했다. 기존 writer,
  구형 목록 API와 비공개 DB는 유지했다. 새 API RED 16건 후 Publishing 전체 150개 통과.
  Ruff·Mypy 통과. 기존 Starlette/httpx deprecation 경고 1개는 남아 있다.
- 동시 WAL 철회 테스트로 건수·카테고리·페이지가 같은 읽기 snapshot임을 검증했다.
  선택 페이지의 digest·slug·topic-index 불일치는 503, 페이지 밖 본문은 해석하지 않는다.
- 프론트: 생성 OpenAPI 타입, 목록 서버 route·상세 route, URL helper·기술 주제 표시명,
  카테고리·제한된 페이지 번호·건수·빈 상태를 연결했다. 최종 관련 60개 테스트와 타입 검사 통과.
  화면 확인에서 구성 관리·대화 카테고리의 한글 표시를 보완하고 미등록 키 보존을 검증했다.
- 실제 Edge 1440/960/390: 15건이 12+3으로 분할, 중복 없음, 카테고리 필터 1건,
  카테고리 변경 시 1페이지, 상세 새로고침·목록 복귀 상태 유지와 가로 넘침 없음을 확인했다.
  익명 기존 API 응답 전후 동일, 공개 데이터 변경 없음. 첫 브라우저 검사에서 비동기 탐색
  완료 전에 URL을 단정한 검사 타이밍을 보완한 뒤 전체 통과했다.
- 독립 리뷰는 계약·SQL·프론트·테스트를 읽고 차단 사항 없음으로 승인했다. 프론트의
  정확한 작업 전 사본이 없어 해당 부분의 보존 비교는 현재 소스·기존 회귀 테스트로 제한됐다.
- production build, 생성 schema --check, 전체 ESLint 통과. 빌드가 추가한 테스트 인스턴스
  타입 경로만 원복하고 TypeScript 재검증했다. 기존 빌드 캐시를 재사용했다.
- 공개 reader만 18001에서 재시작했다(exec 85562, 최초 server PID 9688).
  PowerShell 프로세스 종료/생성 시도가 실패해 상태를 재확인한 후 정확한 공개 reader
  프로세스 트리만 종료하고 최소 OS 환경·기존 절대 DB 경로로 실행했다. 실제 API 200 확인.
- 프론트 개발 HMR을 다시 관찰해 반복 serverComponentChanges·Rendering 표시 없음을 확인했다.

## 사용자 확인

`http://127.0.0.1:5173/labs/rag/studies`에서 카테고리와 페이지를 선택하고 기록을 연다.
상세에서 새로고침 후 돌아가기 버튼을 눌러 선택한 목록이 유지되는지 확인한다.
모든 주제는 현재 공개 기록에서 파생된다. 새 주제도 표시하며 표시명만 레지스트리에서 확장한다.
전체 페이지 수는 최대 7개 번호와 생략 표시로 제한해 렌더링한다. 기본 정렬은 기존 slug 순서다.
관리자 화면·게시 상태·모델·개인 원본·비공개 API는 변경하지 않았다. 커밋/푸시는 하지 않았다.
