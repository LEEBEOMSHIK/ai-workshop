## 조사와 역할

높은 위험의 저장소/DB 수명주기 변경으로 분류했다. 메인은 요구사항·시스템 경계·문서,
별도 DBA는 업로드 트랜잭션·잠금·FK, 별도 조사 담당은 파서/OCR/뷰어 임시물과 작업 기록을 확인했다.
독립 프라이버시/설계 검토자는 소유권과 불명 상태를 검토했다.
UI·모델 품질·배포 변경은 없으므로 해당 구현 역할은 제외했다.

- 원본 파일은 현재 DB 버전 생성보다 먼저 쓰며, adapter 내부 임시 이름은 사전 등록하지 않는다.
- 새 버전의 번호는 초기에 읽은 버전 목록에서 계산돼 동시 업로드 시 경쟁할 수 있다.
- 독립 예약에 source FK를 붙일 수 없고 요청 세션이 잠근 행의 FK는 자기 교착 위험이 있다.
- 파서/DOCX/PDF OCR/preview는 OS 임시 폴더를 사용한다. preview의 자식 종료·회수 이후 정리 순서는 보존해야 한다.
- 일반 jobs의 상세 기록은 asset version CASCADE와 연결되며 별도 Platform 참여자가 필요하다.

## 설계 검토

독립 검토에서 실패한 신규 업로드가 실제 Document/AssetVersion 없이 남을 때 발견 경로가 빠진 점을 지적했다.
문서별 목록과 별도로 workspace/attempt 미확정 예약 조회를 정의하고 권한·페이지 소진·revision 대조·locator 비노출을 추가했다.
보완 후 독립 재검토에서 major 해소와 잔여 차단 없음이 확인됐다.
그 밖의 예정 ID·독립 예약·확정 RESTRICT·commit 불명 보존·legacy 차단은 상위 계약과 일치함을 확인했다.
