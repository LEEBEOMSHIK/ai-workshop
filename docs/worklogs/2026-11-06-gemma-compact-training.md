# Gemma 5차 짧고 완결된 답변 학습

## 실행 전 고정 계획

사용자는 4차에서 개선되지 않은 원인을 바탕으로 다음 학습을 실제 진행하고, 속도보다 답변 품질에 집중하며, 승인한 학습 단계·전후 답변 카드 형식으로 결과를 남기도록 요청했다.

[4차 관측](2026-11-06-gemma-calendar-training.md)은 학습 손실 감소와 달리 완전 정답 3/9 유지, 휴일·접수일·마감 시각 계산 오류 및 답변 잘림 1→2건, 인용 소실 증가다. 학습 예제 수와 마지막 층만 갱신한 범위가 부족했을 가능성은 가설이며 확정 원인이 아니다.

5차는 **정확한 날짜를 먼저 답하고, 필요한 영업일 순서와 인용까지 짧게 완료하는 타깃**으로 바꾼다. 접수일 제외·휴일 건너뛰기·셋째 영업일·14시 경계 전후·잘못된 날짜 전제 부정 예제를 포함한다. 날짜 순서는 원문에 근거한 사용자용 계산 설명이며 모델 비공개 내부 추론을 수집하지 않는다.

공개 합성 [자료](../../sample-data/public/rag/evaluation/gemma-compact-study-20261106.jsonl)는 18문항이다. 학습8(이전 학습3의 짧은 타깃+새 예제5), 과거 오류 재검증4, 기존 회귀2, 이번에 처음 만든 서로 다른 가상 문서4의 미사용 질문4를 분리한다. 기존의 실패 사례는 이미 설계에 영향을 줬으므로 새 일반화 증거로 세지 않는다. 가상 달력은 실제 공휴일 달력과 무관하다.

부모는 **4차 후보** `6db0f50b30db7fab09701a899f4e80c9fd6d295b47652b7539bf78ebc0ee435e`다. 기반 Gemma E2B-IT revision `4adf15748de9e1a0097b6274cee9c15836c41c37`, BF16 기반/FP32 rank4 어댑터, 마지막 언어 층 q_proj a/b 22,528파라미터만 갱신한다. 나머지 가중치는 고정한다. AdamW 0.005, weight decay0, gradient clip1, seed7, batch1, CPU6스레드를 유지한다. 새 optimizer에서 train-01부터08까지 3번 반복하는 **24회 갱신**을 사전 고정한다. 결과를 본 뒤 예제·횟수·후보를 재선택하거나 자동 재시도하지 않는다.

출력은 96→192토큰으로 여유를 주되 **5차 전후 모두 같은 192 한도·같은 지시·같은 입력·greedy**로 18회씩 생성한다. 학습 효과는 이 새로운 baseline과 after로 판정한다. 4차96과 5차192의 결과 차이를 학습 효과로 합치지 않는다. 데이터 형식·예제 수·갱신 수를 함께 변경하므로 개선돼도 단일 원인의 인과 증거는 아니다.

로컬 실행기는 `.local-data/gemma-e2b-step/compact-study/run_study.py`다. 전체 모델과 마지막 층 재사용 계산의 logits 정확 일치를 학습8개 모두에서 확인한다. 정답 및 응답 종료 토큰에만 손실을 계산한다. 평가 정답은 학습 텐서·예제 선택에 전달하지 않는다. 후보 저장/재로드, 변경 텐서 범위, 전후 입력 및 부모·자료·설정 해시를 검증한다. 실행 폴더에 자료·설정·실행기·중간 관측·실제 답변·최종 어댑터를 보존한다.

## 사전 판정 기준

날짜 정확성, 질문 완전성, 인용 번호 유효성, 실제 주장 지지, 필요한 근거 커버리지, 잘림을 구분한다. 정확 날짜를 물었는데 일반 규칙만 답하면 실패다. 주 날짜가 맞아도 덧붙인 계산이 틀리면 실패다. 모든 근거 번호를 포함해도 계산이 틀리면 지지된 답변이 아니다.

새 문서 정답은 가람 7월15일(12→15일), 도담 8월9일 지급 부정·13일 정정, 마루 접수9월6일·지급13일, 미리내 접수10월7일·지급18일이다. 정답과 의미가 같은 표현을 허용한다. 과거 질문의 판정은 4차 기준을 유지한다. 학습 질문은 질문에 명시된 계산 순서/기준 요구를 모두 충족해야 한다.

성공 여부는 학습/과거 오류/새 문서/회귀별 완전 정답과 개별 퇴행으로 보고한다. 손실 감소나 답변 길이 변화만으로 개선을 주장하지 않는다. 소규모 합성 평가 통과는 실서비스 일반 품질 보장이 아니며 이번 범위에서 서비스 기본값을 승격하지 않는다.

## 학습 전 기준 답변 관측

동일192토큰 기준의 학습 전18회 생성을 완료했다. 독립 검토와 원문 대조에서 완전 정답은 학습3/8(train-01/04/06), 과거 오류0/4, 회귀2/2, 새 달력1/4(fresh-03), 합계6/18이다. 의미상 올바른 일반 규칙만 답한 new-01은 정확한 지급 날짜를 빠뜨렸으므로 완전 정답에 포함하지 않는다. 필요한 인용 번호 전체 포함은13/18, 잘림은1/18이다.

4차96토큰에서 잘렸던 train-03은192토큰에서 끝까지 나오고 인용이 복구됐지만, 휴일12월9일을 영업일로 세고 지급일을11일로 잘못 답했다. same-01은192토큰에서도 반복하다 잘렸다. 이 비교는 **출력 한도 변경의 관찰**이며 추가 학습 효과가 아니다. baseline-review.json/md에 판정축·실제 답변·입력 해시 대조를 보존했다.

## 독립 감사와 본래 화면 마감

독립 검토자가 저장된36개 답변을 공개 근거와 대조했고 완전 정답6/18→4/18, 개선1·퇴행3에 동의했다. 모델을 다시 호출하지 않고 입력·자료·부모·설정·실행기·후보 해시와 safetensors 바이트를 확인하여 마지막 층 q_proj 두 텐서만 변경됨을 검증했다. 감사 원문은 실행 폴더의 `baseline-review.json/md`, `after-review.json/md`, `independent-review.md`다.

인용 번호가 있는 응답은16→17, 필요한 번호 전체 표시는13→14로 늘었지만 출력 전체의 표기 근거 지지는7→4로 줄었다. 번호 표기 증가를 답변 품질 향상으로 해석하지 않는다. 존재하지 않는 인용 ID와 미완료 응답 채널은 전후0건이다.

본래 [5차 학습 기록](http://127.0.0.1:5173/workshop/learning/2a911e61-8fc0-40ae-97fc-a154fa81fd62)을 수행 완료로 저장했다. 전체 품질 기준으로 ‘개선 관찰되지 않음’을 선택하고 결과 요약 첫 문장에 악화6/18→4/18, 개별 개선1·퇴행3을 명시했다. 입력→정답→학습 카드와 SFT·24회 갱신, 사전 지정 train-02의 학습 정답/전/후 카드 및 오답 판정을 실제 Chrome에서 확인했다. 상세 관찰을 펼쳐18문항의 입력·정답·전후36개 답변과 판정이 표시됨을 확인했다.

새로고침 후 편집 화면에서 본문475자와 관찰14,913자가 실행 자료로 만든 원문과 정확히 일치함을 대조했다. 줄바꿈과 fresh-03의 반복 문자179개도 그대로 보존했다. 서비스 기본값·검색 색인·제품 코드는 변경하지 않았다. 추가 생성·재학습 없이 이번 기록을 마감한다.

최종 검사에서 completed/finished·24회 갱신·전후18쌍, 자료18개 고유 ID와8/4/2/4 분리, 원본/복사본8개 파일 해시, 문서 상대 링크와 공백, WORKBOARD 최근 완료5개를 확인했다. `git diff --check`도 통과했다. 제품 코드 변경이 없어 제품 전체 테스트를 재실행하지 않았다.
