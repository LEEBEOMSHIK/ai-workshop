# 관리자·작업소 내비게이션 통일

## 승인된 범위

기존 메뉴의 제한된 UI 보완이다. 상단에는 `AI Lab / 비공개 작업소 / 관리자` 영역 전환을
고정된 순서로 표시하고, 하단에는 현재 영역의 세부 메뉴만 표시한다. 관리자 링크의 owner
제한과 서버 인증·권한 경계는 유지한다. 공개 화면 헤더, API, 모델 설정과 데이터는 변경하지 않는다.

## 수용 기준

- 관리자와 작업소에서 브랜드·영역 전환·사용자 정보의 배치가 동일하다.
- 현재 영역과 하위 메뉴는 배경·강조 표시 및 접근성 속성으로 구분된다.
- 파일 관리 상세와 학습 기록 상세에서도 해당 상위 메뉴를 유지한다.
- RAG 도메인 대화와 원문 경로는 RAG 대화 메뉴에 속한다.
- 유사한 문자열의 잘못된 경로를 prefix만으로 활성화하지 않는다.
- 일반 사용자에게 관리자 영역 전환을 노출하지 않는다.
- 기존 메뉴 목적지, 키보드 접근과 작은 화면에서 메뉴 접근을 유지한다.
- 메뉴 클릭 자체로 설정 저장·모델 실행을 수행하지 않는다.

## 역할과 검증

프론트엔드 담당이 TDD 구현을, 독립 코드 리뷰어가 명세·회귀 검토를 맡는다.
메인은 통합 및 실제 로그인 화면에서 영역 전환과 활성 표시를 확인한다.
요구·React UI·기능 구현 신호의 역할 선택기를 프로젝트 Python 환경으로 실행했다.
시스템 Python에는 PyYAML이 없어 프로젝트 환경을 사용했으며 의존성을 새로 설치하지 않았다.

## 구현과 검증 결과

- `AreaNavigation.tsx`: 공통 상단·영역별 하단을 표시하는 클라이언트 컴포넌트.
- `areaMenus.ts`: 기존 메뉴의 명시적 목록과 경로 구간 단위 활성 판정.
- `AreaNavigation.module.css`: 영역 안에서만 적용되는 2단 배치·활성·초점·줄바꿈 스타일.
- 기존 `AdminNavigation`·`WorkspaceNavigation`은 동일 props를 유지한 래퍼로 연결.
- 신규 공통 테스트와 기존 두 래퍼 테스트를 보완했다. 라이브러리 추가 없음.

메인 재검증: navigation 및 workspaces 5개 파일의 테스트 34개 통과(29.48초),
전체 TypeScript 검사와 navigation 디렉터리 ESLint 종료 코드 0.
동결 패치 SHA256 `6f0fe269f7ee85f91b189c6a1f72f0a10fe0382083f8d972dddd9db68b6ccec3`와
역적용 검사 성공을 확인했다. 실제 패치를 적용하거나 기존 변경을 되돌리지 않았다.

실제 Chrome owner 화면 약 1174px에서 작업소 파일 관리 → 관리자 모델 → 관리자 구성
전환 및 작업소 RAG 대화의 상단·하단 활성 표시를 확인했다. 관찰한 화면의 헤더 가로 넘침은
없었다. 상세 경로·일반 사용자 노출·키보드 순서는 자동 테스트로 확인했으며 모바일 실측은
수행하지 않았다. 메뉴는 문서 흐름에 위치하며 새 sticky/fixed 동작을 도입하지 않았다.

실제 정책 저장·문서 업로드·모델 실행은 하지 않았다. RAG 도메인은 여전히 준비 중이며
이번 메뉴 변경을 RAG 서비스 전체 검증 완료로 표시하지 않는다.

독립 명세·품질 리뷰 모두 승인, 수정 필요 finding 없음. 리뷰어가 패치 및 8개 파일 해시,
owner 필터와 기존 서버 guard, 경로·접근성 계약, 스타일 범위를 독립 확인했다.
