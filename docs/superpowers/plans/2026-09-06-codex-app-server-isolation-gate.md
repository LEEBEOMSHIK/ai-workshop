# Codex App Server Isolation Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove or reject, before any Provider/DB/UI implementation, that the pinned Codex App Server can expose and enforce the complete no-tool isolation contract required for development-only RAG generation.

**Architecture:** A repository-local probe starts the configured exact `codex app-server --stdio --strict-config` process with a dedicated `CODEX_HOME` and empty temporary `cwd`. It performs the official JSON-RPC handshake, reads effective configuration and runtime inventories, and emits one sanitized immutable gate report; no RAG question or Evidence is sent until the preflight verdict is PASS.

**Tech Stack:** Python 3.13, standard-library `asyncio` subprocess/JSON, pytest 8+, Codex CLI/App Server `0.151.0`, JSON Schema generated by the exact CLI version.

**Spec:** `docs/superpowers/specs/2026-09-06-codex-app-server-rag-adapter-design.md`

## Global Constraints

- Work only on `main`; do not create a worktree.
- Pin the first allowed CLI/App Server version to exact `0.151.0`; changing it requires rerunning this gate and recording a new result.
- Use stdio JSONL only; WebSocket, Unix socket, daemon and proxy transports are outside this gate.
- Use a project-owned dedicated `CODEX_HOME`; never read or copy the user's normal Codex home, token, account id or email.
- Do not send a RAG question, history or Evidence before every preflight assertion passes.
- Shell, filesystem tools, web, MCP, apps/connectors, plugins, skills, hooks and multi-agent must all be absent or effectively non-callable; unknown state is FAIL.
- `approvalPolicy="never"` and `sandbox="readOnly"` do not replace tool inventory proof.
- Raw JSON-RPC, paths, account values and exception messages must not enter Git, the database or normal logs.
- A gate failure must leave `codex_app_server` unregistered and must not trigger Provider, migration or UI implementation.
- Preserve unrelated `.pytest-task11-openapi-red/`, `backend/.pytest-nextjs-final-contract/` and `references/` paths.

```python
@dataclass(frozen=True, slots=True)
class IsolationObservation:
    cli_version: str
    config_read: bool
    requirements_read: bool
    effective_tool_inventory_read: bool
    forbidden_builtin_tool_count: int | None
    shell_enabled: bool | None
    web_enabled: bool | None
    apps_enabled: bool | None
    plugins_enabled: bool | None
    multi_agent_enabled: bool | None
    mcp_callable_count: int | None
    app_callable_count: int | None
    plugin_enabled_count: int | None
    skill_enabled_count: int | None
    hook_enabled_count: int | None
    approval_policy: str | None
    sandbox_mode: str | None


@dataclass(frozen=True, slots=True)
class IsolationGateReport:
    schema_version: Literal["codex-app-server-isolation-gate-v1"]
    status: Literal["pass", "fail"]
    safe_error_code: str | None
    cli_version: str
    violations: tuple[IsolationViolation, ...]
    observation_hash: str
```

`attest_isolation` must compare `cli_version` with the module constant
`ALLOWED_CODEX_APP_SERVER_VERSIONS = frozenset({"0.151.0"})`. Every `None`, unreadable RPC,
missing effective per-thread tool inventory, non-empty callable inventory, non-`never` approval
policy or non-`readOnly` sandbox adds a stable rule id and returns FAIL. A disabled feature flag does
not set `effective_tool_inventory_read=True`; that value requires a stable App Server response that
enumerates the tools actually exposed to the target thread. `observation_hash` is SHA-256 of sorted
canonical JSON; the canonical JSON contains booleans and counts only, never paths or raw payloads.

- [ ] **Step 3: Implement the bounded client and exact RPC sequence**

Start the child with:

```python
await asyncio.create_subprocess_exec(
    *command,
    "app-server",
    "--stdio",
```

The client sends newline-delimited messages in this exact order and matches responses by numeric id:

```json
{"method":"initialize","id":1,"params":{"clientInfo":{"name":"ai_workshop_rag_gate","title":"AI Workshop RAG Gate","version":"1.0.0"}}}
{"method":"initialized","params":{}}
{"method":"config/read","id":2,"params":{"includeLayers":true}}
{"method":"configRequirements/read","id":3,"params":{}}
{"method":"mcpServerStatus/list","id":4,"params":{"cursor":null,"limit":100,"detail":"toolsAndAuthOnly"}}
{"method":"skills/list","id":5,"params":{"cwds":["<empty-cwd>"],"forceReload":true}}
{"method":"hooks/list","id":6,"params":{"cwds":["<empty-cwd>"]}}
{"method":"app/installed","id":7,"params":{"forceRefresh":true}}
{"method":"plugin/list","id":8,"params":{"cwd":"<empty-cwd>"}}
```

Continue cursor pagination until each `nextCursor` is null; more than 20 pages is a failure. Read
`features.shell_tool`, `features.web_search`, `features.apps`, `features.plugins` and
`features.multi_agent` from effective `config/read`. Missing keys remain `None`; do not substitute
defaults. The probe must also locate a non-experimental generated-schema method that returns the
effective per-thread built-in tool inventory; if the exact `0.151.0` schema has no such method,
record `effective_tool_inventory_read=False` and do not infer success from configuration. The
documented `plugin/list` method is under development, so absence from the non-experimental schema or
an unreadable response also remains unknown and fails closed. Only counts and booleans cross into
`IsolationObservation`. Bound each line to 2 MiB,
bound stderr to 64 KiB in memory, never include stderr or JSON values in exceptions, and terminate
then kill the child on timeout.
