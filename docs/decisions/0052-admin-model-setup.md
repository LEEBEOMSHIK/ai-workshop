# ADR-0052: 관리자 모델 연결과 RAG 후보·검증·적용의 통합 흐름

- 상태: 사용자 요청에 따른 구현
- 결정일: 2026-10-30

## 후속: 모델 이름 선택과 고급 메뉴

OpenAI 신규 등록은 모델 ID 직접 입력 대신 최신 공개일 내림차순의 주요 텍스트 모델 선택을 기본으로 한다. 모델 ID·이름·공개일·공식 문서 URL·확인일은 프론트엔드의 명시적 버전 카탈로그(JSON)에서 관리하고 업무 컴포넌트에 모델명을 분산하지 않는다. 공식 모델 문서의 Responses/구조화 출력 지원과 API 변경 이력의 최초 공개일을 함께 확인한다. 같은 공개일은 이름순이며 성능 순위가 아니다. 조회 API의 생성 시각을 출시일로 간주하지 않는다.

이 목록은 확인일 당시의 공개 카탈로그이며 실시간 전체 목록이나 계정별 권한 확인이 아니다. 키가 없어도 이름을 고를 수 있지만 서버 연결·인증 준비와 기존 품질 수용 게이트는 여전히 필요하다. 자동 갱신·기본 모델 자동 변경은 하지 않으며 새 모델 추가 시 출처·공개일·호환성·확인일과 카탈로그 버전을 함께 갱신한다. 목록 밖 모델은 명시적인 고급 직접 입력 경로로 보존한다. 공급자/입력 방식 변경은 이전 모델 ID와 지원 기능 확인을 지워 잘못된 조합을 제출하지 않는다. 로컬 설치 모델 ID 입력은 유지한다.

일상 작업의 진입점은 `모델 연결·RAG 설정`이며 기존 `RAG 구성 · 고급`·`RAG 모델 · 고급`은 상세 버전·프로파일·평가·모델 등록 관리용으로 유지한다. 기존 URL과 저장 데이터는 변경하지 않는다. 이 후속 변경은 프론트엔드 선택 UI에 한정하며 서버 API 계약·모델 요청·활성 설정을 변경하지 않는다.

내부 모델 정의·배포·생성 프로파일·RAG 구성·도메인 연결의 불변 버전은 유지하되, 관리자는 하나의 화면에서 연결/선택·구성·검증·적용을 수행한다. 기존 고급 화면과 URL은 보존한다. [사용자 흐름과 수용 기준](../superpowers/specs/2026-10-30-model-setup-design.md).

추가 조회 계약은 owner 전용 `/api/v1/admin/rag/deployment-setup-options`다. 설정에서 허용된 연결 참조 이름·dialect·인증 참조 이름·환경과 명시적인 신규 후보용 답변 프리셋을 반환한다. 실제 endpoint URL·인증값·임의 환경값·비공개 본문은 반환하지 않는다. 조회는 외부 서비스 호출이나 상태 변경을 하지 않는다. 실제 키와 주소의 서버 설정 경계는 ADR-0009를 유지한다.

흐름은 모델 연결 → 기존 RAG 구성 복제 → 연결 상태·답변 평가 → 도메인 명시적 적용이다. 기존 RAG 구성을 복사할 때 처리/색인/검색·답변 정책·지식 공간을 정확히 보존한다. 호환되는 생성 설정은 config 전체를 복사하고 공급자 비호환 필드를 조용히 제거하거나 변환하지 않는다. 기반이 추출식 답변이면 별도 체크박스 확인 후 해당 후보만 LLM 생성 답변으로 전환한다. 그 밖의 정책과 원래 구성은 유지한다.

신규 답변 프리셋에는 `supported_providers`를 포함한다. 기존 OpenAI Responses 런타임은 schema1만 허용하므로 `rag-answer-v1`/schema1 후보를 제공하고, 로컬 HTTP에는 `rag-answer-v3`/schema2 후보를 제공한다. 단일 schema2 프리셋을 양쪽에 공통 적용하거나 추론 코어를 확장하지 않는다. 프리셋은 사용자가 명시적으로 고른 신규 평가 후보이며, 과거 결과·활성 연결·전역 기본값·프롬프트 본문은 변경하지 않는다. 버전된 프리셋의 유한한 대화·출력 정책과 로컬 schema2의 명시적 문맥 근거 예산은 해당 프리셋 모듈에서 관리한다. OpenAI schema1에는 해당 프롬프트가 지원하지 않는 문맥 근거 설정을 주입하지 않는다.

기존 API의 준비 상태·정확한 버전 평가·외부 전송 승인·owner 검사와 도메인 활성화 게이트는 유효하다. health 성공, 검색 준비, 답변 준비와 답변 품질 수용은 별개로 표시한다. 검색 평가도 설정의 `evaluation_state`를 `passed`로 만들 수 있으므로, 그 값과 `canApplyCandidate`만으로 적용을 허용하지 않는다. 현재 후보 버전에 대한 `acceptGenerativeRun` 성공 응답의 `configuration_version_id` 일치와 이후 재조회한 준비 상태를 함께 요구한다. 후보/연결/범위 변경 뒤 이전 수용 확인이나 오래된 비동기 결과를 재사용하지 않는다.

새로고침 뒤 화면의 평가 수용 확인이 사라지면 해당 버전의 기존 완료 답변 평가에서 통과 반영을 다시 실행한다. 서버가 저장된 결과를 다시 검증해 반환한 수용 응답으로 확인을 복구하며, 새 모델 호출이나 평가 재실행을 요구하지 않는다. 이 화면의 수용 확인은 기존 서버 권한·평가 게이트를 대체하는 별도 권한 증명으로 취급하지 않는다.

적용 전 후보와 도메인 연결의 최신 상태를 재조회하고, 대상·모델·지식 공간을 표시해 명시적으로 확인받는다. 확인 이후 연결이 바뀌면 다시 확인해야 한다. 사용자 확인 없는 활성화/전역 승격/모델 실행은 없다. 부분 저장은 생성된 객체와 남은 단계를 보여주고 입력을 보존하며, 후속 재시도에서 저장된 객체와 비활성 연결을 재사용한다. 응답 유실은 정확한 저장 결과를 대조하고 대조 실패 시 중복 생성을 차단한다. 여러 기존 API 호출을 단일 DB 트랜잭션이라고 표현하지 않는다.

화면은 공통 다크·청록 토큰, 44px 조작 영역, 키보드 초점과 모바일 줄바꿈을 따른다. 고급 모델·RAG 구성 화면은 보조 링크로 유지한다. 상세 표현은 [UI 스타일 기준](../guidelines/ui-style-guide.md#관리자-모델-연결과-rag-설정)을 따른다. 이 결정은 구현·검증 기준이며 본래 환경 반영, 실제 브라우저 확인 또는 신규 모델 품질 수용의 완료 선언이 아니다.
