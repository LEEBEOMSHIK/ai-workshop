# RAG 실행 모니터링 검증

- 구현·반영일: 2026-09-28
- 관련 문제: ISSUE-00005 (열림 유지)
- 범위: 대화 실행 기록, 관리자 조회, 단계·근거·점수 화면
- 설계: [실행 모니터링·생성형 평가](../superpowers/specs/2026-09-27-rag-execution-monitoring-and-evaluation-design.md)

## 구현과 기존 환경 반영

관리자 RAG 메뉴에 **실행 모니터링**(`/admin/rag/executions`)을 추가했다.
질문별 실행 상태와 답변 상태·품질 검증 상태를 구분하고, 단계별 시간·실패 코드·검색 순위와
원점수·문맥 점수·근거 선택 사유·입력 예산·구성 버전·공급자가 보고한 사용량을 표시한다.
실제 답변 인용과 생성에 전달된 전체 근거를 구분하며 원문과 기존 대화로 연결한다.
문서 본문·질문·답변을 실행 메타데이터에 복사하지 않고 권한이 있는 원래 저장 기록에서 읽는다.

기존 DB에 가산 migration `0054_rag_executions`를 적용하고 기존 API18000을 재시작했다.
직접 API와 프론트5173 경유 health가 모두 정상 응답했다.
기존 계정1개·문서6개·대화2개를 보존했다. 실제 DB 읽기에서 접근 가능한 과거 요청8건과
상세8단계의 미기록 상태를 확인했다. 과거 기록에 실행 ID나 시간을 소급 생성하지 않았다.
DB 통합 테스트는 기존 연결의 외부 transaction을 rollback했으며 계정·DB를 만들지 않았다.

## 자동 검증과 독립 리뷰

- 관련 백엔드 단위 테스트145개 통과. 마지막 메타데이터 필드 보완 후 실행 모듈21개 재검증 통과.
- 기존 DB rollback·인증 API 통합2개 통과.
- 관리자 탐색·실행 화면·원문 모달 관련 프론트37개 통과. 인용 표시 보완 후 관련3개 재검증 통과.
- 전체 백엔드 Mypy359개 소스 통과, 변경 Python Ruff 통과.
- 프론트 TypeScript·ESLint·생성 API 계약 검사 통과.
- 독립 리뷰의 중요 지적3건을4개 실패 회귀 테스트로 재현 후 수정했다.

목록 열거 뒤 삭제된 대화와 늦게 권한이 철회된 이전 대화 의존성이 조회되지 않도록
현재 의존성 전체를 다시 확인한다. 마지막 관측 저장 실패는 정상 답변을 실패로 뒤집지 않으며,
관측 완료로 잘못 표시하지 않는다. 종료된 실행 상태는 뒤늦은 완료 처리로 역전되지 않는다.
전체 통계는 권한 검사된 동일 모집단을 사용한다. 현재는 그 모집단을 메모리에 누적하므로
매우 큰 이력의 집계 최적화는 별도 작업이다.

## 미완료 검증

현재 기존 브라우저가 로그인 화면에 있어 실제 마스터 로그인으로 데스크톱·모바일의 새 메뉴,
새 질문→단계 상세→인용 원문 이동은 아직 확인하지 않았다. 인증을 우회하거나 새 계정을 만들지 않았다.
새 실사용 질문의 기록 오버헤드·행 크기 측정과 문제 관리 DB에 이 문서 연결도 남아 있다.
자동 테스트와 원본 DB 조회를 브라우저 검증으로 대신 보고하지 않는다.

생성형 평가 실행·정답 판단·후보 승격 경로도 구현해 본래 환경에 반영했다.
[후속 구현 기록](2026-09-28-rag-generative-evaluation-verification.md)의 실제 모델 검증은 로그인 대기다.
이 모니터링 구현만으로 답변 품질이 개선됐거나 인용 유효성이 정답을 보장한다고 판단하지 않는다.
현재 활성 검색 구성은 유지한다.
