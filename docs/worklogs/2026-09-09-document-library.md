# 파일 관리 탐색기·독립 원문 열람 구현 기록

- 상태: 구현·자동 검증·독립 최종 보완 재검토 통과, 실제 화면 확인 후 시각/초점 보완 2건 기록
- 설계: [독립 문서 라이브러리](../superpowers/specs/2026-09-09-document-library-design.md)
- 결정: [ADR-0021](../decisions/0021-platform-document-library.md)
- 계획: [단계별 구현](../superpowers/plans/2026-09-09-document-library.md)

## 해결하려는 문제

기존 파일 관리 화면은 실제 회사/개인 공간·폴더를 충분히 표현하지 않았고, 문서 제목은
열람 동작이 없는 텍스트였다. 공간 생성 폼과 목록의 폭도 달랐다. 기존 RAG 근거 뷰어를
그대로 연결하면 파일을 읽기 위해 검색 projection 준비가 필요하므로 Platform 원문 열람을 분리했다.

## 구현·검증한 백엔드

- 실제 공간·폴더·활성/최신 버전 메타데이터, 직접 자식 목록과 범위에 연결한 서명 cursor.
- 폴더 업로드 전 공간 소속 검사, 같은 부모의 중복 폴더 생성 경쟁을 직렬화.
- 문서·버전 목록을 제한된 페이지로 조회. 기존 unpaged 버전 API는 기존 소비자를 위해 유지하되
  새 탐색기는 bounded 버전 API를 사용한다. API 하나가 추가되지만 전체 버전 적재를 피한다.
- 정확한 READY 버전의 크기·SHA-256을 검증한 동일 바이트로 원문·다운로드·PDF 렌더링을 제공.
- 원문 처리 후 권한·만료·상태·원본 식별을 다시 확인. 모델·외부 뷰어·OCR 호출 없음.
- 로컬 PDF 프로세스에 입력·출력·페이지·화소·시간·동시성 제한을 적용하고 종료·회수 후 슬롯 반환.

## 검증 중 발견한 문제와 보완

### DB 세션이 이전 READY 상태를 재사용

ORM 인스턴스가 세션에 남아 있으면 다른 세션이 상태를 바꿔도 이전 READY를 읽을 수 있었다.
인스턴스를 유지한 상태에서 동시 변경하는 실패 테스트로 재현했다. 정확한 버전의 scalar-column
조회로 바꾸어 최종 검사가 현재 DB 값을 확인하도록 했고, 권한 제거·만료·상태 변경 SQL 검증을 통과했다.

### PDF 취소 중 다시 취소되면 프로세스 소유권을 일찍 반환

단일 취소 테스트는 통과했지만 독립 검토에서 연속 취소가 종료·회수 대기를 중단할 수 있음을 확인했다.
별도 정리 작업을 보호하는 것만으로는 부족하므로 요청도 정리가 끝날 때까지 슬롯·임시 경로의
소유권을 유지하도록 변경했다. 일반 취소 및 시간 초과 정리 중 추가 취소를 실제 자식 프로세스로 검증했다.

### 성공 응답에만 적용되던 안전 헤더

원문 경로의 인증·검증·업무 오류에도 `private, no-store`와 `nosniff`가 적용되도록 했다.
원문 라우터에만 적용하며 기존 전역 오류 정책과 안전한 오류 봉투는 유지했다.

### 프론트 검토에서 발견한 화면 상태·표시 누락

초기 41개 테스트는 통과했지만 독립 검토에서 네 가지 누락을 확인했다. 잘못된 URL을 뒤로가기로
복원할 때의 처리, 폴더 변경 뒤 늦게 완료되는 추가 조회/새로고침, 새 폴더의 트리 반영과
성공한 저장 뒤 조회 실패 안내, 좁은 화면의 트리 접기다. 요청이 발생했는지만 확인하던 테스트를
실제 표시·현재 범위·부분 실패 구분으로 보강했다. 독립 재검토에서 네 항목 모두 해결을 확인했다.
메인 회귀 46건은 통과했으나 새 지연 업로드 테스트의 React act 경고가 남아 최종 보완 대상으로 기록했다.
최종 보완에서 사용자 이벤트와 완료 상태를 순서대로 기다리도록 바꾸었으며, 메인 55건 재검증에서는
해당 경고가 출력되지 않았다. 경고 출력을 숨기는 처리는 하지 않았다.

전체 연결 검토에서는 별도의 네 가지 연결 누락을 확인했다. 폴더 이동 대기/실패 중 표시 위치와
작업 대상 불일치, 경로 복원으로 만든 상위 폴더 가지에서 다른 하위 폴더 누락, 업로드 응답의
작업 ID 손실, 선택 버전 정보 표시 누락이다. 반복 페이지 요청 중복과 위 테스트 경고까지 한 번의
최종 프론트 보완으로 묶어 실패 테스트 후 수정했다. 기존 버전 API를 추가 변경하지 않고 확인된 크기·미리보기 유형과
정확히 일치하는 버전의 메타데이터만 표시하며, 아직 조회되지 않은 과거 형식은 명시적으로 미조회로 표시한다.

## 검증 근거와 경계

- 1단계: 메인 관련 테스트 76건·타입·린트 통과, 독립 설계/품질/권한 검토 승인.
- 2단계: 관련 회귀 154건, 격리 SQL 6건 통과. 메인 원문/Assets/PDF/SQL 재검증 63건 통과.
- 2단계 보완: 실패 테스트 후 관련 36건 통과, 메인도 36건 재실행 통과. 독립 재검토에서 두 항목 해결 확인.
- 기존 TestClient deprecation 경고 1건은 별도 유지보수 대상이며 이번 작업에서 패키지를 변경하지 않았다.
- 3단계: 프론트 관련 8개 테스트 파일·41건 통과, 메인도 41건 재실행 통과. TypeScript·범위 제한
  ESLint 통과, 18개 변경 파일 해시 일치 및 검토 패치 역방향 적용 검사 통과. 이후 독립 검토에서
  위 네 가지 미포함 경계를 발견했다. 보완 후 46건·타입·린트 통과 및 독립 재검토를 통과했으며,
  이후 최종 보완 관련 55건을 구현자와 메인이 각각 통과했다(메인 8개 파일, 42.63초, 경고 없음).
  메인 TypeScript·범위 제한 ESLint·API 타입 일치 검사를 통과했고, 전체19개/보완8개 파일의
  해시와 두 패치 역방향 적용 검사를 확인했다. 독립 최종 보완 재검토에서도 I1–I4·M1/M2
  모두 해결됐고 새 결함은 발견되지 않았다. 로그인 후 실제 화면 확인은 아직 별도다.
- 프론트 API 타입 생성·일치 검사 통과. 비공개 로컬 API 재시작 후 health 및 프론트 경유 DB 조회 200.
- 실행 중 원문 API에 무인증 요청 시 401과 `private, no-store`·`nosniff` 헤더를 확인했다.
- 사용자 문서·폴더·승인 상태를 변경하지 않았다. DB 검증은 고유 임시 DB 생성·삭제 하네스를 사용했다.
- 프론트 연결은 구현됐으나 실제 문서 화면 검증은 아직 진행하지 못했다. 브라우저 로그인 화면 전환 후
  재로그인을 요청했고, 다시 확인했을 때도 로그인 화면이었다. 데스크톱/좁은 폭 시각 검증을 완료로 표시하지 않는다.

## 2026-09-09 로그인 후 실제 확인

computer-use 스킬의 읽기 전용 브라우저 절차로 기존 합성 자료만 열었다. 회사/개인 공간 구분,
공간 이름과 미분류 목록, 문서 클릭 후 Markdown 원문과 정확한 버전1·1,141 B·text/markdown,
새로고침 및 뒤로가기 복원을 확인했다. 합성 자료의 AM-LAB-730/840 기재 내용도 일치했다.
기본 데스크톱과 760px·390px를 확인했으며 작은 화면의 전체 폭 뷰어·줄 바꿈·트리 접기/펼치기가
동작했다. 390px에서 document scrollWidth는375px로 페이지 가로 넘침이 없었다. 화면 크기는 원복했다.

실제 화면에서 두 가지 보완을 발견했다. 경로 및 루트 버튼은 공통 버튼 스타일 대상에서 빠져
기본 흰색 배경으로 표시된다. 또한 직접 문서를 클릭한 경우 닫기 초점 복귀는 정상이나,
새로고침으로 복원된 뷰어는 openerRef가 없어 닫은 후 문서 버튼으로 초점이 돌아가지 않는다.
별도 소규모 보완 대상으로 WORKBOARD에 기록했으며 이번 읽기 전용 확인에서는 소스를 수정하지 않았다.
기존 공간에 하위 폴더나 추가 버전을 만들지 않았고 PDF 업로드·다운로드·외부 AI 호출·승인 변경도
수행하지 않았다. 해당 범위의 자동 테스트와 실제 UI 검증을 혼동하지 않는다.

### 형식별 지원

첫 독립 뷰어는 TXT/Markdown 원문과 PDF 페이지 이미지다. Office/HTML은 문서 정보 및 명시적
원본 다운로드를 제공하며 독립 미리보기 지원 완료로 표현하지 않는다. 기존 RAG 근거 뷰어는 유지한다.
문서 이동·이름 변경·휴지통과 외부 AI 승인 화면 재배치는 후속이며, RAG 전체 테스트 준비와도 구별한다.
