# 에이전트 단계 본문 보관과 상세 재조회

- 날짜: 2026-10-23
- 상태: 수집·보관·조회 구현과 본래 API 반영 완료. 추가 승인된 실제 Gemma 평가2회에서 본문 수집·저장·새로고침 상세 조회를 확인했다. 답변 품질은 별도로 실패했다.
- 문제: ISSUE-00036 (`995f16b0-b48f-48f0-b52f-9e5433e9e85e`). 기존 가독성 문제 ISSUE-00035와 원인을 분리했다.
- 정본: [ADR-0040](../decisions/0040-private-agent-step-content.md), [수행 계획](../superpowers/plans/2026-10-23-agent-step-retention.md)

## 사용자 요구와 확인한 원인

사용자는 질문·최종 답변뿐 아니라 내부 에이전트에 전달한 지침·입력·결과를 실행 후 상세에서 확인하기를 요구했다. 기존 화면의 ‘전체 단계 기록’은 관계·모델·시간 등의 메타데이터를 보여줬으나, 본문 미보관 정책 때문에 이 목적을 충족하지 못했다.

기존 실행의 지침·입력 펼치기에서 `본문 수집 안 함`과 일반적인 빈 안내를 재현했다. 코드에는 세 경계가 있다: `include_diagnostics`에 종속된 수집, observer/DB projection의 본문 제거, 이력 UI의 complete 본문 강제 숨김. 에이전트 자체 입력을 hook에 넘기지 않는 누락도 확인했다. 최초 ADR-0039의 요청 한정 정책과 후속 사용자 요구를 구분하고 이번 변경으로 ADR-0040을 채택했다.

## 역할과 보존 경계

본문 저장·조회·권한 노출 변경으로 분류했다. 결정론적 역할 선택기는 requirements/system architecture/frontend/python backend/database/test design/integration/security/privacy/independent review/documentation 역할을 선택했다. 메인은 요구·아키텍처·문서·통합, backend 담당은 수집/보관/조회·DB·테스트, frontend 담당은 본문 표시·테스트를 맡는다. 독립 검증자는 제품 구현과 분리했다. 모델 교체·검색 평가·인프라 설치 역할은 실제 변경 범위가 없어 제외했다.

이 checkout의 기존 변경143파일 SHA를 `.local-data/project-agent-work/agent-trace-retention-20261023/baseline-sha256.json`에 기록했다. 이전 SDK/모니터링 변경에 이어 작업하므로 별도 설치·환경·DB·계정·worktree를 만들지 않는다. 새 모델/임베딩 호출, 일반 worker 실행, 재색인, 임의 데이터 보정, 커밋·푸시가 범위에 포함되지 않는다.

## 설계

새 SDK 실행의 본문을 기존 private execution trace에 한 번 보관한다. 대화/평가 JSON은 기존 질문·최종 답변 및 메타데이터를 유지한다. `content_retention` 표식 없는 과거 기록은 본문 없는 기록으로 취급한다. agent 입력은 실제 Runner/input builder 값, model 입력은 실제 허용 HTTP 필드, delegation 입력은 실제 도구 인자다.

관측 반환값은 최종 답변과 다를 수 있다. 안전하게 해석한 반환값을 관리자 원인 분석용으로 보관하되, 일반 대화의 검증 실패 초안 가림과 인증·예외·비공개 내부 추론 제외를 유지한다. 상세 반환 직전 현재 소유권·정확한 실행 연결·원문 ACL을 다시 검사한다. 기존 관측 크기 한도와 revision/종료 쓰기 보호를 유지한다.

## 확인한 실제 저장 상태

기존 실행 `7ed26877-3575-42d1-8c4f-ffdde32145cd`를 읽기 전용으로 확인했다. 질문은 평가 사례의 `query_bytes`, 최종 답변은 `rag_generative_attempts.result.answer`에 있었다. trace에는 에이전트2·모델2·위임1의 총5단계가 있지만 본문text는0개이며, 지침·입력·출력15필드가 모두 `disabled`였다. 단계가 없는 것이 아니라 본문을 수집하지 않은 기록이다. 실제 본문은 이 작업 문서나 검사 로그에 복사하지 않았다.

## 구현 결과

- `capture_agent_trace`와 pipeline은 실행 observer가 있으면 현재 응답의 진단 옵션과 무관하게 수집한다. 실제 Runner 입력과 specialist input builder 결과를 agent hook에 연결했다.
- `storage_agent_trace`는 새 `retained` trace를 기존 execution JSON에 보관한다. 기존 `persisted_agent_trace`는 metadata projection으로 남겨 대화 저장·이력 응답에 본문을 중복 저장하지 않는다. 과거 표식 없는 기록은 metadata only로 읽는다.
- 저장과 조회 모두 본문의 Unicode 길이·SHA·전체 한도·단계 수를 검사한다. revision/실행·span 동일성 및 종료 후 늦은 쓰기 거부를 유지했다.
- conversation 상세는 actor·turn·conversation·실행 연결, dependency와 현재 원문 ACL을 재검증한다. evaluation 상세는 attempt·run·owner와 최종 시점의 source manifest를 다시 읽는다. 독립 RED에서 발견한 조회 중 평가 자료 연결 변경도 차단했다.
- history 화면은 보관된 지침·입력·반환값을 펼쳐 보여준다. 당시 미수집·미보관, 해당 없음, 실제 빈 문자열, 한도 초과, 검증 실패 가림을 구분한다. 관측 반환값과 검증된 최종 답변의 차이를 표시한다.

제품 변경은 backend9파일(`executions/agent_trace`, `observer`, `service`; `search/pipeline`; `orchestration/domain`, `openai_agents`, `sdk_hooks`; `conversations/service`; `evaluation/generative_monitoring`)과 화면 `AgentTracePanel.tsx`, 생성된 API 타입이다. 그림·CSS·모델·검색·품질 기준은 변경하지 않았다.

독립 새 회귀18개는 구현 전17실패/1통과였다. 이후 최종 평가 source manifest 변경 회귀1개를 추가해 RED를 확인하고 수정했다. 관련 backend317개가 독립 실행에서 통과했다(39.50초, 독립 회귀19개 포함). 실제 SDK mock HTTP 수집 회귀9개도 RED→GREEN으로 검증했다. 변경14개 Python Ruff와 제품9개 Mypy를 통과했다.

## 본래 반영과 보존

최종 독립 검증 후 활성 execution/turn/run/attempt0과 기존 API의 정확한 경로·명령·18000 listener를 재확인했다. 앞서 승인된 동일 기존 API 반영 범위에서 PID128020을 PID119944로 교체했다(08:18:55 UTC). 본래 Conda·루트 작업 디렉터리·Selector loop·포트·설정을 유지하고 숨김 시작했다. health `ok`·ready `ready`, live OpenAPI의 `content_retention`과 `not_applicable` 반영을 확인했다. worker·Ollama는 조작하지 않았다.

기존 로그인된5173 화면을 새로고침해 같은 실제 완료 실행의 질문·최종 답변·품질 실패·5단계가 보존됨을 확인했다. 세 본문을 펼치면 ‘당시 본문 수집 안 함’과 ‘빈 입력이나 빈 결과라는 뜻은 아닙니다’가 표시된다. 기존143파일은120개 바이트 동일·이번 허용 범위23개 변경·누락0·예상 밖 변경0이다. 추가 작업 대상은 이전에 깨끗했던 ADR-0038과 신규6파일이다.

검증 전후 관련22개 RAG 테이블의 행 수와 primary key 순서별 전체 행 SHA를 READ ONLY/UTC로 비교해 모두 동일함을 확인했다(08:07:15→08:20:14 UTC). 기존 평가·모델·구성·도메인·실행·감사 데이터는 변경되지 않았다. 보존 증거와 API 반영 기록은 `.local-data/project-agent-work/agent-trace-retention-20261023/`에 있다.

정상 인증 관리자 UI로 ISSUE-00036에 구현·검증·남은 범위를 갱신했다. 상태는 ‘구현됨·검증 남음’이며 새 실제 모델의 본문 수용이 미실행임을 명시한다. 검증 요약 문서 `b8b03ef2-74b2-4d54-8ed8-32b90ece9bd6`의 정확한 버전1을 연결했다. 기존 ISSUE-00035·문서 버전들은 변경하지 않았다. 캐시 삭제·새 환경·staging·commit·push는 없다.

변경 문서8개의 상대 링크205개와 최근 완료5개 유지, 프로젝트 에이전트 계약 검사 및 `git diff --check`를 확인했다. 문제 문서 연결 후 오래된 편집 버전의 저장 충돌은 최신 내용을 다시 읽고 연결을 보존한 상태로 저장해 해결했다. 본래 API와 실제 모니터링 탭을 남기고 직접 시작한 합성 화면 서버와 검증용 탭은 종료했다.

새 Gemma 실행은 미실행이다. 기존 실제4/4 생성 예산과 품질 실패 결과를 유지한다. 새 실제 실행의 모델 입력 전문 보관을 운영 화면에서 확인한 것으로 보고하지 않는다. 새 실행을 허용받을 때 같은 경로의 실제 수집→보관→재조회를 확인할 수 있다.

## 승인된 질문1건 실제 검증

사용자는 위 결과를 확인한 뒤 ‘질문 한건 해서 확인해’라고 승인했다. 위의 실제 본문 미검증과 추가 호출0은 이전 단계의 상태다. 처음 안내한 별도 범위는 기존 공개 합성 질문1사례×반복1, 로컬 생성 최대2회·재시도0과 필요한 기존 검색 임베딩이었다. 기존 SDK 구성·모델·품질 기준을 유지한다. 메인이 실행·화면·AI 평가·DB 운영을 맡고 독립 담당이 읽기 전용 사전 조건과 결과·권한/privacy·기존 행 보존을 확인한다. 제품 구현·UI 재설계·인프라 설치는 하지 않는다. 실행 범위가 확정되면 새 실행을 정상 등록한 뒤 exact `execute_run` 경로로 그 실행만 처리한다.
