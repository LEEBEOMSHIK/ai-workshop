# ADR-0045: 고정 평가 실행 안의 임베딩 계산 재사용

- 상태: 구현·고정 질문2회 실측 완료, 일반 기본값 승격 보류 (2026-10-26)
- 근거: [v6 실제 결과](../worklogs/2026-10-26-rag-reference-packing.md), ISSUE-00038

## 목적과 선택

v6 반복 평가에서 검색14.178초·선택15.638초 중 임베딩 모델 준비11.637초·문서 계산15.069초가 관측됐다. 현재 각 attempt는 새 frozen 검색 객체와 CPU 모델을 만들고 생성 전에 해제한다. 토큰 수 계산도 같은 모델의 초기 적재를 일으킨다. 동일 고정 질문의 다음 반복에서 준비·계산을 다시 수행하는 구조를 확인했다. 환경 변화의 기여도까지 확정한 것은 아니다.

모델·tokenizer를 계속 보관하는 안은 생성 시 메모리 경계와 충돌하므로 사용하지 않는다. 일반 사용자 요청 사이의 공유 캐시는 이번 범위보다 넓고 권한·보관 정책이 추가로 필요하다. 선택한 방식은 하나의 생성형 평가 claim에 속한 완료 계산값만 유한 메모리에서 재사용하는 것이다. 일반 대화나 첫 요청의 전체 속도를 개선한 것으로 보고하지 않는다.

## 활성화와 수명주기

typed setting `frozen_evaluation_embedding_cache_bytes`는 기본0(비활성), 최대64MiB다. 검증 실행은 명시한 한도(예:16MiB)로만 활성화하며 `.env`나 일반 기본값을 변경하지 않는다. claim의 worker_runtime에 버전·활성 여부·상한·scope를 기록해 지연 비교에서 재사용 조건을 확인할 수 있게 한다.

저장소는 `_execute_claimed` 한 번의 지역 객체이며 정상·실패·취소·종료 미확인·재claim 때 외부로 공유하지 않는다. outer finally에서 모든 키·값 참조를 지우고 닫는다. 재claim은 빈 저장소다. 각 attempt의 새 production CPU owned runtime factory를 lazy wrapper로 감싼다. borrowed 포트와 다른 device, 추출형 평가, 일반 검색은 바꾸지 않는다. 기존 생성 전 close와 finally의 멱등 close를 유지한다. cache hit는 runtime을 생성·적재하지 않는다.

## 정확한 입력과 품질

namespace는 actor·candidate 구성/버전·case·전체 frozen component/execution snapshot·권한 scenario의 해시다. 따라서 pinned 모델 정의/revision/모든 설정·프로파일·색인/문서 버전·범위가 다른 결과를 섞지 않는다. 각 연산은 query token count, document token count, query vector, document vector batch로 분리한다. 본문 문자열과 문서 배치 전체의 순서·중복을 정확히 키로 사용한다.

문서별 부분 hit를 골라 새 배치를 만들지 않는다. 전체 ordered batch가 같을 때만 재사용하며 miss는 원래 호출을 그대로 수행한다. 배치/padding 차이로 수치 결과가 달라지는 것을 피한다. 토큰 수·벡터 차원·유한 값·정규화·반환 개수를 검증한 완료값만 atomic하게 게시한다. 실패·취소·부분 결과는 저장하지 않는다. immutable tuple로 저장하고 항상 새 list를 반환한다.

키·값·컨테이너의 Python 객체 크기를 보수적으로 합산해 저장 상한을 지킨다. 상한을 넘으면 해당 결과를 보관하지 않고 같은 원래 모델 계산을 수행한다. 상한은 캐시 보관량이며 전체 프로세스 RSS나 임시 계산 메모리 상한이 아니다. 모델·클라이언트·예외·추론 상태를 값으로 보관하지 않는다. 개인 원문과 벡터는 메모리 내에서만 유지하며 로그·DB·파일로 저장하지 않는다.

## 권한·실패·관측 계약

매 attempt의 frozen snapshot 검사, 현재 구성 해석, 초기/선택/생성 전/반환 전 권한 재검사와 실제 검색·선택을 모두 유지한다. 저장소는 권한 결과·검색 결과·최종 답변을 재사용하지 않는다. 다른 actor·claim·case·후보는 격리한다. warm 상태에서 권한 철회가 계속 거절되는지 검증한다.

실제 cache hit만 본문 없는 `embedding.result_reuse` 연산으로 기록한다. items/reused_items는 반환한 계산 항목 수이며 token/query는1, 문서 배치는행 수다. 원래 query/documents 계측은 기존 요청 내부 재사용을 그대로 표시한다. 새 연산은 포함 관계의 진단 정보이므로 다른 연산 시간과 합산하지 않는다. 기존 단계의 최대16연산 계약 안에 추가한다.

동일 claim은 고정된 논리 모델 버전의 실행으로 취급한다. 실행 중 로컬 모델 파일 교체는 지원 범위 밖이다. 이미 검증된 hit는 파일 삭제 후에도 성공할 수 있고 miss는 기존 loader의 오류를 그대로 드러낸다. 캐시 없는 실행의 모든 runtime 오류까지 동일하다고 주장하지 않는다. 설치/건강 검증에는 setting0을 사용한다. 무결성을 보장하지 못하는 mtime 검사나 매 hit 가중치 전체 재해시는 추가하지 않는다.

## 수용

기존 결과와 토큰 수·벡터·선택 근거·인용 입력이 정확히 같고, 같은 반복의 모델 load/encode 호출 수가0이 되는 것을 합성·독립 테스트로 입증한다. batch 민감 fake·변경 입력·모델/권한/범위·작은 메모리·불량 출력·실패/취소·late 사용·borrowed 경계를 검증한다. 구현 중 실제 호출0회 이후 사용자 새 승인4/4회·retry0으로 제한 실측을 완료했다. 두 입력/답변/인용·28근거가 동일했고 반복46.797→16.810초, 첫205.070→210.948초를 관측했다. 기존정답0/2와 첫 지연은 남아 일반 기본값은0으로 유지한다.
