# 근거 지시 후에도 남는 실패를 이용한 추가 학습

## 목적과 사전 비교 원칙

사용자 요청(2026-11-05): 근거 번호를 주고 인용을 요청해도 틀리는 사례를 찾고, 그 실패 사례로 추가 학습한 뒤 학습에 사용하지 않은 비슷한 질문을 같은 조건으로 비교해 비공개 학습 기록에 남긴다.

앞선 [추가 학습](2026-11-04-gemma-local-training.md#후속-비교-기준)은 입력에 번호와 인용 지시를 제공하자 학습 전부터 세 질문에 올바르게 답했다. 추가 학습의 생성 품질 개선은 없었다. 이번에는 그 결과를 성공으로 확대하지 않고 실제 실패 탐색부터 시작한다.

- 공개 합성 규정만 사용한다. 기존 로컬 체크포인트와 이전 추가 학습 후보를 비교 기준으로 삼는다.
- 탐색 질문, 미사용 유사 질문, 새 문서의 질문, 회귀 질문을 첫 생성 전에 구분하고 입력·정답·근거·설정 식별값을 고정한다.
- 탐색 답변에서 확인한 실패만 학습 대상으로 선택한다. 의미 오류·필수 조건 누락·잘못된 근거·인용 누락을 구분하며 표현 차이를 오답으로 취급하지 않는다.
- 학습 순서·횟수·설정을 미사용 질문 결과를 보기 전에 고정한다. 평가 결과를 보고 후보를 다시 고르거나 반복 학습하지 않는다.
- 전후 질문·근거·인용 지시·생성 설정을 동일하게 유지한다. 실제 생성 답변과 의미 판정, 인용 판정 및 판정 이유를 기록한다.
- 같은 문서의 미사용 질문과 새로운 문서의 질문을 따로 보고한다. 소표본 결과를 전체 모델 성능으로 일반화하지 않는다.
- 실험 담당과 독립 검토 담당을 분리한다. 서비스의 검색·모델 연결·기본 프로파일은 바꾸지 않는다.

## 실행 상태

첫 생성 전에 공개 합성 19문항을 고정했다: 탐색 10, 같은 문서의 미사용 질문 3, 새로운 문서의 질문 4, 기존 회귀 2. [자료 원문](../../sample-data/public/rag/evaluation/gemma-failure-study-20261105.jsonl)의 SHA-256은 `203405185e8bc759a618b3b4219746ebc21a3b9c2918868483a92df67fae9dea`다.

학습 대상은 의미 실패를 인용만의 실패보다 우선하고 각 분류 안에서 문항 번호순으로 최대 3개를 고른다. 독립 검토로 확인한 각 실패를 4번씩 반복하므로 최대 12회 업데이트다. 출력 제한으로 잘리거나 응답이 끝나지 않은 사례를 의미 오류로 선정하지 않는다. 최종 선정은 탐색 뒤, 미사용 질문 생성 전에 확정한다.

기반 모델은 기존 고정 revision, 비교 기준은 이전 4회 추가 학습 후보(SHA-256 `3cbcf56d3edd3f7647ee550cb1abc54c23b276030013f7d97d2a40a79f08cf74`)다. 마지막 언어 층 query projection의 FP32 LoRA(rank 4) 22,528개 파라미터만 갱신한다. BF16 기반 가중치와 다른 층 어댑터는 고정한다. AdamW 학습률 0.005, weight decay 0, gradient clip 1, batch 1, seed 7, CPU 6스레드로 고정했다. 생성은 동일한 번호 포함 근거와 인용 지시, greedy, 최대 96토큰이다.

실행 디렉터리는 `.local-data/gemma-e2b-step/failure-study/run-20261105-103017-b9ad4c/`다. 실행과 독립 검증을 완료하고 [비공개 학습 기록](http://127.0.0.1:5173/workshop/learning/df88d927-1f96-4419-940d-fd284bc9be07)에 저장했다. 학습 문항 한 개만 개선됐으며 미사용 질문의 의미·완전성 개선은 관찰되지 않았다.

독립 검토에서도 위 세 실패를 확인했다. dev-04/05의 묶음 인용은 번호 두 개가 존재하므로 인용 누락이 아니다. dev-06의 실제 문장 자체는 e3가 지지한다. 인용된 숫자가 존재한다는 것과 답변의 날짜·완전성이 맞는지는 별개다.

dev-03은 신청일과 접수일 중 어느 날을 기준으로 세는지 물었으며 모델은 접수일 T를 정확히 답했다. 기준 답변의 ‘다음 영업일’과 e2는 부가 설명이므로 이를 생략했다는 이유만으로 실패로 선정하지 않는다. 고정 자료는 수정하지 않고 이 판정 이유를 남긴다.

탐색 10문항은 681.33초에 끝났다. 의미와 답변 완전성을 충족한 문항은 6개(01, 02, 03, 07, 08, 10), 내용 오류 3개(04, 05, 09), 요청한 수치 생략 1개(06)였다. 출력 잘림·미완료는 0개다. 문구 일치가 아닌 실제 질문·원문을 읽은 수동 판정이며 독립 검토와 일치했다.

고정 정책에 따라 dev-04, dev-05, dev-06을 네 차례씩, 총 12회 갱신하도록 확정했다. dev-09는 상한 때문에 학습하지 않고 이후 재평가도 하지 않는다. 따라서 전체 탐색 10개의 학습 후 성능이 개선됐다고 주장하지 않는다. 선정 결과와 사유를 저장한 뒤에만 미사용·회귀 질문 9개의 학습 전 답변 생성을 시작한다.

선정 파일은 학습 전 평가를 시작하기 전에 고정했으며 SHA-256은 `e5716735eca6ff2b260a6a09af3f3906b1d23d4ca0305d54680daf7730c60e00`이다. 미사용·회귀 9문항의 기준 답변은 전체 실행 1,209.90초 시점에 수집을 마쳤다.

사전 분류의 ‘같은 문서’는 탐색 문서를 기준으로 삼았다. 실제 선정 후 학습 문서는 누리·다온 2종이다. 따라서 same-01(가람)은 탐색에만 사용했으며 학습하지 않은 문서, same-02/03만 실제 학습 문서의 미사용 질문이다. 최종 보고는 이 차이를 명시한다. 새 문서 4문항은 탐색·학습 모두에서 제외한 바다·소담·아람 3종이다.

미사용 기준 답변의 보수적 판정: 완전한 정답 3, 명확한 날짜 오류 1, 불완전하거나 모호한 답변 3이다. hold-02의 ‘다음 영업일부터 계산’은 접수일 제외 여부가 모호하며, hold-03은 올바른 상대 규칙을 답하지만 계산 날짜는 생략했다. 이를 날짜 오답으로 확정하지 않는다. same-03은 ‘1영업일 안인가’라는 질문에 ‘아니요, 일반 기한’을 답했으므로 날짜를 생략한 dev-06과 달리 핵심 질문을 충족한다. 회귀 2개는 정확했다.

실험 과정에서 학습 비교 UI가 `[e1, e2]`를 인용 누락으로 표시하는 별도 결함을 발견했다. 원문과 의미 판정을 바꾸지 않고 묶음 번호를 읽는 표시 로직만 수정·회귀 검증한다(ISSUE-00051 후속).

## 추가 학습과 학습 문항 비교

세 입력 모두 마지막 층 이전의 고정 계산을 재사용한 경로와 전체 모델의 출력이 정확히 일치했다. 정답과 응답 종료 토큰에서만 손실을 계산해 지정한 12회 업데이트를 완료했다. 각 사례의 첫→마지막 손실은 04: 2.0689→0.6914, 05: 2.0647→0.8954, 06: 2.2830→1.0096이다. 손실 감소를 생성 품질 개선으로 대체하지 않는다.

후보 SHA-256은 `1d7b525baad10a06d7686c4da417ed3b2809ada7fb2e9bc32e8a054b3d6a0057`이다. 독립 파일 검토에서 70개 텐서 중 마지막 층 query projection의 A/B 두 개만 바뀌었고 변경된 FP32 값은 모두 유한했다. 부모 어댑터·자료·설정·선정 파일의 식별값은 보존됐다. 저장한 후보를 다시 읽은 뒤 생성한 실제 답변은 다음과 같다.
