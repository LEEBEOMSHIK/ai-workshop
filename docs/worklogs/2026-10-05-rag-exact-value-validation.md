# 2026-10-05 RAG 숫자·날짜 인용 검증 원인 수정

- 상태: 숫자·날짜 검증 수정과 새 주장 기록의 명시한 검증 범위 완료; 전체 RAG 마감과 후보 승격은 별도
- 문제: ISSUE-00023; 관련 ISSUE-00005/00017/00021
- 계약: [ADR-0035](../decisions/0035-rag-exact-value-canonicalization.md)
- 계획: [구현·검증 계획](../superpowers/plans/2026-10-05-rag-exact-value-canonicalization.md)

## 확인한 원인과 수정

기존 인용 검증은 숫자·날짜를 정규식으로 찾아 원시 문자열 집합으로 비교했다.
동일한 한글/ISO 날짜, 공백, 천 단위 쉼표와 소수 끝의 0을 다른 값으로 판단했다.
반대로 음수 부호와 퍼센트포인트 단위를 놓치고 무쉼표 숫자의 뒤 세 자리만 읽어
서로 다른 값이 통과하는 결함을 합성 입력으로 재현했다.

비교 전용 `exact_values.py`에서 유효한 날짜와 Decimal 수치·동일 단위를 비교한다.
원래 주장·원문은 변경하지 않는다. `%p`와 `%`, 원·만원·억원은 구분하고 부호를
보존한다. 단위 환산·반올림·계산·추론으로 지원 값을 추가하지 않으며, 현재 주장에
실제로 인용된 허용 근거만 사용한다. 거절 답변 초안은 노출하지 않는다.

독립 리뷰에서 `% p`·`퍼센트 포인트` 내부 공백 및 전각 퍼센트가 단위를 잃는
문제도 재현해 같은 계약으로 수정했다. 인식 범위는 ADR의 날짜·단위 있는 수치이며,
숫자 일치와 구조적 인용 검증이 문장 전체의 의미 검증을 대신하지 않는다.

- 독립 발견 6개 경계 사례 추가 후: 5실패/31통과. 수정 후 최종 관련 생성·검색·평가
  158통과(25.01초); 독립 평가·문맥·인용 173통과(12.90초).

## 실제 모델 평가와 남은 확인

v5 본래25문항×3회 평가는 수정 전 코드를 메모리에 유지해 21:22UTC에 종료했다.
최종75건은 성공70/실패5이며, 마지막 모델 실행의 cleanup 확인 및 정상 workflow 종료를
관찰했다. 실패는 Q04의3반복 및 Q12의2반복으로 모두 인용 검증 단계다.
그 실행의 숫자 인용 실패는 `exact_value_not_supported` 단계까지 확인했지만,
거절된 주장 초안이 미기록이므로 표기 차이인지 실제 잘못된 값인지 확정할 수 없다.
이 실패의 정확한 문구를 추측하거나 이번 코드 결함의 직접 원인으로 단정하지 않는다.

실패5건만 정상 재시도 API로 새 attempt3에 접수했다(21:25:38UTC).
이전150시도와70정답 판정을 유지하고 helper/제품 코드 SHA와 신규 attempt ID를 기록했다.
21:26:24UTC 독립 대조에서 원래150시도의 JSON/canonical bytes/저장 SHA·상태·원인·
실행 단계와 기존 판정60건이 일치하며, 추가 등록10건도 모두 정확한 결과/규칙에 결속됐다.
별칭 open/frozen1·receipt0, 기본 프로파일/구성, 후보 pending/defaultfalse 및 이전
미완료 취소 실행을 보존했다.

첫 보조 도구 요청은 Publishing 헤더와 JSON 본문 누락 때문에403으로 거절됐으며
새 시도·모델 실행은 생성되지 않았다. 실제 프론트의 `x-codex-request:1`과 `json:{}`
요청 계약으로 맞춘 뒤 정상 접수했다. 관리자 승인·권한·원본 정책은 바꾸지 않았다.
21:32:54UTC 신규5건이 모두 완료됐고 workflow가 정상 반환했다. Q04의3반복과
Q12의2반복 모두 실제 답변·인용 검증을 통과했다. 독립 담당이 새 exact claim5개를
각각 자기 인용 원문과 직접 대조해 정답·주장별 의미 인용5건을 통과 판정했다.
새 날짜 주장의 한글 표기와 ISO 원문 날짜가 같은 유효 날짜인 사례도 실제 확인했다.
이 새 결과에 대한 판정5건을 정상 API로 정확한 result/rule digest에 등록했다.

| 실행 범위 | 완료 | 실패 | 검토 범위 |
| --- | ---: | ---: | --- |
| 수정 전 attempt2 전체75건 | 70 | 5 | 새 실제 답변 전체의 정답70건; 주장 경계는 미기록 |
| 수정 후 attempt3 실패 재시도5건 | 5 | 0 | 새 exact claim5개의 정답과 자기 인용 원문 의미 대조 |

최신 시도75개는 수정 전 성공70과 수정 후5가 섞인 결과다. 수정 코드로 전체75건을
새로 실행한 것으로 보고하지 않는다. 누적155시도에는 과거 실패10/중단70도 그대로
남아 있으며 최신 성공과 누적 이력 수치를 구분한다. 후보는 pending/defaultfalse를
유지했고 별도의 활성화·승격은 수행하지 않았다.

실제 Chrome 검토 탭에서 새 주장 텍스트가 원래 문구 그대로 표시되고 PDF2쪽의
2근거가 하나의 원문 링크로 묶이는 것을 확인했다. 그 링크 URL로 허용된 버전1의
PDF2쪽이 로딩·표시되는 것도 확인했다. 중간 자동화 연결 실패는 기존 열린 탭의
연결을 복구해 이어갔으며 API 또는 인용 오류로 분류하지 않았다.

종료 후 독립 보존 대조에서도 이전150시도의 본문 없는 digest/bytes 검증·상태·
원인·실행 단계, 이전 판정, 별칭·기본 구성·미완료 취소 실행이 모두 그대로였다.

후보 승격 게이트는 유지하며 후보를 임의 활성화하지 않는다. 별칭 종료 증거,
과거 미종료 대화 복구와 실제 첨부·모바일·Git 인계는 다른 남은 기능 작업이다.
이번 변경으로 RAG가 품질 개선만 남았다고 보고하지 않는다.

## 기록과 보존

ISSUE-00023은 본래 관리자 API로 DB에 등록했다. ISSUE-00023과 주장 기록 문제
ISSUE-00021은 명시한 코드·새 실제 결과·화면 검증 범위로 verified를 갱신하며,
과거 실패 초안/주장 경계 미기록과 전체 수정 런타임75건 미실행을 remaining에 남긴다.
이전 보고서의 DB 문서 버전과 연결은 변경하지 않는다. 이 보고서를 별도 새 DB
문서 v1으로 연결하고 정확한 본문·SHA·버전·문제 연결을 독립 대조한다.
새 환경·DB·계정·worktree는 만들지 않았고 commit/push는 수행하지 않았다.
