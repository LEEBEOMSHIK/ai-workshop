# 저장된 표 근거의 선택·입력량 비교 — 2026-10-16

## 결론

이 표본에서는 구조 opt-in이 기존 경로보다 선택을 개선했다는 근거가 없다. 원본 청크는 표 뒤의 두 칸짜리 footer 때문에 `ambiguous_structure`로 판정된다. 높은 모의 의미 점수에서 33개가 선택되는 것은 **일반 점수 경로의 결과**이며 구조 선택 성공이 아니다. 기존 32-unit 예산에서도 그대로 대체할 수 없다. 제품 코드·테스트·활성 설정은 수정하지 않았다.

## 자료와 방법

- `backend/tests/fixtures/rag/stored_payment_table.json`: 실제 PDF에서 파싱해 저장한 **공개 합성 평가 문서의 페이지2 단일 청크**, 33근거·원문 합계712글자. 원본 PDF 전체나 실제 업체 운영 자료를 새로 읽어 검증한 것은 아니다. fixture의 고정 canonical SHA 검사도 실행했다.
- `.local-data/project-agent-work/rag-v3-two-calls-20261016/case-1-input.json`, `case-2-input.json`: 당시 저장된 생성 입력. 각각 28근거를 포함하며 같은 근거 집합이다. 저장 SHA와 prompt SHA를 확인하고 현재 v3 직렬화로 바이트 그대로 재현했다. 과거 모델 응답을 재실행하지 않았다.
- 비교는 동일 입력에 대해 질문3개(저장 지급 질문, 저장된 근거 없는 수익률 질문, 지급 질문의 조사 제거·공백 변형) × 모의 의미 점수2개(0.87/0.95) × 단위 예산2개(32/33) × 전략2개로 **24조합**을 직접 실행했다. 저장 문구·좌표·ID·footer를 삭제하거나 고치지 않았다.
- `select_context`의 기존 `payment-v1`과 `structure-v1`, 의미 기준0.9·키워드 기준0.5·그룹8·원문 문자12,000·빈 extractive anchors로 비교했다. 임베딩은 고정 벡터 mock이다. **실제 검색/임베딩 점수 재현이나 운영 설정 변경이 아니다.**
- 선택된 원문으로 `_grounding_evidence → _generation_user_content`를 실행하고 v3/v4 각각 `restore == evidence_payload`를 확인했다. 비교하는 각 쌍은 같은 질문·같은 프롬프트이며 생성 요청의 예산도 선택 예산과 일치시켰다. 모델/HTTP 요청은 없었다.

## 동일 저장 지급 질문의 선택 결과

질문: `AM-SYN-101을 현금화하면 돈은 며칠 뒤 받을 수 있어?`. 키워드 점수는0.4였다.

| 모의 의미 점수 | 단위 예산 | 기존 경로 | 구조 opt-in |
|---|---:|---|---|
| 0.87 | 32 | 28개, structured_table_selected | 0개, below_threshold |
| 0.87 | 33 | 28개, structured_table_selected | 0개, below_threshold |
| 0.95 | 32 | 28개, structured_table_selected | 0개, budget_exceeded |
| 0.95 | 33 | 28개, structured_table_selected | 33개, **일반 selected** |

구조 진단은 모두 `ambiguous_structure`다. 실제 multi-cell band 인덱스가 `[6,7,8,9,10,21]`이며, 마지막 band는 footer의 ordinal31/32다. `structural_context.py::inspect_grid_candidate`의 연속된 격자 검사에서 거절된다. 공백 변형 질문도 이 구조 판단을 바꾸지 않는다. footer를 억지로 제거하거나 새 예외를 추가하지 않았다.

근거 없는 수익률 질문은 낮은 점수에서 양쪽 모두0, 높은 점수·예산32에서 양쪽 모두 예산 초과, 높은 점수·예산33에서 양쪽 모두33개를 일반 경로로 선택했다. **청크 선택은 답할 규칙의 존재·답변 가능성 판정이 아니다.**

## 보존·누락·다른 열

기존 선택28개는659글자이고, 전체33개는712글자다. 제외 ordinal `8,11,14,17,20`의53글자는 정확히 질문 대상이 아닌 **AM-SYN-202 표 열**이다: 상품 헤더, 영업일14:00까지, 다음 영업일 접수, T+3 기준가격, T+7 지급일. 제목·행 이름·AM-SYN-101 값·주변 조건/예시/부정문/주석/footer는 기존28개에도 모두 남는다.

33개를 선택하면 해당 열5개가 추가되며 누락은0이다. 무관 정보가 실제 답변에 혼입되는지는 확인하지 않았다. 0개 선택은 전부 미전달된 결과이며 부분적인 근거 축약으로 표현하지 않는다.

선택된 항목은 모두 원래 Evidence 객체다. 문구·인용 ID·순서·document/asset/projection/chunk/element·문자 위치·bbox가 저장 원문과 일치했다. 저장된28개를 **원래33개 청크에 대조하여** 검사기에 넘기면 `incomplete_source`이며, 선택 후 입력만으로 전체 표 보존을 입증할 수 없다. 새 source로28개만 재포장하는 것을 주 비교 근거로 쓰지 않았다.

## 적용 전 필요한 근거

현재 표본으로 기본값 승격을 권하지 않는다. 다음 판단에는 서로 다른 실제 보존 레이아웃에서 표/본문/footer 경계의 정확성, 32-unit 예산에서 조건을 잃지 않는지, 질문 대상 외 열의 증가가 필요한 참조 보존인지 잡음인지에 대한 사례 검토가 필요하다. 업체명·지급일 용어 예외를 더하는 방식이나 조건 없는 예산 확대는 이 비교의 결론이 아니다.

전체 PDF·다른 업체 문서에 대한 일반화, 실모델 답변/조건 해석/인용 의미 정확성, 토큰·지연·비용, 실검색 권한 및 tenant 격리는 미검증이다. 이번 기록은 기존 [구조 opt-in 구현](2026-10-16-rag-structural-context.md)의 오프라인 적용 범위를 좁히며 기존 RAG P0 우선순위나 운영 완료 상태를 바꾸지 않는다.
