# 개인 Codex RAG 연결 진행 기록

- 상태: 구현·통합 검증 중 — 사용자 전체 테스트 준비 미완료
- 계획: [애플리케이션 연결](../superpowers/plans/2026-09-09-codex-rag-activation.md)
- 선행 실제 진단: [CLI 호환성 확인](2026-09-09-codex-live-feasibility.md)

## 해결한 문제

### 실행기 등록과 검색 준비 상태의 구분

실행 파일이 존재하고 설정이 유효하다는 사실만으로 답변 기능이 검증된 것은 아니다.
관리자가 저장한 정확한 구성 버전에 대해 명시적으로 합성 연결 검사를 수행하고,
그 결과와 현재 실행 파일·모델·프롬프트·정책의 결합을 확인하도록 구현했다.
같은 생성 프로파일을 사용하는 다른 구성에 검사 결과를 빌려 주지 않는다.
목록 조회와 상태 확인은 모델을 호출하지 않는다.

### 실패한 실행의 진단 정보 누락

초기 구현은 최종 응답 형식이나 모델 식별 검증에 실패하면 유효한 사용량 정보까지
감사 기록에서 놓쳤다. 사용량과 관측 모델 메타데이터를 각각 검증해 보존하도록
수정했다. 실패한 답변은 계속 폐기하며, 원시 응답·추론·문서 본문은 저장하지 않는다.
필수 감사 저장소가 없는 경우에도 실행을 허용하지 않는다.

### 비동기 어댑터의 반환형 불일치

SQL 오류를 안전한 코드로 바꾸는 장식자가 실제로는 비동기 함수를 반환하면서
더 넓은 Awaitable 타입을 선언해 통합 타입 검사에서 계약 충돌이 발생했다.
실제 반환형을 정확히 선언했고, 어댑터 전체를 강제 형변환해 검사를 우회하지 않았다.
DB 잠금·승인 소비·실행 종료의 동작은 바꾸지 않았다.

### 요청 모델과 관측 모델의 분리

개인 개발용 Codex에서 실제 모델 식별자가 반환되지 않을 때는 사용자가 승인한
예외에 따라 `미확인`으로 표시한다. 요청한 모델을 실제 관측값으로 복사하지 않는다.
알려진 모델 불일치는 계속 거부하며, 다른 제공자의 검증 기준은 완화하지 않는다.
검색 연결은 실제 생성 단계의 관측값을 응답으로 전달한다. 문맥 재작성만 실행되고
근거 부족으로 생성을 생략했다면 답변의 생성 모델은 미확인으로 유지하며,
문맥 재작성 단계의 관측값은 해당 단계 감사 기록에 따로 남긴다.

### 질문별 권한과 취소 완료의 연결

대화 요청마다 현재 사용자·정확한 구성·지식 공간·명시적 입력 동의를 결합하고,
첫 답변과 후속 질문의 문맥 재작성·답변 생성은 각각 별도 승인을 소비한다.
브라우저 연결이 끊기면 해당 요청을 취소하고 실행기·감사·동시 실행 자리의 정리가
끝날 때까지 기다린다. 오류 추적 번호는 내부 실행 ID와 분리해 기록하며 권한으로 쓰지 않는다.

## 검증된 범위

관리자 API, 정확한 구성별 준비 상태, 동의 고지, 문서 버전 승인, 실행 감사 저장의
백엔드 변경은 독립 리뷰를 통과했다. 동결된 변경에 대한 메인 재검증 결과는 다음과 같다.

- 전체 백엔드 단위·계약: 1,760 통과, 기존 4 skip, 기존 Starlette 경고 1건
- 승인·실행 자리·검사 기록의 격리 PostgreSQL 통합: 63 통과
- mypy: 234개 소스 통과 / Ruff: 변경 32개 파일 통과

이 검사는 실제 격리 DB와 가짜 실행기·응답을 구분한다. 실제 CLI 응답 가능성은
선행 소형 합성 진단에서 확인했지만, 위 결과가 실제 대화 화면 검증을 대신하지 않는다.

검색/도메인 연결도 독립 명세·코드 리뷰를 통과했다. 메인 최종 재검증은 전체 단위·계약
1,808 통과·4 skip, 신규 SQL 통합 12건 통과, mypy 235개와 변경 파일 Ruff 통과다.
구현 담당의 기존 포함 SQL 회귀는 75건 통과했다. SQL 저장·승인·취소는 실제로 검증했고,
검색 후보·임베딩·모델 응답은 이 통합 테스트에서 합성 포트를 사용했다.
API 타입 내보내기와 일치 검사도 통과했다.

관리자·대화 UI는 구현 후 독립 리뷰의 두 항목을 수정하고 재승인을 받았다.
보조 검색의 새 대화 시작 시 진행 중 요청이 남아 늦은 응답이 섞이던 문제는 기존 취소
경로를 재사용해 해결했다. 실행 전 모델 안내도 과거 실행을 단정하지 않는 문구로 바꿨다.
구현 담당의 첫 동결본 전체 프론트 테스트는 421건·83개 파일 통과였고, 수정 후에는
관련 40건과 타입·린트를 검증했다. 메인도 수정 후 영향 테스트 23건과 최종 Next 빌드를
통과했다. 앞선 전체 결과를 수정 이후의 전체 재실행으로 표기하지 않는다.
새 관리자 모델·연결 검사·문서 승인과 질문별 동의 흐름은 합성 응답 테스트이며,
실제 로그인한 브라우저·모델·현재 도메인의 E2E 검증은 아직 수행하지 않았다.
세 단계의 최종 전체 연결 리뷰도 승인됐다. 수정 후 빌드가 자동 추가한 검증용 타입 경로는
원래 개발 경로로 복원했고, 복원 후 TypeScript 검사를 다시 통과했다.

## 로컬 반영

검토된 migration 0026~0029를 기존 로컬 DB에 적용하고 사용자·문서·버전·구성·도메인
개수가 유지됨을 확인했다. 데이터와 색인을 초기화하지 않았다.
Git 제외 설정에는 기존 CLI의 버전·실행 파일 해시와 전용 작업 경로를 등록했고
읽기 전용 실행기 사전 검사를 통과했다. 인증 파일은 읽거나 복사하지 않았다.

아직 모델·외부 전송 정책·문서 승인·도메인 연결을 실제 사용자 데이터에 적용하거나
이 설정을 이용한 모델 호출을 수행하지 않았다. 서버 재시작도 아직 하지 않았다.
별도로 기존 E5 임베딩은 합성 질문 한 건으로 실제 오프라인 실행을 확인했다.
고정 revision에서 16개 토큰·정규화된 768차원 벡터를 반환했다. 다운로드나 문서 읽기,
외부 전송은 없었다. 기존 차원 조회 메서드의 폐기 예정 경고가 있으나 실행은 성공했다.

## 남은 사용자 테스트 게이트

구현된 관리자 설정·명시적 연결 검사·문서 승인·모델 변경을 정상 소유자 로그인으로 검증한다.
이후 승인된 합성 데이터로 실제 답변·인용·하이라이트·후속 질문·근거 부족·취소를
검증하고, 실제 검색 평가를 통과한 구성만 도메인에 연결한다.
그 전에는 사용자에게 전체 RAG 테스트 준비가 끝났다고 안내하지 않는다.

실제 자료 등록에는 추가 보관 확인이 필요하다. 현재 문서·공간의 완전 삭제 UI가 없고,
평가 스냅샷에는 본문이 보존되며 문서 버전 승인을 철회해도 참조 이력이 남는다.
따라서 작은 합성 참조 자료와 평가·승인 이력의 로컬 보관을 사용자에게 명시적으로
확인 중이다. 답변 전 실제 자료 등록은 하지 않고 코드·화면 검증을 계속한다.
후속 사용자 로그인 안내 후 새 작업소 탭과 관리자 모델 화면 접근을 확인했다.
개인 Codex 설정·문서 승인·데이터 정책 UI가 실제로 로드됐다. LLM·실행 배포·생성 프로파일은
아직 미등록이며, 회사 정책은 외부 전송 차단 상태다. 이 확인에서 등록·정책 변경·문서 승인·
모델 호출은 하지 않았다. 자료 보관 동의가 필요한 실사용 단계는 계속 보류한다.
과거 평가 통과 기록만으로 현재 원문이 남아 있거나 검색 가능한 것으로 판단하지 않는다.

## 후속 실제 관리자 등록

사용자가 소형 비개인 합성 문서와 평가·승인 이력의 로컬 보관을 허용했다.
공개 게시·파인튜닝·기존 비공개 문서는 승인 범위에 포함하지 않는다.
관리자 UI에서 GPT 5.5 모델 정의 v1(식별자 `gpt-5.5`), 개인 Codex 배포 v1,
근거 기반 대화 생성 프로파일 v1 등록 성공을 확인했다. 서버 runner는 codex-personal,
CLI 0.153.4이며 신뢰 지침 answer-v3/contextualize-v1/schema2를 선택했다.

최초 등록의 invalid_model 오류는 9월 8일부터 자동 재로딩 없이 실행하던 private API에서
발생했다. 현재 소스에 같은 입력이 유효함을 확인하고 해당 API만 재시작한 뒤 같은 등록이
성공했다. PowerShell Stop-Process 오류 후 정확히 재확인한 PID를 taskkill로 종료했다.
실패한 첫 새 프로세스는 포트를 점유하지 않았고, 공개 API·프론트·인프라는 변경하지 않았다.

회사 정책은 여전히 외부 전송 차단이다. computer-use 지침의 보안·개인정보 설정 변경
제한에 따라 사용자에게 직접 설정하도록 인계한다. 기존 두 공간은 명시적 차단을 유지하고
회사 허용 목록에는 개발용 Codex CLI만 추가하도록 안내한다. 정책을 다른 경로로 우회하지
않는다. 문서 업로드·승인, 연결 검사, 실제 CLI 호출, 평가와 도메인 활성화는 아직 남아 있다.
