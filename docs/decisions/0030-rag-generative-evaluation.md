# ADR-0030: 실제 대화와 생성형 평가의 실행 경로 공유

- 상태: 구현·자동 검증 완료, 실제 생성 품질 검증 대기
- 날짜: 2026-09-28
- 관련: [승인 설계](../superpowers/specs/2026-09-27-rag-execution-monitoring-and-evaluation-design.md)

## 결정

실제 대화와 생성형 평가는 하나의 `RagExecutionPipeline`을 사용한다.
대화 서비스는 현재 구성·범위를 해석하고, 평가 어댑터는 불변 구성·물리 색인·원문 스냅샷을
해석한다. 검색·문맥 예산·요청 내 임베딩 재사용·생성·인용 검증 알고리즘은 복제하지 않는다.
평가 스냅샷은 현재 권한이나 외부 전송 승인을 대신하지 않는다. 생성 전에 현재 승인을 검사한다.

기존 추출형 평가 v1의 의미와 승격 증거는 유지한다. 생성형 평가는 별도 종류·지표 버전으로
실행·인용·정답·거절을 구분한다. 인용 ID의 유효성만으로 정답 통과를 부여하지 않는다.
후속 시도는 이전 실패를 보존하며 실행 ID로 모니터링에 연결한다.
새 생성형 승격은 불변 원시 관측과 버전된 정답 규칙·검토 증거를 PostgreSQL에서 확인해야 한다.

## 구현 경계

먼저 공통 코어를 추출하고 기존 대화 동작의 회귀와 결정적 입력의 parity를 검증한다.
이어 평가 제출·시도·정답 판정·DB 승격 게이트·비교 화면을 연결한다.
후속 단계 구현과 실제 합성 PDF 검증 전에는 생성형 평가 또는 품질 개선 완료를 주장하지 않는다.

동결 입력의 현재 권한과 READY 상태는 정확한 원문·projection·build를 대상으로 검증하며
현재 활성 버전과 분리한다. 새 활성 버전으로 동결 검색을 대체하지 않는다.
정답 규칙 필드는 누락/NULL을 허용하지 않고 DB가 claim별 인용 구조까지 확인한다.
worker 종료가 불명확한 시도는 중단으로 남기고 명시적 재시도만 새 실행을 만든다.
