# 학습 기록 페이지당 표시 개수

## 요구와 범위

긴 카드 목록에서 사용자가 스크롤 양을 조절하도록 페이지당 표시 선택을 추가한다. 공통 `SelectField`를 재사용하며 기본 5개, 선택 5·10·20개다. 옵션은 학습 기능 registry에서 관리한다.

프론트엔드 동작 변경으로 분류했다. 요구 정리·프론트엔드·테스트 설계·독립 코드 검토·본래 환경 검증을 수행한다. API의 기존 `limit` 계약을 사용하므로 서버·DB·모델 변경은 없다.

## 동작

- 선택 개수는 목록 요청의 `limit`으로 전달한다.
- 개수 변경 시 커서와 이전 페이지 이력을 초기화한다.
- 주제·종류·보관·정렬은 유지하고, 이 조건을 변경하거나 다음/이전 페이지로 이동해도 선택 개수는 유지한다.
- 새로 목록에 진입하면 기본 5개다. 브라우저 영구 저장은 추가하지 않는다.
- 늦게 도착한 이전 요청이 최신 선택 결과를 덮지 않아야 한다.

## 검증

- 신규 3건 실패를 먼저 확인한 뒤 목록·순서·계승·API 관련 30건/4파일 통과. TypeScript 및 대상 ESLint 통과.
- 독립 코드 검토 차단 0건, 목록 테스트 9건 재실행 통과.
- 본래 Chrome에서 기본 5개와 10·20개 선택, 주제·정렬 조건 유지, 현재 네 카드와 최신순을 확인했다. 라이트/다크 및 375/320px 가로 넘침 없음. 검증 후 기존 다크와 기본 크기, 모든 주제·최신순·5개를 복원했다.
- 실제 기록은 4건이므로 다음/이전 페이지와 늦은 응답은 합성 API 회귀 테스트로 검증했다. 제품 데이터 생성은 하지 않았다.
- ISSUE-00051에 이력을 저장하고 재조회했다. 프로덕션 빌드는 미실행이다.

## 변경 파일과 기존 제약

`LearningListPage.tsx`, `registry.ts`, `LearningListPage.test.tsx`와 디자인 시스템의 사용 안내, UI 가이드 및 작업 기록을 변경했다. API·DB·학습 모델 변경은 없다.

기존 새 기록 작성기의 참조 후보는 현재 목록 페이지 결과를 사용한다. 별도 검색 방식으로 분리하는 개선은 이번 범위에 포함하지 않았다.
