# 로그인 전용 레이아웃

## 승인 범위

로그인 화면의 왼쪽 공개 메뉴와 공통 상단 경로 표시를 제거한다. 상단에는 기존 브랜드 로고/홈 링크와 공통 화면 모드 선택만 두고, 나머지 공간 중앙에 로그인 폼을 배치한다. 작은 높이에서는 잘리지 않고 문서 스크롤로 사용할 수 있어야 한다.

기존 로그인·복귀 경로·초기 설정 이동·실패 안내·제출 중 상태·자동완성을 유지한다. 로그인 경로의 서버 오류 상태도 동일 레이아웃을 사용한다. 공개 페이지와 로그인 뒤 작업소 메뉴는 변경하지 않는다. 로그인 없이 공개 콘텐츠로 이동하는 링크는 폼 아래 보조 링크로 유지한다.

## 책임과 검증

메인이 요구/문서/통합을 담당하고 UI 구현과 독립 화면 검증을 분리한다. 인증 API·권한·DB·설정 계약은 변경하지 않으므로 백엔드 및 모델 역할은 제외한다. 기존 사용자 로그아웃·실제 자격 증명 입력·저장 자료 변경 없이 검증한다.

로그인 성공/실패/서버 오류 레이아웃, 안전한 복귀 경로, 공개 메뉴 보존, 두 테마와 좁고 낮은 화면, 키보드 모드 선택을 확인한다.

## 구현과 검증 결과

- `LoginLayout`을 추가해 로그인 폼·로그인 후 전환·서버 오류에 같은 헤더와 중앙 배치를 적용했다. 기존 로고 자산, ThemeChoice, Button 및 디자인 토큰을 재사용했다.
- 로그인 관련 테스트 29건과 공개/공통 탐색 회귀 15건 통과. TypeScript, 변경 TypeScript/TSX ESLint 및 diff 공백 검사 통과.
- 기존 브라우저의 만료된 세션에서 실제 로그인 화면을 확인했다. 강제 로그아웃이나 자격 증명 입력·로그인 제출은 하지 않았다.
- 1440×797 라이트/다크에서 사이드바 없음과 448px 중앙 폼, 320×800 두 테마에서 가로 넘침 없음을 확인했다. 320×400에서 자연 세로 스크롤과 비밀번호에서 로그인 버튼으로 Tab 이동을 확인했다.
- Space 키로 테마 변경과 초점 표시를 확인했다. 실제 인증 성공/실패 및 서버 오류는 단위·라우트 테스트 범위이며 실서버 로그인 제출로 재검증하지 않았다.
- 공개 `/labs`의 기존 사이드바와 경로 헤더가 유지됨을 실제 화면에서 확인하고 로그인 URL·다크 모드·기본 뷰포트로 복원했다. 독립 소스 검토에서 차단 결함은 발견되지 않았다.

## 후속: 로그인 모드 선택 제거 및 메뉴 이동

사용자 후속 요청에 따라 로그인 헤더의 ThemeChoice를 제거했다. 저장된 테마와 다른 화면의 모드 설정은 유지한다. 공통 메뉴·영역 이동·로고 링크에는 `target="_self"`를 명시했다. 일반 클릭은 현재 탭에서 이동하며 브라우저의 Ctrl/Cmd 클릭 같은 명시적 새 탭 동작은 가로채지 않는다.

수정 전 기존 Chrome에서 링크 target과 base 태그는 없었고 일반 클릭은 같은 탭에서 이동했다. 보고된 새 탭 현상은 재현하지 못해 원인을 확정하지 않았다. 이번 조치는 현재 탭 이동 계약을 명시하고 회귀 검증하는 변경이다. 로그인/라우트/메뉴 테스트 3파일 42건 통과.

TypeScript·변경 파일 ESLint 통과. 독립 실제 Chrome에서 홈→AI Labs 일반 클릭 전후 탭 ID와 탭 수1개 유지, 로그인 화면 모드/라디오0개, 데스크톱 및320×800 가로넘침 없음을 확인했다. 원래 로그인 URL·다크·기본 뷰포트로 복원했다.
