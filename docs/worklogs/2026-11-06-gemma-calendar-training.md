# Gemma 4차 영업일 계산 학습

## 실행 전 계획

사용자는 다음 학습 실행과 연구소 기록 저장을 요청했다. 3차 후보의 미사용 날짜 계산 오류를 대상으로, 공개된 가상 달력에서 접수일 제외·첫째·둘째 영업일의 관계를 답변에 명시하는 예제를 학습한다. 답변에 필요한 날짜 계산 근거만 포함하며 모델의 비공개 내부 추론은 저장하지 않는다.

[자료](../../sample-data/public/rag/evaluation/gemma-calendar-study-20261106.jsonl)는 학습 3, 학습 문서의 미사용 질문 1, 새 문서 질문 3, 회귀 2문항이다. 같은 새 문서 질문 2개는 상호 연관돼 있으므로 독립 문서 2종의 3질문으로 해석한다. 이 가상 달력은 실제 공휴일 달력과 구분한다. SHA-256은 403c6c2b1773989045dcf8d472fc1c4ecbf0dc70ec928b00f6cedd61fc428be4다.

부모는 3차 후보(1d7b525baad10a06d7686c4da417ed3b2809ada7fb2e9bc32e8a054b3d6a0057)다. 모델 revision은 4adf15748de9e1a0097b6274cee9c15836c41c37이며 기존 학습 실행기의 검증된 마지막 층 계산 재사용 경로를 사용한다. 마지막 query projection의 FP32 rank 4 어댑터 22,528개 파라미터, AdamW 0.005, weight decay 0, gradient clip 1, batch 1, seed 7, CPU 6스레드로 설정한다. train-01/02/03 순서를 두 번 반복해 6회 갱신한다.

모든 생성은 번호를 붙인 동일 근거·인용 지시·greedy·96토큰 한도다. 전 9회·후 9회로 고정한다. 학습·평가 출력 확인 후 예제·횟수·후보를 재선택하지 않는다. 출력 잘림은 따로 표시한다. 날짜·완전성 및 원문 인용 지지를 독립 검토하고, 미사용 질문과 학습 질문의 개선을 분리한다.

이번 순서는 이전 3차 후보에서 시작하는 추가 학습이며 옵티마이저 상태는 새로 만든다. 기록에는 부모·후보 해시, 실제 학습 순서·손실·기울기, 전후 답변, 입력 동일성, 걸린 시간 및 관측 가능한 메모리를 남긴다.

## 독립 평가 기준

날짜·기간의 의미 정확성, 질문이 요구한 설명의 완전성, 인용 번호의 유효성, 인용 원문의 주장 지지를 각각 판정한다. 정답 문구와 달라도 의미가 같으면 인정한다. 주답의 날짜가 맞아도 덧붙인 날짜 계산이 틀리면 의미 정답으로 세지 않는다. 생성 한도에 따른 잘림은 별도 표시한다.

train-01은 11월 17일과 접수일 제외 후 두 번째 영업일이라는 기준이면 충족한다. train-02는 11월 19일과 17→19일 순서, train-03은 12월 15일과 10→11→15일 계산이 필요하다. same-01은 11월 20일과 접수일을 제외한 계산 설명, new-01은 1월 11일, new-02는 1월 8일 지급 부정과 11일 정정, new-03은 접수 2월 3일과 지급 8일을 모두 요구한다. reg-01은 접수일 기준 3영업일, reg-02는 긴급 1영업일이다.

구체 날짜 계산의 완전한 인용에는 규칙과 가상 달력이 함께 필요하다. new-03은 마감 시각 규칙도 필요하다. 유효한 번호가 있다는 사실만으로 오답을 지지된 주장으로 처리하지 않는다. 이 기준은 갱신 전 독립 검토로 확정했으며 학습·같은 문서·새 문서·회귀를 분리해 집계한다.

본래 사이트 [4차 학습 기록](http://127.0.0.1:5173/workshop/learning/b17ed4ed-a445-4fb7-894f-1bc41bc5c635)에 진행 상태와 부모 기록 참조를 저장했다. 실행 식별자는 `run-20261106-020518-583ecc`다.

## 결론과 후속 조건

**이번 4차 후보의 답변 품질 개선은 확인되지 않았다.** 정답 수는 그대로이고 일부 완결성·인용이 악화됐다. 후보는 실험 산출물로 보존하며 기존 서비스 설정은 유지한다.

다음 실험은 학습 정답을 짧고 완결된 형식으로 정리하고, 접수일 제외·휴일 건너뛰기·마감 시각 적용의 오류를 별도 유형으로 나눠 데이터와 검증 세트를 설계하는 것이 우선이다. 출력 한도의 영향을 분리하려면 별도 고정 조건의 긴 출력 평가가 필요하지만, 현재 출력에 이미 드러난 잘못된 날짜 계산까지 해결됐다고 볼 수 없다. 추가 생성·추가 학습은 이번 실행에 포함하지 않았다.

## 기록 마감

독립 검토에서 같은 품질 집계와 후보 비승격 판단을 확인했다. 실제 dataset·parent·candidate·config·runner의 SHA-256, 결과 내부 자료/설정과 파일, 고정 갱신 순서 및 9쌍 입력 해시가 일치했다. 감사는 모델을 재실행하지 않고 결과와 실제 파일을 대조했으며, 로짓 동등성과 변경 텐서 범위는 실행기의 검증 결과로 구분했다. 독립 감사 원문은 실행 폴더의 `independent-review.md`에 보존한다.

본래 사이트 4차 기록에 수행 완료·개선 관찰되지 않음, 3차 출발점, 실행일, 모든 입력 근거와 학습 정답, 실제 답변 9쌍, 개별 판정, 자원·해시와 후속 조건을 저장했다. 새로고침 후 완료 상태·품질 요약이 유지되는 것을 확인했다. 제품 코드·서비스 설정 변경이나 추가 모델 생성은 수행하지 않았다.

마감 검사는 완료 상태·갱신 6회·전후 9쌍·파일 해시 5개 일치, 문서 상대 링크, WORKBOARD 최근 완료 5개 및 `git diff --check`를 통과했다. 전 생성 합계 717.91초·후 생성 합계 1,003.15초는 원시 관측으로 보존하며 품질 성과에 합산하지 않는다.

## 같은 날 후속: 3차와 동일한 상세 표시

사용자가 4차 학습 데이터 상세가 3차보다 불명확하다고 보고했다(ISSUE-00051 후속). 3차는 `readTrainingPipeline`과 `readAnswerComparison`이 인식하는 명시적 단계·비교 형식이고, 4차는 일반 본문 형식으로 저장해 같은 카드 표현이 활성화되지 않았다. 제품 코드·디자인 컴포넌트를 바꾸지 않고 저장 형식을 기존 계약에 맞췄다.

대표는 날짜 오류가 남은 학습 문항 train-02다. 입력 규정과 질문, 정확한 학습 정답(17일 첫째→19일 둘째), 6회 LoRA 갱신을 입력·정답·학습 카드로 표시한다. 전후 실제 답변은 동일한 17일 오답으로, 두 카드 모두 의미 평가 오답이다. 학습 전이 3차 어댑터라는 설명과 전체 품질 미개선 결론을 유지한다. 단일 대표가 전체 평가를 대신하지 않는다.

기존 본문 1,773자와 관찰 2,767자(실제 전후 답변 9쌍)는 새 관찰의 상세 영역에 문자 그대로 포함했다. 저장 후 편집 조회로 두 원문 포함·새 본문/관찰 일치·기존 결론 불변을 확인했다. 상세 관찰을 펼쳐 미사용·회귀 사례와 전체 입력 자료가 실제로 노출되는 것도 확인했다. 원문에 의미 평가/비교 조건 제어행이 없어 기존 파서가 원문을 추가 해석하지 않음을 확인했다. 독립 검토는 실제 결과 파일과 질문·정답·전후 답변·부모 계승을 대조했다.

본래 Chrome에서 세 단계 카드·전후 오답 카드와 원문 펼침을 검증했고 ISSUE-00051 진행 이력을 저장했다. 제품 소스 변경이 없어 새 코드 테스트·타입·린트 실행을 주장하지 않는다. 재학습·모델 호출은 없다. 이후 기록 작성 시 같은 명시적 단계/비교 형식을 사용하고 실제 카드 활성화와 원문 보존을 확인한다.
