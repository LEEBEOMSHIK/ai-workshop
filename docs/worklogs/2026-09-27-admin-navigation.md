# 관리자 메뉴 구조와 모바일 탐색

## 승인 범위

관리자 메뉴가 늘어도 탐색할 수 있도록 7개 항목을 RAG 관리 / 공개 콘텐츠 / 시스템 관리로 묶는다.
사용자가 선택한 표시명은 시스템 관리다. 문제 카테고리의 공통 플랫폼 명칭과 문제 번호는 이번에 변경하지 않는다.
PC는 왼쪽 그룹형 사이드바, 모바일은 메뉴 버튼·현재 화면명과 필요할 때 여는 패널을 사용한다.
현재 메뉴·그룹과 키보드 탐색을 제공하며 기존 경로와 서버 마스터 권한 검사를 유지한다.

## 분담·성공 기준

- 중간 위험의 기존 UI 변경으로 분류했다. 프론트 구현, 독립 검토·검증, 메인 통합·본문 반응형 점검을 분리한다.
- 메뉴 레지스트리에 그룹을 정의하고 새 기능은 해당 그룹에 추가한다. 존재하지 않는 기술이나 기능은 만들지 않는다.
- 모바일에서 닫힌 메뉴는 본문과 탭 순서를 차지하지 않는다. 열면 초점이 패널 안에 머물고 Escape/닫기로 돌아온다.
- 메뉴 이동과 화면 크기 변경 때 패널을 닫고 스크롤·포커스를 복구한다. 현재 그룹은 경로 이동에 맞춰 펼친다.
- 사이드바 때문에 줄어든 본문 폭에서도 필터·편집·표가 페이지 전체를 가로로 밀지 않도록 확인한다.
- DB·계정·RAG 모델·실행 설정을 바꾸거나 별도 환경을 만들지 않는다.

## 확인 기록

기존 본래 마스터 브라우저의 390px 모바일 폭에서 상단 메뉴가 약284px를 차지했다.
새 메뉴는 닫힌 상태 약56px다. 본래 계정으로 관리자 7개 화면을 390px와 1100px에서 열어
페이지 전체의 가로 넘침이 없음을 확인했다. 모바일 실제 기기 검증은 포함하지 않는다.

- 메뉴를 3그룹의 접이식 레지스트리로 구현하고 기존 7개 URL을 유지했다.
- 기존 viewport 기준만으로는 사이드바가 차지하는 폭을 반영하지 못하므로 본문에 `admin-content` 컨테이너를 두고 필요한 레이아웃에 컨테이너 쿼리를 적용했다.
- 런타임의 긴 이미지명 제목이 모바일에서 페이지를 515px까지 밀어내던 문제를 줄바꿈으로 수정했다.
- 실제 Chrome에서 열기·Tab/Shift+Tab 순환·Escape·초점 복귀·메뉴 이동 후 닫힘·PC 전환 시 닫힘과 스크롤 복원을 확인했다.
- native dialog만으로 브라우저 영역으로 초점이 빠지는 경우를 확인해, 숨김·비활성·접힌 그룹 내부를 제외한 명시적 첫/마지막 초점 순환을 보완했다.
- 모바일 초기 서버 렌더링에서도 PC 사이드바·계정 영역을 CSS로 숨겨 화면 전환 흔들림을 줄였다.
- 관리자 권한 검사·일반 작업소 메뉴·계정 및 RAG 데이터는 변경하지 않았다. 이번 개선 기록과 관련 문서는 기존 문제 이력 DB에 보존한다.

## 자동 검증

- 내비게이션 45건(독립 검토 7건 포함), 기존 관리자 레이아웃·화면 74건의 고유 테스트를 확인했다.
- 화면 회귀 첫 실행은 73건 통과, 권한 화면 1건이 상세 로딩을 기다리는 기본 1초 제한에서 실패했다.
  구현 변경 없이 해당 파일을 단독 재실행해 17건 모두 통과했다. 최초 실패를 숨기거나 대기 시간을 임의로 늘리지 않았다.
- TypeScript 전체 타입 검사와 관련 ESLint 통과. 별도 서버·계정·DB나 영속 테스트 자료는 만들지 않았다.
- 이 결과는 현재 관리자 화면과 메뉴 탐색 범위이며 RAG 답변 품질·실제 모바일 기기 검증을 뜻하지 않는다.
