# 서명된 ARM 후보 비교 실행 연결

요구: 기존 Gemma·질문·28근거·schema2·인용 검증을 유지하고 입력 처리 개선 후보를 실제 비교할 수 있게 연결한다. [기존 준비와 제한](../../worklogs/2026-10-28-gemma-signed-runtime-candidate.md), 로컬 상세 계약 `.local-data/project-agent-work/gemma-signed-runtime-20261028/compatibility-plan.md`를 따른다.

## 범위와 성공 기준

- 기존 서비스·설치·모델·프로파일·DB를 수정하지 않는 비기본 비교 도구를 `.local-data/project-agent-work/gemma-signed-comparison-20261028/`에 구현한다. 현재 작업 자료와 기존 미커밋 변경을 이어 쓰며 별도 DB/계정은 만들지 않는다.
- 실제 생성 전 현재 ACL·고정 요청/스냅샷·모델/실행기 식별자·원래 환경·이전 종료 ledger를 확인한다. 모델은 동일 main GGUF이며 runtime/compiler/초안 생성 설정 차이를 기록하고 CPU 명령어 하나의 효과로 단정하지 않는다.
- 비교 도구는 기본 실행 불가다. 새 명시 승인 뒤에만 별도 승인 파일과 exclusive 실행 ledger를 열며 이전4/4 예산을 재사용하지 않는다. 예정 범위는 후보2회→소유 후보 종료→기준2회, 합계 최대4회·생성 재시도0이다.
- 최초 Ollama 적재 모델이 없고 프로젝트 실행이 유휴일 때만 진행한다. 기존 사용자 모델을 unload하거나 기존 서버를 재시작하지 않는다. 후보를 먼저 종료한 뒤 기준을 실행해 두 모델을 동시에 적재하지 않는다.
- 입력·응답·내부 추론·원문 로그는 저장하지 않는다. 허용된 시간·토큰 수·해시·품질 판정만 기록한다. 후보 로그는 비활성화하고 소유 프로세스와 임시 인증 파일을 한정해 회수한다.
- 첫 실행과 반복 실행을 구분한다. 요청 실패/불확실 전송도 호출 수를 소비하고 입력 변동·품질 불일치·truncation·정책 차단이 생기면 남은 호출을 중단한다. 기존 정답0/2는 별도 미해결로 유지한다.

## 수행 순서

1. 독립 모듈로 서명 bundle 검증·loopback 전용 후보 서버 수명 관리와 순수 native 결과/품질 검증을 구현한다. Windows Job Object로 이 작업의 자식만 회수하며 warmup 추론은 끈다.
2. 기존 순수 입력 mapper 및 현재 ACL reference loader를 coordinator에 연결한다. 새 승인/예산 ledger, 제한된 HTTP, 후보 종료 후 기준 전송 순서를 검증한다.
3. 외부 모델/네트워크 없는 실패 경로·회수·응답 파서·예산 테스트와 타입/린트, 별도 코드/프라이버시 검토를 수행한다.
4. 본래 설정과 현재 자료를 사용하는 읽기 전용 사전 검사를 수행한다. 실제 모델 호출·새 서버 시작 없이 준비 결과를 저장한다.
5. 위 코드와 호출 범위가 검토 가능한 상태가 되면 새 최대4회 실측 범위를 사용자에게 확인한다. 승인 전에는 후보 모델 로드나 생성 호출을 하지 않는다. 이후 실측·입력/답변/인용 비교·기존 환경 보존·WORKBOARD/문제 이력을 기록한다.

## 역할과 검증 경계

AI 엔지니어는 입력/출력 연결과 coordinator, 인프라 담당은 후보 수명, 별도 코드 리뷰·프라이버시 담당은 독립 검증을 맡는다. 화면·DB schema·일반 기본값을 바꾸지 않아 해당 구현 역할은 제외한다. root만 통합·WORKBOARD 마감을 한다. 진단 준비의 통과를 실제 모델 호환·속도 개선으로 보고하지 않는다.
