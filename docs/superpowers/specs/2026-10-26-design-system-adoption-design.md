# 디자인 시스템 체계화와 화면 적용

- 요청: 기존 시스템의 미적용 화면부터 확인하고 사용성과 현대적인 시각 품질을 개선한다.
- 기준: 사용자 선택인 “다크·청록 유지, 차분하고 세련되게 정돈”과 기존 작업 흐름을 유지한다.
- 경계: 프론트엔드 표현과 공용 UI. 검색·생성·백그라운드 실행·API·권한·저장 데이터는 유지한다.

## 조사와 결정

공통 토큰은 있으나 global styles와 기능 CSS가 표면·컨트롤·상태색을 각각 정의한다.
전역 h1의 Georgia·과도한 크기가 업무 제목에도 적용되고, 파일함·문제 이력에는44px보다
작은 조작 영역이 있다. 평가 작성의 radio도 텍스트 입력 선택자에 포함된다.

단순 색 치환은 조작 규격과 재발을 해결하지 못하고, 새 UI 프레임워크 도입은 현재
기능·의존성을 크게 바꾼다. 기존 CSS Modules/React 위에서 의미별 토큰과 실제 반복
컴포넌트를 정리하고 화면별 적용 현황과 브라우저 수용 검사를 함께 유지한다.
이 방식은 기존 시스템을 체계화해 적용하라는 요청과 프로젝트 정본을 따른 구현 판단이다.

## 시각 및 접근성 계약

- 기본 배경/표면/상위 표면/입력 표면과 hover·선택 표면을 의미별로 정의한다.
- 본문/보조/강조/강조 위 글자와 success/warning/danger/info의 글자·표면·경계를 정의한다.
- 업무 제목은 공통 산세리프, 최대2.25rem·줄높이1.25로 정돈한다. 공개 소개 hero와 문서 읽기는 예외다.
- body1rem, control.9375rem, caption.8125rem 기준. 핵심 상태를 작은/희미한 글씨에만 의존하지 않는다.
- 버튼·텍스트 입력·선택·직접 조작 summary는 최소44px, checkbox/radio 기호는16px로 분리한다.
- primary/secondary/quiet/danger 버튼은 동일한 모양·focus·disabled 계약을 갖는다.
- 포커스2px와3px offset, 키보드 탐색, 긴 한글·ID 줄바꿈,320/375/1280px를 확인한다.
- 장식은 절제된 표면 차이·1px 경계·적은 그림자 위주다. 원격 폰트·아이콘 패키지와 새 애니메이션은 추가하지 않는다.

## 코드 경계와 적용 범위

`shared/ui/tokens.css`가 값의 정본이다. 기존 토큰 이름은 호환한다. 공용 버튼은
native button 속성/disabled/aria/ref를 전달하고 기본 type=button으로 예기치 않은 폼
제출을 막는다. label/설명/오류는 기존 연결을 보존하고, 단순 스타일만 필요한 네이티브
폼은 토큰과 공통 규격을 사용한다. 모든 입력을 감싸는 거대한 추상화는 만들지 않는다.

업무 표면: 탐색 셸, 작업공간·파일함, 검색·원문, 일반 대화, RAG 도메인·모델·구성·평가,
실행 목록/상세, 문제 이력·권한·런타임, 학습 기록·흐름도·Publishing 관리.
로그인은 공통 값에 연결한다. 공개 Publishing은 읽기용 크기/행간을 유지하며 공통
색·입력·포커스만 연결한다. 게임·픽셀 연구실의 씬 색상과 캔버스는 의도적 예외다.

## 성공 기준

1. 실제 route와 CSS별 적용/예외 목록 및 코드 근거가 있다.
2. 공통 값에 연결되고 유형 충돌·작은 조작 영역·전역 업무 제목 누출이 수정된다.
3. 새 공용 컴포넌트는 실제 화면에서 사용되며 같은 동작·접근성 이름을 유지한다.
4. 기존 대화 자동 조회/입력 보존, 폼 제출/disabled, 메뉴·탭·원문 표시 회귀가 통과한다.
5. 실제 CSS의 반응형·focus·상태·대비를 검증하고 본래 로그인 화면도 읽기 전용 확인한다.
6. 업무 API 쓰기·실모델 호출 없이 검증하며 합성 브라우저와 본래 화면 확인을 구분한다. 저장소 지침의 관리자 문제 이력 기록은 기존 로그인된 화면에서 별도로 저장한다.
