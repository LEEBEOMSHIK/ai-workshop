# 문제 이력 문서 보기의 제목 스타일 수정 — 2026-10-05

문제 이력에 연결된 정확한 문서 버전을 실제 Chrome에서 열었을 때, 제목이 페이지 상단 대부분을 차지하고 공개 화면의 Georgia 글꼴로 표시됐다. 전역 `frontend/src/app/styles.css`의 무범위 `h1` 규칙(최대8rem·행간0.9·음수 자간)이 전용 클래스가 없는 문서 보기의 제목에도 적용된 원인이다.

프론트 담당이 문서 route와 기존 IssueHistory CSS module 두 파일만 수정했다. 문서 보기에 한정한 제목·링크·메타데이터·본문 클래스를 적용하고 제목을 기존 시스템 글꼴·1.4~1.9rem·행간1.4로 지정했다. 전역/공개 스타일, 인증·조회·쿼리·뒤로가기, 정확한 버전의 원문 문자열과 기존 문서 관리의 `.documentBody`는 유지했다. 문서 보기의 고정 높이나 내부 스크롤은 추가하지 않았다. 구현과 브라우저 검증 담당을 분리했다.

메인은 본래 로그인과 연결 보고서 `be92047d-3036-4755-a5a9-59651d42815e` v1에서 다음을 확인했다.

- 1440px: 제목30.4px·시스템 sans-serif·제목 높이42.55px, 문서 가로 폭1425≤viewport1440.
- 390px: 제목22.4px·폭343px로 줄바꿈, 문서 가로 폭375≤viewport390, 본문 scrollWidth/clientWidth 모두343.
- 두 크기 모두 raw pre의 `white-space:pre-wrap`, `max-height:none`, 정확한 기존 문제 ID로 돌아가는 href 유지.
- DB의 정확한 버전1 내용과 원문 연결을 유지했고 문서 본문은 React 텍스트로 출력한다. 모바일 검증 후 viewport override를 해제했다.

처음 관련5파일은20통과·재시도 입력 테스트1건의 기존5초 timeout이었다. 해당 사례를 따로 실행해 같은 timeout을 재현했다. 승인된 후속으로 그 테스트의 완성 입력 두 값만 실제 click+paste로 바꿨다. 실제2회 저장, 일시 오류, 입력 보존과 동일 요청 ID/payload 검사를 그대로 유지했으며 제품 코드·전역 timeout·경고 설정은 바꾸지 않았다. 변경한 사례를 포함한 좁은9회귀가 모두 통과했고 해당 입력 재시도는2.850초였다. 앞선 전체 실패 결과를 전체 통과로 바꿔 쓰지 않는다. 전체 TypeScript 및 변경 route의 ESLint·공백 검사는 통과했다.

이 문서는 해당 문서 보기 스타일과 재시도 테스트의 입력 비용에 대한 검증이다. RAG 전체 기능·실제 모델 품질의 완료를 의미하지 않는다. 원본 DB·계정·자료·모델·API·전역 스타일 변경, staging/commit/push는 없다.
