# 전체 화면 AI 연구소 월드 설계

- 상태: 구현됨
- 기준일: 2026-09-03
- 범위: 공개 `/`, `/labs`, RAG 연구실 장면, 기술 관리자 캐릭터와 소개 대화상자
- 관련 설계: `docs/superpowers/specs/2026-09-02-public-ai-lab-rag-service-design.md`
- 관련 결정: `docs/decisions/0005-public-ai-lab-world.md`,
  `docs/decisions/0006-separate-public-entrance-and-labs.md`,
  `docs/decisions/0007-public-rag-agent-workroom.md`

## 1. 배경

현재 공개 화면은 최대 폭 `76rem` 안의 카드형 랜딩과 Lab 목록으로 구현돼 있다. 캐릭터를
선택하면 화면 중앙에 일반적인 모달이 열린다. 이 구조는 공개·작업소·관리자 URL 경계와
접근성은 충족하지만, 방문자가 하나의 AI 연구소 공간에 들어가 방마다 일하는 기술 관리자를
발견한다는 제품 의도를 충분히 전달하지 못한다.

공개 첫 화면을 문서형 랜딩이 아니라 전체 화면 AI 연구소 월드로 바꾼다. 현재 실제로 공개된
RAG만 방으로 표현하고, RAG 관리자가 방 안에서 작업하는 모습을 보여준다. 캐릭터를 선택하면
캐릭터와 시각적으로 연결된 말풍선에서 자기소개와 상세 기능 진입을 제공한다.

## 2. 목표와 비목표

### 목표

- `/`에서 돌아다니는 기술 관리자를 발견하는 AI 연구소 입구를 바로 보여준다.
- `/labs`에서 각 기술 관리자가 실제 연구실 안에서 일하는 작업 현장을 보여준다.
- 두 화면은 같은 공개 catalog를 사용하되 서로 다른 탐색 단계와 동작을 제공한다.
- RAG 방, 작업 중인 RAG 기술 관리자와 실제 공개 RAG 상세 진입 관계를 공간적으로 표현한다.
- 데스크톱, 태블릿, 모바일과 낮은 높이의 화면에서도 핵심 콘텐츠와 대화 동작을 보존한다.
- 키보드, 화면 읽기 도구와 동작 감소 설정을 지원한다.
- 새 게임 엔진이나 그래픽 런타임 없이 현재 Next.js와 React 구조 안에서 구현한다.

### 비목표

- WebGL, Canvas 게임 엔진, 물리 엔진 또는 자유 이동 게임을 도입하지 않는다.
- 아직 연구하지 않은 Lab의 빈 방이나 가짜 캐릭터를 미리 만들지 않는다.
- 이 작업에서 RAG 검색, 공개 릴리스, 모델 구성, 공개 catalog·schema·content 계약, 백엔드
  API 또는 DB migration을 변경하지 않는다.
- 장식용 장비를 실제 동작하지 않는 버튼이나 제어판으로 오인하게 만들지 않는다.
- 두 번째 Lab이 생기기 전에 범용 월드 빌더나 방 스키마를 과도하게 일반화하지 않는다.

## 3. 검토한 방식과 결정

### A. DOM·CSS 기반 2D 연구소 — 선택

React 컴포넌트와 CSS Grid, gradient, pseudo-element로 방과 장비를 구성한다. 캐릭터와
대화상자는 의미 있는 HTML 요소로 유지한다.

- 현재 프론트 구조와 테스트 방식을 재사용할 수 있다.
- 반응형과 접근성 동작을 DOM 계약으로 검증할 수 있다.
- 한 개의 RAG 방에서 시작해 실제 Lab이 추가될 때 확장할 수 있다.

### B. Canvas 기반 장면

공간 연출 자유도는 높지만 키보드 탐색, 화면 읽기와 반응형 UI를 별도 계층으로 다시 만들어야
한다. 현재 범위에 비해 구현·검증 비용이 크므로 선택하지 않는다.

### C. WebGL 또는 게임 엔진

입체적인 표현은 가능하지만 번들 크기, 성능, 유지보수와 콘텐츠 접근성 부담이 크다. AI 기능을
설명하고 연결하는 현재 목적에는 과도하므로 선택하지 않는다.

## 4. URL과 화면 책임

| URL | 책임 |
| --- | --- |
| `/` | 돌아다니는 기술 관리자를 만나는 공개 AI 연구소 canonical 입구 |
| `/labs` | 각 기술 연구실과 작업 중인 관리자를 보여주는 canonical 작업 현장 |
| `/labs/rag` | RAG 공통 기술과 조직을 설명하는 독립 상세 화면 |

`/labs`는 `/`로 리다이렉트하지 않는다. 두 경로는 같은 공개 catalog를 사용하지만 `/`는
`LabEntrancePage`, `/labs`는 `LabWorldPage`를 렌더링한다. `/`의 전체 보기 동작은
`/labs`로, 입구와 `/labs`의 캐릭터는 해당 Lab 상세로 안내한다. 새로고침과 직접 접근
모두 인증 없이 성공해야 한다.

## 5. 사용자 흐름

1. 방문자가 `/`에 들어오면 전체 화면 연구소 입구와 현재 공개된 기술 관리자를 본다.
2. 입구의 관리자는 돌아다니는 상태이며 소개 말풍선에서 자신의 Lab 상세를 안내한다.
3. 방문자가 `/labs`에 들어오면 공개된 RAG 방과 그 안에서 작업 중인 관리자를 본다.
4. 방 안의 관리자를 클릭하거나 키보드로 선택하면 캐릭터에 연결된 소개 말풍선이 열린다.
5. 작업 현장 말풍선은 역할 자기소개와 catalog의 `RAG 연구실 들어가기` 동작을 제공하고
   `/labs/rag`로 이동한다.
6. 닫기, `Escape` 또는 상세 이동으로 대화를 종료한다. 닫은 경우 초점은 캐릭터로 돌아간다.

## 6. 컴포넌트와 데이터 경계

```text
app/page.tsx ----------------------> LabEntrancePage (Server Component)
                                      ├─ PublicNavigation
                                      ├─ EntranceIntro / Status HUD
                                      └─ AgentCharacter (roaming, `/labs` 안내)

app/(public)/labs/page.tsx --------> LabWorldPage (Server Component)
                                      ├─ PublicNavigation
                                      ├─ WorldIntro / Status HUD
                                      └─ RagLabRoom
                                           ├─ 장식·작업 장비
                                           └─ AgentCharacter (working, Lab 상세 안내)
                                       └─ body portal의 AgentDialog
```

- 두 route 파일에는 장면 마크업을 복제하지 않는다.
- 서버 컴포넌트가 공개 catalog를 읽고 현재 공개된 Lab만 렌더링한다.
- 캐릭터 열기·닫기, 초점 관리와 위치 측정만 클라이언트 경계에 둔다.
- 이름, 소개, 상태와 상세 URL은 기존 공개 catalog 계약을 사용하고 컴포넌트에 중복 고정하지
  않는다.
- 현재는 RAG 한 개에 맞춘 `RagLabRoom`을 사용한다. 두 번째 실제 Lab이 승인되면 공통 방
  계약을 추출할지 다시 평가한다.
- catalog가 비었거나 읽기에 실패해도 미래 방을 만들어 채우지 않는다. 공개 가능한 연구실이
  없다는 정직한 상태와 다시 시도 가능한 탐색만 표시한다.

## 7. 공간과 시각 계층

월드는 페이지 중앙의 카드가 아니라 viewport 너비 전체를 사용한다. 최소 높이는 `100vh`와
`100dvh`를 함께 사용해 모바일 브라우저 UI 변화에 대응한다. 세로 콘텐츠가 화면보다 커질 수
있으므로 페이지 전체의 세로 스크롤을 막지 않고 가로 넘침만 방지한다.

레이어 순서는 다음과 같다.

1. 연구소 배경, 벽·바닥과 빛
2. RAG 방 경계와 장비
3. 장비 앞에서 작업하는 캐릭터
4. 상태 HUD와 공개 탐색
5. 대화 backdrop과 말풍선

공개 탐색은 화면을 가리는 절대 위치 메뉴가 아니라 문서 흐름 안의 HUD로 표현한다. 방의
주요 장비는 Grid로 배치하고 작은 조명·배선·질감은 CSS 장식으로 표현한다. 장식 요소는
보조 기술에서 숨기며 클릭 가능한 것처럼 보이지 않아야 한다.

캐릭터의 위치 기준이 되는 바깥 anchor는 움직이지 않는다. 작업 동작은 내부 시각 요소만
작게 애니메이션해 말풍선 위치와 클릭 영역이 흔들리지 않게 한다.

## 8. 캐릭터 소개 대화상자

### 데스크톱과 태블릿

- 대화상자는 transformed ancestor의 영향을 받지 않도록 `document.body` portal을 유지한다.
- 캐릭터 trigger의 `getBoundingClientRect()`로 위치를 측정해 말풍선을 캐릭터 옆이나 위에
  붙인다.
- 기본 방향에 공간이 부족하면 반대 방향으로 뒤집고, 최종 위치는 viewport 여백 안으로
  제한한다.
- resize, orientation 변화와 scroll에서 위치를 다시 계산한다.
- 말풍선 꼬리는 캐릭터 방향을 가리키되 viewport 제한으로 실제 위치와 어긋나지 않게 한다.

### 모바일

너비 `48rem` 미만에서는 정밀한 캐릭터 연결보다 읽기와 조작 안정성을 우선해 고정 하단
대화 패널로 전환한다. safe-area inset을 반영하고 최대 높이를 제한하며 긴 내용은 패널
안에서 스크롤한다. 가로 스크롤이나 viewport 밖 닫기 버튼을 허용하지 않는다.

### 접근성 동작

말풍선의 시각 형태와 관계없이 현재의 modal dialog 계약을 유지한다.

- `role="dialog"`, `aria-modal="true"`와 접근 가능한 제목을 제공한다.
- 열리면 기존 회귀 계약과 같이 닫기 버튼으로 초점을 이동한다.
- `Tab`과 `Shift+Tab`은 대화상자 안에서 순환한다.
- `Escape`와 닫기 버튼으로 닫고 초점을 원래 캐릭터 trigger로 복원한다.
- 열린 동안 배경 상호작용을 막고 스크롤 잠금 이전 상태를 닫을 때 복원한다.
- 시각적 backdrop은 연구소와 캐릭터 관계가 보일 정도로만 적용한다.

## 9. 반응형 기준

| 범위 | 장면과 대화 |
| --- | --- |
| `64rem` 이상 | 넓은 RAG 방, 장비와 캐릭터를 공간적으로 분리, 캐릭터 연결 말풍선 |
| `48rem` 이상 `64rem` 미만 | 장비 밀도를 줄인 방, 캐릭터 연결 말풍선과 viewport 제한 |
| `48rem` 미만 | 세로로 재배치한 방, 핵심 장비와 캐릭터 유지, 고정 하단 대화 패널 |
| 높이 `40rem` 이하 | 장식 밀도와 여백 축소, 핵심 안내와 동작 우선 |

최소 검증 화면은 `1440×900`, `1024×768`, `768×1024`, `390×844`, `320×568`,
`844×390`이다. 브라우저 확대 `200%`에서도 핵심 탐색, 캐릭터와 대화 동작이 가려지지
않아야 한다.

## 10. 동작과 성능

- `prefers-reduced-motion: reduce`에서는 캐릭터 작업, 상태등과 장면 진입 애니메이션을
  제거한다.
- 애니메이션은 transform과 opacity 중심으로 제한하고 레이아웃을 계속 다시 계산하지 않는다.
- 장면은 의미 전달에 필요한 CSS와 기존 자산을 우선 사용한다. 새 대용량 이미지나 런타임
  의존성은 별도 근거와 승인 없이 추가하지 않는다.
- 장면 장식이 느리거나 CSS가 적용되지 않아도 RAG 이름, 설명, 캐릭터 선택과 상세 링크는
  읽고 사용할 수 있어야 한다.

## 11. 오류와 빈 상태

- 공개 catalog가 비어 있으면 `/`는 `현재 공개된 기술 관리자를 준비하고 있습니다`,
  `/labs`는 `현재 공개된 연구실을 준비하고 있습니다` 상태를 표시한다.
- catalog 조회가 실패하면 `/`는 연구소 입구 오류를, `/labs`는 연구실 정보 오류를 각각
  명시하고 공개 탐색은 유지한다.
- catalog 조회가 실패하면 비공개 데이터나 하드코딩된 RAG 항목으로 조용히 대체하지 않는다.
- 캐릭터 위치를 측정하지 못하면 viewport 안의 안전한 중앙 대화상자로 명시적으로 대체한다.
- 위치 계산 실패는 콘텐츠 접근 실패가 되어서는 안 되며 닫기와 상세 이동은 계속 동작한다.

## 12. 검증 기준

1. `/`와 `/labs`는 redirect 없이 각각 `200`으로 서로 다른 탐색 장면을 렌더링한다.
2. `/`의 전체 보기 링크는 `/labs`로 안내하고, 입구와 `/labs`의 관리자 말풍선은 해당 Lab
   상세 URL로 안내한다.
3. 페이지의 주요 연구소 배경과 RAG 방은 고정 `76rem` 카드 안에 갇히지 않고 viewport 전체
   너비를 사용한다.
4. 현재 공개된 RAG만 방으로 나타나며 미래 Lab의 빈 방이나 가짜 항목이 없다.
5. RAG 관리자는 방 안에서 작업하는 상태로 보이고 마우스와 키보드로 선택할 수 있다.
6. 데스크톱 대화상자는 캐릭터에 시각적으로 연결되며 모든 경계가 viewport 안에 있다.
7. 모바일 대화 패널은 safe area와 작은 화면을 포함해 가로 overflow 없이 닫기와 CTA를
   제공한다.
8. 대화상자가 열리면 닫기 버튼이 초기 초점을 받고, Tab 순환, Escape 닫기와 trigger 초점
   복원이 동작한다.
9. 대화상자가 열린 동안 배경 상호작용이 차단되고 닫힌 뒤 이전 스크롤 상태가 복원된다.
10. 동작 감소 설정에서 비필수 애니메이션이 실행되지 않는다.
11. `/labs/rag` 직접 접근과 캐릭터 CTA 이동이 인증 없이 동작한다.
12. catalog 빈 상태와 오류 상태는 11절의 경로별 문구와 공개 탐색을 렌더링한다. 두 상태
   모두 비공개 데이터나 하드코딩 fallback을 노출하지 않는다.
13. 공개 catalog·schema·content 계약, 백엔드 API와 DB migration에는 변경이 없다.
14. frontend 단위·컴포넌트 테스트, TypeScript, ESLint와 production build가 통과한다.
15. 지정된 desktop·tablet·mobile·landscape 화면과 `200%` 확대를 실제 브라우저로 점검한다.

## 13. 예상 변경 범위

- `frontend/src/app/page.tsx`: 공개 연구소 입구 조합 사용
- `frontend/src/app/(public)/labs/page.tsx`: Lab 작업 현장 조합과 독립 canonical 사용
