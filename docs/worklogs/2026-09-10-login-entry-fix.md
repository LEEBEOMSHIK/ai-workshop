# 공개 진입의 중복 로그인 수정

- 사용자 승인: 공개 작업소·RAG 버튼은 목적지로 직접 연결하고 이미 로그인한 사용자는 로그인 폼을 다시 보지 않는다.
- 원인: 공개 nav·게임 입구·RAG 연구실이 로그인 경로를 직접 사용했고 login route는 기존 세션을 조회하지 않았다.
- 변경: 공개 링크를 기존 보호 경로로 연결하고 RAG 버튼의 강제 로그인 문구를 제거했다.
  로그인 route는 기존 세션 resolver에 쿠키를 전달한다. 인증되면 안전한 next로 이동하고,
  비로그인은 폼/초기 setup 흐름을 유지한다. 로그인·setup으로 돌아오는 경로는 정규화 후 작업소로 대체한다.
- 경계: 인증 오류401만 비로그인으로 처리한다. 다른 서버 오류·공개 전용 runtime 차단,
  작업소 인증·관리자 권한 확인은 유지한다. DB·계정·세션 수명 변경 없음.
- 역할: 프론트 담당은 login route/테스트, 메인은 공개 진입 링크와 통합 검증,
  독립 보안/리뷰 담당은 우회·외부 redirect·반복 이동·오류 경계를 검증했다.

## 검증

- TDD: 로그인 route 21실패→25통과, 공개 진입 3실패→7통과.
- 통합 관련 12파일76테스트 통과. 독립 4파일32테스트 통과, 차단 발견 없음.
- 프론트 전체 타입 검사·ESLint 및 변경 diff 공백 검사 통과. 빌드/전체 테스트는 이번 범위에서 미실행.
- 실제 로그인 브라우저: 공개 RAG 버튼→검색, 기존 login?next→검색 자동 이동,
  로그인 폼0/로그아웃 버튼1 확인. 로그인·로그아웃·자료 변경 요청을 하지 않았다.
- 쿠키 없는 HTTP 요청: 검색 경로307→로그인, 로그인 페이지200. 비로그인 보호 유지.
