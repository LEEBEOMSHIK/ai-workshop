# ADR-0035: 숫자·날짜 인용의 표기 동등성과 값 보존

- 상태: 구현·회귀·독립 리뷰·본래 API 반영 및 실제 실패5건 재검증 완료; 수정 런타임 전체75건 평가와 후보 승격은 별도
- 날짜: 2026-10-05
- 관련: [생성형 평가](0030-rag-generative-evaluation.md), [주장 기록](0034-rag-claim-citation-trace.md)

## 원인과 결정

기존 검증기는 정규식으로 찾은 문자열 집합을 직접 비교했다. 동일 날짜의 한글/ISO 표기,
공백·천 단위 쉼표·소수 끝의 0을 다르게 판단했다. 또한 네 자리 이상의 무쉼표 수에서
뒤 세 자리만 잡고, 부호와 퍼센트포인트를 잃어 다른 값을 통과시켰다. 합성 회귀 테스트로
이 결함을 재현했다. 진행 중인 실제 평가의 실패 초안은 보존되지 않아 그 실패의 정확한
문구나 이번 결함과의 인과관계는 확정하지 않는다.

- 기존 인식 범위의 날짜·단위 있는 수치를 전체 토큰으로 읽고 비교용 값만 정규화한다.
- 유효한 한글/ISO 달력 날짜는 같은 날짜로, 수치는 Decimal과 동일 단위로 비교한다.
  공백, 올바른 천 단위 쉼표, 소수 끝의 0, 퍼센트의 한글/전각 표기만 동등하게 취급한다.
- 음수 부호와 `%p`를 보존한다. `%p`와 `%`는 다른 단위다. 원·만원·억원은 서로 다른
  단위이며 단위 환산, 반올림, 계산·추론으로 원문에 없는 값을 인정하지 않는다.
- 잘못된 쉼표 묶음·달력 날짜를 임의로 고치지 않고 원래 표기 그대로 비교한다.
- 주장과 근거 원문은 변경하지 않는다. 현재 인용한 허용 근거에서만 지원 값을 모은다.
  실패 상태·안전한 원인 코드·초안 비노출·권한 계약을 유지한다.
- 실행 중인 평가 프로세스는 바꾸지 않는다. 기존 결과·실패·판정을 재작성하지 않으며,
  수정 후 실모델 검증을 기존 런타임 결과와 구분한다. 후보 승격 게이트는 그대로다.

## 검증

동등 표기 통과, 부호/단위/전체 값/날짜 변경 거절, 다른 허용 근거라도 인용하지 않았다면
거절, 기존 주장 기록·검색·평가 회귀를 외부 모델 없는 테스트로 검증한다. 본래 API 반영과
실모델 결과 확인은 별도로 기록하며 단위 통과를 전체 RAG 완료로 보고하지 않는다.

## 2026-10-19: 짧은 수치 표기의 지원 검사 확대

A/B/C 실제 비교에서 주장에 포함된 연도 없는 `09-10`, `09-14`가 인용하지 않은 조각에만 있어도 자동 검사를 통과했다. 사용자 승인 후 기존 값 보존 검사를 다음과 같이 확대한다. 구현·회귀 결과와 본래 서버 반영은 [후속 기록](../worklogs/2026-10-19-rag-relation-improvement.md)에서 구분한다.

- 단독 `숫자-숫자` 형태의 짧은 표기는 날짜·범위 중 하나로 의미를 단정하지 않고 문자값으로 비교한다. 다른 표기, 연도 포함 날짜 또는 제품 코드와 자동으로 동등하게 만들지 않는다. 영숫자·하이픈 식별자의 일부는 분리 추출하지 않는다.
- `T+N` 등 한 글자 영문 기준점의 상대 오프셋은 기준 문자·부호·수치를 보존한다. `N 영업일` 수치는 영업일 단위를 따로 보존한다. 기준점이나 단위가 다른 값을 동일하게 취급하거나 달력 날짜를 계산하지 않는다.
- 현재 주장에 실제 인용한 허용 근거만 비교하고, 다른 검색 조각의 값으로 보충하지 않는다. `exact_value_not_supported`와 초안 비노출을 유지한다. 확대는 schema1/2의 `CitationValidator`에 적용한다. schema3가 공유하는 기존 `_VALUE` 패턴과 계산·증명 인식 범위는 유지하고 호환성 회귀를 검사한다.
- 누락된 답변 내용을 자동 생성하거나 답변 완전성·조건의 의미를 판단하는 검사는 아니다. 날짜처럼 보이는 범위도 표기 보존을 요구할 수 있으며, 인식하지 못하는 자연어·숫자 표기는 여전히 남는다.
