# RAG 대화 세션과 문서 첨부 사용성

상태: 사용자 요구를 반영한 검토안. 조사 완료, 신규 저장 계약과 화면 변경은 아직 구현 전.

## 목표

사용자는 대화 목록에서 이전 대화를 다시 열어 이어서 질문한다. 문서는 입력창의 `+`에서 추가하고,
각 답변 아래에서 어떤 문서가 검색되었고 왜 답변에 사용되거나 제외되었는지 확인한다.
본래 계정·DB·문서·모델을 사용하며 별도 테스트 환경을 만들지 않는다.

## 확인된 현재 상태

- `ConversationPage.tsx`의 transcript는 React state뿐이다. 새로고침·페이지 이탈·새 대화에서 사라진다.
- 세션 목록·상세·이름 변경·삭제 API와 서버 대화 테이블이 없다. 감사 기록은 질문/답변 전문을 저장하지 않는다.
- 성공한 서명 답변만 제한된 후속 문맥에 들어가며, 근거 부족·실패 메시지 저장도 없다.
- 실제 활성 구성은 v3, `rag-codex-answer-v3`, `context_enabled=false`, 의미 임계값0.9다.
- 현재 유사도는 질문 전 `검색 진단 포함` 체크 후 해당 응답의 `검색·근거 진단`을 펼쳐야 보인다.
- 문서 선택 버튼이 입력창에서 떨어져 있고, 첫 진입에는 검색 공간 선택까지 요구한다.
- 이미 새로고침으로 소실된 대화는 현행 감사 정보로 복구할 수 없다. 복구 가능하다고 안내하지 않는다.

## 화면과 동작

1. 왼쪽 대화 목록: 최근 갱신순 제목, 새 대화, 이름 변경, 삭제. 모바일에서는 접는 목록.
2. 중앙에는 선택한 세션의 질문·답변·실패·근거 부족·범위 변경을 시간순으로 표시한다.
3. 아래 고정 입력창: `[ + ] 질문 입력 [보내기/중지]`. `+` 메뉴는 `기존 문서 선택`, `PC 파일 첨부`다.
4. 기존 문서 선택은 접근 가능한 문서의 탐색·미리보기·선택만 제공한다. 이동·폴더 관리·버전 관리는 파일함에 둔다.
5. 파일을 선택하면 입력창 위에 파일명과 처리 상태, 제외 버튼을 표시한다. 파일 하나를 선택하기 위해 공간을 먼저 고르게 하지 않는다.
6. PC 첨부는 해당 사용자·대화에 묶인 비공개 첨부다. 전사 파일함에 자동 게시하지 않는다.
   기존 Asset 업로드·원본 추적·처리 파이프라인을 재사용하고, 처리 중/실패/검색 가능 상태를 표시한다.
  첨부와 외부 모델 전송 승인은 별개이며, 새 첨부의 허용이 확인되기 전 외부로 보내지 않는다.
   대화마다 별도 workspace를 만들지 않는다. 기존 사용자 소유 비공개 공간 중 도메인/구성의 허용 범위와
   쓰기 권한을 모두 만족하는 공간에만 저장하며, 복수 후보일 때 첨부 메뉴에서 저장 위치를 선택한다.
   적격 공간이 없으면 업로드를 명시적으로 비활성화하고 이유를 표시한다. 전사 공간으로 자동 대체하지 않는다.
   대화-첨부 연결은 별도 레코드로 보관한다. `제외`는 이후 질문의 선택 범위만 바꾸며 원본을 지우지 않는다.
   첨부 원본은 세션 삭제 전까지 보존하고 자동 만료를 새로 도입하지 않는다. 세션 삭제 시에도 다른 참조나 실행이
   남아 있으면 추적 계약에 따라 보존하며, 관련 upload/ingestion 종료 확인 후 정리 후보로 전환한다.
7. 공간·폴더 전체 검색은 입력창의 검색 범위 보조 메뉴로 유지한다. 사용자가 선택한 범위를 임의로 넓히지 않는다.
8. 테스트 진단을 기본 수집하며 응답 바로 아래 `검색 근거·유사도` 진입과 검색 문서 수를 표시한다.
   상세에는 문장/문맥 cosine, BM25/dense 원점수, RRF, 선택 사유, 임계값, 소요 시간을 구분한다.
   점수는 정답 확률로 표시하지 않는다. 오래된 응답에 진단이 없으면 `이 응답에는 진단 기록이 없습니다`라고 표시한다.
9. 근거 부족은 검색 결과 없음/근거 기준 미달/생성 입력 예산 제한/내용 불충분을 실제 서버 상태에 따라 구분한다.
   검색된 문서와 근거가 있으면 답변 생성 실패와 관계없이 확인할 수 있게 한다. 추정 원인을 확정적으로 표시하지 않는다.

## 서버 세션 계약

- 기존 DB에 `rag_conversations`, `rag_conversation_turns`를 추가한다. 소유자·도메인별로 세션을 분리한다.
- 세션: ID, owner, domain, 제목, 생성/갱신 시각, revision. 목록·생성·상세·제목 변경·삭제를 제공한다.
- turn: 세션, 순번, client request ID, 질문, 상태, 검증된 응답, 인용 근거/버전, 검색 범위,
  구성/연결 버전, 문맥 구간, 시각을 저장한다. 세션 내 request ID와 순번에 unique 제약을 둔다.
- 서버가 저장된 turn으로 후속 문맥을 조립한다. 클라이언트가 보내는 임의 답변/인용 snapshot을 정본으로 저장하지 않는다.
- 부족·실패·취소도 기록하되 검증된 답변처럼 LLM history에 끼워 넣지 않는다.
- 범위·문서 버전·연결 변경 시 이전 대화를 지우지 않고 새 문맥 구간을 만든다. 이전 구간을 조용히 재전송하지 않는다.
- 긴 모델 호출 동안 DB 잠금을 유지하지 않는다. 요청 예약을 짧게 확정하고 실행 후 조건부 완료한다.
  중복 요청은 같은 결과를 재사용하며, 중단된 실행은 재접속 후 무한 생성 중으로 남기지 않는다.
- 삭제/취소 revision 뒤 도착한 완료는 본문을 다시 생성하지 못한다. 재접속 시 상태만 복구하며 모델을 자동 재실행하지 않는다.
  취소 후 아직 시작하지 않은 외부 호출은 막고, 이미 시작한 호출은 취소 요청과 실제 종료 확인 상태를 구분해 기록한다.
- 새 대화는 기존 세션을 보존한 새 ID다. 삭제는 대화와 대화 소유 첨부의 수명주기만 바꾼다.
  선택해 참조한 기존 원본 문서나 독립 감사 기록을 삭제하지 않는다. 첨부 물리 정리는 기존 추적·종료 확인 계약을 따른다.

## 권한과 기존 대화 이어가기

- 세션 소유자 필터를 목록/상세/쓰기 전에 적용한다. 마스터라도 다른 사용자의 대화를 자동으로 열람하지 않는다.
- 저장 답변과 인용에도 현재 문서 권한을 재검증한다. 철회된 자료에서 나온 답변은 본문과 출처를 노출하지 않는다.
- 저장 history를 조립하기 전에도 문서 권한·현재 외부 전송 승인을 재검증한다. 숨겨진 답변을 후속 LLM에 전달하지 않는다.
  새 질문 동의만으로 과거 turn과 새 첨부의 승인을 확대하지 않는다. turn별 근거와 앞선 문맥 의존성을 기록한다.
- 권한 철회 시 문서명·excerpt·resolved query·진단과 이 자료에서 파생된 후속 응답도 가린다.
  기본 제목은 문서 내용을 요약하지 않고 `새 대화`와 생성 시각으로 제공하며 사용자 지정 제목을 지원한다.
  제목을 포함한 모든 대화 본문 API에 `no-store`를 적용한다.
- 상세 응답은 `Cache-Control: no-store`. 대화 본문·진단은 서비스 저장소에만 두고 로그/전역 캐시에 복제하지 않는다.
- 서버 저장 도입 후 대화는 새로고침·재로그인·세션 전환으로 복원된다.
- 도입 이전 소실된 세션을 새로 구성하거나 가짜 기록으로 만들지 않는다. 아직 열린 화면도 검증되지 않은 응답 snapshot을
  그대로 서버에 올리지 않는다. 사용자 작성 질문과 검증 가능한 답변을 구분하는 별도 이관 계약 없이는 소급 가져오지 않는다.

## 실제 답변 문제의 마감 조건

기존 승인 합성 자료로 신규 문맥 profile의 기간/금액/절차/조건/예외/부정/무관/다대상 질문을 실제 실행한다.
동일 문맥에 다른 대상의 값이 있어도 올바른 대상만 답하는지, 인용이 정확한 원문을 여는지 확인한다.
통과한 profile/configuration만 정상 관리 서비스로 활성화한다. 임계값을 임의로 내리거나 평가 성공을 SQL로 기록하지 않는다.
사용자 화면의 실제 질문→답변 또는 명확한 근거 부족 사유→유사도→인용 원문까지 확인해야 테스트 준비 완료다.

## 검증과 책임

메인은 요구·UI/API 구현과 통합을 담당한다. DBA는 추가 migration·동시 요청·기존 데이터 보존을 검토하고,
독립 검토자는 소유권·문서 권한 철회·세션 복원·인용·외부 전송을 검증한다. 모델 학습과 환경 분리는 범위 밖이다.

검증: 재로그인 복원, 다중 세션 전환·이름 변경·삭제, 중복 클릭 비용 방지, 생성 중 종료 복구,
사용자 간 접근 차단, 문서 권한 철회 후 저장 본문 차단, 연결/범위 변경 후 이전 구간 보존,
첨부 준비 전 검색 차단, 기존 문서 불변, 근거 부족의 실제 이유와 진단 표시, 모바일/키보드 조작.

기존 ADR-0008/0015의 영속 저장 유보와 ADR-0023의 대화 선택 전용 원칙을 이 계약에 맞춰 갱신한다.
실행 전 기존 DB의 백업·복원 및 migration 검증 경로를 정하며 새로운 영구 테스트 환경을 추가하지 않는다.
