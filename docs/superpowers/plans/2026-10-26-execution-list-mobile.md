# 실행 목록 초기 조회와 모바일 검증

2026-10-26. 사용자 승인 범위: 기존 기능과 답변 품질을 유지하면서 초기 실행 목록 조회 지연 수정 및 모바일 업무 화면 검증.

## 원인과 성공 기준

기존 환경 읽기 전용 계측에서 실행 508건, 첫 페이지 25건 조회는 29.93초였다. 대화 25건 5.78초/331 SQL, 평가 483건 23.29초/1,863 SQL로, 전체 JSON 복원과 중복 검증용 읽기·digest 계산 비용이 크다. cProfile 수치는 계측 오버헤드를 포함하며 합산하지 않는다.

- 같은 기존 DB와 요청의 응답 SHA-256, 전체 통계, 정렬 및 페이지를 보존하고 전후 시간을 비교한다.
- 현재 권한·의존 대화·전후 변경 탐지·숫자 증명·손상 결과 제외 검증을 유지한다. 요청 사이 권한 캐시는 도입하지 않는다.
- 생성·검색·프롬프트·모델·인용 및 배경 처리 경로는 변경하지 않고 모델을 호출하지 않는다.
- 본래 API에 반영해 실제 실행 목록 진입, 필터와 상세를 확인한다.
- 실제 제품 컴포넌트를 320/375/1280px 합성 미리보기에서 검증하고 재현된 모바일 결함을 수정한다. 합성 폭 검증과 기존 환경 검증을 구분한다.

## 역할과 구현 순서

중위험 성능/UI 작업. 메인: 요구·설계·실측·브라우저·통합·기록. 백엔드/DB 담당: 아래 목록 경로와 회귀. 프론트엔드 담당: 네트워크 차단 합성 모바일 하네스 및 재현된 결함만 수정. 독립 리뷰/보안/통합 검증 담당은 구현과 분리한다.

1. 읽기 전용 DB 기준선과 파일 보존 기준선을 확보한다.
2. 대화 목록 ID만 열거하고 실제 최초/최종 검증은 유지한다. kind로 제외된 분기를 읽지 않는다.
3. 평가 목록에서 사용하지 않는 중복 bytes 열만 읽지 않는다. 동일 결과로 계산한 judgment digest를 같은 복원 중 재사용한다. 전체 상세 검증은 유지한다.
4. 먼저 실패하는 회귀를 확인하고 구현한다. 기존 DB 응답 해시와 시간을 재측정하여 남은 비용을 판단한다.
5. 모바일 폭/가로 넘침/터치 대상/모달과 키보드 동작을 확인하고 재현한 결함만 고친다.
6. 독립 회귀·타입·린트, 원래 API 실제 동작, 데이터/설정 보존을 검증한다. ISSUE-00042와 작업 기록·WORKBOARD를 갱신한다.

추가 계측 결정: 첫 최소 변경만으로는 계측 29.94초로 개선을 확정하지 못했다. 같은 역할/제품 4파일 범위에서 평가 run 읽기를 최대 4개의 독립 session worker로 중첩한다. task 수를 제한하고 기존 순서를 복원하며 오류·취소 때 형제 작업을 정리한 뒤 원래 예외를 전달한다. 동일 snapshot 식별자 추출 재사용은 변경 탐지 부담 때문에 제외하여 전후 추출을 그대로 보존했다. 프로파일러 없는 기준선은 보존한 이전 4모듈을 계측 프로세스에서만 로드해 원래 파일/API 교체 없이 측정한다.

공개 API/DB 스키마 변경은 없다. 저장소 내부 읽기 계약만 확장하며 새 ADR은 필요하지 않다. 범위 확장이 필요하면 역할과 설계를 먼저 갱신한다.
