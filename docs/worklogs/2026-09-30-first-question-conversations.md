- 날짜: 2026-09-30
- 상태: 구현·독립 리뷰·본래0060·서버 반영 및 관련 검증 완료. 전체 RAG 품질 완료 판정은 아니다.

## 문제와 변경 범위

첨부 패널이 질문 전 대화를 생성하고 첫 질문도 create/submit을 나눠 처리한다.
사용자 요구에 따라 질문 전 파일은 초안으로 관리하며 첫 유효 질문과 첨부를 원자적으로 접수한다.
첫 질문의 대상·요청을 보존하는 제목을 로컬에서 한 번 만들고, 수동 변경을 보존한다.
첫 turn의 원문 권한이 사라지면 제목도 목록·상세·재접수 조회에서 함께 가린다.

응답 대기 중 세션 ID를 아직 모를 수 있으므로 request_id 기반 접수 조회를 포함한다.
fetch abort와 서버 취소를 구분하며, 조회404만으로 나중의 접수를 배제하지 않는다.
기존 후속 질문·대화 저장·생성 실행 코어를 유지한다. 제목용 외부 모델 호출과 품질 프로파일 변경은 없다.

## 역할과 검증 경계

요구/RAG/문서·아키텍처/DB·개인정보 계약 검토를 반영했다. 백엔드 구현 이후 프론트 계약을 연결하고,
구현 담당과 별도 담당의 코드 리뷰·통합 검증을 수행했다. 세부 작업 증거는 Git 제외 작업 원장에 기록했다.

기존 RAG integration fixture는 별도 PostgreSQL DB를 생성·삭제하므로 이번 검증에 사용하지 않는다.
본래 DB outer transaction·SAVEPOINT·outer COMMIT 차단·최종 rollback의 opt-in 검증을 수행했다.
이 검증은 실제 파일 저장·worker·모델·브라우저 전체 실행을 대신하지 않으며, 단일 연결로
다중 연결의 commit된 동시 접수까지 입증할 수는 없다. 실행한 검증과 미실행 범위를 분리해 기록한다.

READ ONLY·repeatable-read 거래에서 원문/제목/파일명/계정/비밀을 출력하지 않고 metadata만 확인했다.
적용 전 revision은 `0059_generative_raw_proof`, 계정1·공간3·문서6·Asset Version6·대화2·turn9·첨부0이었다.
대화 상태는 완료8·실패1이며 질문 없는 legacy 대화와 종료 미확인 turn은0이다.
적용 전에는 신규 draft/start 테이블이 없었다. 기존 원본·권한·상태 metadata fingerprint를 작업 원장에 보존했다.
API18000 health200 및 기존 PostgreSQL·Redis·Elasticsearch healthy를 확인했다.

## 실제 적용과 최종 결과

프론트 구현의 관련12파일83개 검사·TypeScript·ESLint를 통과했다.
수정 전 시작한 전체 프론트 검사를 최종 코드 통과 증거로 쓰지 않는다.
독립 프론트 검토에서 늦은 포기 오류의 화면 침범, 앱 내 이동 시 취소 복구 중단,

서버의 현재 권한 detail로 제목·편집창·본문·근거 cache를 갱신한다.
전체 검사에서 관찰된 검색 화면 timeout과 권한 상세 로딩 실패는 두 사례의 분리 실행에서도 재현됐다.
해당 제품·테스트는 수정하지 않았으며 원인과 이번 변경의 인과관계는 확정하지 않았다.
이를 전체 검사 통과나 별도 기능 해결로 표시하지 않는다.
전체 경계의 최종 검토에서는 확정 거절 뒤 동일 질문 재전송이 종료된 접수 객체를 재사용하는 경로와,
거절된 객체가 있으면 명시적인 초안 포기를 건너뛰는 경로를 추가 발견했다.
서버 반영 전 같은 작업에서 처리했고, 불확실한 요청의 원래 key/payload와 실제 접수 뒤 취소를 유지했다.
두 경로를 보완한 관련4파일78건·TypeScript·ESLint는 통과했다. 범위 재검토에서 POST404도
접수 이후 권한 변경으로 발생할 수 있음을 확인해 상태·오류 코드가 검증된 접수 전 거절만 확정 처리했다.
