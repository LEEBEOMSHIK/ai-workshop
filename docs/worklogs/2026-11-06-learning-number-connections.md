# 목록 순번과 학습 계승 연결선

## 목록 열 구조 보완

사용자 화면에서 외부 숫자가 소속 없이 떠 보이는 점을 확인했다. 그룹별 순번/학습 기록 열 제목, 동일한 열 폭·숫자 중앙 정렬, 번호와 카드 영역을 함께 가로지르는 행 구분선을 추가했다. 번호 배지나 학습 연결 노드를 추가하지 않고 기존 계승선 전용 여백과 카드 클릭을 유지한다.

관련 UI17건·타입·린트 통과, 본래 두 테마desktop/320px에서 숫자가 순번 제목 아래 같은 축에 놓이고 가로선이 행을 묶는 것을 독립 확인했다. 긴 모바일 카드에서는 열 제목이 스크롤 밖으로 나갈 수 있으며 고정 헤더는 이번 범위에 추가하지 않았다.

실제 화면 점검 중 다른 세션이 갱신한 출발점의 `6회 추가 갱신 완료` 문구 때문에 연결 하나가 미확인되는 것을 발견했다. 명시 문법의 완료 접미사만 지원하도록 보완하고 신규 실패 테스트 확인 후 연결 판정10건을 통과했다. 저장 기록은 수정하지 않았다.

## 최종 순번 배치 변경

사용자 후속 요청에 따라 순번을 카드 밖 왼쪽 독립 열로 옮기고 `No.`·앞자리0 없이 1, 2, 3으로 표시한다. 카드와 번호 사이32px 여백 안에서 연결선을 그리며 번호를 연결하지 않는다. 페이지 연속 순번·카드 내부 학습 차수·계승 판정은 유지한다. 아래 교정 기록의 카드 우측 No. 배치는 이 요청으로 대체됐다.

순번/방향/목록/카드 이동3파일17건, TypeScript·변경파일 ESLint·공백 검사를 통과했다. 변경 전 카드 내부 순번을 금지하는 테스트2건 실패를 확인한 뒤 구현했다. 본래 다크320px에서 번호 영역 x16–48과 연결선 약x52가 분리되고 가로 넘침이 없음을 독립 확인했다.

최종 라이트/다크 desktop/320px 모두 숫자와 선이 닿지 않고 연결3건의 방향·카드 포트가 유지됨을 확인했다. 다크·기본 폭·기본 목록으로 복원했다.

## 후속 시각 수정

사용자 화면에서 번호 배지에 화살표가 닿아 목록 순번과 학습 노드가 혼동됐다. 번호의 상자와 외부 번호 열을 제거하고 카드 상단의 작은 일반 텍스트로 옮긴다. 화살표는 별도의 학습 관계 표시와 정렬된 카드 경계에 닿게 한다. 동일 관계를 반복하는 목록 내부 파이프라인은 필요한 출발점 설명을 보존하며 간결하게 정리한다. 연결 판정과 실제 학습 차수는 유지한다.

교정 구현: No.는 우측 보조 텍스트이며 관계 연결은 카드 상단의 계승 설명 옆 별도 포트에 닿는다. 실제 연결이 있는 포트만 표시한다. 출처 설명이 있지만 기록 연결 대상을 식별하지 못한 경우에도 이어 학습 사실과 원문은 보존한다. 상세 화면의 출발점 구성은 유지한다.

교정 검증: 구현 담당 관련27건·타입·린트 통과. 메인 목록/상세28건 중27건 통과 후 편집 이동 보호 테스트1건이5초 제한에 걸려 단독 재실행했고3.72초에 통과했다. 검사 시간을 늘리거나 제품 동작을 변경하지 않았다. 메인 TypeScript와 공백 검사 통과.

독립 실제 화면의 두 테마·320px 스크린샷에서 No.의 회색 일반 텍스트와 학습 관계 포트가 분리됨을 확인했다. 화살표는 계승 문구 옆에 닿고 본문 겹침·가로 넘침이 없다. 관계 문구 클릭으로 상세 이동하고 상세의 기존 출발점 원문이 유지됨을 확인했다.

## 승인된 표시 계약

- 왼쪽 `No. 01`은 현재 정렬·필터에서의 목록 순번이다. 페이지당 개수와 페이지 위치로 순번을 이어 표시한다.
- 카드 안의 `N차 학습`은 기존 저장된 실제 학습 차수이며 변경하지 않는다.
- 연결선은 출발 학습에서 후속 학습으로 향한다. 최신순에서는 아래에서 위로 향한다.
- 원본 시작·계획은 이전 카드와 연결하지 않는다. 관계가 불명확하면 연결 미확인, 출발점이 명시됐지만 현재 목록에 없으면 이를 문구로 표시한다.

## 기존 데이터 호환

현재 모델에는 부모 ID가 없으며 출발점 설명과 시작 방식이 저장되어 있다. 본래 화면에서 이어 학습 기록은 `N차 학습 결과에서 이어 학습 · 추가설명` 형식으로 명시돼 있다. 이 명시적 형식만 해석하고 `continued` 여부·동일 흐름·유일한 이전 차수 대상 여부를 확인한다. 제목·수정 시각·인접 순번으로 계승을 추측하지 않는다. 모호한 문구나 중복 대상은 미확인으로 남긴다. API·DB·저장 자료는 변경하지 않는다.

## 구현과 검증 계획

연결 판정은 별도 순수 함수로 테스트하고, 화면은 판정 결과와 실제 요소 위치를 이용한다. 비인접 연결은 중간 카드가 계승 대상처럼 보이지 않게 한다. No. 페이지 이동/초기화, 최신순/과거순, 누락·중복·계획·미확인 출발점, 반응형 두 테마와 키보드 이동을 확인한다. 구현과 독립 검증은 담당을 분리한다.

## 검증 결과

- 목록 페이지 테스트9건 통과: 5개 기준 다음 페이지 No.06, 10개 기준 No.11, 크기 변경·이전 페이지 복귀 No.01 확인.
- 전체 학습 회귀18파일111건 통과. 구현 전 순번 및 연결 판정 실패 테스트를 확인했다.
- 독립 연결 판정·방향·목록·카드 이동26건 통과. 명시하지 않은 출처, 부정문, 중복 대상, 계획 출처, 페이지 밖 출처와 비인접 관계를 확인했다.
- 전체 TypeScript와 변경 파일 ESLint 통과.
- 본래 화면에서 No.01~05와 실제4차~1차/계획 구분, 연결3건, 최신순에서 이전→후속 방향, 카드 본문 영역 클릭 이동을 확인했다. 페이지 밖 순번과 비인접 사례는 합성 테스트로 검증했다.
- 두 테마 desktop/320px에서 가로 넘침·본문 침범 없음, 범례 한 줄 표시를 독립 확인하고 다크·기본 폭·기본 목록으로 복원했다.

표시는 저장된 출발점 설명을 기준으로 하며 가중치 계승을 새로 검사하지 않는다. 동시에4개를 초과해 겹치는 관계선은 혼동 방지를 위해 선을 생략하고 관계 문구를 유지한다. 기존 계정·저장 자료·다른 세션 모델 작업은 변경하지 않았다. 문제 이력 DB 쓰기는 앞선 자동 승인 차단으로 재시도하지 않았다.
