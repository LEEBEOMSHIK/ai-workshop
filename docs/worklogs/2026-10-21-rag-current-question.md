# 현재 Gemma 환경의 동일 질문 단발 검증

2026-10-21. 사용자가 과거 질문을 현재 환경에서 새로 요청하고 실제 입력·출력을 분석하도록 승인했다. **정상 검색·생성 1회는 완료됐지만, 일반 지급 규칙과 예시 조건을 빠뜨려 질문 충족 품질은 실패했다.** 과거 Codex 요청을 재활성화하거나 저장된 LLM 입력을 재생한 결과가 아니다.

## 범위와 실제 실행

## 검색 근거 → 실제 LLM 입력 → 답변

PDF 2쪽의 28개 원문 조각이 최종 입력에 포함됐다. 진단 후보 110행은 청크와 근거 단위 행을 함께 포함하므로 문서 110개나 LLM 입력 110개라는 뜻이 아니다. 실제 선택된 문서는 한 개다.

| 대조 항목 | 실제 확인 |
|---|---|
| 핵심 근거 | 상품 식별자, 대금 지급 항목, 접수일 T+4 영업일 규칙이 입력에 존재 |
| 기준 시점·단위 | T는 접수일이며 다음 영업일부터 세는 정의가 입력에 존재 |
| 접수 조건 | 영업일 15:00 마감과 이후 신청의 다음 영업일 접수가 입력에 존재 |
| 지침 | 일반 규칙을 먼저 설명하고, 날짜 예시만으로 일반 질문에 답하지 않으며, 예시 조건을 생략하지 말라는 system 지침이 존재 |
| 실제 생성 답변 | 특정 신청일·접수일·기준가격일·지급일의 날짜 예시 두 문장만 반환 |
| 누락 | 질문의 핵심인 4영업일 지급 규칙과 예시 기간에 휴일이 없다는 조건 |
| 인용 | 반환한 두 인용 ID가 모두 실제 선택 근거에 존재. 원문의 예시 날짜는 지원되지만 규칙·조건까지 완전하게 설명한 답변은 아님 |

[실제 LLM 입력](../../.local-data/project-agent-work/rag-current-question-20261021/llm-input.json)은 `response_received`, `content_status=complete`, 11,318 bytes / 9,294 characters다. SHA-256은 `1f39175ae12233f63dcc0f37495fdb71e0f7863125e77f61fc3e3f5f41e40759`다. 이 SHA는 실제 최종 messages·temperature·max_tokens·response_format·reasoning_effort의 안전한 투영값이다. 모델 식별자·URL·헤더를 포함한 전체 HTTP body의 SHA는 아니며 공급자 내부 입력 절단 여부는 `unknown`이다. 비공개 내부 추론을 수집하지 않았다.

**관찰된 직접 실패는 생성 답변의 지침 준수와 질문 충족이다.** 이번에는 지급 규칙이 검색이나 최종 메시지에서 빠진 것이 아니다. 표의 대상·항목·값이 분리돼 전달되어 해석 부담을 줄 수 있다는 가설은 남지만, 이번 단일 결과로 원인을 분리하지 못했다. 모델 역량만이 유일한 원인이라고 확정하거나 모든 질문에 일반화하지 않는다. 현재 정상 경로의 결과를 과거 저장 입력 재생 A/D/E 실험과 동일 입력 비교로 합산하지 않는다.

## 시간과 상태 해석

| 단계 | 시간 |
|---|---:|
| 검색 | 30,438ms |
| 선택 | 2,765ms |
| 생성·검증 경로 | 117,432ms |
| 전체 파이프라인 | 150,704ms |

감사에 기록된 공급자 구간은 117,398ms, 공급자가 보고한 입력/출력은 4,568 / 171토큰이다. 이번에는 360초 시간 초과가 발생하지 않았다. 전체는 목표 120초를 30.704초 넘었고 생성 구간만은 120초 이내다. **표본 1회이므로 P95 성능 통과를 선언하지 않는다.** 단계 합과 전체의 차이는 기타 처리 구간이며 브라우저 왕복 전체를 정밀 측정한 값은 아니다.

HTTP 200, `generation.status=answered`, 감사 `succeeded`는 정상 반환과 현 검증 경로 완료를 뜻한다. 정확성·문맥 완전성 통과 판정이 아니다. 응답 최상위 `status=insufficient_evidence`는 기존 추출 답변 선택 상태이며 생성 상태와 별개다. 이 값만으로 생성 거절이나 LLM 미호출을 판단하면 안 된다. 이번에는 구조화 표 선택과 문맥 28조각으로 생성했다. 상태 계약의 사용성 한계는 기존 ISSUE-00005의 후속 범위로 유지한다.

## 보존·검증·남은 범위

[DB 전후와 감사 대조](../../.local-data/project-agent-work/rag-current-question-20261021/audit-and-preservation.json)에서 생성 감사만 495→496행으로 증가했다. 대화·턴·실행·평가 실행·평가 시도·작업 큐·도메인 7테이블의 행수와 지문, 구성·프로필·배포·도메인 연결 5테이블의 지문은 동일하다. 기존 취소 미종료, 대화 5개·턴 23개, queued job 1개를 보존했다. 원자적 전체 DB 스냅샷이 아니라 읽기 전용 트랜잭션들의 전후 관측이다.

제품 코드는 변경하지 않았다. 추가 모델 호출·자동 재시도·큐 worker 시작·재색인·활성화·승격·품질 기준 완화·설치·커밋·푸시는 하지 않았다. 이번 요청은 정상 사례 1회 검증이므로 근거 부족 사례의 거절 정확도와 다중 사용자 ACL 음성 시험, 전체 평가 게이트 및 일반 대화 E2E 수용은 완료한 것이 아니다.
