# SDK 실제 연속 질문·화면 복귀 검증 (2026-10-27)

사용자가 요청한 실제 같은 대화의 문맥·답변/인용과 화면 이동 후 결과 복원을 검증한다. [문맥 관측 보강](2026-10-27-sdk-context-monitoring.md)의 본래 반영 이후 수용이며, 이번 명시 요청 범위에서 로컬 Gemma 최대 3회·자동 재시도 0으로 제한한다. 기존 활성 direct 연결4·프로파일·검색 자료를 유지한다. 목록/스레드 성능 실험은 계속 보류한다.

## 고정 시나리오와 판정

1. 첫 질문: `AM-SYN-101을 현금화하면 돈은 며칠 뒤 받을 수 있어?` — 기존 실행과 답변/근거 동등성을 비교한다. 원문의 일반 규칙인 접수일 T+4영업일 누락은 같은 답변이어도 품질 한계로 유지한다.
2. 같은 대화의 후속: `그 상품의 신청 접수 마감 시각은 언제인가요?` — 기존 H06의 질문·정답 기준을 사용한다. 실제 대화 이력은 이번 첫 질문/답변이므로 과거 고정 H06 입력과 동일한 실험이라고 주장하지 않는다. AM-SYN-101 지시어 해소, 원문 2쪽의 영업일 15:00 마감과 일치하는 답변/인용을 확인한다.
3. 각 접수 후 다른 업무 화면을 사용하고 동일 대화로 돌아온다. 저장된 턴·실행·문맥화/SDK 기록과 실제 화면을 대조한다. 결과를 보기 위해 질문을 다시 전송하지 않는다.

## SDK 오케스트레이션 구조

전체 흐름은 애플리케이션이 제어한다. 권한이 허용된 이전 대화를 준비하고 프로파일 한도만큼 선택한 뒤, 이력이 있으면 별도 로컬 모델 요청으로 질문을 문맥화한다. 이어 BM25+dense+RRF 검색·근거 선택을 수행하고 SDK 답변 경로를 호출한다. 문맥화는 SDK 에이전트 위임 span 밖에 있는 실제 pipeline 단계다.

- 현재 활성 `direct_answer`: SDK `Runner.run(answer_specialist, max_turns=1)`로 답변 담당을 직접 실행한다. 관리자·위임 도구 호출은 없으며 첫 질문은 답변 1회, 유효 이력이 있는 후속은 문맥화 1회+답변 1회다.
- 구현된 관리자 경로: manager가 `answer_specialist.as_tool()`을 `write_grounded_answer`라는 도구로 정확히 한 번 호출한다. `tool_choice=required`, `stop_on_first_tool`이며 담당 결과를 애플리케이션에 반환한다. 답변 뒤 관리자 모델을 다시 호출해 문장을 재작성하지 않는다.
- SDK handoff에 의한 자유로운 제어권 이동·다중 계획/재위임 루프는 설정하지 않았다. 현재는 제한된 manager→specialist 도구 위임 또는 specialist 직접 실행이다.
- 원래 질문·문맥·선별 근거는 애플리케이션이 담당 입력에 보존한다. SDK 밖에서 현재 권한·인용/숫자 검증·호출/토큰 한도와 저장을 통제한다. SDK tracing 외부 전송은 꺼져 있고 허용된 비공개 기록만 로컬에 남긴다.

정본 코드: [SDK orchestrator](../../backend/src/ai_workshop/labs/rag/orchestration/openai_agents.py), [RAG pipeline](../../backend/src/ai_workshop/labs/rag/search/pipeline.py), [호출 예산](../../backend/src/ai_workshop/labs/rag/orchestration/budget.py). 이는 현재 프로젝트 구현 설명이며 SDK의 모든 기능을 제한적으로 설명하는 문서는 아니다.
