## 요청과 현재 상태

사용자는 Codex가 테스트하며 만든 산출물을 모두 정리하도록 요청했다.
자동 회귀 테스트 소스는 유지하고 임시 생성 데이터만 대상으로 해석했다.
정책 반영·재조사 후 사용자가 정확한 네 경로의 삭제를 승인했다.
2026-09-07 해당 26파일의 삭제와 경로 부재를 검증했다.

## 삭제 결과

- 네 디렉터리·26파일, 논리 용량 23,548,116bytes를 제거했다. 휴지통 복구는 불가하지만
  합성 테스트 실행으로 재생성 가능하다.
- 루트 캐시 삭제 전후 host 여유 공간: 169,971,552,256 → 169,971,564,544bytes.
- Windows 임시물 삭제 전후: 169,971,294,208 → 169,994,911,744bytes.
  host 수치는 동시 실행 서비스의 변동을 포함하므로 논리 삭제량과 동일시하지 않는다.
- 상승 권한 실행에서는 사용자 Temp 경로 읽기가 거부되어 삭제 전 중단됐다.
  원래 테스트 실행 계정의 일반 실행에서는 재검증과 삭제가 정상 수행됐다.
- 사용자 references, 객체 저장소, 실행 모델, 프론트 의존성과 자동 테스트 소스는 보존했다.
- 삭제 후 웹 `/`와 API `/api/v1/health` HTTP 200, 문서 `git diff --check` 통과를 확인했다.
  최초 점검의 `/health`는 존재하지 않는 경로로 404였으며 정본 경로로 다시 검증했다.

## 보존 및 추가 확인

- 사용자 `references/`, 문서·계정·설정, 실행 모델, 회귀 테스트 소스는 보존한다.
- `.local-data/project-agent-work/rag-docx-ocr`의 pytest 디렉터리 24개는
  112파일·477,030bytes지만 작업 기록의 종료 상태를 추가 확인해야 한다.
  작업 폴더 전체를 일괄 삭제하지 않는다.
- `full-screen-lab-world-20260903`, `public-dialog-viewport-20260903`은 검증 보고서가
  포함되어 있어 공식 기록 이관·종료 게이트 확인 전 보존한다.
- `.local-data/pytest*`, backend pytest 임시 디렉터리와 루트 tmp 잔여물은 발견하지 못했다.
- DB 합성 fixture 41행과 관련 원본·파생 파일·ES 색인은
  [별도 데이터 복구 조사](2026-09-07-local-alias-integrity-audit.md)를 따른다.
  파일 키·외부 참조 확인 없이 `.local-data/objects`를 삭제하지 않는다.
- Docker 이미지·볼륨·공유 캐시는 이번 임시 파일 조사로 삭제하지 않는다.

## 서비스 상태

DB 정리의 동시 실행 방지를 위해 worker와 beat를 중지했다. 대상 프로세스의 종료는
확인했으며, 아직 복구 및 재시작 검증은 완료하지 않았다. 웹/API는 중지하지 않았다.
정합성 복구와 실제 큐 검증이 남아 있으므로 사용자 전체 검증 준비 완료 상태가 아니다.
