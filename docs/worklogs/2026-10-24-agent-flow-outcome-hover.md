## 요청과 원인

사용자는 `?` 클릭으로 열린 설명이 고정되지 않고 호버에서만 보이도록 요청했다. 현재 컴포넌트가 클릭으로 pinned 상태를 만들고 포커스도 유지해 포인터가 떠나도 설명이 남았다. 포인터와 키보드 포커스를 구분하고 클릭 고정을 제거한다. 키보드 포커스와 Escape 설명 닫기는 접근성을 위해 유지한다.

실행 흐름 안에서 전체 결과 판단과 시간을 확인할 수 있도록 요청했다. 기존 화면은 전체 실행·답변·품질·시간 요약과 흐름이 분리돼 흐름의 모든 단계가 완료로 보이더라도 품질 실패를 놓칠 수 있다. 본래 로그인된 저장 실행에서는 처리 완료·답변 생성·품질 실패·전체16.56초를 확인했다. 이 값을 흐름에 연결하며 새로운 품질 판정이나 LLM 요약을 생성하지 않는다.

## 구현·검증 경계

- 기존187파일 해시를 `.local-data/project-agent-work/flow-outcome-hover-20261024/baseline-sha256.json`에 보관했다.
- 요구·통합, 프론트엔드 구현/테스트, 독립 리뷰·통합 검증 책임을 분리한다.
- 전체 시간은 저장된 duration_ms를 표시하며 중첩 단계 시간을 합산하지 않는다. 0초·미기록, 실행 완료·품질 통과/실패/미검증을 구분한다.
- 새 생성·임베딩·설치·서비스 변경·RAG DB/프로파일 변경·commit/push는 없다. 기존 품질 실패와 멀티턴 후속을 보존한다.

## 검증 결과

프론트엔드 수용 테스트는 변경 전8실패/10기존통과를 확인했다. 독립 검토도 pointerdown→focus→click→leave 순서와 키보드 선포커스 후 클릭 전환에서2실패를 별도로 재현했다. pinned 상태를 제거하고 포인터로 생긴 포커스와 키보드 포커스를 구분했다.

ExecutionDetail의 status/answer_status/quality_status/duration_ms/observation_complete만 좁은 표현 계약으로 전달한다. 흐름이 있는 상세는 기존 상단 요약을 흐름 내부로 옮겨 한 번만 표시한다. 흐름이 없는 과거 상세는 기존 요약을 유지하고 전체 실행 정보가 없는 재사용 경로는 미기록·품질 판단 불가를 표시한다.

독립 검증의 실행 모니터링·대화 진단 범위는 고유160개(독립15개 포함)다. 넓은 시행에서159/160개가 통과했고 유일한 실패는 새 테스트의 Mermaid 연결선 fixture 누락이었다. 테스트 fixture와 비동기 준비 대기만 보강한 뒤 영향2파일14개가 모두 통과했다. 나머지146개의 제품/테스트 소스는 변경되지 않았다. 이 범위를160개로 보고하며 최종14개나 자체32개를 추가 합산하지 않는다. 최종 전체 TypeScript와 변경 TS/TSX9파일 ESLint를 검증했다.

- `pnpm exec vitest run src/features/rag/executions src/features/rag/conversation/SearchDiagnostics.test.tsx --reporter=dot`
- `pnpm exec vitest run src/features/rag/executions/AgentFlowOutcome.test.tsx src/features/rag/executions/AgentFlowOutcome.independent.test.tsx --reporter=dot`
- `pnpm exec tsc --noEmit --pretty false --incremental false`
- 변경 TS/TSX9파일 `pnpm exec eslint ... --max-warnings 0`

본래 로그인된5173 화면을 새로고침해 흐름 안 단일 요약, 처리 완료·답변 생성·품질 실패·16.56초, 실제5단계를 확인했다. `?` 클릭은 추가 모달을 만들지 않으며 다른 곳으로 포인터를 옮긴 클릭 뒤 설명은 닫힌다. Tab으로 설명 열기, Escape의 도움말→모달 순서, 원래 노드 포커스 복귀를 확인했다. 관리자에서 실제 답변 담당 자료로 이동해 자동 펼침과 근거 규칙 본문이 유지되는 것도 확인했다. 포인터 이탈만의 이벤트 검증은 단위 테스트로 확인했으며 실제 네이티브 hover·터치 장치 수용과 구분한다.

검증 캡처와 좌표는 `.local-data/browser-verification/flow-outcome-hover-20261024/`, 실행 로그·독립 검토·보존 비교는 `.local-data/project-agent-work/flow-outcome-hover-20261024/`에 보관한다. 화면 크기 검사에서 넓은 기존 `.page dl` 규칙의2열 덮어쓰기를 발견해 흐름 내부 CSS 범위로 보강했다. 375px의 과도한 세로 배치는 기존480px 규칙에서 요약 좌우 여백만 줄여 수정했다. 마지막 CSS 한 줄은 독립 해시 비교로 검토했으며 TS/테스트16파일은 그대로다.

## 문제 이력과 마감

ISSUE-00035의 증상·원인·수정·검증을 누적하고 이 문서를 `실행 흐름 전체 결과·호버 도움말 검증 (2026-10-24)`으로 등록했다. 문서 `feaece98-82fb-4c55-a1a0-949651135609` 버전1을 연결했다. 브라우저 도구 연결이 끊긴 뒤 같은 Chrome의 새 연결로 정확한 문서 ID·버전 링크를 재조회했으며 완료 진행 이력의 저장 성공을 확인했다. 이전 기록·문서 버전과 별도 멀티턴 후속을 보존해 전체 이슈 상태는 진행 중을 유지한다.

문서4개의 로컬 링크133개는 누락0, 최근 완료 목록5개, 기본 `git diff --check` exit0이다. 결과를 과거 RAG 품질 개선·실제 새 생성 검증으로 확대하지 않는다.
