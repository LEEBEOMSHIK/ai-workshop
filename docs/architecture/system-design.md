# AI Workshop 전체 시스템 설계

- 상태: 승인됨
- 기준일: 2026-08-29

## 1. 목표와 범위

이 문서는 AI Workshop의 공통 플랫폼, 첫 번째 RAG 연구 영역, 데이터 경계와 단계별 구현 범위를 정의한다.

초기 시스템은 한 명의 소유자가 로그인해 비공개 작업소를 관리하고, 외부 방문자는 별도 공개 전시실에서 승인된 콘텐츠만 보는 구조다. 다중 사용자 협업과 부서·팀 UI는 후속 범위지만 데이터 모델은 이를 수용할 수 있어야 한다.

초기 범위에 포함하지 않는 기능은 다음과 같다.

- 자동 투자 판단과 자동매매
- 실제 민감 문서를 사용하는 공개 데모
- 모든 작업자를 LLM 에이전트로 구현하는 것
- 에이전트별 마이크로서비스
- Word, PowerPoint, Excel을 원본 애플리케이션과 동일하게 재현하는 뷰어

## 2. 아키텍처 선택

시스템은 모노레포의 모듈형 모놀리스로 시작한다. React 프론트엔드와 FastAPI 백엔드를 사용하며, 긴 작업은 같은 Python 코드베이스를 공유하는 별도 워커 프로세스가 수행한다.

```text
React Web
    |
FastAPI Application ---- Background Worker
    |                         |
    +---- PostgreSQL ---------+
    +---- Elasticsearch ------+
    +---- Object Storage -----+
    +---- Local Model Runtime-+
```

내부 모듈은 네트워크 API 대신 명확한 Python 인터페이스로 통신한다. 파서, 검색 엔진, 모델 런타임과 저장소는 어댑터 뒤에 둔다. 부하나 보안 경계가 실제로 요구될 때 특정 어댑터 또는 워커만 독립 서비스로 분리한다.

## 3. 최상위 모듈 경계

```text
AI Workshop
├─ Platform
│  ├─ Identity
│  ├─ Workspaces
│  ├─ Assets
│  ├─ Agents
│  ├─ Learning
│  ├─ Publishing
│  └─ Evaluation
└─ Labs
   └─ RAG
      ├─ Documents
      ├─ Ingestion
      ├─ Chunking
      ├─ Indexing
      ├─ Retrieval
      ├─ Highlighting
      ├─ Generation
      ├─ Models
      ├─ Experiments
      ├─ Agents
      └─ Evaluation
```

`Platform`은 특정 AI 기술을 알지 못한다. `Labs/RAG`는 플랫폼이 제공하는 사용자, 권한, 파일, 실험과 공개 인터페이스를 사용한다. 미래의 서로 다른 `Labs` 모듈은 직접 참조하지 않는다.

## 4. 공통 플랫폼 책임

### Identity

로그인, 사용자, 역할과 세션을 관리한다. 첫 버전은 한 명의 소유자를 대상으로 하지만 소유자, 조직 관리자, 팀 관리자, 구성원, 공개 방문자의 역할을 표현할 수 있어야 한다.

### Workspaces

문서와 학습 자산이 속하는 지식 공간을 관리한다.

```text
조직
├─ 전사 공간
├─ 부서·팀 공간
├─ 개인 공간
└─ 임시 작업 공간
```

첫 버전 UI는 전사, 개인, 임시 작업 공간을 제공한다. 부서·팀은 데이터 구조와 권한 정책만 준비한다.

### Assets

원본 파일, 논리 폴더, 태그, 문서 버전, 저장 위치와 접근 권한을 관리한다. 논리 폴더를 실제 디스크 경로와 분리한다.

`Platform/Assets`는 기술에 무관한 파일과 권한을 관리하고, `Labs/RAG/Documents`는 그 파일을 검색 가능한 문서로 해석한 상태, 구조 요소와 색인 연결을 관리한다. 원본 자산의 소유권과 RAG 처리 상태를 같은 책임으로 합치지 않는다.

### Agents

에이전트의 부모·자식 관계, 역할, 도구 권한, 모델 정책과 실행 기록에 대한 공통 계약을 제공한다.

### Learning과 Evaluation

자유 메모, 구조화된 실험, 실행 환경, 지표와 결과 스냅샷을 관리한다. RAG 전용 평가 방식은 `Labs/RAG/Evaluation`에 둔다.

### Publishing

공개 후보, 검토 상태, 비식별화 확인과 공개 패키지 내보내기를 관리한다.

## 5. 저장소 역할

- PostgreSQL: 사용자, 권한, 지식 공간, 폴더, 문서 메타데이터, 버전, 작업 상태, 에이전트 정의, 학습·실험·공개 기록
- Elasticsearch: BM25 색인, dense vector, 권한 및 메타데이터 필터, RRF 검색 결과와 검색용 하이라이트
- 객체 저장소: 원본 파일, 파서 산출물, 페이지 이미지와 변환된 뷰어 자산
- 작업 큐: 파싱, OCR, 청킹, 임베딩, 재색인 작업
- 로컬 모델 런타임: 임베딩과 향후 추가할 리랭커 및 LLM 실행

## 6. 배포와 데이터 경계

비공개 작업소는 첫 버전에서 한 대의 개발 PC에 Docker Compose로 실행한다. 문서 원본, 파싱 결과와 임베딩은 로컬 또는 승인된 사내 환경에만 저장한다.

공개 전시실은 별도 데이터베이스와 저장소를 사용하는 별도 배포다. 두 환경을 런타임 네트워크로 연결하지 않는다. 공개 콘텐츠는 검토, 비식별화, 승인 상태를 포함하는 내보내기 패키지를 통해서만 이동한다.

외부 모델 API는 공개 또는 비식별 데이터가 명시된 프로파일에서만 사용할 수 있다.

## 7. 에이전트 실행 원칙

에이전트는 데이터베이스나 Elasticsearch를 직접 호출하지 않는다. `문서 등록`, `권한 범위 검색`, `실험 실행`과 같은 애플리케이션 도구만 사용한다. 이 도구에는 사용자와 에이전트 모두에게 동일한 권한 및 감사 규칙이 적용된다.

실행 기록에는 모델의 비공개 내부 추론 대신 다음 정보를 남긴다.

- 선택한 도구와 프로파일
- 정규화한 입력
- 도구 결과와 원문 근거
- 실행 시간과 상태
- 재시도와 오류

## 8. 단계별 구현 범위

### 1단계: 작업소 기반

React와 FastAPI 기반, 로컬 Docker Compose, 소유자 로그인, 전사·개인·임시 공간, 파일·버전·권한, 비동기 작업 상태, 모델 프로파일 등록 구조를 만든다.

### 2단계: RAG AI 검색

PDF, DOCX, Markdown, TXT와 스캔 PDF를 우선 지원한다. BM25 기준선과 BM25 + bi-encoder + RRF 검색, 검색 범위 선택, 의미 하이라이트, 원문 이동과 권한 필터를 구현한다.

### 3단계: 문서 형식 확장

PPTX, XLSX, HTML, HWPX 어댑터와 형식별 하이라이트를 추가한다.

### 4단계: 모델 연구실

임베딩, 리트리버, 리랭커, LLM 등록, 색인·검색·생성 프로파일, 병렬 색인과 비교 실험, 승인된 기본 프로파일 승격을 제공한다.

### 5단계: RAG 에이전트 조직

RAG 총괄과 작업자 캐릭터, AI 검색 모드, 에이전트 리서치 모드, 근거 검증, 답변 작성과 실행 추적을 추가한다.

### 6단계: 학습과 공개 전시실

자유 메모, 구조화된 실험, 공개 검토와 비식별화, 공개 데이터 데모와 캐릭터 안내 경험을 완성한다.

## 9. 품질 목표

- 검색 결과는 권한이 허용된 원문 위치로 이동할 수 있다.
- 전사, 개인, 임시 작업 공간의 검색 범위를 정확히 분리한다.
- 권한 밖 문서가 결과, 점수, 제안 또는 근거에 노출되지 않는다.
- BM25와 hybrid 검색을 동일한 평가 세트에서 비교할 수 있다.
- 모델, 파서, 청커, 프로파일과 문서 스냅샷으로 결과를 재현할 수 있다.
- 실패 또는 부분 처리 문서를 정상 문서처럼 표시하지 않는다.
- 외부 API에 비공개 원문을 전송하지 않는다.

검색 정확도의 수치 기준은 실제 자산운용 공개·합성 평가 세트를 만든 뒤 BM25 기준선과 함께 결정한다. 데이터 없이 임의의 Recall@K 목표를 먼저 고정하지 않는다.
