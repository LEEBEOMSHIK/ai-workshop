# ADR-0054: 요청 응답성을 보존하는 검사·DB 수명주기

- 상태: 승인됨, 구현·본래 환경 검증 완료
- 날짜: 2026-10-31
- 관련: ISSUE-00048, [진단](../worklogs/2026-10-31-backend-latency-diagnosis.md)

## 결정

사용자가 무결성 검사 유지, 다른 요청 차단 해소, DB 연결 재사용, 조회 일괄화와 본래 환경 전후 비교를 승인했다.

1. Codex 실행파일 검사 자체의 경로·reparse·파일 정체성·전체 SHA-256 검사는 그대로 실행한다. async 상태/검증 경로에서는 이벤트 루프 밖에서 수행하고 실제 진행 중 검사 수를 제한한다. 취소돼도 아직 끝나지 않은 검사의 슬롯을 먼저 반환하지 않는다. 성공 결과를 요청 간 캐시하지 않는다.
2. HTTP용 DB engine/session factory는 FastAPI 앱 lifespan에 속한다. 요청마다 별도 세션·트랜잭션을 열고 종료 시 commit/rollback/반납한다. 현재 사용자·권한은 요청마다 다시 확인한다. 앱 종료 시 배경 작업을 정리한 다음 engine을 폐기한다. worker/독립 서비스의 별도 엔진 및 트랜잭션 소유권은 유지한다. 앱·이벤트 루프 간 engine을 전역 공유하지 않는다.
3. 구성 목록의 최신 버전·관계 조회를 집합 조회로 바꾼다. 권한 필터는 조회 전에 적용하고 순서·필드·현재 정책·승인·상태의 의미를 유지한다. 준비 상태에 필요한 자료의 요청 내 중복 조회만 줄이며 장기 준비 완료 캐시를 만들지 않는다. 동시 DB 세션 작업으로 조회를 병렬화하지 않는다.

## 불변 조건

공개 API 응답 계약, 모델 선택·기본 설정, 프롬프트·근거·답변·인용 검증과 품질 게이트를 보존한다. 모델 호출이나 외부 데이터 전송 없이 검증한다. DB schema 변경이나 migration은 계획하지 않는다. 원래 계정·DB·자료를 유지하고 테스트용 새 계정/환경을 만들지 않는다.

## 검증과 한계

회귀 테스트에서 무결성 실패·취소·동시성, 요청별 transaction 격리·종료, 권한 취소·최신 버전·누락 관계를 확인한다. 원래 DB의 같은 목록·준비 상태를 전후 해시로 비교하고 SQL 횟수와 실제 동시 health 지연을 따로 기록한다. 새 engine 연결 비용과 재사용 비용을 비교한다. host 메모리 압박이 남아 있으므로 짧은 표본을 전체 서비스 P95나 모델 생성 속도 개선으로 일반화하지 않는다.

구현·실측과 남은 호스트 한계는 [검증 기록](../worklogs/2026-10-31-backend-response-improvements.md)에 남긴다.
