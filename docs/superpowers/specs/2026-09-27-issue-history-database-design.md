# 문제·개선 이력의 카테고리 및 문서 DB 연결

- 상태: 사용자 승인, 구현 중. 본래 DB 적용·검증은 작업 기록에서 별도 확인한다.
- 날짜: 2026-09-27
- 기존 화면: `/admin/system/issues`
- 현재 데이터: [문제 이력](../../issues/README.md)

## 목적과 성공 기준

운영 중 발견한 문제를 카테고리로 분류하고 수정·검증·재발을 같은 문제에 누적한다. 관련 문서는 서버 체크아웃 없이도 당시 내용을 읽을 수 있어야 한다. 기존 8개 문제의 ID·내용·날짜·검증·남은 작업을 보존한다. 마스터만 조회·변경하며 공개 환경에 노출하지 않는다.

사용자가 승인한 범위는 한글 카테고리 관리, 문제와 변경 이력의 DB 저장, 문서 본문·버전 저장과 정확한 버전 연결, 기존 기록 이관이다. 대화 세션 생성 변경은 별도 RAG-0001 작업이며 이 기능의 완료에 포함하지 않는다.

## 선택한 구조와 대안

1. 경로만 DB 저장: 단순하지만 배포에서 파일이 누락되면 읽을 수 없고 과거 내용이 바뀐다. 제외한다.
2. 일반 파일함 Asset으로 등록: 기존 업로드·버전을 활용하지만 공간·휴지통·RAG 구독 수명주기에 운영 이력을 결합한다. 이번 관리용 Markdown 기록에는 사용하지 않는다.
3. **Platform Issue History 모듈에서 본문과 불변 문서 버전 저장**: 작은 운영 기록을 PostgreSQL에 보존하고 여러 문제에서 같은 버전을 참조한다. 채택안이다.

Learning의 학습 메모·실험과도 의미 및 공개 흐름이 달라 재사용하지 않는다. SQLAlchemy·인증·오류·감사 기반은 기존 공통 구현을 사용한다. 새 DB·서비스·저장소·계정은 만들지 않는다.

## 정본과 변경 경로

전환 뒤 운영 화면의 정본은 DB다. 저장소 JSON은 최초 이관 입력 및 이전 기록으로 보존하며 매 요청 자동 동기화하지 않는다. DB 장애 때 JSON으로 조용히 대체하지 않는다.

관리자 화면에서 카테고리 추가·수정·비활성화, 문제 등록·수정과 진행 이력 추가, Markdown 문서 등록·새 버전 추가·문제 연결을 제공한다. 일반 바이너리 업로드, 문서 자동 수집·RAG 색인, 공개 배포, 영구 삭제는 범위 밖이다. 향후 Codex 작업도 인증된 관리 API로 이력을 갱신하고 작업 문서에는 문제 ID를 연결한다. 접근할 수 없으면 DB 반영 미완료를 보고하고 Git 수정만으로 반영됐다고 하지 않는다.

## 데이터 계약

| 엔터티 | 주요 필드 및 제약 |
| --- | --- |
| issue_categories | UUID PK, 고유 code, 한글 name, sort_order, is_active, revision, 생성·수정 시각 |
| issues | UUID PK, 고유 issue_key(기존 RAG-0001 유지), category_id FK, title, status, symptom, cause, resolution, verification/remaining/commits 배열, revision, 생성·수정 시각 |
| issue_events | UUID PK, issue_id FK, 사건 날짜, 기록 시각, 행위자 FK, 종류, 설명, 변경 전후 revision 및 변경 스냅샷. 수정·삭제하지 않는 누적 기록 |
| issue_documents | UUID PK, 제목, 선택적 고유 import_source_key, current_version, revision, 생성·수정 시각 |
| issue_document_versions | 복합 PK(document_id, version), Markdown 본문, SHA-256, 선택적 원본 경로·Git 커밋, 작성자 FK, 생성 시각. 본문은 불변 |
| issue_document_links | issue_id FK + document_id/version 복합 FK, 표시 순서. 동일 문제·동일 문서 버전 중복 금지 |
| issue_import_runs | 고유 source_key, 입력 manifest 해시, 적용 시각, 실행자, 항목 수와 결과 요약. 성공 결과만 트랜잭션과 함께 저장 |

category·document·version·issue의 참조 삭제는 RESTRICT다. 상태는 open/implemented/verified만 허용하고 revision·version은 양수다. 문서 current_version도 같은 문서의 존재하는 버전만 가리키는 복합 FK를 둔다. 카테고리를 비활성화해도 기존 문제에서 이름·필터를 유지하되 신규 배정은 금지한다. 비활성 카테고리를 유지하는 기존 문제의 다른 필드 수정은 허용한다.

최초 분류는 기존 area code를 안정적인 code로 유지하고 한글 이름을 이관한다: 대화 수명주기, 파일 첨부, 대화 화면, 문서 선택, 검색·근거, 대화 준비, 요청 처리, 로컬 실행 환경. 실행 코드의 enum으로 고정하지 않고 초기 데이터로 등록한다. 카테고리는 이번 범위에서 단일 단계다.

문서 새 버전 등록은 기존 링크를 바꾸지 않는다. 현재 버전과 연결 버전이 다르면 화면에서 구분하며 관리자가 명시적으로 연결을 교체할 때 변경 이력을 남긴다. 연결 제거도 문서·버전·기존 사건을 삭제하지 않는다. 같은 본문 재등록은 동일 문서의 기존 버전을 반환하며 current_version을 과거로 되돌리지 않는다. 새 연결은 반환된 정확한 version을 사용한다. 제목 변경과 원본 경로 이동은 문서 ID를 바꾸지 않는다.

## 쓰기와 동시성

서비스 계층에서 권한 확인·현재 revision 비교·변경·사건 추가를 단일 트랜잭션으로 수행한다. stale revision은 409로 반환하고 새로고침 안내를 표시한다. 문서 버전 증가는 문서 행 잠금으로 직렬화한다. 불변 본문은 업데이트하지 않는다.

모든 생성·사건 추가·버전 추가 요청은 request_id와 정규화 payload 해시를 사용한다. 사용자·작업·request_id 고유 제약의 DB 명령 기록을 별도 테이블에 두고 결과와 같은 트랜잭션에 커밋한다. 동일 요청 재전송은 기존 결과, 다른 payload 재사용은 409다. 실패한 트랜잭션은 성공 이력을 남기지 않는다. 수정 요청도 동일 원칙으로 재전송 시 사건 중복을 막는다.

이관된 과거 사건 날짜와 실제 수입 시각을 분리한다. 과거 기록 작성자를 추측하지 않고 `imported` 출처와 현재 이관 실행자를 기록한다. 업무 문제 ID는 입력 가능한 고유 식별자로 유지하며 RAG 외 문제도 허용한다.

## API와 화면

기존 owner 의존성과 내부 런타임 제한을 적용한 `/api/v1/admin/issue-history` 아래에 categories, issues, documents 리소스를 둔다. 목록·상세·생성·수정·사건 추가·문서 버전·링크 변경을 제공한다. UUID와 정확한 version으로 문서를 읽으며 클라이언트 파일 경로를 받지 않는다.

목록 검색은 문제 ID·제목·증상·원인·수정·남은 작업을 대상으로 한다. 상태·카테고리 필터와 페이지 크기 기본 20/최대 100을 적용한다. 정렬은 updated_at 내림차순, id 보조키로 고정한다. 전체 상태 집계와 필터 후 건수를 구분한다. 문서 본문은 상세 조회 때만 전송한다.

기존 목록·상세 배치를 유지하고 `카테고리` 한글 표시, 관리 버튼, 문제 등록/편집, 진행 이력 추가 및 관련 문서 연결을 제공한다. 문서 링크에는 제목·버전·출처를 표시한다. 입력 오류, 충돌, DB 조회 실패와 빈 목록을 구별한다. 현재 파일 경로 기반 링크는 전환 뒤 새 링크로 교체하며 구형 `document=숫자` 요청에는 재선택 안내를 표시해 다른 문서를 잘못 열지 않는다.

프론트의 파일 로더를 인증된 서버 API 호출로 교체한다. FastAPI DTO에서 기존 방식으로 TypeScript 타입을 생성한다. 백엔드 service/repository 분리와 의존 방향 Platform → Labs 금지를 유지한다.

## 보안과 한도

권한 검사는 백엔드의 매 조회·쓰기·문서 버전 요청에서 기존 require_owner로 수행한다. 프론트 owner 검사는 보조다. public_app에는 라우터를 등록하지 않고 프론트 public 런타임도 차단한다. 성공·오류 응답 모두 private/no-store로 제공한다. 쿠키 인증 쓰기는 기존 Publishing의 CSRF/Origin 검증 방식을 재사용한다. 비공개 본문은 로그·감사 메타데이터에 넣지 않는다. 관리자 이력 스냅샷은 권한이 같은 DB 내부에만 저장한다.

문제에 연결된 문서를 여는 API는 정확한 issue-document-version 관계를 확인한다. 별도 관리자 문서 관리 화면은 owner 권한으로 아직 문제에 연결되지 않은 문서도 조회할 수 있다. 두 경로의 목적과 검증을 구분한다.

Markdown은 처음에는 기존처럼 이스케이프한 텍스트로 표시한다. 문서별 UTF-8 512KiB 제한, 제목 200자, 문제의 각 장문 20,000자, 배열별 100항목/항목별 2,000자 제한을 API/이관 모두 적용한다. 원본 경로는 출처 메타데이터이며 런타임 파일 읽기에 사용하지 않는다. 기존 문서 중 한도 초과는 잘라 넣지 않고 이관 전 오류로 보고한다.

## 최초 이관 및 본래 환경 전환

1. 현행 Alembic head와 본래 DB 대상을 확인하고 기존 runbook에 따라 복구용 백업·사전 수량을 남긴다. 사용자 데이터는 출력하지 않는다.
2. 가산 migration으로 새 테이블·제약·인덱스만 생성한다. 기존 RAG·계정·문서 테이블을 수정하지 않는다. revision 번호는 구현 당시 head에서 배정한다.
3. 이관 도구 dry-run: 명시한 `issues.json`과 evidence Markdown만 읽는다. ID·상태·필수 필드·한도·경로/심볼릭 링크를 검사한다. 각 파일은 한 번 읽은 바이트로 해시·본문을 구성하고 입력 manifest를 만든다. 사용자 원본 파일을 자동 탐색하지 않는다.
4. 모든 입력 검증 후 단일 트랜잭션으로 카테고리·8개 문제·과거 사건·중복 제거한 문서/버전·연결을 넣는다. 같은 source_key/manifest의 재실행은 변화 없음이다. 다른 manifest 또는 기존 ID 충돌은 409로 중단하고 자동 덮어쓰기하지 않는다. 변경은 이후 관리 API에서 수행한다.
5. DB의 ID·본문 해시·관계·사건 수를 입력 manifest와 대조한다. 누락 또는 불일치 때 전환하지 않는다. 검증 성공 시 기존 서버에 API·화면 변경을 적용하고 실제 마스터로 확인한다.
6. 기존 JSON/Markdown은 삭제하지 않는다. DB 전환 후 원본 파일이 없어도 문서 조회가 가능한지 파일 로더를 사용하지 않는 통합 검증으로 확인한다. 원본을 실제 삭제하거나 새 테스트 환경을 만들지 않는다.

롤백은 앱 버전을 이전 상태로 되돌리고 새 테이블·데이터를 보존한다. DB에서 추가된 기록은 이전 파일 화면에 나타나지 않는다는 제한을 보고한다. 운영에서 테이블 drop으로 되돌리지 않는다. 부분 수입은 트랜잭션 롤백하며 재시도는 manifest 일치 때만 허용한다.

## 검증 및 구현 인계

- 단위: 상태·카테고리 제약, inactive 처리, revision 충돌, request_id 재전송/충돌, 문서 버전 고정, 순서·검색·페이지.
- API: 익명401/비owner403, public 차단, 문서 직접 ID 접근 보호, 본문 한도와 오류 응답, 변경 감사 원자성.
- PostgreSQL 통합: FK·고유키, 동시 문서 버전 생성·동시 이관, 실패 롤백, 동일 manifest 재실행, 누락·과대·경로 이탈 차단.
- 프론트: 한글 카테고리·편집·충돌 안내, 문제/이력/문서 연결·버전 표시, 기존 필터 회귀, 구 링크 안내.
- 본래 환경: 이관 수량·해시 대조, 기존 계정 로그인·8개 조회·문서 버전 조회, 계정/원본/RAG 자료 보존 확인. 시험 수정은 합성 자료의 롤백 트랜잭션으로 검증하고 더미 영속 데이터를 남기지 않는다.
- Python/TypeScript 타입·린트와 독립 검토를 완료하고 WORKBOARD·문제 기록 규칙·실행서를 갱신한다. 기존 JSON은 보존 자료라는 표시로 정본 혼동을 방지한다.

구현 순서는 migration/저장 서비스 → 멱등 이관 도구 → 권한 API·생성 타입 → 메뉴 조회·관리 UI → 본래 DB 이관·대조·적용이다. 상세 실행 계획과 명령은 설계 검토 뒤 작성한다.
