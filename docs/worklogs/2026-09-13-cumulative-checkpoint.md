# 누적 프로젝트 변경 커밋 점검

사용자가 이전 RAG·파일함·연구소 및 권한 구현까지 함께 커밋·푸시하도록 승인했다.
기준 main은 `9082bb5`이며, 최초 점검에서 미커밋665파일(수정165·미추적500)을 확인했다.
최신 권한0033은 미커밋0032와 파일함/도메인 코드에 의존하므로 누적 스냅샷으로 인계한다.

## 검증 및 공개 범위

- 이번 재실행: 백엔드 전체 단위2035통과·4skip(128.16초), 기존 Starlette/httpx 경고1건.
- 프론트 api:check·typecheck 통과. SearchPage22건 단독 재실행 통과(27.46초).
- 커밋 이후 기존 코드 기준 프론트 전체 lint도 exit0을 확인했다.
- 프론트 전체 테스트 첫 실행은 대화 테스트 제한시간 초과를 관찰하고 중단했다.
  단독 재실행은 통과했으나 전체 프론트 통과나 배포 완료로 표현하지 않는다.
- 독립 공개 위험 점검에서 실제 자격증명·개인 키·실행 DB·캐시·로그 후보를 발견하지 못했다.
  두 문서의 Windows 사용자 경로는 비식별 표기로 바꿨다. 이는 전수 보안 감사의 보장은 아니다.
- 합성 검증 자료는 후속 사용자 요청으로 원격 전송 범위에서 제외한다. 로컬 파일은 보존하며 생성 스크립트는 소스로 유지한다.
- `.local-data`, 환경 비밀값, 모델 캐시, 설치물·실행 산출물은 강제 추가하지 않는다.
- 실제 DB migration·API/worker 재시작·모델 호출·파일 삭제는 수행하지 않는다.

다음은 파일함 소유자 전용 기존 구성원 권한 편집 UI다. 신규 사용자 검색·초대와 실사용 DB 적용은 분리한다.

## 커밋과 원격 상태

누적 변경은 `b692dd4cd4ac3e46e58766edcb72b0dab2d70fbe`로 커밋했다(664파일).
후속 사용자가 샘플 제외를 요청하여 이 미푸시 커밋을 수정한다. 위 해시는 최초 체크포인트 이력이지 최신 HEAD를 뜻하지 않는다.
직후 작업트리는 깨끗했고, worktree는 main 한 개뿐이었다. 새 worktree나 설치물은 만들지 않았다.
푸시는 보안 검토가 원격 소유권/공개 범위 확인을 요구하여 차단했다. GitHub 메타데이터 조회도401이었다.
따라서 origin/main 반영은 확인되지 않았다. 사용자에게 정확한 원격과 전송 범위를 제시하고 확인을 요청했다.
원격 HEAD 읽기 조회 시점의 값은 `9082bb5`였다. 우회 전송이나 강제 푸시는 하지 않는다.

## 샘플 제외

PDF2종(`asset-management-ocr-v1.pdf`, `asset-management-text-v1.pdf`), `asset-management-reference.md`,
`asset-management-pdf-validation.md`는 `sample-data/public/rag/`의 로컬 검증 자료로 보존한다.
정확한4경로만 Git 추적에서 제외하고 ignore한다. 새 삭제 커밋만 추가하면 이전 커밋의 파일까지 전송되므로
아직 원격에 올라가지 않은 최초 커밋에서 제외한다. 이전 로컬 커밋은 reflog에 남을 수 있으나 푸시할 main 이력에서는 제외한다.
샘플 이름을 언급하는 과거 작업 기록은 역사적 검증 설명으로 유지하며, 새 clone에 샘플이 포함된다는 뜻은 아니다.
