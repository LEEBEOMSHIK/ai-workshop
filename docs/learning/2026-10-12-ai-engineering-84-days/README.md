## 매일의 운영 절차

1. 전날 실제 기록과 [미해결 질문](questions.md)을 읽는다. 처음이면 Day01로 시작하고 이해도는 미평가로 둔다. 부족한 선수 개념이 있으면 새 진도보다 보충을 먼저 한다.
2. 그날 목표와 원리를 짧게 설명한다. 사용자가 자기 말로 설명하기 전 이해했다고 추정하지 않는다.
3. 입력·내부 상태·변환·출력·실패 경로를 작은 데이터 흐름으로 그린다. 확률적인 모델 단계와 결정적인 검증 단계를 구분한다.
4. 당일 링크의 실제 코드에서 관련 함수·타입·호출자를 찾는다. 확인 시점과 파일 경로를 적고 구현/계획/추정/미검증을 표시한다. 파일이 바뀌면 경로를 재확인한다.
5. 읽기·손계산·합성 사례 문서 과제를 수행한다. 실행 실습이 필요하면 승인된 정확한 대상·환경·자료·예산·중단/원복 조건을 먼저 기록한다. 미승인 또는 차단이면 읽기 대안으로 계속한다.
6. 사용자의 재설명, 흐름 재현, 반례 또는 새 사례 적용으로 당일 기준을 확인한다. 틀린 답은 보충 질문으로 기록하며 AI가 답을 대신 써준 경우 검증 통과로 세지 않는다.
7. 실제 학습일의 기록을 만든 뒤 질문 → 검증 → 진도 순으로 갱신한다. 마지막에 다음 실제 학습 대상과 재검증 조건을 적는다.

운영 예시는 약 45–60분(전날 확인 5분, 원리 10분, 흐름/코드 15분, 과제 15분, 검증/기록 10분)이다. 사용자 시간 예산은 아직 미확인이고 고정 의무가 아니다. 시간이 부족하면 복습·한 가지 원리·미해결 기록까지 진행하고 미완료로 남긴다.

## 기록과 보충 규칙

일일 문서는 템플릿을 복사해 실제 학습일 `YYYY-MM-DD-day-NN.md`로 이 폴더에 만든다. 미리 84개 완료 일지를 생성하지 않는다. 같은 날 다른 Day를 보충하면 파일명/본문의 Day를 구분하고 진도표에 연결한다. 비공개 원문·질의·계정 정보·비밀값·내부 추론은 쓰지 않으며 공개 합성 예제와 비식별 요약만 둔다. 저장소 문서 작성은 공개 게시 승인이 아니다.

개념이 부족하면 `보충 필요`, 설명은 했지만 근거 확인이 남으면 `검증 대기`, 실행 권한/환경 부족이면 실행 실습을 `차단`으로 기록한다. 보충 완료는 다른 예제에 다시 적용한 증거로 판정한다. 주간 복습에서 0–2 또는 미평가 항목을 먼저 재평가하고 완료 개수는 실제 확인 완료 행만 센다. Day84에도 약한 개념은 이월한다.

## 이번 작업의 안전 범위

학습 문서와 WORKBOARD 최소 참조만 수정한다. 기존 미커밋·미추적 코드/설계/기록을 보존한다. 코드 변경, migration, commit/push, 설치, DB/Elasticsearch/Redis/Docker/프로세스 상태 변경, 실제 모델 실행, 외부 예약 변경은 하지 않는다. 스크립트 실행이나 별도 환경/DB/계정 생성은 학습 계획으로 자동 승인되지 않는다.

동시 작업 중에는 쓰기 직전 파일 상태/해시를 확인한다. 읽은 이후 변경됐으면 덮어쓰지 않고 그 대상 작업을 멈춰 충돌을 보고한다. 새 파일은 존재하지 않는지 확인하고 배타적으로 생성한다. 개발 기록의 과거 테스트 결과를 이번 실행 결과로 보고하지 않는다.
