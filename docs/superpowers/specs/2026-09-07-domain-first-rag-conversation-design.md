# 도메인 선택 후 진입하는 대화형 RAG

- 상태: 승인됨 / 구현·독립 리뷰 완료, 실제 연결 검증 대기
- 기준일: 2026-09-07
- 범위: 로그인 사용자 도메인 선택·대화 화면 및 관리자 도메인 연결
- 상위 설계: [다중 도메인 RAG](2026-09-02-public-ai-lab-rag-service-design.md),
  [대화형 생성 RAG](2026-09-04-conversational-generative-rag-v2-design.md)
- 실제 검증 결과는 연결된 작업 기록을 따른다. 기존 OCR·색인·생성 구현은 보존한다.

## 1. 현재 구현과 채택 방식

`SearchPage.tsx`에는 검색 이력과 검증된 assistant turn 전송 기능이 있지만,
구성·공간·폴더 선택 폼과 결과 카드가 중심이다. 첫 검색 이후 범위 변경도 잠긴다.
서버 페이지는 공간과 저장 구성만 조회하며 동적 전문 도메인 계약은 아직 없다.

채택안은 RAG 소유의 동적 도메인·불변 서비스 연결 버전을 추가하고 기존 검색·생성
서비스를 재사용하는 것이다. 공간/구성 이름을 도메인으로 재표시하는 대안은 전문 분야와
저장 위치를 혼동하므로 제외한다. 공개 릴리스·영속 대화·학습을 동시에 구현하는 대안도
여러 독립 단계를 섞게 되므로 제외한다. 이번에는 로그인 사용자 흐름에 집중한다.

## 2. 화면과 URL

| URL | 책임 |
|---|---|
| `/workshop/rag/search` | 사용 가능한 전문 도메인 선택 |
| `/workshop/rag/domains/{slug}/chat` | 도메인 대화형 RAG |
| `/admin/rag/domains` | 도메인 등록·서비스 연결 버전 관리 |
| `/admin/rag/configurations` | 기존 모델·색인·검색·생성 구성 관리 유지 |

입구에는 서버가 제공하는 도메인의 표시명·설명·준비 상태만 보여준다. 자산운용·보험·
금융·법률·HR을 프론트에 하드코딩하거나 빈 서비스로 생성하지 않는다. 등록 도메인이 없으면
준비 상태를 표시하고 owner에게만 등록 경로를 안내한다.

대화 화면은 가용 너비를 사용한다. 상단에는 도메인명·접을 수 있는 검색 범위·새 대화·
도메인 변경, 중앙에는 질문과 답변, 하단에는 입력창을 둔다. 관리자 설정·평가 도구·
프로파일 콤보박스는 제외한다. 응답 중 중복 전송을 막고 취소·재시도·실패를 구분한다.
위쪽 대화를 읽는 중에는 스크롤을 강제로 이동하지 않는다. Enter 전송·Shift+Enter 줄바꿈,
한글 IME 조합 중 전송 방지를 적용한다.

인용 클릭은 옆 원문 패널을 열어 기존 하이라이트와 좌표를 재사용한다. 모바일에서는
전체 너비 패널을 사용하고 닫기·초점 복귀를 지원한다. 정확 일치와 의미 강조를 구분한다.

## 3. 도메인·권한·구성 계약

도메인은 안정적인 slug·표시명·설명·활성 상태를 가진다. 불변 서비스 연결 버전은 정확한
저장 RAG 구성 버전과 허용 지식 공간을 참조한다. 연결 변경 시 새 버전을 만든다.
초기 자산운용의 실제 구성·공간 연결은 owner가 UI에서 명시한다. 기존 문서를 자동 재분류하거나
기존 이름으로 도메인을 추론하지 않는다. 공간의 여러 도메인 연결은 명시적 관리자 선택이다.

허용 범위는 `도메인 허용 공간 ∩ 구성 허용 공간 ∩ 현재 사용자 권한`이다. 도메인은 권한을
추가 부여하지 않는다. 목록·진입·매 검색에서 서버가 검사하며 비공개 공간명도 노출하지 않는다.
빈 교집합을 전체 검색으로 바꾸지 않는다. 폴더의 소속과 권한을 검증하고 기존 폴더 검색
규칙을 재사용한다. BM25와 dense 모두 검색 전에 같은 필터를 적용한다.

owner만 등록·수정·활성화할 수 있다. 활성화에는 평가된 구성과 LLM 생성 준비 조건이 필요하다.
미준비 도메인은 준비 중으로 표시하며 추출 답변을 LLM 대화처럼 보여주지 않는다.
외부 전송 고지·동의, 필수 모델 실패와 리랭커 선택 계약은 유지한다.

## 4. 대화 중 범위 변경

입장 시 도메인 연결 버전을 고정한다. 시작 범위는 권한 교집합 전체이며 대화 안에서 공간·
폴더로 좁힌다. 공간 전체 해제는 검색 불가, 폴더 선택 없음은 선택 공간 전체를 의미한다.

변경은 다음 질문부터 적용한다. 이전 대화·인용·당시 범위는 화면에 남기고 `검색 범위 변경`
구분선 뒤에서 새 문맥 구간을 시작한다. 변경 전 대화를 새 구간의 LLM history에 자동 포함하지
않는다. 지시어가 불명확하면 재질문하도록 안내한다. 이후 같은 구간의 검증된 질문·답변으로
후속 문맥을 이어간다. 이 규칙은 기존 대화를 삭제하거나 새 화면으로 이동한다는 뜻이 아니다.

assistant turn 서명은 사용자·구성 버전뿐 아니라 도메인 연결 버전·정규화된 검색 범위에
결합한다. 이전 범위 토큰 재사용은 서버에서 거절한다. 원문은 열 때도 현재 권한을 재검사한다.
응답 중 범위 변경은 막고, 도메인 변경·새 대화는 진행 요청을 취소한다. 늦은 응답이 새 대화에
붙지 않게 한다. 연결 변경·폐기·권한 회수는 명시적 오류와 새 대화 진입으로 처리한다.
대화는 이번 단계에서 메모리에 유지하며 새로고침 시 초기화됨을 안내한다. URL에 본문은 넣지 않는다.

## 5. 범위와 구현 순서

이번 수직 슬라이스는 도메인 관리·선택, 대화·후속 질문, 범위 조정, 인용·원문 패널이다.
기존 업로드 화면과 데이터는 유지한다. 인라인 임시 첨부·만료 삭제와 실제 피드백 저장은
상위 설계의 후속 단계이며 작동하지 않는 버튼을 완성된 기능처럼 추가하지 않는다.
공개 방문자의 비저장 정책, 로그인 피드백의 동의·수동 학습 승인 정책도 변경하지 않는다.

1. `backend/src/ai_workshop/labs/rag/domains/`에 도메인·연결 버전의 repository/service,
   owner 관리·사용자 조회 계약을 구현하고 migration·권한 테스트를 추가한다.
2. 도메인 검색 진입점은 서버에서 구성과 범위를 해석해 기존 검색 서비스를 호출한다.
   기존 `/api/v1/rag/search`는 관리자 검증·호환 경로로 보존한다. 새 경로는 별도 버전의
   범위 결합 turn 서명을 사용하며 기존 토큰을 받아 권한 검사를 우회하지 않는다.
3. `frontend/src/features/rag/domains/`와 `rag/conversation/`에 선택·등록과 메시지·입력·
   범위·근거 패널 책임을 분리한다. 기존 검색·원문 표시 기능을 재사용한다.
4. route·OpenAPI 타입·탐색·권한 회귀와 문서를 갱신한다. main에서 기존 OCR 변경과 사용자
   references를 보존한다. 모델·Docker 변경이나 공개 검색 활성화는 포함하지 않는다.

## 6. 수용 기준

- 도메인 추가에 프론트 수정이 필요 없고 입구에 공간·폴더·구성 선택 폼이 없다.
- 대화 화면은 메시지·입력·범위·근거 중심이며 관리자 설정이 없다.
- 같은 문맥 구간에서 후속 질문이 동작하고 변경 전 범위 토큰 재사용은 거절된다.
- 범위 변조·타 사용자 공간/폴더·권한 회수·빈 범위에서 문서나 이름이 노출되지 않는다.
- 잘못된 slug·비활성 연결·LLM 미준비·전송 미승인은 명시적으로 표시한다.
- 늦은 응답 혼입·한글 IME 오전송·모바일 폭·패널 초점 복귀를 테스트한다.
- 근거 부족·LLM 실패·인용 검증 실패를 성공 답변으로 표시하지 않는다.
- 단위 테스트는 외부 모델 없이, 통합 테스트는 사용자 DB와 격리해 실행한다.
- 공개 검색·인라인 첨부·피드백 저장이 구현됐다고 보고하지 않는다.
