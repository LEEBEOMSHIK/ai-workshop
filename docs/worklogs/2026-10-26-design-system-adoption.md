# 디자인 시스템 체계화와 업무 화면 적용

2026-10-26 사용자는 기존 디자인 시스템의 미적용 화면부터 조사해 적용하고, 다크·청록을 유지하며 차분하고 세련되게 정돈하도록 요청했다. 기존 체크아웃에서 표현 계층을 수정했다. 사용자에게 작업 등급·위험과 요구/구조/프론트엔드/문서 및 독립 검증 역할을 알렸으며 구현과 리뷰를 분리했다.

## 원인과 적용

- 공통 토큰과 ChoiceGroup은 존재했지만 기능별 직접 색상과 입력·버튼 규격이 분산돼 있었다. 전역 Georgia h1이 업무 화면에도 퍼지고 일부 조작 영역이44px보다 작았다.
- [토큰](../../frontend/src/shared/ui/tokens.css)에 표면·입력·선택·상태 색상, 타이포, 간격, 모서리, 조작 크기와 포커스 값을 모았다. 입력/라디오 선택자를 분리하고 기존 토큰 이름을 호환했다.
- 업무 제목은 산세리프 최대36px, 핵심 버튼·필드는44px 이상으로 정돈했다. 공개 hero·Publishing 읽기·게임·원문 하이라이트·다이어그램은 목적별 표현을 보존했다.
- 공용 [Button](../../frontend/src/shared/ui/Button.tsx)을 로그인, 작업공간 생성, 문제 이력 관리에 사용했다. 명시적 submit·disabled·native 속성·ref·aria와 기존 콜백을 유지했다.
- 탐색 셸·파일함·작업공간·권한·학습·이력·RAG 구성/모델/평가/실행·대화의 공통 값과 입력 규격을 연결했다. 대화 목록은 중립 표면, 선택한 대화만 청록 강조로 구분했다.
- 브라우저에서 발견한 입력 CSS 우선순위 문제는 실제로 이기는 기존 선택자를 수정했다. 토큰 선언만으로 적용 완료로 판단하지 않았다.
- 좁은 평가 카드의 가로 선택지가 세 줄로 갈라지는 문제는 ChoiceGroup 자체의 컨테이너 폭을 기준으로 세로 배치해 개선했다. 375px에서 각 항목44px·방향키 이동·청록 포커스 표시를 확인했다.

정적 조사 대상은 route27개와 기능 CSS27개다. [화면별 적용 현황](../guidelines/design-system-coverage.md)은 구현 연결과 의도된 예외를, [스타일 정본](../guidelines/ui-style-guide.md)은 새 화면 체크리스트를 제공한다. 이 수치는 전체27개 화면의 모든 상태를 E2E로 검증했다는 뜻이 아니다.

## 검증 근거

| RAG 구성·평가·원문 선택·실행 CSS 영향 | 관련12파일136테스트 통과 |
| 독립 기능 검토 | 탐색·대화 백그라운드/종료·평가 준비8파일58테스트 통과; 앞 행과 중복될 수 있어 단순 합산하지 않음 |

| 정적 검사 | 전체 frontend TypeScript와 변경 TS/TSX·합성 하네스 ESLint 통과; 변경 CSS 파싱과 diff 공백 검사 통과 |
| 토큰 대비 | 실제 tokens.css 기반2테스트 통과: 일반 텍스트31조합4.5:1 이상, 입력 경계·포커스3:1 이상. 실제 cascade 전체를 증명하는 검사는 아님 |

| 합성 브라우저 | 실제 컴포넌트/CSS를 exact-width iframe에 렌더링. 작업공간375/1280px, 이력 폼320/1280px, 평가320/375/1280px의 페이지 넘침 없음·관측 컨트롤44px 이상 확인 |
| 입력/상태 | 작업공간 합성403 오류 뒤 입력 유지, 평가 자료 방식 전환 후 입력 복원, 공통 버튼 동작/disabled와 라디오 방향키 이동 확인 |

합성 브라우저는 모든 fetch를 차단하거나 최소 합성 응답으로 대체했다. 평가·저장·모델을 실제로 실행하지 않았다. 기존 설치 의존성만 사용한 작업용 loopback preview를 사용했으며 로그인·라우팅·실제 업무 저장 E2E와 구분한다. 합성 Issue 응답의 envelope 결함은 fixture에서 수정했고 제품 결함으로 집계하지 않았다.

최종 공통 화면320/375px와 세로 선택 배치 적용 후 평가320/375px를 다시 확인했다. 모두 페이지 넘침 없음·관측 버튼/입력44px 이상이며 평가 선택 항목은 각각44px였다. 기존 대화의 최종 화면에서도 중립 목록·선택 강조·저장 답변·인용 표시를 확인했다. 작업용 preview 프로세스는 검증 뒤 종료했다. 문서 상대 링크53개 누락0·최근 완료 목록5개·최종 범위 공백 검사 통과를 확인했다.

최초 sandbox Vitest의 임시파일 EPERM은 수집0건으로 보존하고 통과/RED로 세지 않았다. 허용된 host 실행에서 실제 테스트 결과를 확인했다. Button 테스트는 모듈 미구현 실패 후 구현해 통과했다.

## 보존과 한계

독립 체크포인트의 기존2,224파일은 누락0, 허용된 UI·문서·WORKBOARD33파일 외2,191개 동일했고 `.env`와 backend는 보존됐다. 최종 문서 마감은 그 체크포인트 이후다. 세 Button 사용 TSX 외 업무 상태/계약 로직은 수정하지 않았다. 모델·검색·입력 근거·답변·인용·백그라운드 실행 수명은 변경하지 않았다.

실모델 호출, 설치, 본래 서비스 재시작, RAG 프로파일/DB 변경, commit/push는 수행하지 않았다. 기존 첫 입력 처리 시간과 답변 정답0/2 한계는 그대로이며 UI 회귀 통과를 품질 개선으로 해석하지 않는다. 관리자 문제 이력은 저장소 지침에 따라 기존 로그인된 화면에서 **ISSUE-00040**으로 등록했다. 원인·수정·검증·제한과 날짜별 완료 사건을 저장하고 새로고침 후 재조회했다.

운영 이력 링크: [ISSUE-00040](http://127.0.0.1:5173/admin/system/issues?issue=80d1511b-5f95-4afc-b8b2-b06df458c4c9). 상세 Markdown은 저장소 기록이며 DB 문서 버전으로 별도 등록한 것은 아니다.

모든 route의 권한·빈 상태·오류·모달·툴팁 조합을 실제 브라우저로 확인한 것은 아니다. 신규/수정 화면은 스타일 체크리스트와 적용 목록을 갱신하고 그 화면의 실제 컨테이너·긴 문구·포커스를 확인한다.
