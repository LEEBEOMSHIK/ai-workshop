# 학습 업무 분야와 출발점 연결 표현

## 요구와 범위

- 자유 문자열로 보이던 업무 분야를 선택 가능한 카테고리로 표시한다.
- 작성 패널 아래 목록 구분선이 겹치는 부분을 정리한다.
- 연결선은 인접 차수가 아니라 저장된 출발점과 이번 학습의 관계를 전달한다.

## 설계

기존 `domain_labels` 저장 형식과 모든 기존 값을 유지한다. 현재 학습 API에 공통 업무 분야 카탈로그가 없으므로 다른 Lab의 도메인 API에 의존하거나 임의의 고정 분류를 만들지 않는다. 기록에 있던 값과 작성 중 추가한 값을 선택·해제할 수 있게 한다.

현재 출발점 데이터는 `start_mode`, `source_label`, `source_evidence`이며 부모 기록 ID는 없다. 따라서 같은 흐름의 인접 차수를 연결하는 선을 제거한다. 이어 학습은 저장된 출발점 설명에서 이번 학습으로 이어지는 방향으로 표현하고, 원본 시작·출발점 미확인·미실행 계획은 구분한다. 기록 간 실제 가중치 계승을 새로 검증하거나 추론하지 않는다.

## 책임과 검증

메인이 요구 설계·간격·문서 통합을 담당하고, 카테고리/학습 흐름 구현을 분리한다. 독립 검증 담당이 실제 기존 환경의 두 테마와 좁은 화면을 점검한다. 모델 실행·API·DB 변경은 없다. 다른 세션의 학습 작업과 저장 자료를 보존한다.

## 검증 결과

- 학습 회귀 17파일100건 중99건 통과 후, 기존 텍스트 입력을 찾던 테스트1건을 카테고리 선택·읽기 전용 검증으로 변경했다. 해당 상세 화면19건을 재실행하여 모두 통과했다.
- 독립 검증: 카테고리·편집·출발점·계승 4파일26건 통과. 신규 추가·Enter의 저장 방지·한글 조합·선택 해제와 재선택·기존 분류값 보존을 합성 데이터로 확인했다.
- TypeScript 및 변경 TS/TSX ESLint 통과. 마지막 상세 테스트 변경도 별도 ESLint 통과.
- 본래 브라우저: 라이트/다크 desktop/320px에서 출발점→이번 차수, 모바일 세로 화살표, 계획의 연결 없음, 가로 넘침 없음 확인. 작성기 아래32px 간격과 중복 경계선 제거 확인.
- 실제 기록 변경·저장 없이 검증하고 다크·기본 폭·닫힌 작성기로 복원했다. 분류 입력 상호작용은 자동 테스트에서 검증했다.
- 첫 전체 테스트 시도는 임시 파일 권한 문제로 수집 실패했으며, 권한이 허용된 재실행에서 위 결과를 얻었다.

문제 이력 DB 쓰기는 앞선 자동 승인 차단으로 재시도하지 않았다. 공통 업무 분야 카탈로그나 부모 기록 ID를 추가한 작업은 아니며, 저장된 출발점 설명을 시각화한다.
