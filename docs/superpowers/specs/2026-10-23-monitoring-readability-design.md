# 실행 모니터링 가독성 개선

- 사용자 요청: 실제 모니터링이 텍스트 중심이라 읽기 어렵다는 피드백.
- 목적: 누가 누구에게 위임했는지, 어디서 시간이 걸렸는지, 실행 완료와 답변 품질을 빠르게 구분한다.
- 범위: 기존 실행 상세와 공유 AgentTracePanel의 표시 구조. API·권한·본문 보관·모델·DB 계약은 유지한다.

## 선택한 표현

문구 축약만으로는 반복된 항목과 긴 정보 목록이 남는다. 자유 이동 그래프는 현재 다섯 단계에 과하고 새 의존성·키보드 조작 비용이 크다. 기존 React·CSS로 요약 지표, 부모 관계를 나타내는 연결선과 간결한 노드, 선택 상세를 조합한다. 이는 요청을 구현하기 위한 담당자의 선택이며 새로운 제품 정책을 사용자 결정으로 간주하지 않는다.

## 화면과 의미

- 실행 상세 상단에 실행 상태·답변 상태·품질 결과·전체 시간을 구분한 요약을 둔다. 품질 실패를 완료 색상으로 가리지 않는다.
- 위임 패널은 실제 에이전트/위임/모델 호출 수와 간결한 단계 노드를 먼저 보여준다. 이름·부모 ID·상태는 실제 trace에서 읽고 특정 이름이나 질문으로 분기하지 않는다.
- 연결선은 부모 관계를 뜻한다. 순서가 연속이라는 이유만으로 다른 분기를 연결하거나 병렬 실행을 직렬로 표시하지 않는다.
- 위임 상세는 발신 에이전트 → 수신 에이전트와 as_tool/handoff 의미를 전면에 둔다. 모델·토큰 정보는 해당 모델 단계에서 보여준다.
- 지침·입력·결과는 접어서 열 수 있고 미수집/미보관/크기 제한/검증 실패를 구분한다. 본문 수집 정책과 실패 초안 비노출을 유지한다.
- 정확한 시간·ID·revision·해시 등 기록 정보는 접은 상세에 둔다. 일부 관측 누락·실패·취소와 실제 종료의 차이는 기본 화면에서 숨기지 않는다.
- 단계 시간 막대는 관측된 단계의 상대 소요 시간 비교다. 중첩 SDK span을 합산해 전체 시간이나 실행 진행률로 표시하지 않는다. 시간 미기록은0으로 바꾸지 않는다.
- 기존 어두운 배경·청록 강조 토큰, 44px 컨트롤, 키보드 선택·포커스·320/375px 줄바꿈을 유지한다.

## 성공 기준

1. 기본 화면에서 실행/품질 결과와 위임 방향, 모델 호출 수를 읽을 수 있다.
2. 모든 실제 단계는 선택 가능하고 현재 입력/결과·원문 참조를 확인할 수 있다. 이력 본문은 재노출하지 않는다.
3. 같은 데이터의 새 실행 ID·누락·실패·취소·미보고 사용량을 정확히 표시한다.
4. 관련 UI 테스트·타입·린트·독립 검증과 실제 CSS의 좁은 폭/키보드 확인을 수행한다.
5. 로그인된 기존 완료 실행을 읽기 전용으로 확인한다. 새 생성·임베딩·재시작·설치·commit/push는 없다.

## 후속 요청: 에이전트 그림과 역할 확인

같은 날 사용자는 위임 흐름을 더 그림처럼 표현하고 호버 또는 클릭으로 어떤 에이전트인지 확인하기를 요청했다. 기본 화면을 에이전트 중심의 노드와 방향 화살표로 바꾸고 전체 호출 기록은 펼쳐 보는 구조로 보강한다. 기존 트리만 꾸미면 요청한 시각적 변화가 작고, 자유 이동 캔버스는 새 의존성과 별도 키보드 탐색을 요구한다. 기존 React·CSS·SVG의 고정 흐름도와 버튼을 사용한다는 것은 구현 담당자의 선택이다.

- 기본 그림에는 실제 agent span만 노드로 표시한다. 모델/도구 호출 수는 해당 에이전트의 관측으로 묶되 하위 에이전트의 호출을 부모 호출로 중복 귀속하지 않는다.
- 호출 귀속은 가장 가까운 조상 agent ID에서 중단한다. 조상 에이전트가 없는 호출을 임의 루트에 붙이지 않는다.
- 화살표는 실제 부모 연결로 확인되는 관계만 나타낸다. 위임 선을 선택하면 기존 위임 단계 상세를 연다. 이름 일치만으로 연결하지 않으며 as_tool·handoff와 단순 상하위 실행을 구분한다.
- 카드의 호버·키보드 포커스에 간단한 정보, 클릭/Enter/Space에는 유지되는 상세를 제공한다. 정보는 이름, 이 실행에서 관측된 역할(시작/위임받아 처리/추가 위임), 위임한/받은 대상, 관측 모델·호출 수·상태·시간이다. 임의 이름과 반복된 동일 이름도 span ID로 구분한다.
- 짧은 정보는 포인터가 정보 영역으로 이동해도 읽을 수 있고 Escape로 닫을 수 있다. Escape가 노드의 키보드 포커스나 클릭한 상세 선택을 없애지 않는다.
- 기록된 관계의 설명은 저장된 역할 정의나 원래 지침 전문이 아니다. 제품 UI에 rag_manager/answer_specialist 등의 이름별 설명 분기를 하드코딩하지 않는다. 미기록 정보와 이력 본문 정책은 유지한다.
- 전체 단계 기록은 접힌 영역에서 모두 선택할 수 있고, 그림 선택과 상세 선택은 같은 span ID를 따른다. run ID 변경 시 선택과 임시 정보가 새 기록 기준으로 초기화된다.
- 복수 분기·관측 누락·없는 부모·순환·64단계와 좁은320/375px에서 허위 연결, 잘림, 가로 넘침 없이 정보를 확인한다. 긴 이름은 줄바꿈하며 그래프가 전체 페이지 폭을 강제로 늘리지 않는다.
- 이번에는 표시용 파생 정보만 사용한다. API·DB·생성 정책 변경이나 추가 모델 호출 없이 저장된 실제 SDK 실행을 검증한다.

SDK 질문에 대한 코드 근거는 `orchestration/openai_agents.py`의 `Runner.run(manager, ...)`, manager의 `tool_choice=required`·`stop_on_first_tool`, specialist의 `as_tool`이다. 현재 조정자와 답변 담당은 같은 해석된 배포를 사용한다. 이는 라이브러리 일반 기능 설명이 아닌 현재 프로젝트 구현에 대한 설명이다.

## 사용자 피드백: 중간 단계와 설명 명확성

사용자는 호버 정보가 추상적이고 `#1 → #4`가 중간 단계를 건너뛴 직접 위임처럼 보인다고 지적했다. 앞선 agent-only 그림의 선택이 실제 실행을 설명하는 데 부족했다. 번호는 에이전트 번호가 아니라 전체 span 기록 순서인데, 모델 호출은 개수로만 요약하고 위임 번호·이름도 선에서 숨긴 것이 원인이다.

단순히 번호를 다시 매기면 누락된 정보가 돌아오지 않는다. 모든 span을 일렬로 연결하면 형제 호출·병렬 분기를 인과관계로 오인할 수 있다. 따라서 담당자는 기존 카드 중심 그림을 유지하되 **에이전트 내부 호출과 사이의 위임 단계를 기본으로 노출하는 그룹 그림**을 선택한다. 이는 사용자 피드백을 구현하기 위한 선택이다.

- 에이전트 카드 안에 그 agent ID에 귀속된 모델·도구의 기록 번호·종류·이름·상태·시간을 표시하고 선택할 수 있게 한다. 버튼 안에 다른 버튼을 중첩하지 않는다.
- 위임 연결에 실제 기록 번호·도구 이름·위임 방식·상태를 표시한다. `#1 → #4`처럼 중간 기록을 숨긴 숫자 화살표는 제거한다. 번호는 기록 순서이며 에이전트 수나 의존 순서를 뜻하지 않는다고 짧게 설명한다.
- 예컨대 실제 완료 기록의 manager 안에 모델#2, 별도 위임#3, specialist 안에 모델#5가 모두 보인다. 모델#2와 위임#3이 모두 manager의 자식이라는 구조를 유지한다. 순서만으로 새 인과 화살표를 만들지 않는다.
- 호버·포커스·선택 설명은 ‘다른 에이전트에 작업을 맡김’, ‘누구에게서 어떤 도구로 작업을 받음’, 실제 모델 호출을 이름과 함께 쉬운 문장으로 전달한다. 원래 업무 지침은 미기록임을 구분하며 이름별 역할 설명을 하드코딩하지 않는다.
- 기존 소속 없는 호출·누락/순환·실패·취소와 동일 이름/분기/64단계·본문 정책을 보존한다. 모든 span은 전체 기록에서 접근 가능하다. 모델/도구/위임 표시를 위해 API·DB 계약이나 모델 호출을 추가하지 않는다.
- 검증은 기본 그림의 전체5기록 노출, 호출 선택과 실제 부모 관계, 설명 문장, 키보드·tooltip, 실제 CSS 좁은 폭과 로그인된 기존 실행에 집중한다.
