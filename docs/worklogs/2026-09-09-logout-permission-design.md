# 로그아웃 연결과 기술별 권한 설계

## 구현 완료: 로그아웃 UI

관리자·작업소 공통 AreaNavigation의 사용자 이름 옆에 로그아웃을 연결했다.
기존 logout API를 호출하고 성공 시 로그인 화면으로 전체 문서를 교체한다.
중복 클릭은 막고 실패 시 안전한 오류와 재시도를 제공한다. 백엔드 인증 계약은 변경하지 않았다.

- 버튼 부재로 신규5건 실패 확인 후 GREEN.
- 구현자·메인 관련7파일37건 통과(메인28.29초), 타입·범위 ESLint·패치 역방향 검사 통과.
- 독립 보안/코드 검토에서 차단 결함 없음.
- 실제 작업소와 관리자 모델 화면에서 이름 옆 로그아웃 버튼을 확인했다.
  사용자의 세션을 유지하기 위해 실제 버튼 클릭/로그아웃은 수행하지 않았다.
- 기존 API는 브라우저 세션 쿠키 삭제 방식이며 탈취/복사된 JWT의 개별 서버 폐기를 제공하는
  기능으로 확대 해석하지 않는다. 그런 세션 관리 재설계는 별도 범위다.

## 설계 단계: 마스터·기술별 권한

[상세 초안](../superpowers/specs/2026-09-09-technology-permissions-design.md)을 작성하고
독립 보안 검토를 수행했다. 기존 owner 저장값과 문서 권한을 보존하며 master 표시,
view/configure/execute, 원자적 마지막 마스터 보호, revision/감사, 안전 DTO와 회수 gate를 정의했다.
현재 기술별 권한 기능·관리 페이지·migration은 구현하지 않았고 실제 권한도 변경하지 않았다.
상세 초안 사용자 확인 후 ADR/시스템 계약 갱신과 구현 계획으로 진행한다.

권한은 기존 사용자 대상으로 시작한다. 회원 초대/가입·비밀번호 재설정은 별도 단계이며
현재 한 명이라는 이유로 가짜 회원/미래 기술/테스트 grant를 운영 DB에 생성하지 않는다.
마스터 권한도 외부 전송 승인·자료 membership을 우회하지 않는다.

인계 자료: `.local-data/project-agent-work/logout-ui/`, `technology-permissions/`.
기존 dirty 변경·서버·사용자 자료를 유지했고 커밋/푸시/정리를 수행하지 않았다.
