# ADR-0017: 개인용 Codex exec와 내부 통제 지침을 별도 경계로 설계한다

- 결정일: 2026-09-07
- 상태: 제한 실행 방향·잔여 위험과 상세 설계 승인 / 입력·출력 계약 구현 중
- 정본: [개인용 Codex CLI RAG 상세 설계](../superpowers/specs/2026-09-07-personal-codex-exec-rag-design.md)

## 배경과 승인

사용자는 계정 사용량을 사용하는 Codex CLI로 RAG 답변을 먼저 확인하고, 별도로 로컬 모델과
파인튜닝을 공부하려 한다. 완전한 호스트 읽기·도구 차단을 보장할 수 없다는 설명에 대해
제한 실행을 수용했으며, 내부 시스템 프롬프트로 동작을 통제하도록 추가 지시했다.
학습 기록·공개 화면 확장은 실제 근거 제한 답변·인용·후속 질문 연결보다 후순위다.

## 결정

기존 `ADR-0010`의 SDK, `ADR-0011`의 App Server와 자체 LPAC 실행기 차단은 유지한다.
이들 경로가 기존 격리 기준을 통과했다고 바꾸지 않고 별도 development-only Codex exec Provider를 설계한다.
개인 owner·검토된 공개/합성 자료·현재 외부 전송 정책과 명시적 실행 동의로 한정한다.
코드 구현이나 Provider 활성화가 완료됐다는 결정이 아니다.

내부 지침은 버전된 신뢰 자산으로 관리하고 공식 추가 developer instruction 경로를 사용한다.
질문·문서·이력은 신뢰되지 않은 데이터로 분리한다. 도구/파일 접근 금지, 근거 제한,
역할 위장 지시 무시와 구조화 출력을 명시하며 상위 CLI·모델 정책은 교체하지 않는다.
프롬프트 통제와 서버 권한·전송 정책, 최소 실행 권한, 이벤트/예산·인용 검증을 함께 적용한다.

CLI는 로컬에서 실행해도 모델 추론·입력 처리는 외부이므로 외부 전송으로 표시한다.
인증은 공식 CLI 경로를 사용하며 토큰 추출·복사·DB 저장과 Windows 정책 우회는 금지한다.
요청 모델과 확인된 모델을 혼동하지 않으며, 기존 Provider의 모델 무결성 기준은 완화하지 않는다.

## 결과와 비용

- 전체 도구 사전 증명을 이 별도 제한 경로의 필수 조건으로 사용하지 않는다. 그에 따른
  호스트 읽기·의도치 않은 도구 동작의 잔여 위험은 존재하며 프롬프트로 제거됐다고 주장하지 않는다.
- 개인용 기능을 일반 사용자·공개 서비스·운영 환경·비공개 문서용으로 자동 승격할 수 없다.
- 지침·출력 버전, CLI 수명주기, 실제 모델 identity·사용량, 데이터 정책 접합을 별도로 검증해야 한다.
- 무과금 상태 조회와 계정 사용량을 발생시키는 실제 연결 검사를 구분한다.
- 자동 검사와 실제 RAG 대화 검증을 모두 통과하기 전 사용자 테스트 준비 완료로 표시하지 않는다.

## 후속

2026-09-09 추가 승인: 개인 개발용 Codex exec는 요청 모델과 관측 모델 `미확인`을 분리
표시하고, 모델 식별 증거를 사용 준비의 필수 조건에서 제외한다. 다른 Provider의 기준과
권한·전송·출력·인용 검증은 유지한다. 예외의 정확한 경계와 CLI 출력 호환성 보완은 정본 §7을 따른다.

2026-09-07 상세 문서의 독립 검토 보완과 사용자 확인을 마쳤다.
[입력·출력 계약 구현 계획](../superpowers/plans/2026-09-07-codex-exec-contracts.md)부터 실행한다. 구현은 역할별 엔지니어에게
배정하고 독립 검증·리뷰를 분리한다. 구체적인 실제 호출·DB 변경은 해당 단계의 입력과 영향을 고지한다.
