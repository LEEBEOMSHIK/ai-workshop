# 문서 승인 복구 작업 기록

- 상세 설계 사용자 승인: 2026-09-10
- 구현 계획: `docs/superpowers/plans/2026-09-10-document-transfer-reapproval.md`
- 상태: 구현 중. 실제 DB migration·문서 승인·모델 호출 미실행.

## 원인

기존 승인 테이블은 문서 revision이 기본키이며 취소는 복구 불가능한 변경이었다.
문서 hash 중복 방지와 결합돼 같은 자료를 재승인하려는 사용자가 막혔다.
취소 상태를 단순 해제하면 이전 일회성 호출 승인이 부활할 수 있어 문서 버전이 아닌
승인 세대·불변 이력·새 호출 binding으로 수정한다.

## 책임과 범위

Python/DB 구현과 독립 보안·코드 리뷰를 분리한다. 다음으로 관리자 UI, 사용자 요청 API,
파일함과 관리자 처리함 UI를 연결한다. 기존 Platform assets는 Lab을 직접 참조하지 않고
상위 composition에서 승인 component를 주입한다. Codex owner-only 실행은 유지한다.

## 운영 적용 경계

Task1 관리자 승인/보안/API 구현은 단위845 통과(기존 플랫폼4skip), 격리PG61,
타입7파일/린트16파일 통과 후 독립 검토했다. 목록 상태/이력 조회 경합 지적은
REPEATABLE READ snapshot과 실제 PG 경합 회귀로 보완했으며 관련4건·재검토 통과했다.
실행 세대 검사·이력 보존·구버전 writer 차단·멱등 replay·동시 첫 승인·기존 문서 접근을 검증했다.

Task2 관리자 재승인 UI는 관련109건과 타입/린트/API 검사를 통과했다. 독립 리뷰의
진행 중/재시도 표시 구분과 대칭 오류 경로 테스트 보완 후 focused16건·재검토 통과했다.
일반 사용자 요청 API·파일함/처리함은 후속 구현이며 실제 브라우저 승인은 하지 않았다.

코드 완료만으로 실행 중 서버와 DB가 변경되지 않는다. 구버전 writer를 중단한 상태에서
백업과 스키마 head 확인→migration→신규 서버→상태 조회를 함께 수행해야 한다.
기존 문서 승인은 자동 복구하지 않으며 사용자 최종 확인을 받아 별도 새 이력으로 만든다.
회귀 테스트는 합성 fixture와 격리 DB를 사용하고 실제 사용자 DB를 reset하지 않는다.
