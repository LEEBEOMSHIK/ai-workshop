# 단계 모달의 핵심 정보와 기술 상세 분리

- 요청: 모달에서 무엇을 설명하는지, 무엇이 중요하고 무엇이 부수 정보인지 구분하기 어렵다.
- 범위: 승인된 Mermaid 단계 모달의 가독성 후속. 저장·모델·검색·권한 계약은 변경하지 않는다.
- 성공 기준: 처음 열었을 때 역할, 받은 요청, 반환 결과를 읽을 수 있고 긴 지침·반복 필드·ID가 이를 밀어내지 않는다.

## 접근 방식

글자 크기나 색상만 조절하면 정보 우선순위가 바뀌지 않는다. 자동 LLM 요약은 추가 호출과 원문 왜곡 위험을 만든다. 이번 구현에서는 **기록된 필드를 목적별로 고르고, 핵심 내용과 펼쳐 보는 상세를 분리**한다. 이는 사용자 피드백에 따른 구현 판단이며, 사용자가 개별 문구까지 선택했다는 의미가 아니다.

## 화면 구조

1. 상단: 단계 이름·종류, 상태/시간, 실제 부모·위임 관계에서 확인한 역할 한 줄. 이름에 따라 임의 역할을 지정하지 않는다.
2. 먼저 읽는 내용: `받은 요청`과 `반환한 결과`를 큰 본문으로 나란히 표시한다. 질문/작업 요청과 답변 claims의 본문을 우선한다. 모델·도구 단계의 messages/content/arguments/tool_calls는 관측된 요청·반환과 구분해 표시한다.
3. `적용 지침`과 `함께 전달된 자료`: 펼쳐 보는 원문 지침, 대화 이력, 검색 근거를 제공한다. 동일한 재작성 질문은 기본 화면에 반복하지 않는다. 사용 가능 근거 개수를 실제 전달·인용·검증 개수로 바꾸지 않는다.
4. `원문·기술 기록`: 전체 구조화 내용, 정확한 원문, ID/SHA, 토큰·시각을 필요한 사람만 펼쳐 본다. 원문 연결도 보존한다. UUID와 알 수 없는 필드 개수는 첫 화면 핵심 내용에 노출하지 않는다.

## 사실성·접근성

- 관측한 반환값과 최종 답변 품질 통과는 구분한다. 성공 실행을 정답으로 표시하지 않는다.
- 임의 지침 번역/요약, 중요한 규칙의 추측, LLM 내부 추론 생성은 없다. 기존 영어 지침은 원문으로 보존한다.
- 보관 상태/표시 허용을 먼저 확인하고 미보관·비활성·검증 실패 등의 본문을 DOM에 넣지 않는다.
- 없는 필드를 빈 질문·근거0개·성공 결과로 해석하지 않는다. 명시적인0·false·null은 보존한다.
- 중첩 JSON은 크기·깊이·항목 수를 제한하고 제한/알 수 없는 구조에는 전체 원문 경로를 남긴다.
- 단일 모달의 Escape·Tab·배경 잠금·호출 노드 포커스 복귀, 44px 컨트롤, 320/375/1280px 줄바꿈을 유지한다.

## 제외

새 생성·임베딩, 서비스 재시작, 프로파일 변경, 멀티턴 서버 관측 기능, 위치 영속 저장, 새 라이브러리, commit/push는 수행하지 않는다. 기존174개 변경의 기준 해시를 보관한다.

## 후속: 자료 확인 경로와 도움말

사용자는 함께 전달된 자료를 확인하기 어렵고 아래 펼침 항목의 뜻을 `?` 아이콘으로 설명해 달라고 요청했다. 본래 완료 실행에서 manager 입력은 available_evidence_count만 있고 specialist와 답변 모델의 입력에 실제 evidence 본문이 있다. 이는 현재 확인한 자료 부재의 원인이며 저장 누락으로 판정하지 않는다.

- 현재 단계의 입력에 본문이 없을 때 그 상태를 짧게 설명하고, 실제 기록된 부모/자식 관계로 연결된 단계 중 열람 가능한 근거 본문이 있는 단계로 이동시킨다. 이름·순서·28개 등의 값을 하드코딩하지 않는다. 해당 단계 이름·번호·근거 개수를 표시하며 다른 단계 자료를 현재 단계에 전달됐다고 표시하지 않는다.
- 이동 후 대상 단계의 자료 영역이 열리고 본문이 보인다. 선택·포커스와 모달 닫기 복귀를 유지한다. 관련 단계가 없거나 본문이 숨김/미수집이면 해당 상태를 표시한다.
- `적용 지침`, `함께 전달된 자료`, `원문·기술 기록` 각각의 `?` 도움말에서 무엇을 볼 수 있고 언제 확인할지 설명한다. 기본 화면에 긴 설명은 늘리지 않는다. 마우스 hover·키보드 focus·클릭/터치로 확인하며 도움말과 본문 펼침은 독립 동작한다. Escape는 열린 도움말부터 닫고 다음 Escape에서 모달을 닫는다.
- 근거 본문은 읽을 수 있는 구분과 번호를 제공한다. 입력에 없는 문서 제목/출처·자료 내용은 추정하지 않으며 기존 정확한 원문 경로와 본문 표시 정책을 유지한다.

접근 선택은 기록을 복제하거나 manager 입력을 바꾸는 대신 실제 본문이 있는 단계로 연결하는 것이다. hover 전용 title 속성은 모바일·키보드 설명에 부족하므로 접근 가능한 도움말을 선택한다. 기존 모달 요청의 구체적 보완이며 별도 모델 실행·저장 계약 확장은 없다.

## 후속: 도움말 호버와 흐름 전체 결과

사용자 요청(2026-10-24): `?`의 클릭 고정을 없애고 실행 흐름에 전체 판단과 시간을 추가한다.

- 도움말은 포인터가 아이콘/설명 위에 있을 때만 유지한다. 클릭으로 고정하거나 다른 모달/펼침을 열지 않는다. 마우스 클릭으로 생긴 포커스가 툴팁을 남기지 않는다. 키보드 포커스 설명과 Escape 우선 닫기는 접근성을 위해 유지한다.
- Mermaid 흐름 안의 상단에 전체 결과를 짧게 설명하고 실행·답변·품질·전체 소요 시간을 구분한다. 기존 ExecutionDetail의 저장된 상태와 duration_ms를 전달하며 에이전트 단계 성공에서 품질을 추정하지 않는다.
- 완료+품질 실패는 ‘실행 완료 · 품질 실패’로 구별하며 미검증, 진행/취소/실패, 시간 미기록과 0초도 사실대로 표시한다. 전체 시간에 중첩 단계 시간을 합산하지 않는다.
- 전체 실행 정보가 없는 재사용 경로는 미기록/미검증으로 명시하고 성공을 만들지 않는다. 새 API, 모델 호출, 프로파일/DB 변경은 없다.
- 흐름 배치·노드 상세·자료 이동·키보드/Escape와 320/375/1280px 가독성을 보존한다.
