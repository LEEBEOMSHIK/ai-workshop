# 원문 관계를 보존하는 상대 영업일 인용 검증

- 작업: ISSUE-00045, 2026-10-30 사용자 실행 승인.
- 근거: [실제 비교](../../worklogs/2026-10-30-terra-gemma-new-question.md), [ADR-0035](../../decisions/0035-rag-exact-value-canonicalization.md).

## 목적과 범위

같은 주장에 인용된 원문의 T/N 정의와 표의 `T+2`를 함께 풀어 쓴 `2영업일`을 검증한다. 단순 숫자 집합 비교로 생긴 Terra 두 저장 응답의 거절을 해결하되 다른 상품·항목·기준점·기간을 합성하는 새 허용은 막는다. 모델/프롬프트/기본 설정, DB 스키마, API 응답 계약, 과거 응답·판정은 바꾸지 않는다. 신규 모델 호출 없이 저장 응답과 공개 합성 근거로 검증한다.

## 접근 선택

- 무조건 `T+숫자`를 영업일로 변환하면 단위·기준점·대상 관계를 잃으므로 제외한다.
- 추가 LLM 판정은 비용·비결정성을 늘리므로 제외한다.
- 선택: **명시적 정의와 같은 출처 표의 관계를 증명하는 결정론적 제한 경로**. 기존 어휘 값 검사에서 누락된 영업일 값만 보충하며 해석할 수 없는 형식은 기존 거절을 유지한다. 구현 세부 형식 제한은 메인 Codex 판단이며 보편 자연어 추론 기능을 뜻하지 않는다.

## 수용 계약

1. schema1/2 CitationValidator 내부 helper에서 현재 주장에 실제 인용된 허용 근거만 사용한다. exact_values 및 schema3 계산 검증은 그대로다.
2. 같은 document/version/projection/chunk/page/source kind/part/section에서 인접 ordinal·문자 범위를 갖는 정의 조각만 연결한다. 입력 순서를 임의 정렬해 불연속·역순·중복 출처를 복원하지 않는다. 원문이나 citation ID는 수정하지 않는다.
3. 명시된 영업일 단위, 기준 문자와 접수일, 다음 영업일부터 N일을 세는 정의가 필요하다. 상충·부정·미완성 정의, 다른 기준 문자/방향/단위는 지원하지 않는다.
4. 표의 대상 머리·항목·값을 같은 주장에 인용해야 한다. 명시적 문구와 기존 보존 PDF 위치로 유일한 행·열 연결을 확인한다. 위치만으로 의미를 만들지 않으며 다른 상품 열·중복 대상·다른 행 값은 거절한다.
5. 주장은 같은 기준점·계산 시작·기간·상대 오프셋·항목을 명시해야 한다. 잘못된 숫자/부호/상품/항목/시작점이나 지원하지 않는 문구는 새 허용으로 통과시키지 않는다.
6. 추가된 지원 값 외의 모든 값은 기존 검사대로 검증한다. 기존 오류 코드 `exact_value_not_supported`, 권한/출처 검사, 실패 초안 비노출을 유지한다.

## 성공 기준과 한계

- 저장 Terra 두 응답은 원문·claim·citation을 바꾸지 않고 수정 검사에서 수용된다.
- 정의 누락/미인용/분절 단절/출처 혼합, 잘못된 단위·기간·기준점·상품·행·부정·충돌은 거절된다.
- 기존 수치·인용·schema3 회귀 및 독립 리뷰를 통과한다.
- Gemma의 기존 숫자 검사 통과와 의미 검토 실패는 별도 상태로 보존한다. 기존 숫자 검사에 없던 모든 의미 오류 검출까지 약속하지 않는다.
- CitationValidator는 질문을 전달받지 않는다. 주장에 명시된 상품과 인용 표 머리의 일치, 표의 행/열 관계를 검사하며, 상품이 생략된 주장이 원래 질문 대상을 뜻하는지까지 검증하지 않는다. 이 기능은 숫자 인용 지원이며 질문 완전성 판정이 아니다.
- 저장 비교의 과거 판정은 수정하지 않고 새 재검증 기록에 전후를 남긴다. 본래 API 반영과 기존 환경 확인, ISSUE45 이력을 마감한다.
