# 사용자 작업 순서의 모델 관리자 탭

## 승인된 구성

1. 현재 구성 확인: 등록된 모델·프로파일·배포 조회. 등록과 실제 활성 상태를 구분한다.
2. 모델·실행 환경 설정: 모델 등록과 공급자별 기존 실행 설정.
3. 처리·검색·답변 구성: 문서 처리 → 색인 → 검색 → 생성 순서.
4. 데이터 사용 범위·승인: 기존 정책 저장과 정확한 문서 버전 승인.
5. 연결 검사·사용 준비: 기존 저장 구성 화면으로 이동. 검사 자동 실행 없음.

JSON/YAML 등록은 접힌 고급 설정으로 분리했다. LLM 정의·Codex 배포·생성·자료 승인을
각 단계에 한 번만 배치하고 runner 목록을 공유한다. 조회 탭에서는 health 검사 버튼을
제공하지 않는다. 기존 HTTP 배포 조회/검사는 유지하지만 신규 HTTP 배포 작성 폼을
새로 추가하지 않았다. 공개 embedded 레지스트리에는 관리자 탭을 적용하지 않는다.

탭은 숨긴 패널을 유지해 입력 초안과 상태를 보존한다. 방향키·Home·End, ARIA 선택 상태와
고유 패널 식별자를 제공한다. 탭 이동은 저장·승인·모델 실행을 일으키지 않는다.
문서 처리 프로파일이 빠졌던 모델 관리자 SSR과 공용 클라이언트 loader에 기존 GET을
추가했다. 별도 구현인 구성 스튜디오 SSR까지 수정한 것은 아니다.

## 검증과 한계

- 탭 동작/문서 처리 조회 RED 확인 후 구현. 관련 51개 테스트 통과, 기존 act 경고 있음.
- 메인 재검증: 탭·client loader·SSR 8개 테스트와 TypeScript 통과.
- 실제 약1174px 관리자 화면에서 5탭 표시·전환·Home/Right 포커스와 가로 넘침 없음을 확인.
- 마지막 SSR 데이터 재조회는 로그인 화면으로 이동해 문서 처리 목록의 최종 실제 표시를
  확인하지 못했다. 재로그인을 요청했으며 인증 우회는 하지 않았다. 모바일 별도 미검증.
- 정책 화면에서 사용자가 저장한 회사v2(Codex만 허용), 기존 공간 둘의v1(전송 차단)을
  읽기 전용으로 확인했다. 이번 작업에서 정책·문서·모델 실행은 변경하지 않았다.

신규 패키지·백엔드 계약 변경 없음. main의 기존 변경을 보존했고 커밋·푸시하지 않았다.
메인의 변경15개 TS/TSX 린트도 통과했고 최종 독립 명세·품질 리뷰 승인,
남은 Critical/Important/Minor 지적 없음. 전체 RAG 사용 준비 완료를 뜻하지 않는다.

후속 재로그인 후 관리자 SSR 실제 조회를 다시 확인했다. 문서 처리 프로파일5개 버전이
표시되어 위의 최종 목록 표시 미검증은 해소됐다. 모바일은 여전히 별도 미검증이다.
