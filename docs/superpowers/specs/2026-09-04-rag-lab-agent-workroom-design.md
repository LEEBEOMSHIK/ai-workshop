# RAG 연구실 담당 에이전트 작업실 설계

- 상태: 승인됨
- 기준일: 2026-09-04
- 범위: 공개 `/`의 RAG 총괄 진입 동작과 공개 `/labs/rag` 작업실
- 관련 설계: `docs/superpowers/specs/2026-09-02-public-ai-lab-rag-service-design.md`
- 관련 결정: `docs/decisions/0007-public-rag-agent-workroom.md`

## 1. 목표

- 공개 입구에서 RAG 총괄에게 말을 걸면 전체 Lab 목록을 한 번 더 거치지 않고 RAG 연구실로
  들어간다.
- RAG 연구실에서 총괄과 현재 구현된 기술 담당자들이 각 작업 구역에서 일하는 모습을 본다.
- 각 담당자를 선택하면 자기 역할, 입력과 결과, 현재 사용 기술과 다음 인계 대상을 설명한다.
- 공개 화면은 실제 구현 상태만 표현하고 미구현 리랭커·LLM 생성 담당자를 일하는 상태로
  만들지 않는다.

## 2. 사용자 흐름

1. `/`의 `연구실 전체 보기`는 모든 공개 Lab을 보는 `/labs`로 이동한다.
2. `/`의 RAG 총괄 캐릭터는 catalog의 `/labs/rag`와 `RAG 연구실 들어가기`를 사용한다.
3. `/labs/rag`에는 RAG 총괄 지휘 구역과 여섯 기술 작업 구역이 한 화면의 연구실로 나타난다.
4. 담당 캐릭터를 마우스나 키보드로 선택하면 기존 접근 가능한 연결 말풍선이 열린다.
5. 말풍선은 담당자의 현재 작업과 인계 흐름을 설명한다. 공개 상세 URL이 없는 기술 작업자는
   거짓 CTA를 만들지 않고 닫기 동작만 제공한다.
6. 로그인 사용자용 현재 검색 기능 진입은 연구실 상단의 명시적 CTA로 유지한다.

## 3. 현재 공개 작업자 계층

```text
RAG 총괄
├─ 파싱·구조 분석 담당
├─ 청킹 담당
├─ 임베딩·색인 담당
├─ 검색·융합 담당
├─ 근거·하이라이트 담당
└─ 품질 평가 담당
```

각 작업자는 현재 구현된 Markdown·TXT·텍스트 PDF 파싱, 구조 청킹, 임베딩 색인,
BM25·bi-encoder·RRF 검색, 원문 근거·정확/의미 하이라이트, 저장 구성·평가 비교 범위만
설명한다. Generation과 reranking은 구현 후 같은 공개 계약과 검증을 거쳐 추가한다.

파싱·청킹·색인·검색 같은 이름은 제품 안의 책임을 사람이 이해하도록 표현하는 캐릭터다.
실제 처리는 결정적 서비스와 worker가 담당하며, 모든 캐릭터가 LLM 에이전트로 실행된다는
뜻이 아니다.

## 4. 데이터와 컴포넌트 경계

- 작업자 이름, 역할, 상태, 소개, 현재 작업, 입력·결과와 인계 문구는
  `frontend/src/content/rag-lab-agents.json`을 정본으로 둔다.
- `rag-lab-agents.ts`가 exact-key, 고유 slug와 필수 문자열을 검증한다.
- RAG 상세 컴포넌트에 작업자별 문구나 모델명을 흩뿌리지 않는다.
- 기존 `AgentCharacter`의 portal, focus trap, Escape, scroll lock과 위치 계산을 일반화한
  상호작용 캐릭터 경계로 재사용한다.
- 공개 catalog와 작업자 registry는 책임이 다르므로 하나의 schema로 합치지 않는다.

## 5. 공간과 반응형

- 넓은 화면에서는 총괄 지휘대 아래에 여섯 작업대를 파이프라인 순서로 배치하고 흐름선을
  연결한다.
- `64rem` 미만에서는 두 열, `48rem` 미만에서는 한 열로 재배치한다.
- 캐릭터 버튼과 구역 제목은 DOM 순서도 파이프라인 순서를 유지한다.
- 장식은 `aria-hidden`으로 숨기고 작업 구역과 캐릭터만 의미 있는 탐색 대상으로 둔다.
- 기존 `48rem` 미만 하단 대화 패널과 `prefers-reduced-motion` 계약을 그대로 적용한다.

## 6. 수용 기준

1. 메인 RAG 총괄 말풍선 CTA는 `/labs/rag`, 전체 보기 CTA는 `/labs`다.
2. RAG 상세에는 총괄과 여섯 현재 작업자가 나타나며 미구현 Generation·Reranker 작업자는 없다.
3. 여섯 작업자 각각은 고유한 접근 가능 이름으로 선택할 수 있다.
4. 선택한 작업자의 말풍선에서 역할, 현재 작업, 입력·결과와 다음 인계를 읽을 수 있다.
5. 닫기 초기 초점, Tab 순환, Escape 닫기, trigger 초점 복원과 body scroll 복원이 유지된다.
6. 작업자 데이터가 잘못되면 조용한 부분 표시 대신 검증 경계에서 오류가 발생한다.
7. desktop·tablet·mobile에서 가로 overflow 없이 총괄과 모든 작업자에 접근할 수 있다.
8. 공개 catalog, backend API, DB, 실제 검색·모델 동작과 인증 경계는 바꾸지 않는다.
