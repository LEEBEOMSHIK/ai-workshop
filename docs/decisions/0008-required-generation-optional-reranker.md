# ADR-0008: 생성 RAG에는 LLM을 필수로 하고 리랭커는 선택 단계로 둔다

- 상태: 제안됨
- 결정일: 2026-09-04

## 배경

현재 RAG V1은 BM25 또는 BM25+dense+RRF 검색, 근거 선별, 하이라이트와 원문 추적을
제공하지만 사용자 답변은 LLM 생성문이 아니라 원문 발췌다. 관리자 모델 registry에는
reranker와 LLM 종류가 존재하지만 V1 저장 구성은 둘의 실행을 허용하지 않는다.

프로젝트가 목표로 하는 대화형 RAG 서비스에는 근거에 제한된 LLM 답변과 인용 검증이
필요하다. 리랭커는 일부 데이터셋에서 품질을 개선할 수 있지만 RAG의 필수 조건은 아니다.

## 결정

대화형 생성 RAG V2의 고정 실행 순서는 다음과 같다.

```text
Hybrid Retrieval → Optional Reranking → Evidence Selection
→ Required LLM Generation → Required Citation Validation
```

- LLM generation profile과 인용 검증은 서비스 완료 및 `answer_ready`의 필수 조건이다.
- 리랭커 프로파일이 없으면 단계를 정상 생략하며 준비 상태를 낮추지 않는다.
- 리랭커를 구성했다면 그 모델과 runtime은 해당 구성의 필수 의존성이 된다.
- 구성된 리랭커나 LLM이 실패할 때 다른 모델 또는 추출 답변으로 조용히 전환하지 않는다.
- BM25와 추출식 V1은 비교·회귀 기준선으로 유지하되 완성된 생성 RAG로 표시하지 않는다.
- 모델, provider와 주요 파라미터는 registry·versioned profile·typed settings로 관리한다.
- 첫 로컬 adapter는 typed setting이 가리키는 로컬 OpenAI-compatible HTTP endpoint를
  호출하며 provider SDK를 도메인에 노출하지 않는다.
- LLM은 첫 검색 순위를 결정하지 않으며 LLM 변경은 검색 색인을 재구축하지 않는다.
- 기존 검색·근거 응답 계약은 유지하고 생성 상태·본문·문장별 인용을 별도 additive 객체로
  제공한다.

## 결과

### 장점

- 선택 기능의 부재와 구성된 기능의 장애를 명확히 구분한다.
- 리랭커 없이도 완성된 생성 RAG 구성을 만들 수 있다.
- 추출식 검색 결과를 LLM 답변으로 오인하거나 장애를 숨기는 fallback을 막는다.
- 검색과 생성 모델을 독립적으로 평가·교체할 수 있다.

### 비용

- V1과 V2의 준비 상태·응답 schema·평가 기준을 함께 유지해야 한다.
- LLM runtime health, 구조화된 출력과 인용 검증 구현이 추가된다.
- 구성한 선택 단계가 실패하면 가용성보다 구성 재현성과 정확성을 우선해 요청이 실패한다.

## 비채택 대안

- 리랭커를 모든 구성에 필수화: 측정되지 않은 비용과 지연을 강제하므로 채택하지 않는다.
- LLM 장애 시 추출 답변으로 자동 전환: 사용자에게 다른 서비스 결과를 정상 답변처럼
  제공하고 실행 재현성을 깨뜨리므로 채택하지 않는다.
- 범용 파이프라인 DAG: 현재 요구보다 큰 설정·검증 복잡성을 만들므로 채택하지 않는다.
