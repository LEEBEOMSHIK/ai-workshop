# 공개 AI Lab과 다중 도메인 RAG 서비스 설계

- 상태: 승인됨
- 기준일: 2026-09-03
- 범위: 공개 전시실, 비공개 작업소, RAG 다중 도메인, 공개 릴리스, 대화형 생성, 피드백과 수동 파인튜닝
- 구현 상태: 1단계 URL·권한 경계 완료. 공개 첫 화면의 전체 화면 연구소 월드 표현은
  `2026-09-03-full-screen-ai-lab-world-design.md`에서 재설계 중이며, 2~7단계는 승인된 후속
  범위로 미구현

## 1. 배경과 결정

AI Workshop의 공개 화면은 로그인한 업무 사용자를 위한 일반 관리 화면이 아니다. 외부
방문자가 기술 관리자 캐릭터의 안내를 따라 실제로 완성된 AI 기능을 사용하고, 그 기능의
설계와 시행착오를 살펴보는 공개 전시실이다.

1단계 이전 프론트엔드는 공개 홈의 정적 카드에서 보호된 `/app/rag/*`와 `/admin/*`로 바로
이동했다. 이 때문에 공개 기술 관리자 캐릭터와 시스템 권한 관리자인 `owner`가 혼동되고,
방문자가 기능을 살펴보려면 관리자 로그인이 필요한 것처럼 보였다. 1단계는 이 문제를
공개 `/labs/*`, 사용자 `/workshop/*`, owner `/admin/*` 경계와 호환 리다이렉트로 해소했다.

이 설계는 다음을 결정한다.

- 공개 방문자는 로그인 없이 캐릭터 기반 랜딩과 AI Lab에 접근한다.
- 공개된 기능은 축소판이 아니므로 사용자 화면에서 `데모`라고 부르지 않는다.
- RAG는 자산운용 전용 기능이 아니라 여러 전문 도메인을 수용하는 기술 Lab이다.
- 자산운용은 첫 번째 RAG 도메인 패키지다.
- 공개 RAG 서비스는 검색뿐 아니라 근거에 제한된 LLM 답변을 대화형으로 제공한다.
- 공개 환경은 검증·승인된 불변 공개 릴리스만 사용한다.
- 문서 첨부, 개인 지식, 피드백 제출과 학습 데이터 관리는 로그인 뒤에만 제공한다.
- 피드백 기반 파인튜닝은 자동 실행하지 않고 관리자가 명시적으로 시작한다.

## 2. 용어와 주체

### 기술 관리자 캐릭터

방문자에게 기술 영역을 설명하고 기능으로 안내하는 화면상의 캐릭터다. RAG 총괄과
도메인별 관리자가 여기에 포함된다. 이 캐릭터는 시스템 권한 역할이 아니다.

### 시스템 관리자

인증과 RBAC에서 `owner` 권한을 가진 실제 운영 주체다. 모델·구성·도메인·공개
릴리스·학습을 관리한다.

### 서비스 작업자와 LLM 에이전트

파싱, 청킹, 색인처럼 결정적인 작업을 수행하는 서비스 작업자와 판단·생성이 필요한 LLM
실행 주체를 구분한다. 캐릭터가 존재한다는 이유만으로 모든 작업을 LLM으로 구현하지 않는다.

### 공개 릴리스

도메인 정보, 공개 콘텐츠, 문서·색인 스냅샷, 모델 구성과 평가 결과를 함께 고정해 공개
환경에 배포하는 불변 버전이다. 공개 화면의 `현재 적용 모델`은 관리자 편집 중인 설정이
아니라 현재 활성화된 공개 릴리스의 모델을 뜻한다.

## 3. 화면과 URL 경계

### 공개 전시실: 인증 불필요

| URL | 책임 |
| --- | --- |
| `/` | 전체 화면 AI 연구소 월드의 canonical 입구 |
| `/labs` | `/`와 같은 연구소 월드를 직접 렌더링하는 별칭 |
| `/labs/rag` | RAG 공통 기술과 조직 소개 |
| `/labs/rag/architecture` | 공통 파싱·검색·생성·평가 설계 |
| `/labs/rag/domains` | 공개된 RAG 전문 도메인 목록 |
| `/labs/rag/domains/{domainSlug}` | 도메인 관리자 소개와 기능 메뉴 |
| `/labs/rag/domains/{domainSlug}/search` | 해당 도메인의 대화형 RAG 서비스 |
| `/labs/rag/domains/{domainSlug}/journey` | 문제·실패·해결·검증 기록 |
| `/labs/rag/domains/{domainSlug}/configuration` | 활성 모델·버전·구성의 읽기 전용 설명 |

캐릭터를 선택하면 먼저 짧은 자기소개 대화상자를 연다. 데스크톱에서는 캐릭터에 연결된
말풍선, 모바일에서는 하단 대화 패널로 표현하되 modal 접근성 계약을 유지한다. 기능 안내를
선택하면 새로고침, 공유와 직접 접근이 가능한 독립 URL로 이동한다. 구체적인 장면과 상호작용
계약은 `2026-09-03-full-screen-ai-lab-world-design.md`를 따른다.

### 비공개 작업소: 로그인 필요

`/workshop/*`는 전사·개인 지식 공간, 문서 등록, 첨부 검색, 자유 메모, 구조화된 실험과
비공개 실행 기록을 제공한다. 공개 전시실과 동일한 데이터 저장소를 사용한다고 가정하지
않으며 공개 승인은 별도 릴리스 절차를 거친다.

### 시스템 관리: owner 필요

| URL | 책임 |
| --- | --- |
| `/admin/rag/domains` | 도메인 정의와 공개 상태 관리 |
| `/admin/rag/models` | 모델 등록과 버전 관리 |
| `/admin/rag/configurations` | 색인·검색·생성 구성 편집 |
| `/admin/rag/feedback` | 로그인 사용자 피드백 검토 |
| `/admin/rag/datasets` | 평가·학습 데이터셋 구성 |
| `/admin/rag/training` | 수동 파인튜닝 실행과 상태 확인 |
| `/admin/rag/evaluations` | 기존·후보 모델과 구성 비교 |
| `/admin/rag/releases` | 공개 승인·배포·활성화·롤백 |

1단계에서 이전 `/app/rag/configurations`의 편집 책임은 `/admin/rag/configurations`로
이동했다. 이전 주소는 호환 리다이렉트로만 유지한다. 공개 구성 화면에는 후속 공개 릴리스
단계에서 읽기 전용 설명만 제공한다.

## 4. 공개 기능 명명 원칙

공개된 기능에는 기능 또는 서비스 자체의 이름을 사용한다.

- `자산운용 문서 AI 검색`
- `보험 문서 AI 검색`
- `법률 문서 AI 검색`
- `온톨로지 탐색`
- `지식 그래프 검색`

`RAG 데모`, `온톨로지 데모` 같은 명칭은 공개 사용자 화면에서 사용하지 않는다. 공개
릴리스가 활성화된 기능은 `서비스 중`, 아직 검증되지 않은 기능은 비공개 작업소에 두거나
`연구 중`으로 표시한다. 내부 테스트 데이터나 격리 환경을 설명할 때만 `데모 데이터` 같은
기술 용어를 사용할 수 있다.

## 5. RAG 기술과 전문 도메인

```text
RAG 기술 Lab
├─ RAG 총괄
├─ 공통 기술 작업자
│  ├─ Parser
│  ├─ Chunking
│  ├─ Embedding
│  ├─ Retrieval
│  ├─ Highlighting
│  ├─ Generation
│  └─ Evaluation
└─ 전문 도메인 관리자
   ├─ 자산운용
   ├─ 보험
   ├─ 금융
   ├─ 법률
   └─ HR
```

RAG 공통 기술은 도메인마다 복제하지 않는다. 도메인 고유 처리가 실제로 필요할 때만
전용 파서, 어휘 정책 또는 평가 작업자를 추가한다.

도메인 패키지는 다음을 소유한다.

- 안정적인 slug, 표시명, 설명과 관리자 캐릭터
- 공개 문서 집합과 색인 스냅샷
- 적용할 RAG 구성 버전
- 도메인별 질의·근거·평가 세트
- 전문 용어, 동의어와 최신성 정책
- 공개할 설계·이슈·실패·해결 기록
- 활성 공개 릴리스

도메인 이름, 목록과 공개 상태를 프론트 코드에 고정하지 않는다. 같은 동적 계약으로 새
도메인을 등록한다.

## 6. 불변 공개 릴리스

도메인 공개 릴리스는 다음을 하나의 매니페스트로 묶는다.

```text
Domain Public Release
├─ 도메인 정보와 캐릭터 버전
├─ 공개 설명과 기술 구조
├─ 선별된 이슈·실패·해결 기록
├─ 공개 문서 스냅샷과 체크섬
├─ 물리 검색 색인 버전
├─ Parser·Chunker 구성
├─ BM25·Embedding·RRF·Reranker 구성
├─ LLM·생성·인용 검증 구성
├─ 모델명과 정확한 버전
├─ 평가 데이터·결과 스냅샷
└─ 공개·비식별화 승인 기록
```

수명주기는 `초안 → 검증 중 → 승인 대기 → 공개 승인 → 배포 완료 → 활성` 순서다.

- 공개 승인 뒤의 패키지는 수정하지 않고 새 버전을 만든다.
- 도메인별로 한 시점에 하나의 릴리스만 활성화한다.
- 이전 릴리스는 일반 검색에서 제외하고 재현·감사·즉시 롤백용으로 보존한다.
- 새 릴리스의 문서, 색인, 모델과 평가 연결을 모두 검증한 뒤 활성 포인터를 원자적으로
  바꾼다.
- 새 릴리스 검증 또는 배포가 실패하면 현재 활성 서비스에 영향을 주지 않는다.
- 공개 환경은 비공개 작업소의 DB, 객체 저장소와 검색 색인을 실시간 조회하지 않는다.
- 모든 공개 응답에는 도메인과 릴리스 버전을 연결한다.
- 화면에는 모델명과 버전을 표시하되 내부 UUID, 비밀값과 환경 경로는 숨긴다.

## 7. 대화형 생성 RAG

공개 검색과 로그인 검색은 RAG 관리자 캐릭터와 대화하는 형태로 제공한다. 첫 검색 순위는
계속 `BM25 + bi-encoder dense retrieval + RRF`가 결정하며 LLM을 첫 순위 결정에 사용하지
않는다.

```text
질문
→ 대화 문맥을 반영한 검색 질의 확정
→ BM25와 dense 검색
→ RRF 결합
→ 선택적 리랭킹
→ 근거 선별
→ 근거에 제한된 LLM 답변 생성
→ 문장별 인용 검증
→ 대화형 응답
```

응답은 다음을 포함한다.

- 질문에 대한 직접적인 LLM 답변
- 답변 문장과 연결된 원문 근거
- 정확 문자열 일치와 의미 일치 구분
- 문서명, 버전, 페이지·문단과 위치
- 원문 하이라이트 이동
- 관련 문서 목록
- 사용한 도메인과 공개 릴리스 버전
- 후속 질문과 실제로 확정된 검색 질의 확인

근거가 부족하거나 인용 검증이 실패하면 답변을 꾸며내지 않는다. `확인 가능한 근거를 찾지
못했습니다` 상태와 검색된 근거 또는 실패 사유를 표시한다.

`왜 이런 답변이 나왔나요?`에는 모델의 내부 사고과정이 아니라 다음 실행 근거를 표시한다.

- 해석된 검색 질문과 범위
- BM25·dense 후보와 RRF 순위
- LLM에 제공한 근거
- 모델명·버전과 생성 구성
- 인용 검증 결과와 근거 충분성 상태

## 8. 공개 검색과 로그인 첨부 검색

공개 방문자는 활성 공개 릴리스의 승인된 지식 문서만 검색한다. 공개 검색은 실제 서비스지만
방문자의 문서 업로드를 허용하지 않는다.

로그인 사용자는 다음 범위를 명시적으로 조합한다.

```text
검색 범위
☑ 선택한 도메인의 허용 지식
☑ 내 지식 공간
☑ 현재 검색에 첨부한 문서
```

업로드 수락 전에는 관리자 정책에 따라 다음을 검사한다.

- 허용 파일 형식과 실제 파일 서명
- 파일 크기, 페이지 수와 사용자 사용량
- 암호화, 손상과 악성 파일 여부
- 파싱 가능한 본문과 텍스트 품질
- 중복, 과도한 반복과 무의미한 내용
- 선택한 도메인과의 적합성

결과는 `수락`, `확인 필요`, `거절`로 구분한다. 도메인 적합도가 낮다는 이유만으로 조용히
폐기하지 않고 다른 도메인 선택을 안내한다. 악성·손상·정책 위반 파일은 명시적 사유와 함께
거절하며 사용자가 강제로 진행할 수 없다.

- `현재 검색에 첨부`: 임시 저장·색인하고 세션 만료 뒤 원본, 파싱 결과, 임베딩과 색인을
  모두 자동 삭제한다.
- `내 지식 공간에 저장`: 사용자가 명시적으로 선택한 폴더에 영속 보관한다.

만료 시간, 파일 크기와 사용량 값은 업무 코드에 고정하지 않고 관리자 정책으로 관리한다.

## 9. 오답과 해결 과정

잘못된 답변은 삭제하거나 숨기는 것으로 끝내지 않고 재현 가능한 품질 이슈로 전환한다.

```text
오답 신고
→ 실행 상태 재현
→ 원인 분류
→ 수정 실험
→ 동일·유사 질문 재검증
→ 새 공개 릴리스
→ 선별된 해결 과정 공개
```

원인은 문서 누락, sparse/dense 검색 실패, RRF 또는 리랭킹 문제, 청크·표 구조 문제,
오래된 문서, 도메인 선택 오류, LLM 근거 오해, 인용·하이라이트 오류와 검증 규칙 누락으로
분류한다.

공개 해결 기록에는 문제 현상, 당시 구성, 원인, 효과가 없었던 시도, 최종 해결, 수정 전후
평가, 반영 릴리스와 남은 한계를 포함한다. 사용자 질문과 비공개 문서를 자동 공개하지
않는다. 공개·합성 데이터로 재현하고 비식별화와 관리자 승인을 통과한 사례만 발행한다.

임베딩 또는 청킹 변경은 새 색인 버전을 요구한다. LLM이나 생성 프롬프트만 변경하면 검색
색인을 다시 만들지 않는다.

## 10. 피드백과 학습 데이터

공개 방문자에게는 좋아요·싫어요가 가능하다는 것을 보여주되 선택을 저장하지 않는다.
선택하면 다음 로그인 안내만 표시한다.

> 로그인하면 답변에 대한 의견을 남기고 RAG 정확도 개선에 참여할 수 있어요.

공개 방문자의 질문, 답변, 반응과 자유 입력을 관리·평가·학습 데이터로 사용하지 않는다.
공개 대화 문맥은 현재 브라우저 또는 요청 처리에 필요한 휘발성 범위에서만 사용한다. 운영
로그에는 질문과 답변 본문 대신 요청 식별자, 상태, 지연 시간과 안전한 오류 코드만 남긴다.

로그인 사용자는 전체 답변, 답변 정확성·완전성, 인용 지지 여부, 검색 문서 관련성·누락·
최신성과 하이라이트를 평가할 수 있다. 학습 활용에 동의하지 않은 피드백은 품질 이슈에만
사용하며 파인튜닝 데이터에 포함하지 않는다.

피드백은 즉시 검색 점수나 모델 가중치에 반영하지 않는다.

```text
로그인 사용자 피드백
→ 개인정보·권한·동의 검사
→ 도메인 전문가 검토와 교정
→ 평가 또는 학습 예제 승인
→ 버전이 고정된 데이터셋
→ 후보 구성·모델 실험
→ 회귀 평가
→ 승인된 새 릴리스
```

## 11. 파인튜닝 데이터와 수동 실행

모델별 학습 예제는 분리한다.

| 학습 대상 | 승인된 학습 예제 |
| --- | --- |
| bi-encoder | 질문, 관련 근거, 관련 없거나 혼동하기 쉬운 근거 |
| 리랭커 | 질문, 선호 문서, 비선호 문서 |
| 질의 변환 | 대화 문맥, 원래 질의, 교정된 검색 질의 |
| LLM SFT | 질문, 검증된 근거, 교정 답변과 인용 |
| LLM 선호 학습 | 질문·근거, 선호 답변, 거절 답변 |
| 인용 검증 | 답변 문장, 인용 근거, 지지·불일치 판정 |

좋아요는 검증 전까지 긍정 학습 예제가 아니고, 싫어요는 원인이 확인되기 전까지 negative가
아니다. 검색 상위의 잘못된 근거는 검토 뒤 hard negative 후보가 되고, 싫어요와 함께 작성한
교정 답변은 근거 검증 뒤 SFT 또는 선호 데이터 후보가 된다.

학습 데이터셋은 권한·동의·비식별화, 중복 제거, 악의적 입력 검사와 전문가 승인을 거친다.
도메인 태그를 유지하고 train, validation, 최종 test를 분리한다. 이미 학습에 사용한 질문을
최종 평가 점수에 다시 사용하지 않는다.

파인튜닝은 데이터량 도달만으로 자동 시작하지 않는다. 관리자는 데이터셋 버전, 도메인,
기반 모델, 예상 시간·비용과 데이터 권한 검사를 확인하고 명시적으로 실행한다.

```text
관리자 학습 승인
→ 격리된 Training Experiment
→ 새 모델 버전 등록
→ 기존 기준선·도메인 회귀 평가
→ 후보 RAG 구성
→ 공개 승인과 새 릴리스
```

학습 완료, 평가 통과, 구성 연결과 공개 승격은 각각 별도 승인 단계다. 어느 단계도 다음
단계를 자동 승인하지 않는다.

## 12. 실패와 복구

- 활성 공개 릴리스가 없으면 비공개 데이터를 대신 사용하지 않고 서비스 준비 상태를 표시한다.
- 생성 답변의 근거가 부족하거나 인용 검증이 실패하면 근거 부족 상태로 종료한다.
- 새 릴리스 배포 실패는 현재 활성 릴리스를 변경하지 않는다.
- 임시 첨부 실패는 원본·파싱·임베딩·색인의 잔여물을 정리하고 상태를 기록한다.
- 파서나 모델을 조용히 대체하지 않는다.
- 공개 방문자 입력 본문을 로그나 분석 저장소에 남기지 않는다.
- 파인튜닝 실패 모델은 운영 모델로 등록·승격하지 않는다.
- 재시도, 부분 실패와 대체 처리는 사용자 상태와 관리자 실행 기록에 명시한다.

## 13. 검증 기준

### 화면·권한

- 공개 랜딩, AI Lab과 공개 서비스는 로그인 없이 접근할 수 있다.
- 문서 첨부, 개인 지식, 실제 피드백과 관리 화면은 인증 없이 접근할 수 없다.
- 시스템 관리자와 기술 관리자 캐릭터가 UI·계약·권한에서 구분된다.

### 도메인·릴리스

- 새 도메인을 프론트 코드 복제나 이름 하드코딩 없이 추가할 수 있다.
- 서로 다른 도메인의 문서·색인·평가·릴리스가 섞이지 않는다.
- 공개 검색은 해당 도메인의 단일 활성 릴리스만 사용한다.
- 새 릴리스 실패 뒤에도 이전 릴리스가 응답하고 즉시 롤백할 수 있다.

### 검색·생성

- BM25 기준선과 hybrid 결과를 같은 데이터셋에서 비교한다.
- LLM 답변의 주요 주장은 접근 가능한 인용 근거를 가진다.
- 정확 일치와 의미 일치 하이라이트를 구분한다.
- 근거가 부족한 질문에는 추측 답변을 반환하지 않는다.
- 모델, 프로파일, 데이터와 릴리스 버전으로 결과를 재현할 수 있다.

### 데이터·학습

- 공개 방문자의 질문·답변·반응 본문이 영속 저장되지 않는다.
- 만료된 임시 첨부의 모든 파생물이 삭제된다.
- 사용자 동의가 없는 피드백은 학습 데이터로 승격되지 않는다.
- train·validation·test 간 문서와 질문 누출을 검사한다.
- 새 모델이 승인된 기준선을 만족하지 못하면 구성과 공개 릴리스로 승격할 수 없다.

## 14. 구현 단계

이 설계 전체를 한 작업으로 구현하지 않는다.

1. **공개·작업소·관리자 경계 복원 — URL·권한 경계 완료, 월드 표현 재설계 중**
   전체 화면 AI 연구소 월드, RAG 방과 관리자 캐릭터, `/workshop/*`, `/admin/*` 라우트와
   권한을 정리한다. 이 단계는 공개 검색, 공개 릴리스, LLM 답변, 업로드, 피드백 또는 학습을
   구현하지 않는다.
2. **다중 도메인과 공개 릴리스 기반**
   RAG 공통 기술과 자산운용 도메인을 분리하고 동적 도메인·불변 릴리스 계약을 만든다.
3. **공개 RAG 콘텐츠와 검색 연결**
   자산운용 AI 검색, 기술 구조, 적용 구성, 해결 과정과 평가를 공개 릴리스에 연결하되 아직
   공개 활성화하지 않는다.
4. **대화형 생성 RAG**
   생성 프로파일, 대화 문맥, 인용 검증, 근거 부족 처리와 대화 UI를 구현하고 검증 뒤
   공개 서비스를 활성화한다.
5. **로그인 기반 첨부 검색**
   일시 첨부, 개인 저장, 업로드 검증, 도메인 확인과 자동 삭제를 구현한다.
6. **피드백과 품질 이슈**
   로그인 피드백, 교정 답변, 재현·트러블슈팅과 선별 공개 흐름을 구현한다.
7. **데이터셋과 수동 파인튜닝**
   데이터 검토·버전 관리, 수동 학습, 모델 비교 평가와 릴리스 승격을 구현한다.

각 단계는 별도 상세 설계와 구현 계획, 회귀 검사와 승인 기준을 가진다. 첫 구현 계획은
1단계만 대상으로 했으며, 공개 릴리스·생성·피드백·학습은 승인된 후속 단계로 남는다.

## 15. 연구 근거

- [Elasticsearch Ranking Evaluation](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval): 대표 질의와 관련성 판정으로 Precision, Recall, MRR와 nDCG를 평가한다.
- [ARES, NAACL 2024](https://aclanthology.org/2024.naacl-long.20/): RAG를 context relevance, answer faithfulness와 answer relevance로 분해해 평가한다.
- [Unbiased Learning-to-Rank with Biased Feedback](https://arxiv.org/abs/1608.04468): 사용자 상호작용을 편향 보정 없이 직접 학습 신호로 쓰는 위험을 다룬다.
- [Dense Passage Retrieval, EMNLP 2020](https://aclanthology.org/2020.emnlp-main.550/): 질문·positive passage·negative passage를 이용하는 dense retriever 학습 근거다.
- [RocketQA, NAACL 2021](https://aclanthology.org/2021.naacl-main.466/): denoised hard negative와 데이터 증강을 포함한 dense retrieval 학습을 다룬다.
- [Training language models with human feedback](https://arxiv.org/abs/2203.02155): 모범 응답과 사람의 응답 순위 데이터를 분리해 학습에 사용한다.
- [Direct Preference Optimization](https://arxiv.org/abs/2305.18290): 검토된 chosen·rejected 응답 쌍을 이용하는 선호 학습 선택지다.
- [Feedback Adaptation for RAG](https://arxiv.org/abs/2604.06647): correction lag와 post-feedback performance로 피드백 반영을 평가한다.

## 16. 제외 범위

- 사용자 피드백에 따른 운영 모델의 실시간·자동 학습
- 좋아요 수를 BM25, dense 또는 RRF 점수에 직접 더하는 처리
- 공개 환경의 비공개 저장소 실시간 연결
- 익명 방문자 질문·답변·반응의 분석 또는 학습 활용
- 모델 내부 사고과정의 저장·노출
- 도메인마다 동일한 기술 작업자와 화면 코드를 복제하는 구조
- 검증되지 않은 모델·구성·학습 결과의 자동 공개 승격
