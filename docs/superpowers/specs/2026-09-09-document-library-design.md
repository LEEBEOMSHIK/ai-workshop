# 지식 공간·폴더 탐색기와 독립 문서 열람

- 상태: 단계별 최초 구현 범위 승인(2026-09-09)
- 사용자 목적: 회사/개인 자료가 어디에 저장되는지 구분하고 폴더로 관리하며 파일 클릭으로 열람한다.
- 선행 조사: `WorkspacePage`, `DocumentBrowser`, Platform Assets API/모델과 RAG `SourceViewer`.

## 1. 결정과 경계

기존 `/workshop/workspaces`와 공간별 `/documents` 경로를 유지하며 파일 탐색기로 연결한다.
Platform Assets가 공간·폴더·원본 버전·열람 권한을 소유한다. Platform은 Labs/RAG를 import하지 않는다.
원본 열람에는 로그인 및 해당 공간 접근권한과 원본 버전 READY가 필요하다.
RAG 구독·색인·임베딩·검색 평가·외부 AI 승인은 열람의 선행 조건이 아니다.

대안은 기존 목록에 검색 뷰어만 붙이기, 전체 문서관리 시스템 교체, 기존 Assets 확장이다.
첫 안은 RAG 준비 상태에 종속되고 두 번째는 범위가 과도하므로 기존 Assets 확장을 채택한다.
논리 폴더는 디스크 폴더가 아니다. 폴더 이동으로 원본 파일을 물리 이동하거나 hash를 바꾸지 않는다.

## 2. 화면

공통 작업소 컨테이너에 제목·도구 모음·내용을 배치한다. 기존 생성 폼만 넓어지는 문제를 없애고,
지식 공간 목록과 문서 라이브러리는 같은 여백/폭 기준을 사용한다. 큰 화면 공간을 활용하며
목록을 고정 70rem 폭으로만 제한하지 않는다. 작은 화면에서는 트리를 접고 뷰어를 전체 폭으로 연다.

- 지식 공간 화면: `파일 관리` 제목, 회사/개인 유형별 실제 접근 가능한 공간 목록, `공간 만들기`.
- 공간 생성 폼은 상시 크게 펼치지 않고 버튼으로 열어 파일 탐색을 기본 작업으로 둔다.
- 좌측: 회사/개인/기존 팀·임시 공간을 실제 유형별로 묶고, 선택 공간의 중첩 폴더를 펼친다.
- 중앙: 현재 폴더 바로 아래의 문서 목록과 업로드/새 폴더 버튼. 공간 루트는 미분류 문서 위치다.
- 상단: 실제 공간명·유형과 현재 폴더 경로. UUID는 기본 제목/목록에서 숨긴다.
- 파일명/열기 영역 클릭과 Enter로 오른쪽 뷰어를 연다. 업로드·메뉴 버튼 클릭은 열람과 분리한다.
- 뷰어 헤더: 파일명·선택한 문서 버전·닫기/확대. 내부: 내용, 버전 목록, 문서 정보.

폴더·문서·버전 선택은 URL query에 보존하여 새로고침/뒤로가기에 복원한다.
query는 권한을 부여하지 않는다. 다른 공간/문서의 ID 조합은 서버가 거절한다.
공간 변경 시 이전 목록/본문을 즉시 지우고 늦은 응답·object URL도 정리한다.
트리는 키보드 확장/축소/선택과 현재 선택 상태를 제공한다. 뷰어 닫기 후 원래 문서로 focus를 돌린다.

## 3. 최초 구현 범위

파일 관리 기반과 실제 열람을 먼저 완성하고 승인 정책 이동은 다음 독립 작업으로 연결한다.

포함:

1. 기존 공간 목록·생성 권한 유지, 회사/개인 유형 구분, 실제 공간명과 공통 폭.
2. 중첩 폴더 조회/생성, 폴더별 문서 탐색, 선택 폴더로 업로드, 기존 새 버전 업로드.
3. 문서 선택·버전 선택과 독립 원문 열람: TXT/Markdown 안전한 텍스트, PDF 로컬 페이지 이미지.
4. 기타 업로드 허용 형식도 클릭하면 문서 상세와 버전·형식·상태를 표시하고,
   미지원 미리보기임을 명확히 알린다. 원본 내려받기는 권한 확인 후 명시적인 버튼으로 제공한다.
5. 문서/폴더가 많을 때 목록 제한과 페이지 이동, 트리 노드 지연 조회를 적용한다.

후속 범위(최초 구현 완료와 구별):

- DOCX 문단·표·이미지, PPTX 슬라이드, XLSX 시트의 독립 구조 미리보기.
- 폴더/문서 이름 변경·이동, 휴지통/복원. 지원하지 않는 메뉴를 작동하는 것처럼 노출하지 않는다.
- 공간 정책과 문서 외부 AI 승인/이력을 적절한 화면으로 이동. 실제 일반 사용자와 owner의
  보기/관리 권한을 구분하고 모델 화면에는 준비 상태 및 관리 화면 링크만 남긴다.

사용자가 이 단계 구분을 승인했다. 다운로드만 제공되는 형식을 뷰어 지원 완료로 표현하지 않는다.
기존 DOCX/OCR 검색 근거 뷰어는 유지하지만 독립 문서 뷰어와 혼동하지 않는다.

## 4. 데이터·API 계약

기존 문서 응답에 `workspace_id`, nullable `folder_id`, nullable `active_version_id`와
최신 버전 ID를 추가한다. 최신 업로드와 현재 READY 활성 버전을 구분해 표시한다.
기본 열람은 활성 READY 버전이며, 사용자가 선택한 과거 READY 버전도 열람할 수 있다.
최신 버전이 처리 중일 때 이전 버전을 최신처럼 조용히 표시하지 않는다.

기존 폴더 생성/업로드 API를 재사용하되 상위 폴더와 업로드 대상 폴더가 동일 공간에 속하는지
저장소 접근 전에 확인한다. 빈 이름·길이·같은 부모의 중복을 검증한다.
권한 없는 공간/폴더/문서는 존재 여부를 구분하지 않는 기존 404 규칙을 유지한다.

파일 목록과 폴더 탐색은 새 bounded browsing endpoint로 제공하여 기존 list 응답 소비자를
깨지 않는다. parent/folder별 조회와 서버 정렬·cursor를 사용하고 루트(null)와 전체를 구별한다.
단위 응답 한계는 Settings의 명명된 값으로 관리하고 임의의 전역 문서 전체를 클라이언트에 적재하지 않는다.
트리에 아직 읽지 않은 자식이 있다는 표시와 로딩/실패/재시도 상태를 둔다.

라이브러리 조회 계약은 다음과 같다. 아래 경로는 `/api/v1` 기준이며 모두 로그인과 공간 권한을 요구한다.

- `GET /workspaces/{workspace_id}/library`: `folder_id` 생략은 공간 루트이며 전체 문서 조회가 아니다.
  실제 workspace, 현재 folder, root-to-parent ancestors, 직접 자식 folders/documents와 각각의
  next cursor를 반환한다. 폴더에는 `has_children`을 제공한다.
- `GET /workspaces/{workspace_id}/library/documents/{document_id}`: URL 복원 시 사용하며
  현재 목록 페이지 포함 여부와 무관하게 정확한 공간·문서 소속을 검증한다.
- `GET /workspaces/{workspace_id}/library/documents/{document_id}/versions`: 최신 순 bounded
  버전 페이지다. 기존 unpaged 버전 API는 호환성을 위해 유지하지만 새 탐색기에서는 사용하지 않는다.

기본 페이지 크기는 50, 최대 200, 폴더 깊이는 최대 64이며 Settings로 관리한다.
문서·폴더 cursor는 `(name, id)`, 버전 cursor는 내림차순 `(number, id)`를 사용한다.
서버 서명 cursor를 사용자·공간·현재 폴더/문서·조회 종류에 연결하여 다른 범위로 재사용하지 못하게 한다.

새 원문 열람 서비스는 exact document/version 소속·공간 접근권한·만료·READY를 먼저 검증하고,
저장된 object_key로만 ObjectStore를 읽는다. 클라이언트가 파일 경로나 object_key를 전달할 수 없다.
문서 상태가 READY라도 원본이 없거나 무결성이 맞지 않으면 안전한 오류로 실패한다.
크기/SHA-256을 검증한 동일한 bounded bytes를 응답·렌더한다. 검증 뒤 파일 경로를 다시 여는
방식으로 검증과 실제 내용 사이의 교체 위험을 만들지 않는다. 업로드 MIME나 현재 문서명만
믿지 않고 exact version의 저장 형식과 실제 byte 형식을 검사하여 preview 종류를 결정한다.

문서 정보/버전, 안전한 텍스트 preview, PDF 페이지 preview, 원본 download 경로를 분리한다.

원문 API는 `/api/v1/documents/{document_id}/versions/{version_id}`를 기준으로 한다.
`GET /preview`는 정확한 문서·버전 ID, 버전 번호, 이름, 크기와 `kind`, `text`, `page_count`를
반환한다. `kind`는 `text`/`markdown`/`pdf`/`unsupported`이며 해당하지 않는 본문·페이지 수는
null이다. `GET /pdf/pages/{page_number}`는 1부터 시작하는 페이지의 PNG,
`GET /content`는 명시적인 원본 attachment다.

응답은 private/no-store 및 nosniff를 사용하고 오류·로그에는 본문과 물리 경로를 넣지 않는다.
외부 URL이나 Office 온라인 뷰어로 문서를 전송하지 않는다. 비동기 모델·OCR 호출도 시작하지 않는다.

## 5. 뷰어 안전성

TXT/Markdown은 React text로 출력하며 raw HTML/script를 실행하지 않는다. 외부 이미지·링크를
자동으로 불러오지 않는다. 디코딩 불가/미지원 인코딩은 오류를 명시하고 정상 내용으로 위장하지 않는다.
HTML 파일은 첫 구현에서 실행하지 않고 download-only로 표시한다.

PDF는 기존 로컬 page rendering 기술을 중립 인프라 어댑터로 재사용할 수 있는 최소 범위로 분리한다.
플랫폼 원문 preview는 RAG DTO나 projection을 요구하지 않는다. 페이지 이미지 조회는 페이지 번호,
파일 크기·페이지 수·렌더링 pixel·처리 시간의 명명된 상한을 적용한다.
렌더링은 종료 가능한 별도 로컬 프로세스에서 실행하고 제한 초과 시 종료·회수한다.
thread의 await timeout만으로 실제 native renderer가 중단됐다고 판단하지 않는다.
브라우저에 원본 PDF를 자동 임베드하거나 외부 링크/스크립트를 실행하지 않는다.
이미지 자체를 읽는 데 OCR은 필요 없다.
텍스트 추출과 의미 하이라이트가 없더라도 PDF 페이지는 볼 수 있으며 이를 검색 준비 완료로 표현하지 않는다.

불필요한 새 캐시를 만들지 않고 최초 구현은 제한된 요청 렌더링을 사용한다. 임시 원본/렌더 산출물이
필요하면 CACHE_POLICY의 요청 수명주기로 관리하고 예외·취소에도 정리한다.
원본 다운로드는 Content-Disposition attachment와 안전한 파일명을 사용한다.

## 6. 검증과 실행 순서

1. API metadata/폴더 소속 검증의 실패 테스트 → 구현 → unit/API/격리 DB 확인.
2. 권한 있는 READY 원문의 독립 preview/download → 비허용/만료/비READY/불일치 실패 테스트.
3. 공간/폴더 트리와 폴더 업로드 → 파일 선택/버전/뷰어 연결 → keyboard/late response 테스트.
4. 긴 이름·빈 공간·다중 페이지·좁은 폭·오류/재시도 상태 및 실제 합성 자료 읽기 전용 확인.
5. 기존 업로드/중복 hash/새 버전/RAG SourceViewer 회귀, 타입·린트 및 독립 보안 리뷰.

현재 main에서만 작업하며 기존 변경·원본·공간·정책을 보존한다.
실제 문서 업로드·이동·삭제·외부 승인·LLM 호출을 검증 명목으로 자동 수행하지 않는다.
검증용 fixture는 별도 공개 합성 자료만 사용한다. 사용자 RAG 전체 테스트 준비와 파일 관리 완료는
별개로 보고한다. 공개 계약 변경 ADR/API 생성 타입/실행서는 구현 전에 같은 상세 계약으로 갱신한다.
