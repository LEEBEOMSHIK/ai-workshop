# 일반 대화 연결 복구와 실제 백그라운드 검증

- 날짜: 2026-10-26
- 관련 문제: ISSUE-00006, ISSUE-00039
- 실행 계획: [원래 환경의 연결·수용 계획](../superpowers/plans/2026-10-26-conversation-live-connection.md)

## 원인

일반 대화의 자산운용 도메인은 활성 연결2 → RAG-TEST v4 → 지원 종료된
`development_codex_exec` 배포를 가리켰다. 실제 Gemma 속도 비교는 별도의 비기본
구성에서 실행했고, 일반 대화 연결은 변경하지 않은 상태였다. 본래 UI의
Codex 지원 종료와 입력 비활성화를 재현했고 API health/ready는 정상이다.

작업 시작 시 속도 비교 기준선과 같은 `Gemma E2B 직접 답변 검증 2026-10-26`의
정확한 구성 버전은 검색·답변 준비가 됐지만 평가 상태가 pending이었다. 배치256은
첫 입력 처리 개선이 확인되지 않았으므로 이번 연결 후보에 사용하지 않는다.

현재 계약에는 정확한 구성의 검색 평가를 정상 수용해 도메인에 연결하는 경로가
있다. 생성형 평가 수용 경로와는 별도이며 검색 PASS가 생성 답변 품질 통과를
뜻하지 않는다. 기존 답변의 일반 지급 규칙 누락·정답0/2·생성 지연 실패는 유지한다.

## 정상 연결 절차

기존 공개 합성 문서1개·양성2/음성1의 불변 검색 데이터셋, K5·반복2와 기존
평가 정책을 그대로 사용했다. BM25 기준선과 정확한 direct v6 후보만 비교했다.
새 검색 실행은 `73788dd0-60f5-4113-9f45-eb985ef24f19`이며 정상 관리자 UI로 접수했다.
전체 worker나 beat를 시작하지 않고 정상 production workflow를 이 실행에만
1회 적용했다. 검색 평가의 실제 E5 계산은 수행했으며 Gemma 생성 경로는 호출하지 않았다.

| 항목 | 실제 결과 |
|---|---|
| 데이터셋 | `9f097597-d05c-5b2e-a03a-f0eea870968e` |
| 기존 평가 정책 | `ebeb1494-1533-4c7b-892e-54bf6d33b88d` |
| direct v6 구성 버전 | `ad01c9c6-1d51-46d2-9bfa-af19eaa47d75` |
| 생성 프로파일 | `aa0eb2ae-96d3-4a7f-8d53-5f5dfefb8e3a` |
| 새 활성 연결4 | `6d6bb8df-ba86-4733-879e-1503d4aa8d32` |
| 두 후보의 검색 품질 | Recall@5=1, MRR=0.5, nDCG≈0.630930, supported precision=1, false grounding=0, highlight IoU=1, access leaks=0, reproducibility=1 |
| direct v6 검색 지연 | p50=9.961초, p95=11.733초 |
| BM25 검색 지연 | p50=7.618초, p95=31.373초 |

두 후보 모두 기존 정책을 통과했고 정확한 direct v6 구성의 결과를 정상 평가
수용 API로 반영했다. 동일 지식 공간의 새 불변 연결4를 정상 UI/API로 활성화한 뒤
일반 대화 준비 상태와 질문 입력 가능 상태를 확인했다. 구성의 전역 기본값은
계속 false다. SQL 상태 덮어쓰기, 기준 완화, 모델·프롬프트·근거·인용 규칙 변경과
제품 코드 수정은 없었다.

## 실제 수용 범위

동일 공개 합성 질문 `AM-SYN-101을 현금화하면 돈은 며칠 뒤 받을 수 있어?`로
새 대화2건을 실행했다. 승인 범위인 Gemma 최대2회 중 정확히2회 완료했고
자동 재시도는0회다. 각 대화는 질문1개·실행1개·완료 모델 span1개·성공한 로컬
생성 audit1개이며 external_transfer=false다.

| 항목 | 첫 번째 대화 | 두 번째 대화 |
|---|---|---|
| 대화 ID | `e53e40dd-855d-4b67-96e4-218aa4192e8b` | `b410b58e-3392-4f8f-a14a-e9eb45a015d5` |
| 실행 ID | `e667dfc6-e889-4333-9b7d-37c5e38b49ee` | `5730edc1-e626-4d17-a55c-90c288038304` |
| 브라우저 동작 | 접수 후 파일함·폴더 접근, 대화 복귀 후 자동 결과 표시 | 접수 후 탭 닫기, 완료 후 재접속하여 저장 결과 표시 |
| 저장된 전체 실행 시간 | 197.183초 | 30.442초 |
| 모델 내부 입력 처리 | 134.335초 | 0.082초 |
| 최종 상태 | completed, 실행 종료 확인, 오류 없음 | completed, 실행 종료 확인, 오류 없음 |

첫 실행은 파일함 이동 뒤에도 생성 중임을 독립 DB 조회로 확인했다. 두 번째
실행은 04:25:03.916174Z에 시작했다. 메인이 기록한 탭 종료는 04:25:15.024Z,
저장된 실행 종료는 04:25:34.358454Z로, 탭 종료 후에도19.334초간 계속 진행됐다.
화면 이동·복귀·자동 표시와 탭 재접속은 메인이 직접 확인했고, 독립 검증자는
실행 지속과 저장 결과를 읽기 전용으로 대조했다. 두 번째의 `legacy/97e9...` 주소는
turn 식별자이며 위 표의 최종 실행 ID와 구분한다.

전체 실행 시간은 모델 입력 처리 시간을 포함한다. 둘을 합산하지 않는다.
동일 입력을 연속 실행한 두 번째의 짧은 입력 처리는
첫 요청이나 cold start 성능 개선의 증거가 아니다. 서버 재시작 복구와 기존
취소/별칭/첨부 복구는 이번 수용 범위가 아니다.

## 답변 품질과 보존 검증

비교 기준은 기존 run `76b51592-89ef-480a-845a-5557f5bd2a46`이다. 두 실제 답변의
UTF-8 SHA256은 기준선과 같은
`48e579c13905c4ee9d7a179a41d021e73313ecc75e50e01a1e7f1023859e3715`다.
실제 specialist 입력 전체, 순서가 있는 근거28개, 원문 위치와 alias→UUID 복원,
정규화한 주장·근거 참조가 모두 같았다. 저장된 grounding_evidence28개도 원문
식별자·본문·하이라이트·위치·점수·경고를 포함해 동일했다.

정확한 개수는 **주장1개가 근거2개를 인용**한 것이다. 이전 `citation_count=1`
설명은 주장 묶음 수를 인용 근거 수로 읽은 오류였으며, UI의 근거2개와 모순되지 않는다.
예시 날짜는 휴일이 없다는 조건에서 근거로 뒷받침되지만, 답변은 그 조건과 일반적인
4영업일 지급 규칙을 여전히 생략한다. 이번에 추가 품질 저하는 없었으나 기존 생성
정답0/2와 첫 응답 지연 문제는 해결되지 않았다. 검색 평가 수용을 생성 품질 합격이나
전역 기본값 승격으로 보고하지 않는다.

독립 사전 기준선은25표2547행·시작 원장3행·환경 파일과 기존2222파일 SHA다.
최종 보호 대상25표는2560행이다. 기존2545행은 동일하고 승인한 구성 평가 상태와
도메인 활성 연결2행만 변경됐다. 추가13행은 연결/공간/범위 seal3행, 대화2행,
turn2행, 실행2행, audit2행, audit 공간 연결2행이며 기존 삭제는 없다.
이25표 밖의 검색 실행1행·후보2행·사례 결과6행과 시작 원장 추가2행은 별도로 추적했다.
원장 기존3행은 그대로이며 중복 실행은 없었다.

소유자의 현재 권한 조회는 통과하고 다른 actor의 실행 조회는404로 거부됐다.
실행 중인 대화는0건이고, 기존 terminal Codex 취소의 종료 미확인 기록은 변경하지
않았다. `.env` 해시와 기본 임베딩 재사용 cache0도 유지했다. 최종 문서 마감 전
파일 대조에서 기존2222파일 중 제품 파일 변경·삭제는 없었고 허용된 WORKBOARD만
달라졌다. 이 문서·계획·ADR-0048·로컬 실행서의 마감은 그 검증 이후의 문서 변경이다.
백그라운드 제한 회귀는 backend15개(8.62초), frontend8개(11.42초)를 실제 실행해
통과했다. 모델 수용과 독립 검증을 구분하며, 독립 검증자의 모델 호출·DB 쓰기는0회다.

## 문제 이력 마감

본래 관리자 화면에서 ISSUE-00006과 ISSUE-00039를 검증 완료로 갱신했다.
원인·정상 연결 경로·두 실제 대화의 결과·남은 품질/속도/서버 재시작 한계를 저장하고,
각각 2026-10-26 진행 이력을 추가한 뒤 새로고침해 상태와 이력이 남는지 확인했다.
ISSUE-00006의 첫 이력 추가는 직전 편집으로 인한 버전 충돌에 막혔으며, 최신 내용을
다시 열어 저장된 변경을 대조한 뒤 이력 한 건만 정상 저장했다. 기존 이력은 보존했다.
WORKBOARD의 최신 상태·다음 순서·최근 완료와 ADR-0048·로컬 실행서에도 실제 수용
결과를 반영했다. 문서·기록 마감 외 제품 코드·서비스·설치·commit/push 변경은 없다.
마지막 독립 문서 감사에서 상대 파일 링크188개 누락0·최근 완료 목록5개·실측 수치와
품질 경계의 정합성을 확인했다. 범위 지정 `git diff --check`도 종료코드0이었다.
