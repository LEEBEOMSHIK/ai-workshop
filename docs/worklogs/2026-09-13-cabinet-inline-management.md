# 파일함 기본 관리 연결과 사용성

## 승인 범위와 성공 기준

사용자가 기존 관리 기능 연결 및 사용성 개선을 승인했다. 통합 파일함 설계의 단계2 후속이며,
이름 변경·이동·휴지통·새 API·DB 변경·새 모델 실행은 포함하지 않는다.

- 독립 파일함·도메인 파일함·대화 내 선택 패널에서 공통 업로드/새 폴더/새 버전 기능을 재사용한다.
- 실제 workspace capability가 확인된 뒤에만 쓰기 기능을 허용한다. 공간 유형·소유자 이름으로 권한을 추정하지 않는다.
- 전사·개인 구분, 현재 경로와 저장 목적지를 실행 전에 표시한다.
- 요청 진행·성공·실패와 재시도를 구분하고 중복 제출을 막는다.
- 새 항목 생성 후 현재 폴더와 선택을 유지한다. 파일 저장·미리보기는 대화 검색 범위를 자동 적용하지 않는다.
- 권한 조회 실패·철회·도메인 변경·화면 종료·늦은 응답을 안전하게 처리한다.
- 원본 저장 완료와 RAG 준비 상태는 구분한다. 샘플을 실사용 공간에 업로드하지 않는다.

## 역할과 검증

오케스트레이터가 요구·테스트 기준 및 통합을 맡고 프론트 구현 담당과 독립 보안·통합·코드 리뷰 담당을 분리한다.
DB·인프라·AI 모델은 변경하지 않으므로 해당 구현 역할은 제외한다.
기존 API와 공개 합성 테스트 응답으로 TDD를 수행하며 관련 UI 테스트·타입·린트를 확인한다.
코드 구현·자동 검증 및 읽기 전용 브라우저 확인을 완료했다. 실제 자료의 업로드/생성은 사용자 확인 단계다.

### 중간 확인

- 초기 RED: capability 응답 전 활성 쓰기, 권한 재조회 누락, 중복 폴더 제출, 중복 파일 업로드를 재현했다.
- 독립 리뷰에서 목록 재조회까지 잠금 유지, 위치 변경 시 이전 안내 제거, 재조회 권한 오류 이후 쓰기 비활성화를 보완 요청했다.
- 로그인된 로컬 브라우저에서 권한 조회 중 비활성→확인 후 활성, 저장 위치 안내, 새 폴더 입력 UI와 기존 폴더 이동을 확인했다.
- 실제 사용자 문서 업로드·새 폴더 생성·권한 변경은 하지 않았다. 새 UI의 성공/실패 쓰기 경로는 합성 응답 테스트로 검증한다.

### 최종 검증

- 메인 실행: `pnpm --dir frontend test --run src/features/assets src/features/rag/domains/DomainFileCabinet.test.tsx src/features/rag/conversation/DocumentSelectionPanel.test.tsx src/features/workspaces/WorkspaceMemberPermissions.test.tsx --pool=threads --maxWorkers=1`
  →9파일94건 통과(102.13초).
- `pnpm --dir frontend typecheck` 및 전체 `pnpm --dir frontend lint` exit0, `git diff --check` 통과.
- 독립 도메인/관리22건 통과, 이전 공간의 지연 preflight 실패가 현재 선택을 지우는 RED 회귀 수정 확인.
- 최종 capability 지연 응답이 새 권한 철회를 덮어쓰는 회귀를 추가하고 요청 중단으로 해결했다. 구현 담당 최종 관리12건 통과.
- 실제 브라우저에서 폴더 입력 autofocus·취소 후 버튼 초점 복귀, 폴더 이동 시 목적지 변경을 확인했다. 전사 파일함을 원래 루트로 복귀했다.
- DB·모델·서버 설정·사용자 권한·원본 데이터 변경, 샘플 업로드, 패키지 설치, 커밋·푸시는 수행하지 않았다.

### 변경 역할

- `DocumentBrowser.tsx`: 서버 capability, 목적지·권한 안내, mutation 잠금, 권한 철회/위치 수명주기, 폴더 취소·초점.
- `UploadDialog.tsx`: 중복 제출 차단, 명시 재시도와 폐기된 UI의 늦은 결과 무시.
- `DocumentLibrary.module.css`: 기존 파일함 토큰을 사용하는 관리 버튼·안내 스타일.
- `DomainFileCabinet.tsx`: 도메인 사전 조회와 신호 전달, 대화 내 관리 연결 및 기존 명시 선택 유지.
- 관련 기존·신규 테스트: 권한별 노출, 중복 요청, 오류·재시도, 저장 후 동기화, 위치·도메인 전환 및 검색 선택 보존.

## 권한 경계

Platform 서버는 업로드·새 폴더·새 버전에 현재 쓰기 권한을 검사한다.
도메인 파일함은 기존 domain browse/document 경로로 연결·목적지를 먼저 확인한다.
기존 Platform 쓰기 API에는 도메인 식별자가 없으므로 도메인 사전 확인과 파일 저장은 하나의 원자적 트랜잭션이 아니다.
도메인 연결이 직후 변경돼도 이미 권한이 허용된 Platform 저장이 취소되는 것은 아니다.
이 저장은 도메인 활성화·검색 범위 적용·외부 전송 승인을 부여하지 않는다.

## 사용자 확인 순서

1. 파일함에서 전사 또는 개인 공간을 선택하고 저장 위치 안내를 확인한다.
2. 원하는 기존 폴더를 탐색한 뒤 새 폴더 입력·취소를 확인한다. 만들기를 누르기 전에는 저장되지 않는다.
3. 실제로 보관할 파일만 올린다. 진행/결과와 목록 갱신을 확인하며 저장 완료를 검색 준비 완료로 해석하지 않는다.
4. 대화 내 파일 선택 패널에서는 파일 관리 후에도 기존 선택이 유지되는지, 명시 선택 적용 시에만 검색 범위가 바뀌는지 확인한다.

이름 변경·이동·휴지통은 이번 단계에서 제공하지 않는다. 불필요한 테스트 자료를 실사용 공간에 생성하지 않는다.
