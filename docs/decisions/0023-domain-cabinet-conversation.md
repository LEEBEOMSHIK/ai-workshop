# ADR-0023: 도메인 중심 파일함과 대화

## 2026-09-27 사용자 승인 — 첨부 저장과 생성 사용 권한

대화에 접근할 수 있는 사용자는 기존 본인 소유의 쓰기 가능한 개인·유효 임시 공간에 첨부를 저장할 수 있다.
저장 위치를 외부 생성 구성의 구독 공간으로 제한하지 않는다. 공간·계정을 자동 생성하지 않는다.
도메인 접근과 대화 소유권, 업로드 예약 및 최종 연결 시 현재 저장 권한 검사를 유지한다.
저장 권한은 검색·생성 권한을 부여하지 않는다. 현재 도메인/구성 범위 밖 첨부는 `stored` 및
`attachment_outside_generation_scope`로 표시하고 자동 검색 선택과 질문 추가를 제공하지 않는다.
기존 도메인 검색 범위, workspace 외부 전송 정책, 정확한 원문 revision 승인 및 생성 직전 검증은 유지한다.
범위 안 첨부만 기존 projection/build READY 검사를 통과한 뒤 검색 가능 상태가 된다.
저장된 첨부가 답변 근거로 사용 가능하다는 의미는 아니며, UI는 저장 완료와 사용 제한을 구분한다.

## 2026-09-21 사용자 정정 — 대화 문서 선택의 역할

대화 내 패널은 검색 대상 문서를 탐색·미리보기·선택·해제하고 범위를 적용하는 화면이다.
파일함의 업로드·새 폴더·새 버전·이동 등 관리 기능은 대화 패널에 노출하지 않는다.
공통 컴포넌트는 읽기 전용 모드로 재사용하고 독립 파일함의 쓰기 권한과 관리 기능은 유지한다.
이 결정은 아래 2026-09-13 후속 결정 중 대화 패널의 관리 통합 부분을 대체한다.

- 상태: 사용자 상세 계약 승인(2026-09-10), 1단계 코드 구현·자동 검증·실행 서버 반영 완료, 로그인된 실제 화면 검증 대기
- 정본: [도메인 파일함·대화 설계](../superpowers/specs/2026-09-10-domain-cabinet-conversation-design.md)
- 후속 승인(2026-09-13, 단계별 구현 중): [통합 파일함과 대화 범위](../superpowers/specs/2026-09-13-unified-cabinet-design.md)

사용자는 도메인을 먼저 선택하고 그 안에서 회사·개인 파일함과 대화를 이용한다.
문서를 먼저 고른 뒤 도메인을 선택하는 이전 제안은 채택하지 않는다.
파일함 방문·파일 선택·미리보기는 대화의 필수 선행 순서가 아니다. 도메인 대화에서
공간, 폴더 또는 개별 파일을 검색 범위로 선택할 수 있으며 탐색과 미리보기만으로 범위가 변하지 않는다.
독립 파일함은 유지하되 같은 탐색·관리 컴포넌트를 대화의 선택적 패널에서도 재사용한다.
이 후속 결정은 대화 내 파일 관리 통합을 일괄 제외했던 이전 결정을 대체한다.
관리 기능은 서버의 쓰기 권한·동시 변경·휴지통 정합성 계약을 갖춘 순서대로 제공한다.

후속 삭제 방향은 [휴지통·복원·영구 삭제 상세안](../superpowers/specs/2026-09-13-asset-trash-purge-design.md)으로 분리한다.
사용자는 수동/기간 만료 영구 삭제와 연관 데이터 정리를 요구했고 상세 계약을 승인했다. 현재 영속 기반과 RAG 출처·쓰기 차단을 단계별 구현했으며, 실제 영구 삭제 API/UI는 아직 활성화하지 않았다. 최신 단계는 [작업 보드](../../WORKBOARD.md)를 따른다.

2026-09-13 사용자 승인한 [전사 구성원 권한](../superpowers/specs/2026-09-13-workspace-member-permissions-design.md)은
시스템 마스터와 workspace OWNER를 분리한다. 신규/기존 구분은 최초 기본값에만 쓰며 현재 소유자가 부여한 권한을 적용한다.
권한 저장·감사·동시 변경 및 실제 읽기/쓰기 검사를 함께 검증한 뒤 관리 화면에 연결한다.

2026-09-13 승인한 [파일함 이동 계약](../superpowers/specs/2026-09-13-explorer-movement-design.md)은
null 위치를 미분류가 아닌 파일함 최상위로 취급하며, 후속 승인에 따라 화면 표시는 `root`로 통일한다. 동일 공간의 문서·폴더 이동은 별도 metadata_revision과
기존 workspace 잠금으로 보호하며 원본·버전·색인 ID는 유지한다. 서버 이동, 현재 폴더 검색 정합성,
이동 메뉴·드래그앤드롭 순서로 검증하고 제공한다. 현재 검색은 DB의 권한·위치 기반 정확한 원본/빌드 조합을
사용하되 frozen 평가의 과거 snapshot 의미는 유지한다. 실사용 DB 적용은 별도 백업·복원 검증 후 진행한다.

검색 정합성의 내부 권한은 document/asset/projection/build의 정확한 조합으로 관리한다.
명시적 문서 선택과 대화 fingerprint에는 이 내부 전체 목록을 섞지 않는다. 생성 직전에는 준비된 근거가
현재 허용 목록의 부분집합인지 다시 확인하며, 선택 폴더 밖으로 이동한 근거는 범위 변경으로 중단한다.
폴더 제한 없이 선택한 문서의 위치만 바뀐 경우에는 불변 식별자를 유지한다. 이 검사는 생성 직전 시점의
검증이며 외부 모델 응답까지 DB 잠금을 유지하는 보장은 아니다.

이동 UI는 버튼·내부 드래그앤드롭을 같은 명시 확인 흐름에 연결한다. 대화의 고정 폴더는 검색 선택의
제한이며, 같은 공간에서 쓰기 권한이 허용된 이동 목적지와 혼동하지 않는다. 이동 후 선택한 문서를
재조회하고 검색 범위를 벗어나거나 활성 원본이 바뀌면 대화에도 재선택 필요 상태를 전달한다.
구버전 서버의 응답에 유효한 metadata_revision이 없으면 이동을 비활성화한다. 서버 성공 후 조회 실패는
이동 실패와 구분하며 목록 재조회만 제공한다. 실제 적용은 기존 별도 유지보수 승인 경계를 유지한다.

Platform의 원본·권한 소유권은 유지하고 RAG가 도메인 맥락과 검색 연결을 소유한다.
기존 공통 파일함 주소는 보존한다. 문서 선택은 실제 검색 이전 제한과 대화 문맥 검증까지 연결하며,
대화 첨부는 별도의 사용자·대화 소유권 및 만료 계약이 필요하다.
개인·임시 자료를 전사 허용 공간에 자동 추가하거나 외부 전송 승인으로 간주하지 않는다.

도메인 파일함/선택 검색을 먼저, 개인·임시 입력 확장을 다음 단계로 구현한다.
ADR-0021의 독립 원문 열람과 기존 도메인 권한 교집합을 폐기하지 않고 확장한다.
