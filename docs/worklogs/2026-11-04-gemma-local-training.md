# 로컬 Gemma 파인튜닝 장치 확인

2026-11-04 조사 대상은 기존 RAG 비교에 쓰인 `gemma4:e2b-it-q4_K_M`이다. 초기 축소 모델 확인에 이어 실제 E2B-IT CPU 어댑터 학습 한 스텝을 완료했다. 아래 초기 조사와 마지막 실측을 구분한다.

| 확인 항목 | 관측 |
|---|---|
| Windows 장치 | Windows 11 Home ARM64, Snapdragon X2 Plus 10코어, Qualcomm Adreno X2-45 |
| 메모리·디스크 | OS 가시 RAM 23.50 GiB, 측정 순간 가용 8.35 GiB, C 드라이브 여유 116.41 GiB |
| 프로젝트 실행 환경 | x64 Python 3.13.16, PyTorch 2.13.0+cpu, CUDA 사용 불가, Transformers 5.16.1에서 Gemma 4 구조 지원 |
| 학습 도구 | safetensors 0.8.0 설치. PEFT·TRL·Accelerate·bitsandbytes·torchao·datasets·torch-directml 미설치 |
| 기존 모델 | Ollama에 E2B-IT 및 12B-IT의 Q4_K_M 추론 배포본. 프로젝트 모델 루트·기본 Hugging Face 캐시에서 E2B-IT 학습 체크포인트를 확인하지 못했다. |

**실행 검증.** 기존 프로젝트 Python에서 네트워크 없이 Gemma4ForCausalLM의 2층 텍스트 모델을 임의 초기화했다. hidden size 64, vocabulary 128, 4개 attention head, CPU 스레드 2개, seed 7, 배치 1, 합성 토큰 32개다. 기반 가중치를 고정하고 첫 층 query projection에 PyTorch로 rank 2 어댑터를 붙였다. 총 파라미터 88,072개 중 256개를 대상으로 SGD(lr 0.1) 한 스텝을 실행해 유한한 loss 4.80422와 어댑터 최대 변경량 0.00422856을 확인했다. 실제 배포 모델은 읽거나 갱신하지 않았다.

**실제 E2B-IT 판단.** Google의 동일 IT 계열 원본은 Apache 2.0이고 safetensors 한 파일이 약 10.2 GB(9.5 GiB)다. 이는 가용 RAM보다 크며 BF16 LoRA도 기반 가중치 외에 활성값과 역전파 공간이 필요하다. 파일 크기는 실제 실행 RAM의 하한으로 단정할 수 없다. 체크포인트와 토크나이저를 같은 revision으로 확보해야 한다. 현재 PyTorch에서는 CPU 경로만 확인했다. bitsandbytes의 Windows ARM64 CPU 지원과 이 프로젝트의 x64 프로세스는 구분해야 한다. Adreno GPU 또는 NPU에서 이 모델의 QLoRA 역전파를 수행하는 검증된 경로는 이번 조사에서 확보하지 못했다. CPU 양자화 또는 오프로딩은 후보이며 실제 E2B 한 스텝 전에는 소요 시간과 피크를 확정할 수 없다.

**다음 작업.** 공식 원본과 평가 자료를 내려받거나 학습하기에 앞서 공개 합성 자료로 학습·검증·최종 평가를 문서 단위로 분리한다. 지급일·마감 전후·근거 부족을 포함하고 의미 정답과 인용 자동 검사를 별도 기록한다. 실제 모델 시험은 장치와 메모리 예산을 정한 뒤 격리한 학습 환경에서 배치 1·짧은 입력으로 역전파, 어댑터 갱신·저장·재로딩, 최고 메모리와 스텝 시간을 확인한다. 이 수치로 로컬 반복 학습 여부를 결정한다.

## 첫 어댑터 실험의 준비물과 역할

[합성 시드 v1](../../sample-data/public/rag/evaluation/gemma-adapter-pilot-v1.jsonl)은 이 실험을 위해 만든 가상 규정 3종, 질문 6개다. 문서별로 학습·개발 검증·최종 평가를 분리했다. 정답, 조건부 답변, 근거 부족 거절, 혼동하기 쉬운 표 행 선택을 담았다. 6개는 데이터 형식과 채점 흐름 점검용이다. 이미 내용이 공개된 이 소형 세트는 성능 승격 근거로 사용하지 않는다. 기존 AM-SYN-101 질문은 회귀 사례로 보존한다.

| 단계 | Codex 담당 | 사용자 결정 또는 확인 |
|---|---|---|
| 데이터 준비 | 합성 규정별 질문·근거·기대 답변과 인용을 작성한다. 상품·문서·유사 문구 단위로 중복을 확인하고 개발 검증과 별개인 미사용 최종 평가 세트를 고정한다. | 특수한 업무 규칙이나 선호하는 답변 방식이 있으면 예시를 제공한다. 기본 범위는 공개 합성 문서다. |
| 환경 준비 | 로컬을 우선으로 사용 가능한 RAM과 장치 호환성을 재확인한다. 격리 환경에 고정할 원본 revision, tokenizer, 패키지, 모델 저장 위치와 디스크 예산을 기록한다. | 사용 가능한 별도 GPU가 있으면 종류와 VRAM을 알려준다. 유료 환경을 원하면 허용 예산과 시간을 정한다. |
| 실제 모델 시험 | 기반 가중치를 동결하고 어댑터만 학습한다. 배치 1·짧은 입력으로 forward/backward/update를 한 번 수행해 유한한 loss, 어댑터 변경, 저장·재로딩 시 출력 재현을 검사한다. 이후 실제 근거 길이로 스텝 시간과 최고 RAM/VRAM을 재서 목표 학습 분량의 시간·비용을 산정한다. | 예상 자원과 시간을 보고 본 학습을 실행할 장치를 결정한다. |
| 품질 비교 | 현행 Ollama를 B0로 기록한다. 같은 revision·정밀도·프롬프트·근거·생성 설정에서 어댑터를 끈 B1과 켠 B2를 비교한다. 문서별 정답·조건 누락·인용의 원문 지지·근거 부족 거절과 제품 검사 결과를 기록하고, 동일 장치에서 첫/반복 응답 시간도 측정한다. | 예시 답변과 실패 사례를 보고 일반 대화에 적용할 가치가 있는지 판단한다. |

학습용 변환 시 모델 입력에는 질문과 허용된 근거만 넣고, 학습 split의 검토 답변·인용만 정답으로 넣는다. 평가 정답은 채점 시에만 사용한다. 제품 인용 형식과 채팅 템플릿은 기존 실행 입력으로 대조한다. 학습이 끝나면 한국어 마감 경계, 상대 영업일, 근거 부족 거절에서 새로 발생한 오류를 먼저 확인한다. 기존 Terra 비교의 의미 판정과 자동 인용 판정이 충돌한 사례는 별도로 보고한다.

## 실제 E2B-IT CPU 한 스텝

2026-11-04 기존 Windows ARM64 장치에서 x64 PyTorch 2.13.0+cpu, 6스레드, BF16 기반 가중치, FP32 LoRA rank 4로 실행했다. Google 공식 google/gemma-4-E2B-it revision `4adf15748de9e1a0097b6274cee9c15836c41c37`의 가중치 10,246,621,918바이트와 토크나이저 SHA-256을 공식 메타데이터와 대조했다. 로더 보고에서 누락·예상 밖·형상 불일치 키 및 오류는 각각 0개다.

공개 합성 학습 예제 pilot-1의 근거·질문·정답을 사용했다. 배치 1, 총 52토큰 중 정답 18토큰에 손실을 계산했다. 전체 기반 파라미터 5,104,297,504개를 동결하고 35개 언어 층의 attention query projection에 붙인 어댑터 파라미터 559,104개만 AdamW(lr 0.0002)로 갱신했다. 손실 2.98003, 기울기 모두 유한, 35층 모두 초기 0인 B 행렬의 변화를 확인했다. 70개 텐서(2,245,080바이트)를 저장하고 어댑터를 비운 뒤 같은 프로세스에서 파일을 다시 읽어 마지막 토큰의 전체 logits가 저장 직전과 정확히 일치하는지 검증했다.

| 구간 | 벽시계 시간 | 표본 최고 상주 RAM |
|---|---:|---:|
| 라이브러리 import | 33.037초 | 463 MiB |
| 모델 로더 호출 | 3.099초 | 488 MiB |
| 어댑터·입력·옵티마이저 준비 | 3.554초 | 559 MiB |
| 순전파·손실 | 45.405초 | 5,164 MiB |
| 역전파 | 624.711초 | 5,210 MiB |
| 기울기 확인·가중치 갱신 | 0.079초 | 4,866 MiB |
| 저장·재로딩·출력 재검증 | 29.429초 | 4,892 MiB |

순전파부터 갱신까지 670.195초, import부터 재검증까지 739.314초다. 다운로드·체크섬 확인은 별도다. 로더 반환 뒤 첫 연산에서 메모리 페이지 접근이 일어나므로 3.099초를 모든 가중치의 물리 RAM 적재 시간으로 해석하지 않는다. Windows 프로세스 생애 최고 WS 5.09 GiB, 최고 전용 커밋 20.79 GiB. 약 0.25초 간격 표본의 최고 전용 커밋은 11.66 GiB로 순간 최고치를 놓쳤다. 시스템 전체 최소 가용 RAM은 1.17 GiB였다.

이 환경은 기능 확인용 1스텝에 사용할 수 있다. 52토큰 스텝이 같은 비용으로 반복된다는 가정에서 100스텝은 약 18.6시간이다. 반복 학습이나 긴 근거, GPU 속도·VRAM을 실측한 값은 아니다. 본 학습 장치 후보에서는 같은 52토큰 스텝과 실제 RAG 근거 길이를 각각 측정한 뒤 예산을 정한다. 1스텝은 답변 품질 평가와 구분한다.

로컬 원본은 Git 제외 폴더 `.local-data/gemma-e2b-step/`의 probe.py, result.json, step-adapter.safetensors 및 고정 revision 모델 폴더다. 어댑터 SHA-256은 `e6272d0d0da5da6f3e652fe95311e633e25e22cebb70a98d14157cce20b0544c`다.

## 이 PC에서 직접 실행

PowerShell 7에서 프로젝트 루트로 이동한 뒤 아래 명령으로 사용한다. 실행기는 이 PC의 Git 제외 폴더에 있으며 사전에 받은 고정 버전 가중치를 사용한다.

```powershell
cd C:\projects\ai-workshop
pwsh -NoProfile -File .\.local-data\gemma-e2b-step\try.ps1 -Mode ask
```

근거 입력에서 Enter를 누르면 합성 지급 규정(T+3영업일)을 사용한다. 다음 입력에 질문을 적는다. 이 명령은 기존에 저장한 한 스텝 어댑터로 최대 64토큰을 생성한다. 사이트의 RAG 검색이나 인용 판정을 거치지 않는 로컬 단발 질의다.

같은 공개 예제로 직접 한 스텝 학습하려면 `-Mode train`을 사용한다. 매회 동일한 원본 모델에서 시작해 결과 폴더를 `.local-data/gemma-e2b-step/runs/` 아래 새로 만든다. 해당 결과로 질문하려면 ask 명령에 `-Adapter "실행 출력에 표시된 폴더\step-adapter.safetensors"`를 추가한다. 이전 실측은 학습 약 11분 10초, 준비·저장 검증까지 약 12분 19초였다.

## 후속 비교 기준

첫 학습 예제는 정답에 `[e1]`을 붙였지만 모델 입력에는 해당 규정의 번호를 표시하지 않았다. 첫 어댑터로 실제 질문을 생성했을 때 지급 시점은 맞았고 인용 번호는 빠졌다. 후속 비교에서는 근거 앞에 번호를 붙여 입력·정답을 대응시키고, 기존 어댑터와 추가 학습본을 같은 질의 형식에서 실행한다. 이렇게 해야 번호를 보여주는 효과와 가중치를 갱신한 효과를 구분할 수 있다.

학습 예제에서는 접수일 기준 3영업일과 인용을 확인한다. 학습에 쓰지 않은 점검표에서는 긴급 점검의 기한과 해당 행의 번호, 표에 없는 배상액 질문에서 금액을 단정하는지를 별도로 본다. 최종 평가 문항을 보고 학습 횟수나 후보를 바꾸면 독립 평가로 집계하지 않는다.

11월 5일 실행은 이전 어댑터를 읽고 마지막 층의 query projection에 연결된 LoRA A/B 22,528개 파라미터만 학습하도록 했다. 기반 모델과 나머지 층의 어댑터 가중치는 고정했다. 학습 문항 순서는 평가 전에 pilot-1, pilot-2, pilot-1, pilot-2로 정했다. CPU 6스레드, 배치 1, AdamW(학습률 0.002, weight decay 0), seed 7을 사용했다. 생성은 양쪽 모두 샘플링 없이 최대 64토큰이다. 각 질문의 프롬프트와 해시, 정답, 최종 답변, 학습 및 후보 파일 식별값은 로컬 실행 기록에 보관한다.

**측정 결과.** 전후 생성과 검증을 포함해 1,026.69초가 걸렸다. 세 문항에서 기존·후보의 입력 해시와 실제 답변이 각각 같았다. 지급일 질문에는 접수일 기준 3영업일과 [e1], 미사용 점검표의 긴급 점검 질문에는 1영업일과 [e2], 배상액 질문에는 “알 수 없습니다.”라고 답했다. 인용 번호와 지시를 제공한 조건에서는 기존 어댑터도 이미 세 문항을 충족했다. 이번 추가 학습의 생성 품질 향상은 관찰되지 않았다. 미사용 평가는 한 문서의 두 질문이다.
