# 도메인 선택 기반 대화형 RAG

- 기준일: 2026-09-07
- 상태: 구현·독립 리뷰 완료 / 실제 관리자 연결·사용자 검증 대기
- 설계: [승인 설계](../superpowers/specs/2026-09-07-domain-first-rag-conversation-design.md)
- 계획: [구현 계획](../superpowers/plans/2026-09-07-domain-first-rag-conversation.md)

## 구현 경계

로그인 사용자 검색 입구를 전문 도메인 선택으로 변경한다. 도메인 안에서는 대화와 근거
확인에 집중하고 지식공간·폴더 범위는 대화 화면 안에서 조정한다. 관리자는 별도 도메인
화면에서 정확한 저장 RAG 구성 버전과 허용 공간을 연결한다.

기존 문서를 자동 분류하거나 도메인 예시를 자동 등록하지 않는다. 공개 검색, 인라인 첨부,
피드백 저장·학습은 이번 구현에 포함하지 않는다. 모델·Docker 변경과 외부 모델 호출도 없다.

## 검증할 보안 경계

- 기존 개인 소유 RAG 구성의 직접 조회 권한은 유지한다. 도메인 서비스의 정확한 구성 해석은
  별도 경계에서 수행하되 검색·근거·원문 조회는 실제 로그인 사용자의 권한으로 처리한다.
- 도메인·구성·사용자 권한의 교집합만 검색한다. 외부 전송 승인 검증에 쓰이는 원래 구성
  공간 목록을 검색 교집합으로 덮어쓰지 않는다.
- 활성 서비스 연결 버전을 고정하고 매 검색에 재검사한다. assistant 토큰은 해당 연결과
  정규화한 공간·폴더 범위에 결합하여 다른 범위의 토큰 재사용을 거절한다.
- 활성화에는 평가 통과·생성형 답변 정책·현재 런타임/색인 준비 상태를 함께 검사한다.

## 확인 상태

백엔드 독립 리뷰에서 연결 공간의 저장 후 추가 가능성을 발견해, 최초 생성 트랜잭션 종료 시
DB에서 공간 집합을 봉인하도록 수정했다. 비활성 과거 연결도 같은 규칙을 적용한다. 수정
재검토는 통과했다.

- 메인 실행: backend 디렉터리 단위 테스트 764건 통과, 기존 Starlette 사용 중단 경고 1건.
  루트에서 실행한 최초 검사는 `.env`를 읽는 기존 기본값 테스트가 실패해 실행 위치를 교정했다.
- 구현자 실행: 도메인 24건, 기존 생성·검색 55건, OpenAPI 7건과 Ruff·mypy 통과.
- 수정 후 메인 실행: 격리 DB 마이그레이션·저장소 3건 통과.
- 최종 백엔드 재검증: 단위·계약 테스트 776건, `ruff check src tests`, mypy 184개 소스 통과.
- 로컬 DB는 검토 후 0022에서 0023으로 갱신했다. 도메인·연결은 각 0건이며 기존 데이터를
  자동 연결하지 않았다. API만 재시작해 health 200·신규 경로·익명 401을 확인했다.
- 브라우저 사용자 경로는 로그인 화면으로 이동했다. 계정·세션을 조작하지 않았다.
- 프론트 기존 테스트 211건은 검증 담당이 겹치지 않는 5개 묶음으로 실행해 모두 통과했다.
  순차 jsdom 준비 비용과 출력 지연이 확인됐으며 특정 멈춤은 재현되지 않았다. 이후 검사는
  `--pool=threads --maxWorkers=1 --reporter=verbose`로 진행 상황을 확인한다. 기존 모델 화면의
  React act 경고 2건은 별도 유지보수 대상이다. 새 대화 화면 검증은 아직 진행 중이다.

## 프론트 리뷰에서 발견한 문제

첫 전체 프론트 검사 229건과 운영 빌드는 통과했으나 독립 리뷰에서 다음 두 문제를 발견했다.
두 문제는 재현 테스트와 수정 후 독립 재리뷰를 통과했다.

- 관리자 목록은 `DomainResponse[]`인데 클라이언트가 생성·수정 응답인 `AdminDomainResponse[]`로
  간주했다. 강제 generic 지정과 잘못된 테스트 fixture가 타입·빌드 검사를 통과시켰지만,
  실제 활성 연결 표시와 비활성화 동작은 틀릴 수 있었다. 서버 목록 형식을 그대로 사용하는
  회귀 테스트와 명시적인 화면용 변환으로 보완한다.
- 요청별 외부 전송 확인을 성공 응답 때만 해제하여 실패·취소 후 재사용할 수 있었다.
  요청 시작 시 확인을 소비하고 실패·취소 후 새 확인을 요구하는 회귀 테스트로 보완한다.

## 최종 자동 검증

- 수정 전 실패 3건(실제 활성 목록 1건, 실패·취소 후 확인 재사용 2건)을 재현했다.
- 수정 후 관리자·대화·관리자 경로 15건, 타입·린트·OpenAPI 일치 검사를 통과했다.
- 메인 최종 프론트 검사: 52개 파일, 232건 통과, 199.09초. 기존 모델 화면 act 경고 2건.
- 최종 Next.js 운영 빌드도 통과했으며 새 관리자·사용자 경로는 동적 페이지다.
- 프론트 개발 서버를 다시 실행했고 웹·API의 HTTP 200을 확인했다. Docker·worker는 변경하지 않았다.
- 개별 백엔드·프론트 독립 리뷰는 통과했다. 사용량 오류로 중단된 최종 통합 리뷰를 사용자
  재개 요청 후 이어서 진행했고 두 통합 오류 흐름의 보완을 요청받았다.

## 통합 오류 흐름 보완

- `domain_connection_changed` 이후 화면만 초기화하면 이전 연결 ID로 재요청하는 문제가 있었다.
  도메인 재진입으로 연결·허용 범위·처리 고지를 함께 갱신하도록 안내하고, 기존 화면의
  입력·새 대화·재시도를 차단한다.
- 실제 인용 검증 실패는 성공 응답 내부 상태가 아니라 502 `ErrorEnvelope`로 전달된다.
  실제 403 전송 정책 거절과 503 모델 미준비도 함께 검증해 일반 오류와 구분한다.
- 실제 오류 형식의 회귀 5건을 실패로 재현한 뒤 대화 테스트 16건이 통과했다. 수정 후
  정적 검사와 최종 수정분 독립 재리뷰를 통과했다. 최종 대화·경로 검사는 18건 통과다.
- 전송 정책은 선택한 검색 범위가 아니라 저장 구성 전체 공간에 적용된다. 따라서
  `workspace_external_transfer_denied`는 폴더를 바꿔 재시도하도록 안내하지 않고 관리자 확인 후
  도메인 재진입을 요구한다. `search_scope_empty`만 화면의 범위 수정으로 복구한다.
- 마지막 수정 후 Next.js 운영 빌드, ESLint, OpenAPI 검사를 메인에서 다시 통과했다.
  프론트 서버만 빌드 전 종료·재시작했고 웹 루트와 `/api/v1/health`의 200을 확인했다.
- 마지막 전체 프론트 검사는 52개 파일에서 234 passed / 3 failed, 456.08초였다.
  `ComparisonPanel`과 `ConfigurationStudioPage`의 첫 테스트가 5초를 초과했고, 비교 화면의
  다음 테스트에는 이전 비동기 타이핑이 섞인 UUID 입력이 관찰됐다. 두 소스·테스트는 이번
  작업에서 변경하지 않았다. 실패 결과를 단일 전체 검사 통과로 표현하지 않는다.
- 빌드를 끝낸 뒤 같은 pool·worker·기본 제한 시간으로 두 파일만 재실행했다.
  `node node_modules/vitest/vitest.mjs run src/features/rag/configurations/ComparisonPanel.test.tsx src/features/rag/configurations/ConfigurationStudioPage.test.tsx --pool=threads --maxWorkers=1 --reporter=verbose`
  결과는 2 files / 36 passed, 41.34초다. 제품 코드·테스트·제한 시간 변경 없이 통과했다.
  빌드 동시 실행과 시간 의존성이 관련된 것으로 추정하며, 전체 실행 조건의 안정화는 후속이다.
- `WORKBOARD.md` 최근 완료 항목은 5개로 유지했고 다음 작업은 실제 관리자 연결과 사용자
  검증이다. main의 로컬 변경만 유지했으며 staging·commit·push는 하지 않았다.
- 검증용 소스는 회귀 테스트로 보존한다. 임시 리뷰 diff·스냅샷은
  `.local-data/project-agent-work/domain-conversation/`에만 있으며, 정책상 정확 대상 삭제 승인
  전까지 보존한다. 사용자 references·원본·이전 OCR 작업은 정리하지 않았다.

기존 OCR 변경과 사용자 데이터를 보존한다. 이 기록은 실제 LLM 대화의 실사용 검증 완료를
의미하지 않는다. 실제 도메인 연결·활성화와 로그인 후 화면 확인은 관리자 선택 후 진행한다.
