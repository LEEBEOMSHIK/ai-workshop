# Codex 요청별 작업 폴더와 실행 어댑터 연결

## 범위와 역할

기존 실행기 registry·명령 조립기·stream adapter 사이에 실제 요청별 작업 폴더 수명주기를 연결한다.
Python/AI 구현과 독립 보안/privacy 검토를 분리하며 메인은 통합 검증·문서를 담당한다.
계획: `docs/superpowers/plans/2026-09-09-codex-request-workspace.md`.
main에서만 작업한다. 실제 Codex·모델·인증·네트워크·사용자 DB·설정·UI·서버는 변경하지 않는다.

## 수명주기 계약

1. 이름으로 실행기를 조회하고 예상 설정 지문과 비교한다. 명령·입력 검증 실패는 폴더 생성 전에 처리한다.
2. 전용 루트에 무작위 이름의 새 직접 하위 폴더를 배타적으로 생성한다. 기존 폴더를 재사용하지 않는다.
3. 서비스의 정해진 schema bytes만 고정 파일에 배타적으로 기록한다. 질문·이력·문서·지침은 저장하지 않는다.
4. 실행 직전 실행기 지문·파일과 폴더·schema 소유권을 다시 확인하고 주입된 stream adapter를 호출한다.
5. 프로세스 종료와 자식 0개가 확인된 뒤 자기 파일과 빈 폴더만 정리한다. 결과는 정리 확인 후 반환한다.

파일이나 폴더가 교체되거나 연결 경로가 생긴 경우, 알 수 없는 파일이 추가된 경우,
프로세스 종료를 확인하지 못한 경우에는 답변을 폐기하고 정리 실패로 남긴다. 재귀 삭제로
문제를 덮지 않는다. 이후 정확한 요청 폴더 조사·정리는 별도 승인된 범위에서 진행해야 한다.
보존 상태의 진단에는 무작위 workspace ID와 안전한 코드만 사용하며 호스트 경로·본문을 노출하지 않는다.

## 보장하지 않는 것

이 코드는 권한을 부여하는 공개 API나 사용 준비 상태가 아니다. 기본 live runner도 자동 생성하지 않는다.
영속 승인에 설정 지문을 결합하는 작업, 동시 실행 제한, 현재 권한 재검사, 실제 CLI 유효 설정과 모델
관측 및 RAG runtime/API 배선은 후속 coordinator에서 완료해야 한다. 경로·identity 전후 검사는
검사 사이의 모든 악의적 교체 경쟁을 제거한 OS sandbox 증명이 아니다.

## 검증 기록

실제 합성 파일과 명시적인 가짜 stream을 사용한다. 기존 stream 계층의 실제 Windows 프로세스 검증과
이번 파일/어댑터 검증을 구분한다. 신규 workspace 45건과 기존 Learning 대상 1건은 메인 재검증에서
46개 통과했다. 독립 보안/privacy·설계·코드 검토에서 확정 결함 없이 제한된 단계 인계를 승인했다.

- 전체 unit/contract 재검증: 1,537 passed, 4 skipped, 기존 Starlette 경고 1건(59.66초).
- mypy: 222 source files 통과. 관련 source/test와 Learning test Ruff 통과.
- 4개 skip은 기존 Windows 실제 symlink 생성 권한 제한이며, 이번 모의 reparse 검사로 대체 실증했다고 주장하지 않는다.
- 실제 CLI·모델·사용자 DB·UI·서버·설정 변경이나 준비 상태 활성화는 하지 않았다.

첫 전체 실행은 기존 Learning cursor 변조 테스트에서 1건 실패했다(1,536 passed, 4 skipped).
마지막 Base64 문자만 바꾸면 padding bits 차이로 같은 서명 bytes가 될 수 있었다.
구현 담당이 해당 테스트만 첫 서명 문자를 반드시 다른 값으로 바꾸도록 수정했고 독립 리뷰를 거쳤다.
HMAC 검증 서비스는 변경하지 않았다. 이 수정 후 위 전체 검사를 통과했다.

영속 승인과 실행 설정 지문 결합 → 동시 실행 제한 → 실제 CLI 유효 설정/모델 확인 →
검색·평가·연결 검사 및 관리자 구성 배선을 이어간다. 전체 대화형 RAG 사용자 테스트 준비 완료는 아니다.
