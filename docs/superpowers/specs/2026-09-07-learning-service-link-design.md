# 학습·실험 기록과 AI 서비스 연결

- 상태: 사용자 승인 / 1단계 구현 계획 작성 / 구현 전
- 날짜: 2026-09-07
- 승인된 방향: 서비스와 학습·문제 해결 과정을 연결하고 자유 메모·구조화 실험을 모두 지원한다.
- 정본 경계: [전체 설계](../../architecture/system-design.md), [비전](../../vision/project-vision.md)

## 1. 현재 상태와 범위

RAG 연구실과 담당 캐릭터 설명은 구현되어 있다. 내용은 frontend content registry에서 읽는다.
Platform Learning·Publishing은 목표 구조에만 있고 실제 저장 모듈은 아직 없다.
따라서 기존 기록 CRUD가 있는 것처럼 연결하거나 허구의 실험·성공 지표를 채우지 않는다.

이번 설계는 학습 기록, 서비스와의 연결, 수동 공개 절차를 다룬다. Codex 실행 위험 수용,
실제 외부 모델 호출, 모델 다운로드·학습, 새 공개 서비스 활성화는 별도 승인·검증 범위다.

## 2. 대안과 권고

1. RAG 화면 내부에 학습 글을 직접 작성: 작지만 다른 기술의 기록과 공개 절차를 재사용하기 어렵다.
2. 공통 Learning 기록과 기술별 연결을 분리: 권고. 개인 작업소에서 기록하고 서비스·캐릭터가 관련 기록을 안내한다.
3. 별도 CMS 서비스 도입: 현재 단일 사용자 규모에는 운영 부담이 크므로 보류한다.

## 3. 소유권과 의존 방향

- Platform/Learning: 기술 주제, 자유 메모, 구조화 실험·문제 해결 기록, revision과 관련 참조를 소유한다.
- Platform/Publishing: 공개용 편집본, 특정 revision의 승인, 내보내기·게시·철회를 소유한다.
- Labs/RAG: 검색·생성 실행 및 RAG 평가 결과의 정본이다. 학습 글이 실행 결과를 덮어쓰지 않는다.
- 파인튜닝은 별도 기술 주제다. 향후 실제 학습 구현은 별도 Labs 경계로 두며 RAG에서 직접 import하지 않는다.
- Platform은 RAG의 모델·실행 타입을 import하지 않는다. 기술 연결은 일반화된 종류·식별자·버전 참조로 표현한다.
- 대상 해석기는 애플리케이션 조립부에서 연결한다. 기록의 소유권은 연결된 자료의 접근권한을 부여하지 않는다.
- RAG와 파인튜닝은 주제이며 자산운용·보험·법률·HR은 도메인이다. 기술 주제와 도메인 분류를 혼용하지 않는다.
- 주제 목록·라벨·관련 기능은 명시적 registry/저장 데이터로 관리한다. UI 분기와 모델명을 하드코딩하지 않는다.

## 4. 기록 계약

공통 필드: 내부 ID, 소유자, 제목, 기록 종류, 기술 주제 참조, 선택적 도메인 분류,
작성·수정 시각, revision, 본문, 관련 기록·서비스·실행 참조, 보관 상태.
내부 ID는 사용자에게 의미 있는 이름을 대신하는 표기로 사용하지 않는다.

- 자유 메모: 제목과 본문만으로 저장 가능. 가설·결론·평가 수치를 강제하지 않는다.
- 구조화 실험: 목적, 가설, 데이터 snapshot 참조, 비교 구성, 실행 환경, 절차, 관찰,
  평가 결과, 한계, 결론, 다음 작업. 작성 중에는 일부 필드가 없어도 저장된다.
- 실험 상태: planned / running / completed / failed / cancelled. 실행 상태와 결과의 좋고 나쁨은 별개다.
  completed는 실험 수행 완료이며 품질 개선이나 운영 승격을 의미하지 않는다.
- 문제 해결 기록: 증상, 재현 조건, 확인된 사실, 원인 가설·확정 원인, 변경 사항,
  재검증 결과, 미해결 항목. 추측과 검증 결과를 구분한다.
- 자유 메모를 실험 기록으로 전환할 때 원본과 관련 참조를 보존하고 사용자 확인 후 새 revision을 만든다.
- 연결 삭제·권한 상실 시 원본 내용을 유출하지 않고 이용 불가 상태를 표시한다.
- 연결 생성·조회·미리보기마다 대상 권한을 검증하며 비허용 대상의 제목·본문도 복제하거나 노출하지 않는다.
- 수정은 revision 충돌을 검출하고 조용히 덮어쓰지 않는다. 첫 버전은 보관/복원으로 관리한다.
  영구 삭제·첨부 수명주기는 별도 확인 절차를 설계한 뒤 추가한다.

## 5. 화면과 경로 제안

| 경로 | 대상·역할 |
|---|---|
| `/workshop/learning` | 로그인한 기록 소유자의 목록·주제 필터·새 메모/실험 |
| `/workshop/learning/[recordId]` | 소유자만 열람·편집, 관련 실행·근거·다음 작업 |
| `/admin/publishing` | owner의 공개용 편집본 검토·미리보기·승인·게시·철회 |
| `/labs/[labSlug]/studies` | 해당 기술에 연결된 승인된 공개 학습·실험 목록 |
| `/studies/[publicSlug]` | 공개 snapshot 상세. 여러 기술에서 같은 공개 글로 연결 가능 |

RAG 담당 캐릭터의 말풍선에는 역할 설명과 함께 관련 개념·실험/문제 해결·서비스 링크를 제공한다.
공개 글이 없으면 빈 링크를 만들지 않는다. 채팅 화면은 대화와 필요한 범위 선택 기능만 유지한다.
공개 화면에 편집·모델 설정·학습 데이터 관리 버튼을 넣지 않는다.
파인튜닝 학습 주제를 추가한다고 공개 연구실 방이나 서비스가 완성된 것으로 등록하지 않는다.
전용 파인튜닝 방·학습 관리 메뉴는 실제 기능 개발 시 별도 설계한다.

## 6. 공개 경계

모든 작업 기록은 기본 비공개다. owner가 공개용 편집본을 만들고 필드를 직접 선별한다.
검토는 본문뿐 아니라 제목·태그·링크·이미지·첨부·모델/실행 metadata를 포함한다.
첫 공개 버전은 안전한 텍스트/Markdown과 검증된 링크만 지원하고 임의 HTML·첨부를 허용하지 않는다.
비공개 편집·미리보기도 스크립트·외부 이미지 자동 로딩을 차단한다. 링크 자동 수집·외부 요약은 하지 않는다.

공개 상태는 draft → approved → published → withdrawn이다. 승인은 정확한 편집본 revision/hash에
귀속된다. 수정된 본문은 다시 승인받아야 하며 게시와 철회는 명시적 owner 행동이다.
공개 package는 allowlist 필드만 직렬화한 불변 snapshot으로 별도 공개 저장소/배포 경계에 전달한다.
공개 조회는 비공개 DB 또는 원본 경로를 참조·join하지 않는다. 공개 slug와 공개 참조만 사용한다.
원본 변경은 공개본에 자동 반영하지 않는다. 게시 원자성과 반복 요청 멱등성을 검증한다.
철회 시 공개 조회·목록·배포 캐시 제거까지 확인하며 타인이 이미 복사한 자료의 회수를 보장하지 않는다.
공개 검색색인과 캐릭터 링크에도 철회를 반영한다. 향후 첨부 허용 시 포함 자산 manifest/hash까지 승인에 묶는다.

모델명·버전은 승인된 공개 metadata로만 표시한다. credential, endpoint, host path,
개인정보·비공개 원문·내부 추론·raw protocol log는 공개하지 않는다.

## 7. RAG와 파인튜닝 비교 기록

비교군은 RAG+Codex CLI, RAG+로컬 기본 모델, RAG+동일 모델의 파인튜닝 버전이다.
초기 생성 비교는 질문·허용된 이력·순서와 내용이 같은 검색 근거를 고정한다.
전체 대화형 비교에서는 문맥화·검색 차이도 결과에 영향을 주므로 별도 실험으로 구분한다.
모델/adapter 버전, prompt·generation profile, 데이터 snapshot, 실행 환경, 반복 횟수,
정답성·근거 충실도·인용 정확도·답변 유보·후속 질문·지연·자원/사용량을 기록한다.
파인튜닝 개선을 보장하지 않으며 악화·차이 없음도 정상 실험 결과다.

학습용 데이터와 평가용 데이터는 분리한다. 문서 계보·유사 항목을 고려해 누출을 점검한다.
로그인 사용자 피드백은 권한·데이터 사용 조건을 확인한 뒤 수동 검토·정답 수정·승인된 항목만
학습 후보로 만든다. 좋아요를 정답, 싫어요를 오답으로 자동 변환하지 않는다.
공개 방문자의 입력·피드백은 학습 데이터로 저장·승격하지 않는다.
학습 기록과 실제 학습 데이터셋은 별개다. 기록을 공개해도 데이터셋은 공개되지 않는다.
공개 승인·외부 전송 승인·훈련 데이터 사용 승인은 분리한다. 수동 후보 지정만으로
데이터 권리·개인정보·비식별화 검토와 훈련 승인을 대체하지 않는다.

## 8. 단계별 구현·성공 기준

1. 비공개 Learning 수직 슬라이스: 두 기록 종류의 생성·목록·상세·수정·보관/복원,
   주제 분류와 관련 참조, 소유권 검사. 첫 화면에서 자유 메모와 실험을 모두 실제 저장할 수 있어야 한다.
2. Publishing과 캐릭터 연결: 공개 편집본·revision 승인·분리 snapshot 조회·철회,
   RAG 담당자에서 실제 공개 학습 글로 이동. 승인되지 않은 본문은 어떤 공개 경로에서도 조회되지 않아야 한다.
3. 모델 비교·수동 파인튜닝: 모델 실행 경로의 별도 승인 후 실제 결과 참조와 학습 후보 수동 관리.
   학습 런타임·장치 적합성은 별도 설계하며 미래 코드 폴더를 먼저 생성하지 않는다.

단계 1 구현 위치: backend Platform/learning, frontend features/learning 및 workshop 라우트,
관련 migration·단위/계약/권한 통합 테스트. 기존 공통 인증·DB 어댑터 패턴을 재사용한다.
단계 2에서만 Publishing 모듈과 공개 라우트를 만든다. 구현 전 해당 공개 계약을 ADR로 확정한다.

필수 검증: 비로그인/타인 접근 차단, revision 충돌, 보관 복원, 참조 권한 재검증,
Markdown XSS·위험 URL 차단, 공개 export의 금지 필드, 재승인·게시 원자성·철회/캐시,
키보드 캐릭터 접근·링크 탐색, 학습/평가 분리. 외부 모델 없는 단위 테스트를 유지한다.
검증은 단계별로 실행하며 전체 기능 완성 또는 학습 완료로 오인시키지 않는다.

## 9. 승인과 다음 순서

사용자가 상세 설계를 승인하고 단계 1 계획 작성을 요청했다.
[비공개 Learning 구현 계획](../plans/2026-09-07-private-learning.md)이 첫 실행 범위다.
Codex 잔여 위험 수용, 외부 전송·학습 실행 승인은 이 문서 승인으로 대체하지 않는다.
독립 구조 검토의 참조 권한·공개 철회·승인 분리·안전한 메모 렌더링 요구를 반영했다.
이는 구현 검증이나 최종 코드 리뷰 완료를 뜻하지 않는다.
