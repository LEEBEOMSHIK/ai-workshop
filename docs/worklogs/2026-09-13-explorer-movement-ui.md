# 파일함 이동 메뉴·드래그앤드롭

- 상태: 핵심 구현·자동 검증 마감. 경미한 키보드 초점 보완과 실사용 적용은 후속.
- 설계: [파일함 이동 계약](../superpowers/specs/2026-09-13-explorer-movement-design.md)
- 계획: [UI 연결](../superpowers/plans/2026-09-13-explorer-movement-ui.md)

## 구현 범위

공통 탐색기에서 문서·폴더 하나를 같은 공간의 다른 폴더 또는 파일함 최상위로 이동한다.
버튼과 내부 드롭 모두 출발지·목적지를 표시하는 확인 창을 사용하며 확인 전 저장하지 않는다.
외부 파일 드롭은 이동 명령이나 업로드로 해석하지 않는다.

쓰기 권한과 실제 metadata_revision을 검사하고, 충돌은 최신 자료를 다시 확인한 뒤 사용자가 재확인한다.
서버 저장 후 목록 조회가 실패한 경우에는 목록 재조회만 제공한다.
대화에 선택한 문서는 이동 후 다시 확인하고, 고정 범위 밖으로 나가면 명시 재선택을 요구한다.

## 검증 경계

프론트 계약은 합성 HTTP 응답과 실제 컴포넌트로 검증한다. 별도 Next.js 테스트 인스턴스와
메모리 합성 API를 사용하는 브라우저 검사는 실제 애플리케이션 UI의 동작/레이아웃 검증이며,
실사용 backend 또는 실제 문서의 끝단 검증으로 표현하지 않는다.
메인 검증 결과(정적 검사도 최종 수정 상태에서 재실행):

- `node node_modules/typescript/bin/tsc --noEmit --pretty false --incremental false`: exit0.
- `node node_modules/eslint/bin/eslint.js . --max-warnings 0`: exit0.
- `node openapi-ts.config.mjs --check`: exit0.
- 별도 Next.js + Edge: 문서 이동 버튼·문서 드래그·폴더 드래그 각각 확인 전 POST0,
  확인 후 정확한 목적지/revision POST1. 총3회는 메모리 합성 자료만 변경했다.
- 외부 파일 드롭 무시, Escape 취소/초점 복귀, 로딩 완료 후390px 가로 넘침 없음,
  브라우저 런타임 오류 없음. 총40회 합성 API 요청.
- 후속 실제 브라우저 검사에서 POST 응답을 보류하고 처리 중 Tab/Shift+Tab 초점 유지와
  Escape 닫힘 차단도 확인했다. 일반 이동3회·화면 검사와 함께 통과했다.
- 검증 프로세스 종료 후 자체 포트57647/57648 닫힘을 확인했다. Next가 자동 추가한
  테스트 인스턴스 타입 경로만 원복해 `next-env.d.ts`/`tsconfig.json` 변경은 남지 않았다.
  후속 검사 포트57053/57054와53236/53237도 종료 후 닫힘을 확인했다.

전체 관련 단위 검사는 동시 실행 부하 중 일부5초 시간 초과가 발생하여 중복 실행을 중단했다.
이 실행을 통과로 계산하지 않았다. 이후 순차 실행은150건/12파일, exit0으로 통과했다(287.58초).
최종 복구 행 보완까지 적용한 재검사는 **152건/12파일, exit0**으로 통과했다(273.63초, 경고 없음).

## 독립 검토에서 발견한 보완

- 이동 후 선택 재검사 중 공간 전환이 검사를 취소하면서 이전 선택을 다시 적용 가능하게 만드는 경합.
- 이전 공간의 늦은 POST 실패가 같은 도메인의 새로운 문서 선택까지 무효화하는 경합.
- 열린 문서를 이동해도 주소의 폴더가 갱신되지 않아 새로고침 시 뷰어 복원이 실패하는 문제.
- 이동 처리 중 모든 버튼이 비활성화되면 Tab 초점이 확인 창 밖으로 빠지는 문제.

각 문제는 보완 전 실패하는 검증으로 재현했다. 열린 뷰어의 capture Escape 처리도 이동 확인 창이
열린 동안 잠시 비활성화해 확인 창만 먼저 닫히도록 기존 소비자 연결을 보완했다.
같은 공간의 폴더 뒤로가기에도 선택 검증 의무를 먼저 정리하고, 늦은 복구 조회는 닫히거나
교체된 뷰어를 복원하지 않는다. 같은 열린 문서는 최신 선택 버전을 유지하면서 새 폴더 위치를
반영해 주소 복원을 보장한다. 이 항목들은3차 독립 재검토에서 모두 해소됐고 최종 통합 검토/수정 후 재검토도 마쳤다.

최종 통합 검토는 이동 성공 후 목록 재조회가 실패한 상태에서 오래된 행을 새로 열거나 선택하는
경로를 추가로 발견했다. 처음 선택이 비어 있으면 기존 선택 재검사가 이 경로를 보호하지 못한다.
목록 복구가 끝나기 전에는 오래된 문서 행의 열기·선택을 막고 안내하도록 보완했다.
새 회귀를 포함한 집중8건이 통과했고 독립 재검토에서 기능/정합성 관련 Important는 해소됐다.

## 남은 경미한 UI 항목

복구 중 기존 뷰어를 닫으면 초점 복귀 대상 문서 버튼이 비활성화돼 폴더 제목 대신 본문으로
초점이 빠질 수 있다(`DocumentBrowser.tsx`의 `closeDocument`). 버튼이 disabled이면 제목을
선택하는 후속 보완과 초점 회귀 검사를 남겼다. 데이터/검색 범위 오류는 아니지만 키보드 탐색에
불편이 있다. 최종 검토의 이 조건을 완료로 숨기지 않고 다음 UI 작업으로 명시 인계한다.

## 실사용 적용

현재 작업에는 DB0034 migration, 기존 서버 재시작, 실사용 자료 이동, 커밋·푸시가 포함되지 않는다.
구버전 응답에 revision이 없으면 UI에서 이동을 활성화하지 않는다. 실제 저장 확인은 별도
백업·복원·서버 버전 정합성 확인 이후 진행한다.

추가 라이브러리는 설치하지 않았다. 기존 main 미커밋 변경과 사용자 자료는 보존했다.
검증용 API는 메모리 자료만 사용하고 종료했다. 미커밋 인계 기록·별도 Next 검사 산출물은
프로젝트 캐시 정책의 별도 조사/승인 없이 삭제하지 않았다. 루트에 테스트 파일을 추가하지 않았다.
