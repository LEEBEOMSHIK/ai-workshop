# 실행 모니터링 스타일·사용 안내 — 2026-09-30

ISSUE-00005 후속. 사용자 요청에 따라 실행 모니터링의 기본 브라우저 입력창·버튼과 과도한 카드 강조를 관리자 스타일에 맞춘다. 프론트엔드 구현과 독립 검증을 분리하며 기존 환경·계정·실행 자료를 유지한다.

## 사용 순서

1. RAG 대화에서 질문하거나 비교 실험을 실행한 후 **관리자 → RAG 관리 → 실행 모니터링**을 연다. 이 화면 조회는 질문을 다시 실행하지 않는다.
2. 질문 검색과 실행 상태·답변 상태를 고르고 **조회**한다. **추가 필터 · 실행 종류·기간·구성·단계**의 실행 종류로 실제 대화와 평가를 구분한다. 새 기록이 필요하면 조회를 다시 누른다.
3. 목록의 질문을 누르면 저장된 답변과 **처리 단계**가 보인다. 실패 표시·오류 코드와 각 단계 소요 시간을 확인한다. 근거 부족은 실행 실패와 별개다.
4. **검색 근거·유사도·선택 사유**를 펼쳐 문맥 코사인, 키워드 충족률, BM25/Dense/RRF와 제외 사유를 확인한다. 후보 원문이나 실제 답변 인용 원문을 열어 대조한다.
5. 기존 대화가 연결돼 있으면 **기존 대화 열기**, 평가 실행이면 **품질 평가 → 연결된 평가 사례**로 이동한다.

처리 완료·높은 유사도·인용 유효성만으로 답변의 정답 여부가 보장되지 않는다. 이전 기록의 시간·단계 미기록은0초로 해석하지 않는다. 통계는 접근 권한을 통과한 현재 필터의 전체 결과 기준이다.

## 구현·검증 기록

- 관리자 색상·간격·테두리, 어두운 입력/선택창과44px 조작 영역, 포커스 표시를 적용했다. 목록은 행 형태로, 상태는 일반 텍스트로 구분했다. 상세 답변과 처리 단계는 보이고 검색 후보 진단은 기본 접힘이다.
- 접힌 사용 안내와 검색 진단의 기본 상태를 먼저 테스트해2개 실패를 확인한 뒤 수정했다. 프론트 관련4개·전체 TypeScript·변경 TSX ESLint 통과.
