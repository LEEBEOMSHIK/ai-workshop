# 실행 목록 초기 조회 개선과 모바일 업무 화면 확인

2026-10-26 · ISSUE-00042, ISSUE-00040. 기존 기능·답변 품질 보존을 우선한 목록 읽기 최적화다. 생성 모델 호출은 0회이며 생성·검색·프롬프트·인용·백그라운드 실행 코드는 변경하지 않았다.

## 원인과 반영

전체 통계와 현재 권한을 확인하기 위해 목록이 모든 대화와 평가 실행을 복원한다. 대화는 ID를 얻기 위해 전체 응답을 먼저 검증한 뒤 같은 행을 다시 읽었고, 평가 run은 순차 조회하며 목록에서 쓰지 않는 중복 bytes와 이미 계산한 digest를 다시 처리했다.

제품 변경은 백엔드 4파일에 한정했다.

- 대화 ID만 열거한 뒤 기존 최초·최종 읽기, 의존 관계·현재 ACL·trace·숫자 증명을 그대로 검증한다.
- 평가 종류만 요청하면 대화를 읽지 않는다. 기존 대화 전용의 평가 생략과 대칭이다.
- 평가 목록에서 미사용 snapshot_bytes/result_bytes만 defer/raiseload한다. 상세의 기본 읽기는 유지한다.
- 방금 계산한 규칙 판정의 result/rule digest를 reviewer 일치 검사에 재사용한다. 저장된 digest를 무검증으로 신뢰하지 않는다.
- 평가 run을 최대 4개 독립 session worker로 읽는다. 결과 순서를 복원하고 오류·취소 시 모든 형제 작업 정리를 기다린 뒤 원래 예외를 전달한다. run 전체의 fail-closed와 전후 권한 검사를 유지한다.

snapshot 근거 식별자 재사용은 변경 탐지 복잡성 때문에 제외했다. 권한 결과 캐시, 모델 전환, 통계 생략, 필터/페이지 의미 변경은 없다.

## 실제 시간과 동등성

기존 단일 owner의 동일 DB·요청, 전체508건/첫 페이지25건을 읽기 전용 연결로 비교했다. 본문 대신 건수·시간·응답 해시만 저장했다. 변경 전에는 보존한 이전4모듈을 계측 프로세스 안에서만 로드했으며 제품 파일/API를 되돌리지 않았다.

| 프로파일러 없는 서비스 조회 | 변경 전 | 변경 후 | 감소 |
|---|---:|---:|---:|
| 첫 비교 | 23.124초 | 17.588초 | 23.9% |
| 재비교 | 23.205초 | 16.754초 | 27.8% |
| 두 번 평균 | 23.164초 | 17.171초 | 25.9% |

네 응답 SHA-256은 모두 `7bbdf96f0d940b21f473565c204f5018a03270451acaa2a7cd1b8ca9aea5d048`로 같다. 전체 통계·순서·cursor·질문 요약을 포함한 응답 일치다. 대화 SQL331→295회, 평가1,863회는 유지된다. 동시 SQL의 측정 시간 합은 wall time보다 클 수 있으므로 처리 전체 시간으로 해석하지 않는다.

원인 진단용 cProfile은 변경 전29.93초, 첫 최소 수정29.94초였다. 이 단계만으로 개선을 선언하지 않고 worker를 추가했다. 최종 비교는 프로파일러 오버헤드를 제외한 위 표를 사용한다. 표본2쌍은 일반 P95나 모든 사용자 부하를 보장하지 않는다. **16.8~17.6초는 여전히 길며 즉시 조회 수준의 해결은 아니다.** 전체 권한·숫자 증명·품질 판정을 반복 복원하는 비용은 후속으로 남긴다.

## 검증과 본래 환경

- 구현 회귀238개, 독립 회귀250개(ACL/trace/retention/numeric/기존 실행247 + 별도 고유 session·오류·취소3) 통과. 두 수치를 합산하지 않는다.
- 변경 제품4파일 strict Mypy, 제품/테스트8파일 Ruff 통과. 신규 회귀는 수정 전 실패를 확인했다.
- 진행 중 업무0을 확인해 기존 API만 동일 Conda·루트·127.0.0.1:18000으로 반영했다. health/ready200, 기존 대화202/201/200 계약 유지.
- 본래 로그인 화면에서 전체508건, 대화 필터25건, 저장된 대화 실행 상세의 생성 답변·인용2개·28근거와 단계 표시를 확인했다. 새 모델 실행은 하지 않았다.
- 반영 전후 업무25테이블2,560행의 PK별 해시와 `.env`가 같다. 계정/자료/모델/프로파일/기존 취소 상태를 보존했다.

## 모바일 수용 범위

실제 제품 React 컴포넌트와 CSS를 합성 자료로 렌더링했다. 별도 DB·계정은 없으며 실제 API/외부 요청·저장은 차단했다. Chrome 연결이 viewport 변경을 제공하지 않아 동일 출처 iframe의 실제 innerWidth/innerHeight를 표식과 함께 확인했다. 휴대전화 Safari/Chrome의 주소창·가상 키보드·터치 장치 검증과 구분한다.

- 320/375px 실행 목록, 320px 추가 필터 및 긴 질문 줄바꿈: 페이지 가로 넘침 없음, 검사한 조작 요소44px 이상.
- 320px 모델 관리5개 탭과 도메인 등록/연결 폼: 가로 넘침 없음, 검사한 조작 요소44px 이상. 실제 저장 없이 확인했다.
- 320×640/375×812px 문서 선택 모달: 긴 파일명, 선택 적용, Shift+Tab 순환과 Escape/열기 버튼 초점 복귀. 선택1개 적용은 합성 상태만 바꾼다.
- 320×640/375×812px 단계 흐름·상세 모달: 가로 넘침 없음, 조작 요소44px 이상. 상세 열기·Shift+Tab·도움말 Escape·모달 Escape와 노드 초점 복귀 확인. 합성 script 문자열은 문자로 표시됐다.
- 320px 메뉴 열기·Escape·메뉴 버튼 복귀 확인.
- 320×640px 실행 로딩·오류·빈 상태: 넘침 없음·조작요소44px 이상. 로딩 중에도 메뉴를 열고 닫을 수 있으며 오류 재시도와 빈 결과 안내를 확인했다.

이 범위에서 추가 제품 UI 결함은 재현되지 않아 스타일을 임의로 바꾸지 않았다. 전체27route·모든 권한/모달 상태의 모바일 통과로 확대하지 않는다.

## 후속과 근거

다음 성능 단계는 전체 통계/현재 권한 계약을 유지하는 목록 전용 검증 읽기 설계와 실제 부하 비교다. 단순 캐시나 무검증 요약으로 권한·숫자 증명을 생략하지 않는다. 기존 답변 품질 실패/첫 입력 지연 한계는 이번 목록 개선으로 해결했다고 보고하지 않는다.
