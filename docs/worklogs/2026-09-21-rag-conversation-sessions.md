# RAG 대화 세션·첨부·검색 진단 구현

## 구현 범위

승인 설계: [대화 세션 UX](../superpowers/specs/2026-09-21-rag-conversation-sessions-ux-design.md).
기존 main checkout과 원래 DB를 사용했다. 별도 worktree·DB·계정·업로드 문서를 만들지 않았다.

- 소유자·도메인별 서버 세션 목록, 생성, 복원, 제목 변경, 삭제와 turn 저장을 추가했다.
- 요청 ID 재사용, revision 검사, 취소/삭제 이후 늦은 완료 차단, 실제 종료 기록을 분리했다.
- 현재 문서 권한으로 저장 응답과 파생 응답을 가리고 외부 history에는 현재 자료 승인도 재검증한다.
- 문서/연결 변경은 새 문맥 구간으로 기록한다. 기존 본문을 지우거나 클라이언트 snapshot을 가져오지 않는다.
- 입력창 `+`에서 기존 문서를 선택하거나 PC 파일을 첨부한다. 선택 제외는 원본을 삭제하지 않는다.
- 첨부는 기존 소유 개인/임시 공간과 도메인 허용 범위의 교집합에만 저장한다. 본문 수신 전 예약하고 최종 원본 연결에서 세션/권한을 재확인한다.
- 첨부 준비는 Platform 원본, 정확한 Projection 및 활성 READY index build를 확인한다.
- 검색 진단은 기본 수집하며 응답에서 원점수·문장/문맥 cosine·선택 사유·단계 시간을 확인한다. 점수를 정답 확률로 표현하지 않는다.
- 근거 미선택과 모델의 근거 불충분 판단을 구분한다. 모델 실행 예외로 응답 자체가 없으면 검색 snapshot은 제공되지 않는다.

## 원래 환경 적용

기존 DB의 복구용 dump를 비추적 백업 위치에 보관한 뒤 migration0049/0050을 적용했다.
적용 후 users1/workspaces3/documents3/asset_versions3/projections3을 확인했다.
실제 SQL owner 제한·예약/replay·tombstone 종료 기록을 바깥 트랜잭션으로 검증하고 전부 롤백했다.
검증 행이 남지 않았음을 확인했다. 실제 다중 연결 동시 실행은 이번 SQL 검사 범위에 포함하지 않았다.

기존 모델·검색 설정·의미 임계값0.9를 유지하며 `rag-codex-answer-v4`와 문맥 예산8그룹/32단위/12000자로 구성v4를 등록했다.
실제 Codex 연결 검사, 기존 고정 데이터셋 2회 반복 평가와 정책 게이트를 정상 서비스로 통과했다.
기존 도메인의 연결2로 활성화했으며 search/answer/service 준비 상태가 모두 true다.
모델 requested ID는 gpt-5.5이며 observed ID는 확인되지 않아 unknown으로 유지한다.

원본 자료에 특정 질문용 문자열 분기를 추가하지 않았다.

## 검증과 제한

- 백엔드 RAG: 1803통과/4skip. 첨부 종료 재확인 후 conversations29통과.
- 프론트 대화50통과, Codex 설정16통과. TypeScript와 ESLint 통과.
- Python mypy202파일, 변경 파일 Ruff 통과. OpenAPI 재생성.
- 독립 리뷰의 tombstone 종료·첨부 READY 조건·업로드 polling/다중 선택 경합을 수정하고 재검토했다.
- API를 기존 `.env`/18000으로 재시작했다. 별도 sandbox 자원은 삭제하지 않았다.

브라우저 로그인 세션이 만료되어 마스터 재로그인을 요청했다. 실제 화면의 저장→새로고침→이어가기·인용 확인은 재로그인 후 남아 있다.
서버 저장 도입 전에 사라진 화면 메모리 대화는 복원하지 못한다.

현재 자산운용 도메인은 company 공간만 연결되어 PC 첨부가 비활성화된다. 기존 문서 선택은 가능하다.
개인 저장 공간을 임의 생성하거나 공유 범위를 확대하지 않았다.

삭제된 첨부는 `cleanup_waiting`과 차단 사유를 기록한다. 소유자 전용
`GET /api/v1/rag/domains/{slug}/conversation-attachment-cleanup`에서 종료/참조 미확인 상태를 조회하고 재검사한다.
완전한 참여자 inventory와 실제 writer 종료 증거가 없는 원본은 보존한다. 자동 물리 정리는 구현/활성화하지 않았다.
