# 관리자 모델 연결·RAG 설정 통합

2026-10-30 사용자 요청에 따라 모델 등록·선택·검증·적용과 기존 RAG 재사용을 한 화면으로 연결했다.
[화면 열기](http://127.0.0.1:5173/admin/rag/setup),
[ISSUE-00046](http://127.0.0.1:5173/admin/system/issues?offset=0&issue=a884a457-f700-4772-935e-235d0a804dcd).
중간위험 UI/API 작업으로 메인 통합, 별도 Python/모델 UI 구현, 독립 권한·개인정보·회귀 검토를 분리했다.
기존 checkout과 계정·DB를 사용했다. 새 환경·계정·모델 호출·패키지 설치·commit/push는 없다.

## 사용 경로와 변경

왼쪽 **관리자 → RAG 관리 → 모델 연결·RAG 설정**에서 시작한다. 기존 모델 레지스트리와
RAG 구성 스튜디오에도 같은 간편 설정 링크가 있다.

1. 기존 연결을 고르거나 OpenAI/로컬 HTTP·Ollama 연결을 등록한다. 새 모델 정의는 같은 폼에서
   생성하거나 기존 정의를 재사용한다. 주소·키 값은 서버가 관리하고 화면에는 안전한 참조 이름만 반환한다.
2. 기존 구성의 문서 처리·색인·검색 프로파일, 지식 공간, 인용·충돌 정책과 임계값을 복사한다.
   호환되는 답변 설정을 그대로 가져오거나 공급자별 기본 후보를 명시적으로 선택한다.
   추출식 기반은 생성형으로 바뀐다는 별도 확인을 받는다. 새 후보는 기존 활성 구성을 수정하지 않는다.
3. 연결 상태와 답변 품질을 따로 확인한다. 생성형 평가의 서버 수용 응답이 정확한 후보 버전에
   해당해야 적용 단계가 열린다. 검색 평가의 passed나 정상 health만으로 답변 품질 통과를 표시하지 않는다.
4. 최신 준비 상태·현재 도메인 연결을 확인하고, 기존 도메인의 지식 공간을 보존한 새 연결을 명시 적용한다.
   전체 검색 기본값은 변경하지 않는다. 저장된 비활성 연결은 실패 후 재확인할 때 재사용한다.

서버 API는 owner 전용 `GET /api/v1/admin/rag/deployment-setup-options` 하나를 추가했다.
URL·비밀값을 반환하지 않고 `Cache-Control: no-store`를 사용한다. 조회 중 모델/외부 API/DB 쓰기는 없다.
기존 생성 런타임의 계약에 맞춰 OpenAI Responses는 schema1, 로컬 HTTP는 schema2 기본 후보를 제공한다.
기존 로컬 전용 설정을 OpenAI용으로 조용히 축소·변환하지 않는다.

등록·프로파일·구성의 부분 성공을 보존하고 응답 유실 시 저장 목록과 대조한다. 연결 등록의
성공 여부가 불확실하면 재등록을 잠근다. JSONB 키 순서 차이를 동등 비교하고, 후보 저장 성공 후
동일 입력의 반복 저장도 막는다. 이전 연결의 늦은 결과가 현재 선택을 덮지 않는다.
평가 후보 변경은 외부 전송 확인을 초기화한다. 간편 화면의 평가 수용·재시도는 선택한 정확한
버전에 제한하며 기존 고급 화면의 이력 접근은 보존한다.

이 이슈 저장은 위 DB 동일성 대조 이후의 의도된 관리 이력 추가다.

## 운영 준비와 한계

- 현재 서버에는 일반 대화용 OpenAI endpoint/secret 참조가 없다. 실제 폼에서 준비 안내와 등록
  비활성을 확인했다. `.local-data/openai-comparison.env`의 비교 전용 키를 이동하거나 서버 설정을
  바꾸지 않았다. 승인된 서버 참조 준비 → 등록 → 새 후보 품질 평가 → 명시 적용이 다음 운영 순서다.
- 등록·선택은 추론을 실행하지 않는다. 연결 확인은 provider의 기존 health 경로를 사용하며,
  답변 품질은 실제 평가 버튼으로 별도 실행한다. 이번 작업의 실제 모델 호출·추가 API 비용은0이다.
- 기존 완료 평가를 다시 수용해 화면의 정확 버전 수용 확인을 복구할 수 있다. 새 모델 호출은 없다.
  간편 화면은 최근 목록에서 해당 후보가 포함된 평가를 보여 주며 더 오래된 기록은 고급 평가 화면에 있다.
- 기존 활성화 API는 조건부 갱신(CAS)을 지원하지 않는다. 적용 직전 재조회로 변경을 확인하지만
  마지막 GET과 POST 사이 다른 관리자의 변경까지 원자적으로 막지는 못한다.
- 최초 검색 전략·색인·지식 공간 설계는 기존 고급 화면 범위다. 간편 구성은 기존 검색 기준을 재사용한다.
- 새 모델의 품질 통과나 기존 Gemma의 의미 오류 해결을 주장하지 않는다. 기존 모델·프롬프트·
  검색·인용 검사·활성 연결·저장 답변은 유지했다.

## 후속: OpenAI 모델 선택 목록과 고급 메뉴 구분

사용자가 ID를 몰라도 고를 수 있도록 공개 모델 이름 선택을 기본으로 바꾼다. 모델별 이름·ID·
최초 공개일·공식 출처·확인일을 버전된 JSON 카탈로그에 두고 공개일 내림차순, 같은 날은 이름순으로
정렬한다. 성능 순위·계정별 권한 목록·실시간 전체 목록이 아니며 서버 인증이 없어도 조회할 수 있다.
목록 밖 모델 ID는 명시적인 고급 직접 입력으로, 로컬 모델은 설치된 ID 입력으로 보존한다.
모델/공급자/입력 방식 변경 시 이전 ID 또는 지원 기능 확인을 재사용하지 않는다.

공식 확인일은 2026-10-30이며 [API 변경 이력](https://developers.openai.com/api/docs/changelog)과
개별 모델 문서의 Responses·텍스트 출력·구조화 출력 지원을 교차 확인했다.

| 모델 | 최초 공개일 | 공식 모델 문서 |
| --- | --- | --- |
| GPT-6.1 Terra | 2026-10-26 | [모델 ID·API](https://developers.openai.com/api/docs/models/gpt-6.1-terra) |
| GPT-6.1 Sol | 2026-09-29 | [모델 ID·API](https://developers.openai.com/api/docs/models/gpt-6.1-sol) |
| GPT-6 Luna | 2026-09-22 | [모델 ID·API](https://developers.openai.com/api/docs/models/gpt-6-luna) |
| GPT-6 Sol | 2026-09-22 | [모델 ID·API](https://developers.openai.com/api/docs/models/gpt-6-sol) |
| GPT-6 Astra | 2026-09-03 | [모델 ID·API](https://developers.openai.com/api/docs/models/gpt-6-astra) |

API 생성 시각이나 최근 기능 갱신일을 최초 출시일로 사용하지 않는다. 새 모델이 출시되면
카탈로그·공식 출처·확인일을 함께 갱신해야 한다. 현재 계정의 권한과 실제 앱의 생성 파라미터·
답변/인용 품질은 연결·평가 단계에서 확인해야 한다. 특히 공식 9월3일 이력은 Astra의 custom
temperature 미지원을 명시하지만 현재 OpenAI 어댑터는 profile.temperature를 전송한다.
[최신 모델 마이그레이션 가이드](https://developers.openai.com/api/docs/guides/latest-model)의
Update API and model parameters는 reasoning이 none이 아니면 temperature를 제거하도록 안내한다.
현재 어댑터는 reasoning을 지정하지 않으므로 다른 최신 모델도 기본값과의 충돌 가능성이 있다.
이는 소스·공식 계약 대조이며 이번에 실제 API 오류를 재현한 결과는 아니다.
따라서 공개 기능 지원만으로 이 앱의 실제 실행 호환성을 단정하지 않는다. 이번 화면 수정은
런타임을 변경하거나 해당 모델의 품질을 수용하지 않으며, 파라미터 호환성 보완은 후속이다.

일상 진입점은 **모델 연결·RAG 설정**으로 유지하며 상위 **관리자** 이동도 이 경로로 연결한다.
기존 메뉴는 **RAG 구성 · 고급**, **RAG 모델 · 고급**으로 구분하고 상세 관리 URL·기능은 유지한다.
프론트엔드/설계·테스트 담당과 독립 검토를 분리했으며 서버 API·DB 스키마·추론·자격 증명
변경은 범위에 포함하지 않는다.

후속 검증 결과:

- 신규/변경 패널·카탈로그 25개 RED→GREEN, 설정·기존 등록 경로 포함86개 및 탐색66개 통과.
- 독립 108개 통과, 마지막 공개일 상세 표시 보강 뒤 패널·카탈로그25개 재실행 통과. 중복 범위를 합산하지 않는다.
- 전체 frontend TypeScript와 변경 TS/테스트 ESLint 통과. 탐색 테스트의 잘못된 옵션 한 건을 수정하고 최종 재실행했다.
- 본래 관리자 계정에서 고급 모델 레지스트리·RAG 구성 이동, 상위 관리자→통합 설정 진입, 실제 최신순 옵션·선택 ID·서버 미준비 등록 차단을 확인했다.
- 실제320/375px에서 문서 폭305/360px과 scrollWidth 일치(가로 넘침0), select44px, desktop 방향키 선택·2px 포커스 확인. 작은 폭에서는 잘릴 수 있는 선택 항목의 공개일을 아래에 전체 표시했다. 임시 viewport는 복원했다.
- 독립 전후 대조에서 `.env`, 서버 추론 런타임·옵션·프로파일 파일 해시가 동일하다. 이번에는 DB 전체 보존 스냅샷을 새로 측정하지 않았으며 모델 등록/평가/활성화 쓰기를 하지 않았다. 의도된 쓰기는 관리 문제 이력뿐이다.
- 신규 모델/외부 추론 호출0·추가 API비용0·서버 재기동0. 공개 카탈로그는 2026-10-30 확인본이며 실시간 자동 갱신이 아니다.
