# 지식 공간 생성 UI 보완

## 범위

기존 공간 생성 API에 이름·유형·명시적 생성 버튼을 연결했다. 관리자 메뉴 재구성은 별도 설계 선택 대기이며 이 변경에 포함하지 않는다.

- `WorkspaceCreateForm.tsx`와 CSS: 이름, 유형, 임시 공간 만료 일시, 생성 중·성공·실패 안내.
- `WorkspacePage.tsx`: 서버가 반환한 실제 공간만 목록에 반영하고 기존 문서 관리 링크를 유지.
- `api.ts`: 생성 요청·응답에 기존 생성 타입 적용.
- 작업소 공간 페이지: 기존 서버 세션의 owner 여부를 전달. 인증·권한 계약 변경 없음.
- 두 테스트 파일: 명시적 제출, 중복 제출 방지, 오류, 만료, 이름과 역할별 표시 검증.

## 유지한 계약

전사 공간 생성은 owner만 가능하고 개인 공간은 사용자당 하나다. 임시 공간은 미래 만료 시각이 필요하며 입력은 장치 현지 시각, 전송은 ISO 시각이다. 최종 권한과 유효성 판정은 기존 서버가 수행한다. 입력 변경만으로 저장하지 않으며 실패 시 입력과 기존 목록을 유지한다.

## 검증

메인 직접 실행: 관련 Vitest 11개/2파일 통과(12.58초), TypeScript와 변경 TS/TSX ESLint 종료 코드 0. 독립 리뷰에서 중대 문제는 없었고, 긴 무공백 이름의 성공 안내문 줄바꿈 보완을 권고했다.

후속 보완으로 폼에 `overflow-wrap: anywhere`를 추가했다. 메인이 실제 CSS와 재동결 패치의 역적용 검사를 확인했다. 최종 패치 SHA256: `081f684f1d9ede0f1f18348413baafa843704ff61eb53f04ab4e7342c08ab24b`. 장문 성공 안내의 실제 브라우저 재현은 별도 수행하지 않았다.

실제 로그인된 owner 화면 약 1174px에서 생성 폼, 만료 안내, 기존 두 공간 및 초기 가로 넘침 없음을 읽기 전용으로 확인했다. 실제 공간 생성·모바일·시간대별 검증은 하지 않았다. 만료 테스트는 ISO 변환 전달 검증이며 독립적인 시간대 실측은 아니다.

## 다음 경계

내비게이션은 현재 위치 강조가 없고 관리자·작업소 이동 때 메뉴 목록이 바뀐다. 공통 영역 전환과 영역별 메뉴의 2단 구조를 제안했으며 사용자 선택 후 구현한다. 기존 권한 경계는 유지한다.

이 UI 보완은 실제 Codex RAG 답변·인용·후속 질문의 전체 검증 완료를 뜻하지 않는다.
