# 로그인·파일 관리 스타일 및 초점 보완

- 승인 범위: 로그인 스타일 통일, 경로/루트 버튼 스타일, URL 복원된 문서 닫기 초점.
- 상태: 구현·자동 검사·실제 화면 확인·독립 리뷰 통과.

## 변경

LoginPage 전용 CSS module로 작업소의 어두운 배경·청록 강조색·간결한 글꼴을 적용했다.
읽기 편한 중앙 카드와 반응형 여백을 유지하며 링크 visited, hover, focus와 오류/진행 상태를
표현한다. 기존 PublicNavigation은 수정하지 않고 로그인 영역에서만 강조색을 적용했다.
인증 API·세션·safeReturnPath·라우트·문구 의미는 변경하지 않았다.

파일 관리의 기본 흰색 경로/루트 버튼은 공통 폴더 버튼 스타일과 현재 선택 표시를 적용했다.
닫기 초점은 클릭 시 저장한 단일 opener가 아니라 문서 ID별 현재 DOM 버튼에서 찾는다.
URL 복원된 문서가 현재 페이지에 없으면 다른 문서로 이동하지 않고 현재 폴더 제목에 초점을 둔다.

## 검증

- 로그인 busy 속성 누락 및 URL 복원 초점 3건의 실패를 확인한 뒤 구현했다.
- 구현자 관련65건·TypeScript·범위 ESLint 통과. 메인도 최종9파일65건(44.39초)·타입·린트 통과.
- baseline 대비6파일 패치 역방향 적용 검사 통과. 기존 dirty main의 다른 변경은 포함하지 않았다.
- 실제 브라우저에서 로그인 데스크톱·390px 배치를 확인했다. 과한 배경 효과·명조체 제목·기본
  보라색 링크가 제거되고 카드·입력·청록 버튼이 표시된다. 입력/인증 제출 및 로그아웃은 하지 않았다.
- 기존 합성 문서 URL을 직접 열고 닫아 정확한 파일 열기 버튼에 초점이 돌아오는 것을 확인했다.
  경로·루트 버튼도 어두운 배경 및 청록 선택 스타일로 표시된다. 임시 화면 크기는 원복했다.
- 독립 리뷰에서 필수 수정 없음으로 승인됐다. 추가 확인 메모였던 로그인 nav 포커스는 실제
  Tab 이동 후 computed outlineColor가 rgb(85,217,201)로 확인됐다. hover는 코드 검토 근거이며
  실제 포인터 hover 관찰과 구별한다.
- 서버·사용자 자료·승인·DB·패키지 변경 없음. 전체 build나 무관한 전체 테스트 완료를 주장하지 않는다.
