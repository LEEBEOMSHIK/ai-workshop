# 학습 실행 순서 표시

## 요구와 설계

사용자는 계획 기록과 실제 실행 기록의 관계, 학습한 순서를 목록에서 바로 확인하기를 요청했다. 기존 목록은 수정일 내림차순으로만 표시하며 실험 상태도 목록 응답에 없다. 수정일이나 제목으로 실행 순서를 추측하지 않는다.

기존 experiment JSON에 선택적인 `learning_sequence`를 추가한다. `series`는 같은 학습 흐름의 이름, `step`은 명시적으로 입력한 양의 실행 차수(계획은 null), `performed_on`은 실제 실행일(미기록은 null)이다. 계획은 번호·실행일 없이 같은 흐름에 속할 수 있다. 메모와 미입력 기록에 임의 번호를 매기지 않는다. 기존 자료는 기본 null로 호환한다. 기존 참조 기능은 유지하며 일반 참조를 모델 계승 관계로 추정하지 않는다.

목록 응답은 실험 상태와 학습 순서 정보를 포함한다. 학습 흐름 정렬은 서버에서 전체 필터 결과에 적용하고 같은 흐름에서 실제 차수를 오름차순으로 표시하고 계획은 별도로 구분한다. 수정일 정렬도 선택 가능하다. 페이지 일부를 재정렬해 전체 순서라고 부르지 않으며 커서는 정렬 방식에 맞게 검증한다. 저장된 차수는 필터·페이지·편집으로 다시 매기지 않는다. 흐름 이름과 차수는 사용자가 입력한 기록 정보이며 자동 실행 이력이나 계승 검증을 뜻하지 않는다.

목록은 한 줄씩 읽는 흐름형 카드로 변경한다. 실제 실행을 1·2·3차 순으로 보여주고 관련 계획은 실행 연결선 밖에 둔다. 계획/실행 상태, 차수, 실제 실행일, 제목, 흐름 이름을 구분하며 수정일은 보조 정보로 남긴다. 제목은 한글 단어 단위로 줄바꿈한다. 상세와 편집에도 같은 정보를 제공한다. 프로젝트 색상·공통 컴포넌트·라이트/다크 토큰을 재사용한다.

기존 확인된 실행 세 개에 같은 흐름의 1·2·3차 및 실제 날짜를 인증된 화면에서 입력한다. 관련 계획에는 흐름만 지정한다. 저장 본문을 확인한 결과 이 계획은 선행 실험을 참조하는 후속 계획이므로 최초 실행 이전 단계로 표현하지 않는다. 기존 본문·질문·평가·결과는 보존한다. 모델 호출·재학습·서비스 모델 변경은 없다.

## 대안과 범위

- 수정일·등록일 정렬만 사용하면 편집 또는 뒤늦은 기록 등록을 실제 학습 순서로 오인하므로 사용하지 않는다.
- 제목에 번호를 붙이는 방식은 제목과 상태를 섞고 다른 기록에서 재사용할 수 없어 선택하지 않는다.
- 명시적인 선택 메타데이터와 정렬을 추가한다. 기존 JSON 저장 방식을 유지하여 DB 테이블 migration은 필요 없다.

## 검증 계획

미입력·계획·실행·같은 날짜·다른 흐름·편집 후 순서 유지, 필터와 여러 페이지, 정렬 커서 교차 사용, 소유권, JSON 저장 왕복을 확인한다. 프론트엔드 목록·편집·상세 회귀와 타입·린트, 백엔드 관련 단위·통합·타입·린트, OpenAPI 타입 일치를 검증한다. 본래 화면에서 저장·새로고침과 라이트/다크·좁은 폭·키보드를 확인한다. 구현과 독립 검토를 분리한다.

## 구현과 검증 결과

- 백엔드 `platform/learning/{schemas,repository,service,api}.py`에 선택 메타데이터, 요약 상태, 서버 전체 정렬과 정렬별 서명 커서를 추가했다. 기존 JSON을 사용하므로 새 migration은 없다. 흐름 이름은 서비스 제목 길이 제한, 차수는 양의 32비트 정수로 검증한다. 계획에는 차수·실행일을 허용하지 않는다.
- 프론트엔드 `features/learning/LearningSequence.tsx`와 전용 CSS·회귀 테스트를 추가하고 목록·편집·읽기·API 타입을 연결했다. 기존 SelectField·상태 표시·디자인 토큰을 재사용한다. 학습 흐름순이 기본이며 최근 수정순을 선택할 수 있다.
- 백엔드 관련 테스트 73건, 프론트엔드 관련 테스트 47건, 대상 Ruff·Mypy·TypeScript·ESLint 통과. 독립 검토에서 단위 33건, 프론트엔드 24건과 실제 PostgreSQL의 합성 데이터 통합 1건을 별도로 확인했고 차단 결함은 없었다. OpenAPI 타입을 갱신했다. 이번 작업에서 전체 운영 빌드는 재실행하지 않았다.
- 본래 서버의 진행 중 실행이 없음을 확인하고 기존 실행 방식·환경으로 API만 재시작했다. health와 새 응답 계약을 확인했다. 기존 계정·DB·로그인을 유지했다.
- 인증된 편집 화면에서 기존 실행 3건에 같은 흐름의 1·2·3차와 확인된 실행일을 저장했다. 관련 후속 계획에는 흐름만 지정했다. 네 기록 모두 저장 후 다시 열어 기존 폼의 본문·설정·결과가 보존됨을 비교했다. 날짜는 실제 키보드 입력과 재조회로 확인했다.
- 기존 Chrome에서 학습순/수정순 전환, 주제 필터 후에도 1·2·3차 유지, 상세 표시, 라이트·다크 및 키보드 포커스를 확인했다. 375px·320px에서 가로 넘침이 없었고 긴 제목은 세로로 줄바꿈됐다. 임시 화면 폭과 테마는 원래 상태로 복원했다.
- ISSUE-00051에 위 결과를 진행 이력으로 저장하고 재조회했다. 모델 호출·재학습·서비스 모델 변경은 수행하지 않았다.

## 남는 경계

차수는 명시적으로 기록한 실행 순서다. 모델 가중치의 계승 관계를 자동 증명하지 않으며, 같은 흐름의 차수 중복을 전역 유일 제약으로 제한하지 않는다. 미입력 기록은 임의 차수 없이 표시한다. 작업 범위의 코드·문서는 기존 미커밋 변경과 함께 보존했고 커밋·푸시는 하지 않았다.
